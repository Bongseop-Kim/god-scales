# 신들의 저울 — 실행 계획 색인

`plans/00-index.md` · 시드 문서 세트는 `seed/` 에 있다 (01 시드 / 02 백로그 / 03 게임 규칙 / 04 기술 설계 / 05 준비물)

**이 디렉터리의 용도**
**파일 하나가 세션 하나이고, 세션 하나가 검증 하나다.** 작업할 때는 이 색인이 아니라 해당 세션 파일 하나만 연다. 그 파일에 그 세션을 끝내는 데 필요한 것이 전부 있다.

무엇을 만드는지는 03과 04에 있다. 이 디렉터리는 그것을 **언제, 어떤 검증과 함께** 만드는지만 정한다. 계획을 고쳐서 게임 규칙을 바꿀 수는 없다.

## 세션 규약

**세션의 정의는 산출물이 아니라 검증이다.** 각 파일에 실행하면 참/거짓이 나오는 명령이 하나 있고, 그것이 통과한 상태로 세션이 끝난다. 통과하지 못하면 그 세션은 끝나지 않은 것이며 다음 파일을 열지 않는다.

- 검증이 없는 작업은 세션이 아니다. 문서 수정, 리팩터링, 이름 변경은 세션 사이에 한다
- 검증은 `npm test` 또는 `npm run sim` 한 줄이어야 한다. 수동 확인은 검증이 아니다
- 각 세션은 커밋 하나 이상으로 끝나고, 검증 명령이 `README.md`에 남는다
- **세션이 계획보다 길어지면 쪼개지 말고 검증을 통과시킬 최소한만 만들고 넘어간다.** 세션의 정의는 검증이다

**소요 추정은 S-5의 가정치가 아니다.** S-5의 값은 시뮬이 보정하지만 이 추정은 1회차 실측이 보정한다. 짧음 ≈ 2~3시간, 보통 ≈ 4~6시간, 김 ≈ 8시간 이상. 전체 합은 약 90시간이며 **이 숫자가 계획에서 가장 먼저 틀릴 값이다.**

**픽스처는 I-5 위반이 아니다.** 생성기(P-06)가 동작하기 전까지 `core/`를 테스트하려면 손으로 쓴 카드·적이 필요하다. 이것들은 `core/__fixtures__/`에 두고 **`data/`에는 넣지 않는다.** I-5는 빌드에 들어가는 콘텐츠에 대한 규칙이며 테스트 기구에 적용되지 않는다. 그 경계는 P-01의 순수성 테스트가 함께 검사한다.

## 왜 이 순서인가

**이 프로젝트의 유일한 미지수는 루프가 닫히는가다.** 나머지는 평범한 작업이다. 그래서 계획은 게임을 완성한 뒤 파이프라인을 붙이지 않고, **파이프라인의 얇은 세로 절단면을 먼저 관통시킨 다음 게임을 두껍게 만든다.**

**P-06이 분기점이다.** 그 시점 이후의 실패는 "게임이 덜 재밌다"이고, 그 이전의 실패는 "논지가 증명되지 않았다"이다. 여유 시간은 전부 P-06 앞쪽에 둔다.

**P-13이 되돌릴 수 없는 선이다.** 전역 파라미터와 봇 정책을 여기서 고정하며, 이후에 바꾸면 그 이전 회차의 모든 데이터가 무효가 된다.

## 중단 지점

시간이 떨어졌을 때 어디서 멈추면 무엇이 남는지. 위에서부터 나쁘고 아래로 갈수록 낫다.

| 멈춘 지점 | 남는 것 | 말할 수 있는 것 |
|---|---|---|
| P-05 이전 | 코드 | 없음. 논지가 증명되지 않았다 |
| **P-06 이후** | 생성 → 게이트 → 시뮬 로그 | **"파이프라인이 돌았다."** 최소 성립 지점 |
| P-12 이후 | 게임 규칙 전체 + 얇은 계측 | 게임은 있으나 밸런싱 증거가 없다 |
| P-15 이후 | 조합 히트맵 + 1회차 기록 | 논지는 서지만 보여줄 게임이 없다 |
| P-17 이후 | 놀 수 있는 UI (에셋 없음) | 배포는 가능하나 화면이 골격이다 |
| **P-19 이후** | 배포된 게임 + 계측 기록 | **두 산출물이 모두 존재한다.** 제출 가능 |
| P-20 이후 | 3회차 수렴 데이터 | B-0 충족. **에셋 작업 목록이 확정된다** |
| P-21 이후 | 일러스트 · 이펙트 · 사운드 | 게임이 완성된 모습이 된다 |

**P-06과 P-19가 두 개의 진짜 마일스톤이다.** 그 사이 어디서 멈춰도 제출은 성립하지 않고, P-19 이후는 전부 강화다.

**P-18은 P-19보다 뒤로 미룰 수 있는 유일한 세션이다.** placeholder로 화면이 완성되어 있고 에셋 교체가 파일 드롭이므로(A-2.3), 배포를 먼저 하고 얹어도 된다.

**P-21이 P-20 뒤에 있는 것은 순서가 아니라 제약이다.** 카드는 회차마다 폐기·재생성되고 id가 바뀌므로(T-6 ⑤), 동결 전에 만들면 **만든 것의 일부가 존재하지 않는 카드의 것이 된다.** 일러스트·스프라이트·사운드 셋 다 해당한다 — 이펙트는 카드 효과에 붙고 소리는 사건에 붙는다.

## S-4 축소 순서와 세션의 대응

축소를 실행하면 어느 세션이 줄어드는지. S-4를 읽고도 무엇을 안 만들지 몰라 결국 다 만드는 것을 막기 위한 표다.

| S-4 | 축소 내용 | 영향 | 함께 해야 할 일 |
|---|---|---|---|
| 1 | UI 완성도 | P-17 범위 축소, P-18 연기 | 전투 1화면 + 반출 버튼만 남긴다. **버리는 것은 장식이지 전달이 아니다** — 피해 숫자가 어느 적 위에 뜨는지와 `chain` 파급 stagger는 전투 로그 가독성(B-5)과 같은 등급이다 |
| 2 | 지상 구역 제거 | P-09 축소 | R-11의 승리 조건을 지하 보스로 옮긴다 |
| 3 | 휴식 노드 제거 | P-09 축소 | **T-6 허용 손실을 전투 8/12, 보스 20/28로 함께 내린다.** 안 내리면 완주 불가 |
| 4 | 적 1체 고정 | P-11 축소 | `min_enemies > 1` 요구를 풀에서 제외한다 |
| 5 | 상충 요구 제거 | P-08 축소 | `conflict_outcomes` 지표가 사라진다 |
| 6 | 합성 카드 제거 | **P-12 삭제** | 두 봇의 `fusion_rate` 격차라는 직접 증거를 잃는다 |
| 7 | 마일스톤 2·4만 | P-10 축소 | |
| 8~10 | 총애 효과·역린·은총 축소 | P-07, P-10 축소 | 런 내 성장이 사라진다 |
| 11 | 신 4명 | 전 세션 | 조합이 6칸으로 줄어 행렬이 얇아진다 |

## 위험

**1. P-06이 닫히지 않는다.** 통과율이 0%에 가까우면 스키마가 너무 좁거나 프롬프트가 어휘를 제대로 노출하지 않은 것이다. 대응은 임계값 완화가 아니라 프롬프트 수정이다 — 임계값을 풀면 게이트가 무력해지고 파이프라인이 형식만 남는다.

**2. P-09의 HP 예산이 크게 어긋난다.** 문서가 예고한 위험이다(R-8.3). 어긋나면 적 수치가 아니라 전역 파라미터를 고치고, 동결 게이트 이전이므로 무효화되는 데이터가 없다. **이것이 P-13을 P-12 뒤에 둔 이유다.**

**3. P-17 UI가 늦어 시연이 위태롭다.** UI는 상태를 갖지 않으므로(I-3) 구조적으로 단순하지만 화면이 8개다. 최소 범위를 먼저 완성하고 늘린다. 시작할 때 남은 시간이 이틀 미만이면 전투 화면만 만들고 맵은 텍스트 목록으로 끝낸다.

**4. 구독 한도가 처리량을 제약한다.** API 키를 쓰지 않으므로 예산 대신 사용량 한도가 제약이다(A-6). 생성(P-06 등)은 총 300회 안쪽이라 문제되지 않지만, 에이전트(P-16)는 원래 설계의 2,000 판단이 성립하지 않아 **전략 층만 판단하도록 재설계했다** — 런당 ~30회, 10런. 더 필요하면 모델을 낮추지 말고 A-6.5의 조건을 보고 API로 전환한다.

**5. 세션이 계획보다 길어진다.** 가장 흔한 실패다. 대응은 위 「세션 규약」의 마지막 줄에 있다 — 쪼개지 말고 검증을 통과시킬 최소한만 만들고 넘어간다.
