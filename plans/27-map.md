`plans/27-map.md` · [◀ P-31](../reviews/31-powers.md) · [색인](../reviews/00-index.md) · [P-30 ▶](30-intervention.md)

**크기** 큼 · **착수 조건** P-25 + P-31 완료 (배치할 개성이 있어야 한다)

**실패 시 행동** 휴식이 갈래로 흩어지며 조합 하한 0.05(`npm test`)가 깨지면 **`restHealing`을 올리거나 5층 휴식 보장을 두 갈래로 넓힌다.** `enemyDamageScale`도 층 밴드 기울기도 아니다 — 기울기는 마지막 수단이다.

## 완료 정의

**갈 길을 고른다.** 그리고 고른 길에 따라 다른 것이 나온다.

```bash
npm run validate                                   # 위반 0
npm run sim -- --runs 2000 --stratified
#   → 같은 시드에서 정책 넷이 서로 다른 경로를 탄다 (경로 일치율 ≤ 60%)
#   → 층별 갈래 선택 분포가 각 20% 이상 (한 갈래로 쏠리지 않는다)
npm run sim -- --runs 2000 --stratified --policy-matrix
#   → 층별 1위 정책이 지역 안에서 최소 3종으로 갈린다
```

## 지금 상태 — 길이 하나다

`core/map.ts:10` `mapNode`는 순수 함수 열 줄이다.

```
지역 2 × 6층 = 12노드, 일렬
floor 6      → boss
floor 3, 5   → combat | rest      ← 이게 유일한 "선택"이다
나머지       → combat 만
```

`state.map.node`는 0~11 정수고 `won`은 `node === 12`다(`sim/engine.ts:425`). `encounter()`는 **지역과 seed로만** 고른다 — 층은 인자에 없어서 지하 1층과 5층에 같은 조우가 뜬다.

즉 12층 런에서 플레이어가 지도에 대해 내리는 결정은 **두 번, 그것도 "쉴까 말까"뿐이다.** 갈림길이 없다.

## 조사 — 셋 다 루트가 있고, 셋 다 방식이 다르다

### 슬레이 더 스파이어 — 전체를 보고 계획한다

막마다 17층, 층마다 최대 6칸. 1층에서 아무 칸이나 골라 시작하고 그 뒤로는 **연결된 길로만** 간다. 「가장 낮은 층과 가장 높은 층을 빼면 모든 방은 아래 층에서 1~3개의 길이 들어오고 위 층으로 1~3개가 나간다.」 길끼리 교차하지 않는다.

칸 확률: 일반 53% · 정예 8% · 휴식 12% · 상인 5% · 미지 22%.

배치 규칙이 명시적이다:

- 1층은 전부 일반 전투 — **어디로든 시작할 수 있다**
- 9층은 전부 보물, 15층은 전부 휴식, 16층이 보스
- 정예·휴식은 6층 아래에 못 온다
- 정예·상인·휴식은 **연속으로 못 온다**
- 14층에 휴식이 못 온다 (15층이 전부 휴식이라)

**막 전체가 처음부터 보인다.** 그래서 "3층에서 왼쪽으로 가면 정예 둘을 밟지만 휴식이 둘"이라는 계획이 성립한다.

### 하데스 2 — 문에 보상이 적혀 있다

한 방에 출구 최대 4개. 「방을 나설 때 문에 그 길을 골랐을 때의 **보상 미리보기**가 뜬다.」 그리고 규칙 하나 — 「출구가 여럿인 방은 같은 보상을 보여줄 수 없다. 보온이 여럿이면 반드시 다른 신의 것이다.」

앞을 멀리 못 본다. 대신 **바로 다음 한 걸음의 값어치가 정확히 보인다.**

### 다키스트 던전 2 — 도로와 갈림길, 일부는 물음표

역마차가 길을 달리고 좌측 지도에 갈래와 아이콘이 뜬다. 갈림길에서 앞의 조우 아이콘이 보인다. **일부 노드는 물음표고, 감시탑을 들르면 밝혀진다.** 영웅들이 각자 선호하는 길을 말하고, 따르면 스트레스 −1, 무시하면 +1.

### 셋의 공통점

**갈래가 종류로 갈린다.** 갈래 셋이 다 같은 전투면 고를 이유가 없다 — 하데스가 「같은 보상 금지」를 규칙으로 박아 넣은 이유다.

그래서 루트와 노드 종류는 한 몸이다. **루트 없이 종류를 늘리면 낭비고, 루트를 넣으면 종류가 필수다.**

## 설계

### 1 · 격자 — 층마다 갈래 셋

StS의 7×15를 우리 크기로 줄인다.

```
map: { depth: 0..11, lane: 0..2, completed: string[] }
```

- `depth`가 지금의 `node`를 대신한다. `won`은 `depth === 12` 그대로
- 이동은 **다음 층의 `lane ±1`** 로만. StS의 「1~3개 들어오고 1~3개 나간다」를 최소로 줄인 것이다
- **1층은 아무 갈래로나 시작한다** (StS 1층 규칙)
- **6층(보스)은 하나로 수렴한다**

전체 격자는 시드로 만든다. `generateMap(seed)`를 **순수 함수**로 둔다 — `mapNode`가 지금 순수 함수인 것과 같은 이유고, 재생이 여기 걸려 있다.

### 2 · 노드 종류 넷

| 종류 | 내용 | 보상 |
|---|---|---|
| `combat` | 일반 조우 | 카드 3택1 |
| `elite` | P-25의 강제 사건급 조우 | **은혜**(P-28) + 카드 |
| `rest` | 회복 또는 카드 제거 | — |
| `omen` | 요구(P-29) 또는 신의 개입(P-30) | 그 계획들이 정한다 |

`omen`이 다키스트 던전 2의 물음표 자리다. **새 결정 종류를 만들지 않는다** — 요구와 개입은 이미 다른 계획에 있고, 여기서는 지도에 자리를 줄 뿐이다.

**요구는 전투 앞에 그대로 둔다.** 지금 요구는 조우 직전에 붙고(`README`의 「전투 **앞에서** 신이 조건을 건다」), `omen`은 **그 위에 얹는 자리**다 — 요구를 전투에서 떼어 `omen`으로 옮기지 않는다. 옮기면 요구 빈도가 조우 수에서 `omen` 수로 떨어지고, 그건 P-30이 진노에 닿는 세 경로 중 하나(라이벌 요구 −18)를 **줄이는** 방향이다. `omen`은 요구를 **한 번 더** 만나는 자리다.

### 3 · 배치 규칙 — 전부 게이트가 된다

StS 규칙을 우리 6층으로 옮긴다.

| 규칙 | 근거 |
|---|---|
| 1층은 전부 `combat` | StS 1층 |
| 6층은 `boss` 하나로 수렴 | StS 16층 |
| `elite`·`rest`는 3층부터 | StS 「6층 아래 금지」를 6층짜리로 축소 |
| `elite`·`rest`는 연속 금지 | StS 그대로 |
| **5층에 `rest`가 최소 하나** | StS는 보스 직전 15층을 전부 휴식으로 보장한다. 우리는 갈래를 남기되 경로 하나는 열어 둔다 |
| **한 층의 갈래는 서로 다른 종류** | 하데스 「같은 보상 금지」. 이게 없으면 갈래가 장식이다 |
| 모든 갈래에서 보스까지 경로가 있다 | 막다른 길 금지 |

### 4 · 예고 — 지역 전체를 보여준다

슬레이 더 스파이어 방식이다. 6층 × 3갈래 = 18칸은 한눈에 들어오고, 그래야 "3층에서 오른쪽으로 가면 정예를 밟지만 5층 휴식에 닿는다"가 성립한다.

`omen`만 종류를 감춘다(`?`) — 다키스트 던전 2의 물음표다. 지도 화면은 새로 하나 든다. `RunView`에 격자를 실어 보낸다.

### 5 · 층별 편성과 학습 순서

`data/map.json`이 층마다 등장 그룹 후보와 텍스트를 갖는다.

```json
{
  "region": "underworld", "floor": 4,
  "text": "문이 스스로 닫혔다. 벽에 걸린 방패들이 전부 이쪽을 보고 있다.",
  "groups": { "combat": ["group_under_pair"], "elite": ["group_under_zealot_guardian"] }
}
```

`encounter()`가 `region` 대신 `(depth, lane, 종류)`를 받는다. 갈래마다 다른 조우가 나와야 선택에 뜻이 생긴다.

**한 층에 새 패시브는 하나만** 들어온다. 처음 보는 패시브 둘이 겹치면 무엇 때문에 졌는지 못 읽는다.

| 층 | 새로 등장 | 배우는 것 |
|---|---|---|
| 지하 1 | — | 기본 |
| 지하 2 | `ramp` | 빨리 끝내라 |
| 지하 3 | `curl`·`angry` | 때리는 방식이 문제다 |
| **지하 4** | `guard` + `spite` (`elite`) | 단일 타겟도 방어 일변도도 막힌다 |
| 지하 5 | `shell` | 한 방으로는 못 뚫는다 |
| 지하 6 | `ward` (보스) | 토큰만으로는 안 된다 |
| 지상 1~5 | `support`·`rally` | 처치 순서 |
| 지상 6 | 전부 (보스) | |

**강제 사건은 이제 회피 가능한 강제 사건이다.** 지하 4층 정예를 피해 갈 수 있지만, 피하면 그 층의 다른 갈래는 `rest`가 아니다(연속 금지) — 값을 치른다.

## 게이트

`tools/validate.ts:139` `encounterThresholdFailure`가 지금 지역 2밴드다.

```
underworld  hp [40,90]    damage [8,14]   count [1,2]
surface     hp [90,170]   damage [14,22]  count [2,3]
```

- **층 진행 함수로 바꾼다** — 지역 안에서 1층 하한 → 5층 상한으로 선형. 보스는 고정값 검사
- **`elite`는 같은 층 `combat`보다 세다** — 별도 밴드. 보상이 큰 이유가 있어야 한다
- **배치 규칙 일곱을 전부 검사한다.** 위 표가 문서가 아니라 게이트여야 지켜진다
- **도달 가능성은 생성기 불변식으로 잡는다.** `lane ±1` + 6층 수렴이면 막다른 길이 **구조적으로 불가능**하다 — 어느 갈래에서도 다음 층의 lane 1로 갈 수 있다. 시드 1000개 훑기는 생성기가 참으로 만드는 성질을 검사하는 것이다. `generateMap`에 불변식 하나를 넣고 시드 20개짜리 테스트로 끝낸다

`FailureKey`는 `value_outlier`를 쓰고 배치 규칙만 새 키 `map_layout` 하나. 조우 수치가 아니라 격자 구조 위반이라 나눌 이유가 있다.

## 재생 — 정직하게

`Action`의 `{ type: "path"; choice: "combat" | "rest" }`가 `choice: "1:elite"`(lane:종류)로 바뀐다.

옛 로그의 `"combat"`은 어느 갈래였는지 정보를 안 갖는다. 호환 해석을 넣어도 **재생은 되지만 같은 런이 아니다** — 그러면 검사가 아니라 통과 의식이다. 넣지 않는다.

**`logs/human/` 22개를 `logs/human/v1/`로 아카이브하고 다시 따지 않는다.** 이유는 지도가 아니다 — P-25가 적을, P-31이 토큰을 바꾸는 순간 그 로그들은 이미 다른 게임의 기록이다. **재생 결정론은 엔진 검사지 기록 보관이 아니다.** 검사는 `test/combat.test.ts:30`처럼 같은 실행 안에서 두 런을 맞대면 그대로 서고, 배포본 전 구간 검사는 `npm run e2e -- --dist` 한 번(반출 → CLI 재생 일치)이 P-24에서 이미 하고 있다.

**이 결정이 뒤 세 계획에서 요구사항 하나씩을 지운다** — [P-28](28-boon.md)의 `Action.grace` 병존, [P-29](29-quest.md)의 `"accept"` 별칭, [P-31](../reviews/31-powers.md)의 「전 로그 재생 일치」. 셋 다 그 계획에서 이미 지웠고, 근거는 이 절이다.

아카이브 사실과 사유를 리뷰에 적는다.

## 넣지 않는 것

- **상인·보물 노드.** 금화가 없다. 넣으려면 경제를 만들어야 하고 그건 다른 계획이다
- **감시탑(물음표 밝히기).** 다키스트 던전 2에 있지만 노드 종류가 하나 더 늘고 `omen`이 이미 미지 자리를 한다
- **동료 선호 경로.** 다키스트 던전 2의 스트레스 장치인데 우리에겐 파티가 없다
- **지역 추가.** 12층 완주가 아직 배포본에서 한 번도 안 섰다(P-24)
- **StS의 완전한 격자 생성**(교차 금지, 6회 경로 생성). 6층 × 3갈래에는 과하다. `lane ±1` 규칙이 교차 금지를 자동으로 만든다

## 함정

- **`state.map.node`를 쓰는 곳이 넷이다.** `advanceMap`·`runView`·`encounter(seed + node)`·`won` 판정. `depth`로 갈면서 `encounter`의 시드를 `depth*3 + lane`으로 바꿔야 갈래마다 다른 조우가 나온다 — 안 바꾸면 갈래 셋이 같은 적을 뱉는다
- **`mapNode`의 rest 위치를 바꾸는 것이다.** 3·5층 고정은 P-09에서 잰 값이다(`logs/tuning/p09-map.md`). 이제 휴식이 갈래로 흩어지므로 **휴식 횟수가 줄어든다** — 지금 `rest_choices`가 런당 3264/4000이다. 승률이 그만큼 내려간다. `enemyDamageScale`로 되돌리지 않고 휴식 회복량(`restHealing = 25`)이나 5층 보장으로 조정한다
- **봇이 갈래를 골라야 한다.** `chooseRest` 같은 정책이 하나 더 든다. `bot_policy_version` v4 → 올린다
- **지도 화면은 뼈대만 여기서 만든다.** [P-26](26-hud.md)이 맨 뒤로 갔고, 화면을 여는 다섯 계획(P-27·P-28·P-29·P-30·P-31)의 레이아웃을 거기서 한 번에 본다. 여기서는 격자가 읽히면 된다 — 색·간격·1440px는 P-26이 가져간다
- 층 곡선을 넣으면 전 구간이 세지므로 승률이 떨어진다. **층 밴드의 기울기가 다이얼이고, 위 「실패 시 행동」이 그것을 마지막 수단으로 못박았다**
