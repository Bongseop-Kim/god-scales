# 77 — 피드백 넷: 못 내는 이유의 색, 감소는 파랑, 최소 사이즈 게이트, 능력 툴팁

플레이 피드백 넷을 고친다. 전부 UI다 — 엔진·수치·밸런스 변경 없음(승률 게이트에 닿을 일 자체가 없어야 한다).

1. **거리 부족인데 에너지가 붉다.** 못 내는 카드는 이유 불문 비용 젬이 붉어진다(`ui/style.css:667`). 이유가 거리면 거리 표시가 붉어야 한다.
2. **감소한 값이 붉다.** 훼방·침수로 낮아진 숫자가 `#eb887d`다(`ui/style.css:718`). 진영색 규칙(DD2: 노랑=이로움, 파랑=해로움, `:root`의 `--bane`)에 맞춰 파랑이어야 한다.
3. **작은 창에서 판이 깨진 채로 선다.** 무대가 고정 기하(`420px + slot×180px`, `ui/style.css:484`)라 좁은 창에서 적이 잘리고 부채꼴이 겹친다. 권장 아래에서는 「~부터 지원합니다」 화면으로 대체한다.
4. **호버로 읽어야 할 정보가 `aria-label`에만 있다.** 적 능력(패시브) 칩(`combat.tsx:641`)과 에너지 젬·뽑을 카드 더미(`combat.tsx:474,478`)는 `title`이 없어 마우스로는 못 읽는다. 토큰 배지(`tokens.tsx:114`)·의도·과업 칩은 이미 `title`을 든다 — 빠진 자리만 채운다.

---

## 1. 못 내는 이유대로 붉힌다: 에너지면 젬, 거리면 사거리 칸

낼 수 있음 = `cost <= energy && canReachTarget`(`sim/engine.ts:488`)이므로 UI가 이유를 역산할 수 있다 — 손패에서 `options`에 없는 카드가 `cost <= view.energy`면 남은 이유는 거리뿐이다. 엔진 변경 없음.

`ui/screens/combat.tsx`
- `FanCard`(`:553`)의 래퍼 `m.div`에 `data-why`를 단다: 카드가 `options`에 없을 때 `cost > view.energy`면 `"energy"`, 아니면 `"reach"`. 낼 수 있으면 없음. 둘 다 모자라면 `"energy"`다 — 에너지가 차면 다시 역산되니 한 번에 한 이유만 말한다. `targeting` 중 비활성은 이유가 아니므로 달지 않는다.

`ui/style.css`
- `:667`의 `.fan:not(.aiming) .game-card:disabled .cost-gem` 선택자를 `[data-why="energy"]` 쪽으로 좁히고, `[data-why="reach"]`는 `.card-reach`(`:725`)를 같은 `#eb887d`로 칠한다. 두 줄 교체다.
- `.card-reach`의 hover `title`(`reachText`, `card.tsx:296`)은 이미 어느 칸에 닿는지 말한다 — 붉어진 칸을 호버하면 이유가 문장으로 읽히는 구조가 공짜로 선다.

## 2. 감소는 파랑

`ui/style.css:718` — `.card-fx em b.down`의 `#eb887d`를 `var(--bane)`으로. 한 줄.

**`.game-card.weakened`(`:656`)의 붉은 테는 그대로 둔다** — 그 붉음은 「값이 줄었다」가 아니라 「분노한 신이 그랬다」(진노색 `--stage-wrath`와 같은 계열)라 출처를 말하는 자리다. 값의 증감은 숫자색(`--boon`/`--bane`)이, 출처는 카드 배경이 나눠 든다.

## 3. 최소 사이즈 게이트

지지 하한을 먼저 실측한다: `aside`로 창을 줄여 가며 무대(적 4칸 + 병사)와 부채꼴이 깨지기 시작하는 지점을 확인하고 임계값을 확정한다. 기하상 예상은 대략 1200×720이다(무대 오른끝 `420 + 3×180 + 160 = 1120px`, 무대 360px + 부채꼴 + 상태 바).

`ui/app.tsx`
- 루트에 게이트 한 장을 둔다: `<div className="size-gate" role="status">…부터 지원합니다</div>`. 항상 DOM에 있고 CSS가 보임을 정한다 — JS 리스너·상태 없음.
- 문구는 합니다체 한 문장(WRITING.md): **"1200×720 이상 화면에서 지원합니다."** (임계값은 실측치로.)

`ui/style.css`
- `.size-gate { display: none; }` 기본, `@media (max-width: …px), (max-height: …px)`에서 `position: fixed; inset: 0; display: grid; place-items: center;` + 루트와 같은 바탕색. 층은 voice(4) 위 — 판을 통째로 대체하는 게이트라 「닫는 길」은 창을 키우는 것 자체다(UI.md 층 규칙의 예외로 그 자리에 주석).
- `body`의 `min-width: 320px`(`:74`)는 그대로 — 게이트 아래에서 판이 어떻게 깨지든 이제 안 보인다.

## 4. 호버 툴팁: 빠진 자리 셋

`ui/shared/tokens.tsx`
- `passiveName` 옆에 `passiveTitle = (id) => \`${name} — ${text}\`` 하나를 export한다 — 사전(`:165`)과 칩이 같은 `passiveStyle` 표를 읽으므로 사본이 안 생긴다.

`ui/screens/combat.tsx`
- 적 발밑 패시브 칩(`:641`)에 `title={passiveTitle(id)}`. 안쪽 `title`이 적 버튼의 `title`(`:622`)을 이기므로 그대로 얹으면 된다.
- 에너지 젬(`:474`)·뽑을 카드 더미(`:478`)에 `aria-label`과 같은 문장의 `title`. 글자 라벨을 지운 자리(P-55)라 호버가 유일한 마우스 경로다.

새 툴팁 컴포넌트는 만들지 않는다 — 이 게임의 호버 정보는 전부 네이티브 `title`(카드·토큰·의도·과업·개입)이고, 여기만 다른 그릇이면 그게 튄다.

## 완료 기준

- 에너지는 충분한데 닿는 적이 없는 카드: 젬은 제 색, 사거리 칸만 붉다 — `aside`로 확인.
- 훼방 걸린 카드의 낮아진 숫자가 파랗다.
- 임계 아래로 창을 줄이면 게이트 문장만 남고, 키우면 판이 그대로 돌아온다(상태 유실 없음 — DOM은 그대로였다).
- 적 패시브·에너지 젬·뽑을 더미를 호버하면 설명이 뜬다.
- 완료 후 `reviews/77-ui-feedback.md` 작성, 이 플랜 삭제.

## 이 플랜이 안 하는 것

- 커스텀 툴팁 레이어 — 네이티브 `title`로 충분하고, 지연·스타일이 문제로 확인되면 별도 플랜.
- 작은 창 대응 반응형 레이아웃 — 게이트가 그 요구를 대체한다. 모바일 지원이 목표가 되면 그때.
- 거리 부족 카드의 사거리 강조 애니메이션 — 색 하나면 말이 된다. 맥동은 시야에서 계속 움직여 UI.md에 어긋난다.
