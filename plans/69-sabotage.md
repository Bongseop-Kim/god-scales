# P-69 · 분노한 신은 상대의 선물을 무디게 한다

P-68 완료 뒤에 착수한다. 내기·신탁 삭제가 호의 경제를 바꾸므로, 그 위에서 측정한 승률을 기준으로 수치를 본다.

## 핵심

### 한 줄 결론

**분노 단계의 신은 개입 턴에 행동하는 대신, 조우 내내 상대 후원 신의 카드를 1 무디게 한다.**

```text
제우스 호의가 분노로 떨어짐
        ↓
아테나 카드의 피해·방어 −1 (바닥 1) · 손패 숫자가 깎인 값으로 보임
        ↓
제우스 카드를 써서 호의가 30 이상으로 돌아오면 즉시 원래 값
```

낮은 신의 카드를 깎으면 회복 수단을 스스로 부수는 나선이 된다. 반대로 **높은 신의 카드**를 깎으면
멀쩡한 낮은 신의 카드를 쓸 이유가 생기고, 호의가 돌아오면 훼방이 풀린다 — 저울이 스스로 균형을 찾는
음성 피드백이다.

### 플레이 시나리오

제우스·아테나 조합. 아테나만 따르다가 제우스가 호의 28(분노)로 떨어진 채 전투에 들어간다.

```text
제우스 분노 · 아테나 카드 −1        ← HUD 칩

손패: [ 방패 들기  방어 4 → 3 ]  [ 작은 번개  피해 5 ]
                 ↑ 아테나 카드만 깎인 값, 약화 색       ↑ 제우스 카드는 그대로
```

칩에 호버하면 토큰 툴팁처럼 이유와 해제 조건이 한 줄로 뜬다:
`분노한 제우스의 훼방 — 아테나 카드의 피해·방어·연쇄 −1 · 제우스 호의가 평온으로 돌아오면 해제`

제우스 카드를 몇 장 쓰면 호의가 30을 넘고, 칩과 약화 표시가 그 자리에서 사라진다.

### 플레이 규칙

| 순간 | 규칙 |
|---|---|
| 상대 후원 신이 분노 이하 | 내 덱에서 그 반대 신의 카드 피해·방어·연쇄 −1, 바닥 1 |
| 호의 30 이상 복귀 | 즉시 해제. 별도 지속·해제 타이밍 없음 |
| 분노 신의 개입 턴 | 아무 행동 없음 — 훼방이 상시 벌이므로 개입 벌은 겹치지 않음 |
| 진노 | 기존 그대로 적으로 참전. 훼방도 유지 |
| 진노 신 처치 | 호의만 평온 하한으로 복귀(기존). 보상 승격 없음 |

두 후원 신의 호의 합은 100이므로 동시에 둘이 분노일 수 없다 — 개입 턴에 행동하는 신이 항상 하나는 남는다.

### 없애는 것

- `data/gods.json` 다섯 신의 `anger.on_turn_start` 효과 전부
  (포세이돈·아테나·아레스의 적 회복, 제우스의 자기 감전, 아르테미스의 적 회복)
- 진노 신을 꺾었을 때의 보상 승격 — `tier2Slots`의 `felledGod` 분기

### 완료 모습

```text
상대 신 분노 진입
→ HUD에 `신 이름 분노 · 상대 신 카드 −1` 칩 · 호버 시 이유와 해제 조건
→ 손패의 해당 신 카드 숫자가 깎인 값 · 약화 색
→ `토큰과 기호` 사전에 훼방·파워 항목
→ 개입 턴에 분노 신은 침묵
→ 호의 30 복귀 시 칩과 약화가 함께 사라짐
→ 진노 신을 꺾어도 카드 보상은 평소 전투와 동일
```

## 구현

### 1. 훼방은 `cardEffects` 한 곳에 둔다

- `core/rules.ts:376`의 `cardEffects`가 카드의 실제 효과를 정하는 유일한 관문이다. 은혜가 이미 여기 붙고,
  엔진 집계(`sim/engine.ts:580`)와 손패 화면(`sim/engine.ts:492` → `ui/shared/card.tsx`)이 같은 목록을 읽는다.
- 카드의 `patron`이 후원 신이고 **다른 후원 신**의 `favorStage`가 `anger` 이하면, `damage`·`block`·`chain`
  효과의 값을 1 깎는다. 바닥은 1 — 0이 되는 카드를 만들지 않는다.
- 새 상태·토큰·해제 로직을 만들지 않는다. 매 계산이 현재 호의를 읽으므로 회복 즉시 저절로 풀린다.
- `on_turn_start` 개입은 그 턴 안에 사라지는 효과만 허용된다(`tools/validate.ts`) — 지속 훼방을 개입
  op으로 넣을 수 없는 이유이고, 그래서 단계 파생 패시브다.

### 2. 분노 개입 데이터를 비운다

- `data/gods.json` 다섯 신의 `anger.on_turn_start`를 삭제한다. 데이터가 있는 단계가 곧 개입하는
  단계이므로 코드 변경 없이 분노 신의 개입이 사라진다.
- 훼방 위에 개입 벌이 겹치면 이중 처벌이다. 분노의 벌은 훼방 하나만 남긴다.
- `tools/validate.ts`가 단계 데이터 부재를 막는다면 분노 `on_turn_start` 부재를 허용하도록 게이트만 넓힌다.
- 헌신·평온 개입과 진노 참전·컷인·파티클은 그대로 둔다.

### 3. 손패·상태 칩·사전이 훼방을 보여 준다

- 손패: `ui/shared/card.tsx:257` 주석대로 지금 손패 숫자는 카드 원문에서 읽는다. 훼방이 걸린 카드는
  `cardEffects` 결과 값으로 표시를 바꾸고 약화 색을 입힌다. 값 출처는 두 곳을 만들지 않는다.
- 상태 칩: 토큰 칩과 같은 문법(작은 칩 + `title` 툴팁, `ui/shared/tokens.tsx:96`)으로 상태 영역에
  훼방 칩을 둔다. 칩 글자는 `제우스 분노 · 아테나 카드 −1`. 호버 툴팁은 토큰 툴팁처럼 명사형 한 줄로
  이유와 해제 조건을 적는다: `분노한 제우스의 훼방 — 아테나 카드의 피해·방어·연쇄 −1 · 제우스 호의가
  평온으로 돌아오면 해제`.
- 자리 규칙: 칩이 걸리고 풀려도 이웃이 밀리면 안 된다(UI.md 제1규칙). 빈 줄도 자리를 지키는
  `power-row`(`ui/screens/combat.tsx:683`)와 같은 방식으로 자리를 예약한다.
- `토큰과 기호` 사전(`ui/app.tsx:323`)에 두 항목을 더한다: **훼방**(위 툴팁과 같은 설명)과 **파워**
  (손을 떠난 뒤 전투 내내 매 턴 일하는 지속 효과). 파워 칩은 호버 `title`에 발동 시점과 효과가 이미
  있으나(`ui/screens/combat.tsx:686`) 사전에 개념 항목이 없어 호버를 모르면 닿을 길이 없다.
- 새 컷인·대사·토큰 op는 만들지 않는다. 한글은 `WRITING.md`, 배치는 `UI.md`를 따른다.

### 4. 진노 신 처치의 보상 승격을 삭제한다

- `sim/engine.ts:107`의 `tier2Slots(path, felledGod)`에서 `felledGod` 인자를 없앤다. tier2 슬롯은
  elite·boss만 연다. `offerReward`(`:845`)와 호출부(`:1005`)의 인자도 함께 정리한다.
- 진노 신을 꺾은 보상은 기존 `wrathReconcileFavor`(호의를 평온 하한으로) 하나로 충분하다 —
  엔진 주석이 이미 「개입이 진노에서 평온으로 바뀌는 것이 가장 큰 보상」이라고 적고 있다.
- 전투 자체의 기본 승리 보상 카드 1장은 그대로 준다. 몰수는 벌 파밍 방지지 실패 벌금이 아니다.

## 최소 검증

- 상대 후원 신이 분노일 때 반대 신 카드의 `damage`·`block`·`chain` 값이 1 깎이고 바닥이 1이다.
- 분노 신 자신의 카드와 `draw`·`energy`·`heal` 값은 변하지 않는다.
- 호의가 30 이상으로 돌아오면 같은 전투 안에서 즉시 원래 값이다.
- 손패 카드 숫자가 깎인 값으로 표시되고, 엔진 집계와 화면이 같은 `cardEffects` 결과를 읽는다.
- 훼방 칩 호버에 이유와 해제 조건이 보이고, 칩이 걸리고 풀려도 이웃 레이아웃이 밀리지 않는다.
- `토큰과 기호` 사전에 훼방과 파워 항목이 있다.
- 분노 신은 개입 턴에 아무 효과도 내지 않고, 헌신·평온 신의 개입은 그대로 돈다.
- 진노 신을 꺾은 전투의 보상에 tier2 승격이 없고, 호의는 평온 하한으로 복귀한다.

```bash
npx tsc --noEmit
npm test
npm run validate -- data/gods.json
npm run build
npm run tune
npm run e2e
git diff --check
```

- 밸런스 판정은 조합 승률 하한 하나만 본다. 새 지표·밴드·회차 비교를 만들지 않는다.
- 하한이 깨지면 게이트를 낮추거나 값을 테스트에 맞춰 깎지 않는다. 실패 조합과 원인을 리뷰에 남긴다.
- 라이벌 쌍(포세이돈:제우스, 아레스:아테나)은 과업 벌금 −18로 분노에 자주 닿는다 — 이 두 조합의
  하한을 특히 본다.
- 완료 뒤 `reviews/69-sabotage.md`를 작성하고 이 파일을 삭제한다.

## 설명

### 왜 카드에 닿는 규칙이 하나뿐인가

「헌신이면 자기 카드 +1」을 같이 넣으면 제로섬 저울이 두 효과를 정확히 상쇄시킨다. 한쪽이 71이면
반대쪽이 29(분노)라, 강한 쪽 카드는 +1과 −1을 동시에 받아 0이 된다. 저울이 깊이 기울수록 두 칩이
서로를 지우는 화면만 남는다. 그래서 카드를 만지는 규칙은 훼방 하나다. 헌신의 보상은 이미 있는
헌신 개입이 맡는다 — 단계별 자동 행동 중 가장 세다.

### 왜 낮은 신이 아니라 높은 신의 카드를 깎는가

낮은 신의 카드를 깎으면 호의를 되돌릴 유일한 수단(그 신 카드 사용 +1)을 스스로 부순다 — 빠져나올 수
없는 나선이다. 높은 신의 카드를 깎으면 낮은 신의 카드가 상대적으로 좋아져 쓸 이유가 생기고, 쓰면
호의가 돌아와 훼방이 풀린다. 벌이 곧 출구를 가리킨다.

### 왜 분노 개입을 지우는가

화난 아테나가 몬스터를 치료해 주는 지금의 분노 개입은 테마로도 어색하고, 훼방과 겹치면 이중 처벌이다.
「화난 신이 라이벌의 선물을 무디게 한다」는 신이 제멋대로라는 톤에 맞고, 벌이 저울과 손패에 직접 보인다.
Griftlands가 같은 구조를 검증했다 — 미움받은 인물의 벌은 스탯 하향이 아니라 세계의 개입(전투 난입,
전용 bane)이고, 관계가 풀리면 사라진다.

### 조사에서 가져온 원칙

- [Griftlands · Relationships](https://griftlands.fandom.com/wiki/Relationships): 사랑은 boon, 미움은 bane과 전투 난입. 관계 수치의 벌을 카드 스탯이 아니라 명확히 귀속되는 개입으로 준다.
- [Into the Breach 개발자 인터뷰](https://www.gamedeveloper.com/game-platforms/road-to-the-igf-subset-games-i-into-the-breach-i-): 벌의 이유를 읽을 수 있어야 통제감이 생긴다. 훼방은 손패 숫자와 HUD 칩으로 원인을 그 자리에서 보여 준다.

이 사례를 복제하지 않는다. 이미 있는 `favorStage`·`cardEffects`·진노 참전을 한 줄로 이어 새 상태 없이
같은 효과를 낸다.
