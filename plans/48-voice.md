# P-48 · 신이 말을 건다 — 그리고 요구가 읽힌다

`plans/48-voice.md` · [◀ P-46](46-presence.md) · [색인](../reviews/00-index.md)

**크기** 큼 · **착수 조건** [P-46](46-presence.md) — 컷인 배너 자리가 있어야 대사가 앉는다. [P-47](47-wrath.md)과는 직교한다(저쪽은 판 위의 값, 이쪽은 화면과 말)지만 **뒤가 낫다** — `tear`·`join`·`reconcile`이 P-47에서 터지기 시작하므로, 이 계획이 뒤면 줄이 산 트리거 위에 앉는다

[P-46](46-presence.md)이 만드는 것은 **신이 무엇을 했는지**다. 이 계획은 **신이 무엇을 말하는지**를 만들고, 같은 자리에 있는 부채 하나를 같이 갚는다 — **요구가 무슨 말인지 읽히지 않는다.**

---

## 0 · 조사 — 지금 무엇이 안 보이나

### 요구는 조건을 화면에 안 적는다

`core/demands.ts:13`이 스스로 그렇게 적어 뒀다:

```ts
/** 한 단. `text`가 화면에 나가는 문장이고 `condition`은 사람이 읽을 것이 아니다 */
```

그래서 `DemandScreen`은 `tier.text`만 그린다(`ui/choices.tsx:132`). 열 줄이 실제로 이렇다:

| 화면에 나가는 문장 | 실제 조건 |
|---|---|
| 물러서지 마라. 한 턴에 둘은 맞아야 한다. | `hit_targets_in_turn >= 2` |
| 파도를 둘로 갈라도 좋다. 셋은 안 된다. | `hit_targets_in_turn <= 2` |
| 스물 넘게 내주지 마라. 방벽은 세우고 나서 자랑하는 것이다. | `damage_taken <= 20` |
| **여덟이다. 크게 맞고 이기는 것은 승리가 아니다.** | `damage_taken <= 8` |
| **스물여섯. 그 아래는 상처가 아니라 흠집이다.** | `damage_taken > 26` |
| **다섯이다. 표적이 어디로 달아나든 이미 늦었어야 한다.** | `tokens_applied_in_turn >= 5` |

앞의 셋은 그럭저럭 읽힌다. **뒤의 셋은 무엇의 여덟인지, 무엇의 다섯인지 문장이 말하지 않는다.** 시적인 문장이 조건을 대신하고 있고, 대신하지 못한다.

### 전투 화면은 약속을 아예 모른다

`CombatObservation`(`sim/engine.ts:225`)에 `promise`도 `facts`도 없다. 요구를 수락하고 전투에 들어가면 **화면에 그 흔적이 하나도 없다.** 무엇을 약속했는지, 지금 지키고 있는지, 이미 깨졌는지 — 셋 다 볼 방법이 없다.

### 성공·실패의 순간이 없다

`demandSatisfied`가 조우가 **끝난 뒤** 한 번 돈다. 전투 중에는 아무 신호도 없고, 끝나고 나서 호의 숫자가 조용히 바뀐다.

### 신은 아직 한 마디도 안 한다

`data/gods.json`에 대사가 없다. 지금 화면에 뜨는 신의 말은 요구 문장 열 줄이 전부다.

## 1 · **모든 조건은 확정되는 순간을 갖는다** — 이 계획의 뿌리

요구가 재는 사실 넷이 **전부 단조 비감소**다. 코드로 확인한 것이다:

| fact | 갱신 | `sim/engine.ts` |
|---|---|---|
| `damage_taken` | `+=` | :311 |
| `tokens_applied` | `+=` | :397 |
| `hit_targets_in_turn` | `Math.max` | :402 |
| `tokens_applied_in_turn` | `Math.max` | :405 |

**한 번 오른 값은 내려오지 않는다.** 그래서 배포된 조건 열 줄이 예외 없이 둘 중 하나다:

| 꼴 | 언제 확정되나 | 몇 줄 |
|---|---|---:|
| `fact >= N` · `fact > N` | 처음 넘는 순간 **성공이 확정된다.** 그 뒤로는 깨질 수 없다 | 6 |
| `fact <= N` | 처음 넘는 순간 **실패가 확정된다.** 그 전까지는 미정이다 | 4 |

**새 상태를 하나도 안 만들고** 진행 막대와 성공·실패 알림이 둘 다 나온다. 이 계획의 §5가 전부 이 한 줄 위에 선다.

> `polarity`(`"+"`/`"-"`)가 이미 데이터에 있지만 **그것으로 가르지 않는다.** 아레스의 `damage_taken > 14`는 `polarity: "+"`이고 아테나의 `damage_taken <= 20`은 `"-"`인데, 갈라야 하는 것은 신의 취향이 아니라 **비교 연산자**다. `demandSatisfied`가 이미 그 연산자를 파싱한다(`core/demands.ts:76`) — 정본이 하나다

## 완료 정의

**요구를 받은 플레이어가 전투 화면만 보고 「무엇을 · 얼마나 · 지금 어떤지」를 알 수 있고, 신은 네 단계에서 다 말한다.**

```bash
npx tsc --noEmit && npm test
npm run validate -- data/gods.json data/demands.json   # 대사·조건 게이트
npm run tune       # 조합 승률 하한 0.05 — 유일한 밸런스 판정 (CLAUDE.md)
npm run e2e        # 여덟 화면 · 반출 → CLI 재생 일치
```

| 항목 | 판정 기준 |
|---|---|
| 조건 | 요구 화면이 문장 **아래에** 조건을 사람 말로 한 줄 적는다. 열 줄 다 |
| HUD | 전투 화면 상단에 약속 한 줄 — 무엇을 · 현재값/목표 · 상태 |
| 확정 | 성공·실패가 **그 순간** 뜬다. 조우 끝이 아니다 |
| 대사 | 트리거 아홉에 신 다섯이 다 줄을 갖는다. 빈 트리거가 있으면 게이트가 반려한다 |
| 레벨 | 발화가 셋으로 갈리고 **셋 다 입력을 안 받는다** — `Decision`이 늘지 않는다 |
| 재생 | 대사가 RNG를 안 당긴다. 배포된 replay가 그대로 재생된다 |
| 게이트 | 조합 승률 하한 하나. 이 계획은 판 위의 값을 안 건드리므로 **밸런스 영향이 0이다** |

## 설계

### 2 · 레벨은 셋이다 — 빈도가 정했다

착수 전 생각은 둘이었다. **실측 빈도가 셋을 요구한다.** 600런 층화 기준(조우 7.46/런 · 9.91턴/조우 · 개입 턴 2·5·8·11):

| 발화 자리 | 런당 횟수 |
|---|---:|
| 개입 턴 (`intervenesOnTurn` × 후원 2) | **≈ 49** |
| 조우 시작 (후원 2 × 7.46조우) | **≈ 15** |
| 요구 성공·실패 (수락 6.4/런) | **≈ 6** |
| 단계 경계를 넘는 순간 | **≈ 5** |
| 사건 (찢기 · 진노 합류 · 격파) | **0 ~ 10** (배분에 달렸다) |

**49회와 5회가 같은 연출이면 하나는 피로하고 하나는 밋밋하다.** 두 단계로 가르면 그 사이가 없다 — 49를 위로 올리면 전투가 안 굴러가고, 5를 아래로 내리면 카드가 찢기는 순간이 자막 한 줄이 된다.

| 레벨 | 이름 | 화면 | 머무는 시간 | 런당 | 트리거 |
|---|---|---|---:|---:|---|
| **1** | 속삭임 | 판 **아래** 자막 한 줄. 배경 안 어둡게 · 판을 안 가린다 | 1.2s | ≈49 | 개입 턴 |
| **2** | 말 | **화면 중앙 · 배경 살짝 어둡게 · 신 색 텍스트** | 2.0s | ≈26 | 조우 시작 · 단계 경계 · 요구 성공/실패 |
| **3** | 외침 | 배경 크게 어둡게 + **신 일러 슬라이드인** + 큰 글씨 + 화면 흔들림 | 3.0s | 0~10 | 카드 찢기 · 진노 합류 · 진노 격파 |

L2가 사용자 명세 그대로다(중앙 · 살짝 어둡게 · 신 색). L1은 그 아래, L3은 그 위다.

#### 셋 다 입력을 받지 않는다

L3이 「클릭해서 넘기는 대화창」이면 `Decision`이 하나 늘고 — **replay 형식이 바뀌고 봇이 그것에 답해야 하고 `npm run e2e`의 「반출 → CLI 재생 일치」가 깨진다.** 대사 하나 붙이려고 낼 값이 아니다.

셋 다 시간이 지나면 사라진다. 클릭은 **넘기기만** 하고 기록되지 않는다 — 화면 상태고 게임 상태가 아니다.

#### 겹치면 큐가 아니라 순서다

같은 프레임에 둘이 뜰 수 있다(후원 둘이 같은 개입 턴에 말한다). **큐를 만들지 않는다** — 높은 레벨이 낮은 레벨을 **덮고**, 같은 레벨끼리는 220ms 어긋나게 낸다. P-46 §「컷인 셋이 겹친다」와 같은 규칙이다.

### 3 · 카드 찢기는 [P-47](47-wrath.md)이 든다

찢기는 연출이 아니라 진노 경제의 판돈이다 — hp·화해와 함께 「가능성」 한 줄이 셋을 한 번에 재야 하므로 [P-47 §2](47-wrath.md)가 규칙을 든다. 이 계획은 그 순간의 **L3 「외침」 연출과 `tear` 대사만** 얹는다(§2 · §6). 신을 버려 놓고 그 신의 번개를 쓰는 순간이 이 게임에서 가장 말이 필요한 자리라는 사실은 그대로다 — 말은 여기, 값은 저쪽이다.

### 4 · 요구가 읽힌다 — 조건을 문장 옆에 숫자로

`condition`은 사람이 읽을 것이 아니다. **그래서 사람이 읽을 것을 만든다** — 카드가 이미 그렇게 한다(`effectText`가 `effects`에서 문장을 만든다). 같은 자리다.

fact 넷 × 비교 셋이면 열 줄이 다 덮인다:

```ts
/**
 * 조건 문자열을 사람 말로. **`tier.text`를 대신하지 않고 아래에 붙는다** — 시적인 문장은 신의
 * 목소리고 이 줄은 규칙이다. 둘을 합치면 신이 숫자를 읽는 소리가 되고, 그러면 §5의 목소리가 죽는다
 */
const factName: Record<string, string> = {
  hit_targets_in_turn: "한 턴에 맞힌 적",
  damage_taken: "이 조우에서 잃은 체력",
  tokens_applied: "새긴 토큰",
  tokens_applied_in_turn: "한 턴에 새긴 토큰",
};
// "한 턴에 맞힌 적 2 이상" · "이 조우에서 잃은 체력 8 이하" · "이 조우에서 잃은 체력 26 초과"
```

게이트는 `tools/validate.ts`에 한 줄이다: **`factName`에 없는 좌변을 쓰는 요구는 반려된다.** 지금 조용히 통과하는 오타가 화면에서 빈 줄이 된다.

요구 화면에는 신 일러(`art/gods/{god}.webp`)를 세우고 그 옆에 대사창을 붙인다 — 프레임 한 장은 [P-45](45-fx.md)가 만든다. 지금 요구 화면은 글자만 있다.

### 5 · 약속이 전투 화면에 산다

`CombatObservation`에 필드 하나를 더한다. **전부 파생값이라 새 상태가 없다:**

```ts
/**
 * 지금 걸린 약속. `current`·`settled`는 `facts`와 조건에서 **계산된다** — 상태를 따로 들면
 * 그것이 사실과 어긋날 자리가 생기고, `facts`는 이미 단조라 계산이 언제나 맞다(§1)
 */
promise?: {
  god: string;
  text: string;      // 신의 문장 (tier.text)
  rule: string;      // 사람 말 조건 (§4)
  current: number;   // facts[좌변]
  target: number;
  /** 달성형은 성공으로, 유지형은 실패로 확정된다. 미정이면 undefined */
  settled?: "kept" | "broken";
};
```

전투 화면 상단 한 줄:

```
⚖ 아테나 — 이 조우에서 잃은 체력 8 이하        [ 5 / 8 ]
```

| 상태 | 표시 |
|---|---|
| 미정 | 신 색 · 현재값/목표 |
| **성공 확정** (`>=`·`>`가 넘음) | 초록 · 잠긴 표시 · **L2 말** 한 번 |
| **실패 확정** (`<=`가 넘음) | 회색 · 취소선 · **L2 말** 한 번 |

확정은 **한 번만** 발화한다. `settled`가 처음 생기는 프레임이 그 자리고, 그 뒤로는 값이 안 바뀐다(§1).

`omen`이 걸어 둔 약속(`carried`, `sim/engine.ts:606`)도 같은 줄에 뜬다 — 지금은 그것이 다음 전투에 조용히 따라 들어간다.

### 6 · 대사 데이터 — 트리거가 키다

`data/gods.json`의 신마다 `lines`. **트리거가 키고, 단계로 갈리는 것은 둘뿐이다:**

```json
"lines": {
  "encounter": { "devotion": ["…", "…"], "calm": [...], "anger": [...], "wrath": [...] },
  "intervene": { "devotion": ["…", "…", "…"], "calm": [...], "anger": [...], "wrath": [...] },
  "cross":     { "devotion": ["…"], "calm": ["…"], "anger": ["…"], "wrath": ["…"] },
  "demand_offer": ["…"], "demand_kept": ["…"], "demand_broken": ["…"],
  "tear": ["…", "…"], "join": ["…"], "reconcile": ["…"]
}
```

**`intervene`이 줄이 가장 많다** — 런당 49회 뜨는 자리라 단계당 셋이어야 반복이 덜 느껴진다. `join`·`reconcile`은 런당 한 번이라 하나면 된다. 신당 약 29줄, 다섯이면 **145줄**이 이 계획의 글쓰기 분량이다.

**고르는 것은 난수가 아니다.** `lines[n % lines.length]` — `n`은 그 자리의 턴 수나 조우 수다. 새 RNG 스트림을 만들면 대사를 켜는 것만으로 배포된 replay가 통째로 어긋난다(P-46 §6이 같은 이유로 스트림을 갈랐다).

게이트 두 줄(`tools/validate.ts`):

| 조건 | 잡는 것 |
|---|---|
| 트리거 아홉이 다 있고 각각 최소 한 줄 | 그 자리에서 신이 **침묵한다** — 「조용히 아무 일도 안 하는 것」이 R-30이 갚은 부채다 |
| `encounter`·`intervene`·`cross`는 단계 넷이 다 있다 | 평온이 68%인데 평온 줄이 없으면 대부분의 조우에서 신이 말을 안 한다 |

### 7 · 신마다 목소리 — 데이터가 이미 정해 놨다

대사 145줄을 쓰려면 신마다 태도가 있어야 한다. **새로 지어내지 않는다** — 각 신의 요구 축(`axis` · `polarity`)이 이미 성격이다:

| 신 | 요구하는 것 | 목소리 |
|---|---|---|
| 제우스 | `target_spread +` — 여럿을 쳐라 | **명령한다.** 이유를 안 댄다. 문장이 짧다 |
| 포세이돈 | `target_spread −` — 하나만 쳐라 | **되묻는다.** 서두르는 것을 나무란다 |
| 아테나 | `damage_taken −` — 맞지 마라 | **평가한다.** 잘한 것도 아직 미흡하다고 한다 |
| 아레스 | `damage_taken +` — 맞아라 | **부추긴다.** 다친 것을 칭찬한다 |
| 아르테미스 | `token_load +` — 많이 새겨라 | **세어 준다.** 숫자로 말한다 |

라이벌 쌍(`rivals`)이 그대로 대비다 — 제우스↔포세이돈은 「여럿이냐 하나냐」, 아테나↔아레스는 「맞지 마라 ↔ 맞아라」. **한 신이 헌신이면 상대는 분노 쪽인 배분에서, 둘이 같은 화면에서 정반대를 말한다.** 그게 이 게임이 저울인 이유고, 대사가 그것을 소리 내는 첫 자리다.

예시 넷(제우스 · 배분 100:0의 상대편):

```
tear     :  "그 번개는 내 것이다."
join     :  "네가 버린 것이 여기 서 있다."
intervene:  "아직도 내 이름을 들고 있군."     (진노)
reconcile:  "됐다. 그 정도면 들어줄 만하다."
```

## 함정

- **L3을 `Decision`으로 만들고 싶어진다.** 클릭해서 넘기는 대화창이 자연스러워 보이지만 replay 형식이 바뀌고 봇이 답해야 하고 `npm run e2e`가 깨진다. 셋 다 시간으로 사라진다
- **런당 49회를 L2로 올리고 싶어진다.** 화면 중앙이 2초씩 49번 어두워지면 전투가 아니라 낭독이다. L1이 자막인 이유가 그 숫자다
- **조건 줄이 `tier.text`를 대신하게 된다.** 둘은 다른 것이다 — 문장은 신의 목소리고 줄은 규칙이다. 합치면 신이 숫자를 읽는 소리가 된다
- **`settled`를 상태로 들고 싶어진다.** `facts`가 단조라 계산이 언제나 맞다(§1). 상태로 들면 사실과 어긋날 자리가 하나 생긴다
- **대사가 난수를 당기면 replay가 깨진다.** `n % lines.length`다
- **145줄이 다 명대사일 필요는 없다.** `intervene`은 49번 뜨는 자리라 **눈에 안 띄는 것이 좋은 줄**이다. 힘은 `tear`·`join`·`reconcile` 넷에 몰아준다

## 안 하는 것

- **대사 시스템을 만들지 않는다.** 분기도 상태도 조건식도 없다 — 트리거 하나에 줄 하나고 고르는 것은 나머지 연산이다
- **음성·타이핑 애니메이션을 넣지 않는다.** 자막이 1.2초 머무는데 타이핑을 넣으면 다 읽기 전에 사라진다
- **요구를 다시 설계하지 않는다.** 열 줄의 조건·보상·대가는 그대로다. 이 계획은 **그것을 읽히게만** 한다
- **`polarity`로 확정을 가르지 않는다.** 비교 연산자가 정본이고 `demandSatisfied`가 이미 그것을 판다
- **진노의 스펙·보상·찢기 규칙을 건드리지 않는다.** [P-47](47-wrath.md)이다 — 이 계획은 `tear`의 줄과 연출만 얹는다
- **새 에셋을 이 계획이 만들지 않는다.** 대사창 프레임 한 장은 [P-45](45-fx.md)가, 신 일러 다섯은 이미 있다
