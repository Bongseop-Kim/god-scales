**크기** 작음 · **착수 조건** **P-26 완료** (진영색이 정해진 뒤) + 사용자가 아이콘 슬러그 목록을 고른다 — 그리기 작업은 없다

[R-32](../reviews/32-art.md)에서 28개를 덜어내는 계획이다. 대신 그리지 않는다.

## 왜 P-26 뒤인가

**P-26이 토큰의 색 규칙을 바꾼다.** 지금은 신별 색이다(`ui/tokens.tsx:5` — `shock`이 제우스색, `bulwark`이 아테나색). P-26 §조사가 다키스트 던전 2를 근거로 이걸 뒤집는다:

> 색 = 진영, 아이콘 = 신. 신 색은 아이콘 테두리로 남긴다.

즉 배지 채움색은 **이로움/해로움**이 가져가고, 신 색(`--zeus` 등)은 테두리로 강등된다. 색이 출처를 말하지 않게 되는 순간 **신을 구분하는 유일한 수단이 아이콘 형태**가 된다 — 그래서 아이콘을 먼저 고르면 안 된다. 색 규칙이 정해진 뒤에 형태 기준으로 골라야 한다.

신 색 hex 자체는 바뀌지 않는다. 바뀌는 건 쓰임이다.

---

## 완료 정의

**28개를 하나도 그리지 않고 화면에 띄운다.** 유니코드 글리프와 한글 한 글자가 실제 아이콘으로 바뀌고, P-26이 정한 진영색·테두리 규칙이 그대로 유지된다.

```bash
npm run build && npx tsc --noEmit
npm run e2e -- --dist        # 여덟 화면 1440px 레이아웃 통과
```

라이선스 표기가 `public/ATTRIBUTION.md`에 들어가야 완료다.

### 맵 노드가 셋이 아니라 다섯이다

[R-27](../reviews/27-map.md)이 지도를 지역당 6층 × 3갈래 격자로 만들면서 종류가 넷 + 보스가 됐다. `nodeMark`(`ui/app.tsx:27`)가 지금 한글 한 글자다 — `전`·`정`·`휴`·`?`·`보`. 색은 이미 CSS에 다섯 개 다 있다(`:53`~`:57`).

**두 크기로 뜬다** — 격자 칸에서 16px, 선택지 44×44 원형 안에서 24px. 같은 아이콘이 둘 다 견뎌야 한다.

**`omen`은 감추는 게 뜻이다.** `nodeDetail`이 「무엇인지는 들어가야 압니다」라고 쓰고 있으므로(`ui/app.tsx:34`) 물음표·가림 계열을 고른다 — 나머지 넷과 달리 내용을 말하지 않는 아이콘이어야 한다.

**`elite`와 `combat`은 형태가 갈려야 한다.** 둘 다 전투인데 `elite`는 「더 강한 편성」이다(`:32`). 색은 `#a4615a` ↔ `#b0543f`로 거의 같아서 — **16px에서 구분되는 건 형태뿐**이다.

**조건부**: P-32의 원경 프롭(박쥐·사슬·구름·새·깃발·나뭇잎)도 단색 실루엣이면 대체된다. **저불투명도 원경 한 레이어에만.** 픽셀 캐릭터 옆 근경에 두면 티가 난다 — 근경은 P-32가 그린다.

**대체 불가**: 카드 일러 30 · 캐릭터 15 · 배경 6 · 주인공 일러 3 · 신 일러 5 · 지도 위치 마커. 채색 일러와 스프라이트는 아이콘이 못 메운다.

## 설계

### 1 · 아이콘 선택 기준 — 형태가 신을 말한다

P-26 이후 색은 진영이므로, **아이콘 형태만으로 출처가 읽혀야 한다.**

- **같은 신의 토큰끼리 계열을 맞춘다** — 제우스 `shock`·`displace`는 같은 각진 전기 계열, 아테나 `bulwark`·`deflect`·`thorns`는 같은 방패·기하 계열
- **신끼리는 확실히 갈린다** — 아레스(피·칼날)와 아르테미스(화살·조준)가 비슷한 실루엣이면 안 된다
- **24px에서 실루엣이 남는가**가 유일한 합격 기준이다. 내부 선이 많은 아이콘은 배지 안에서 뭉갠다
- 패시브 8개는 14px다 — **토큰보다 더 단순한 것을 고른다**

### 2 · symbol 시트 1장

파일 28개를 늘리지 않는다. `art/icons.svg` 하나에 `<symbol id="icon-shock">` 식으로 합치고 `<use href="#icon-shock">`로 쓴다 — 요청 1회다.

`ui/card.tsx:5`의 glob은 건드리지 않는다. 카드 아트는 카드당 파일이라 glob이 맞고, 아이콘은 28개가 항상 같이 뜨므로 시트가 맞다.


### 3 · 색 배선 — fill이 아니라 stroke로 내려간다

game-icons SVG는 단색이고 `currentColor`를 받는다. 지금 `.token-badge`는 `color: var(--token-color)`로 글리프와 테두리를 **같은 신 색**으로 칠한다(`ui/style.css:36`).

P-26 이후:

| 요소 | 지금 | P-26 이후 |
|---|---|---|
| 배지 배경 | `#181c27` 고정 | **진영색** (이로움/해로움) — `harmfulTokens`에서 읽는다 |
| 아이콘 채움 | 신 색, `opacity: .35` | **진영 대비색** — 배경 위에서 읽혀야 한다 |
| 테두리 | 신 색 | **신 색** — 유일하게 남는 자리 |

`--token-color` 변수는 남기되 **의미가 "배지 색"에서 "신 색"으로 좁아진다.** `tokenStyle`(`ui/tokens.tsx:4`)의 `color` 필드는 그대로고, `icon` 필드가 유니코드 문자에서 symbol id로 바뀐다.

`label`(한 글자 한글)은 **남긴다.** 아이콘이 안 뜰 때의 폴백이고, `.token-badge b`가 흰색으로 위에 겹쳐 있어(`:38`) 아이콘과 공존하도록 설계된 자리다.

### 4 · 픽셀 정합

아이콘은 벡터라 픽셀 아트가 아니다. P-32가 배경·캐릭터를 **3배 확대 픽셀**로 잡았으므로 원칙적으로는 어긋난다.

- **UI 아이콘 28개는 14~24px로 뜬다 — 티가 안 난다.** 그대로 쓴다
- 정합이 눈에 걸리면 실루엣이 이미 나와 있으니 트레이스가 빠르다. **먼저 그대로 넣고 보고 판단한다**

### 5 · 라이선스

아이콘별로 CC BY 3.0 또는 CC0이고 저자도 다르다 (Lorc · Delapouite · Skoll 등). CC BY는 표기만 하면 상업 배포가 된다.

`public/ATTRIBUTION.md`는 지금 "외부 아이콘·UI·폰트 파일을 포함하지 않습니다"라고 적혀 있다 — **그 문장이 거짓이 된다.** 쓴 아이콘 목록 + 저자 + 라이선스 링크로 갱신한다.

## 함정

- **테두리 하나에 셋이 얹힌다.** P-26이 테두리에 신 색을 주고, 지속 3종을 점선/기본/실선으로 주고(§토큰 줄), 색각 대체로 채움/외곽까지 준다(§함정). 셋이 한 자리에서 부딪힌다 — **P-33이 정하지 않는다. P-26의 결정을 따르고, 결정이 없으면 리뷰에 적어 되돌려보낸다**
- **슬러그를 추측하지 않는다.** 사이트에서 실제로 고른 목록을 받는다. 이름을 맞춰 넣었다가 없는 아이콘이면 폴백이 조용히 뜬다
- **저자별 표기가 다르다.** 28개 중 어느 게 CC0이고 어느 게 CC BY인지 다운로드 시점에 기록해야 나중에 못 찾는다
- **렌더 경로가 바뀐다.** `<i>{style.icon}</i>`가 `<svg><use>`로 바뀐다 — `aria-hidden`과 `prefers-reduced-motion` 경로를 같이 본다. `aria-label` 요약은 P-26이 이미 손대는 자리다(`ui/combat.tsx:83`)
- **`.token-badge i`의 `opacity: .35`가 진영색 배경에서 안 읽힐 수 있다.** 지금은 어두운 고정 배경 위였다
- 원경 프롭까지 쓰면 픽셀 배경 위에 벡터 실루엣이 섞인다. **저불투명도 원경 한 레이어로 제한한다**
