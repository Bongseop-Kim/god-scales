# P-71 · 타격은 몸이 가서 하고, 승패는 한 박자 세운 뒤 넘어간다

UI만 만진다 — 엔진·리플레이·봇·데이터는 그대로다. 관측(`hits`·`hitSource`·`hitSeq`)이 이미 실어
오는 사실을 화면이 더 크게 연기할 뿐이다.

## 핵심

### 한 줄 결론

**때리는 쪽이 맞는 쪽까지 걸어가서 때리고(플레이어·적 공통), 적 여럿의 공격은 순서대로 나가며,
승리·패배는 사망 프레임을 다 보여 준 뒤 천천히 넘어간다.**

### 지금 무엇이 약한가

| 자리 | 지금 | 문제 |
|---|---|---|
| 플레이어 공격 | 제자리 20px 전진(`combat.tsx:346`) | 공격 2프레임이 돌지만 몸이 안 가서 「때렸다」가 안 읽힌다 |
| 적 여럿의 공격 | 공격자 전원이 같은 프레임에 동시에 20px(`combat.tsx:349-353`) | 누가 얼마나 쳤는지 뭉개진다 — 순서가 없다 |
| 승리 | `answer()`가 즉시 `show`/`setResult`(`app.tsx:211-214`) | 마지막 적은 다음 combat 관측이 없어 사망 2프레임·exitPop이 **한 번도 안 보인다** |
| 패배 | 위와 같음 | 병사 사망 프레임(스트립 7~8번)이 **한 번도 안 쓰인다** |

스프라이트 스트립(4032×448, 9프레임: idle 4 · 공격 2 · 피격 1 · 사망 2)과 `data-pose` 배선
(`motion.css:101-111`)은 이미 있다. 새 그림·새 의존 없이 이 프레임들이 설 자리만 만든다.

### 완료 모습

```text
카드 공격 → 병사가 맞을 적 앞까지 달려간다(공격 프레임) → 도착 순간 플래시·셰이크·피해 팝 → 복귀
적 턴     → 공격 의도였던 적이 하나씩 순서대로 병사 앞까지 → 타격 → 복귀 → 다음 적
막타      → 적 사망 2프레임 + 「승리」 배너 → 0.6초 페이드로 보상/결과
전멸      → 병사 사망 2프레임 + 「패배」 배너 → 0.6초 페이드로 결과
```

## 구현

### 1. 플레이어 돌진 타격 (`combat.tsx`의 hitSeq effect)

- `hitSource === "attack"`이고 적이 맞았으면, 지금의 20px 전진을 **맞은 적 앞까지의 돌진**으로
  바꾼다. 거리는 대신 맞기(P-64)와 같은 규칙으로 **DOM을 재지 않고 칸으로 센다**: 적 진영은
  `420 + slot × 180`, 병사는 `60`(`style.css:484-487`)이므로 `360 + slot × 180 − 여백 100px`.
  대상은 `view.hits`의 첫 적, AoE면 칸 0 앞까지 한 번만 간다 — 한 방마다 왕복하지 않는다.
- WAAPI `translate` 3구간(나감 280ms — 머묾 — 복귀 300ms), 지킴이 미끄러짐(`combat.tsx:318-321`)과
  같은 꼴이다. `translate` 채널이라 motion의 layout `transform`과 안 싸운다(기존 주석 그대로).
- **impactDelay를 「도착」 하나로 통일한다.** 지금의 `guarded ? 260 : 0`을 돌진 도착 280ms로 바꾸고,
  지킴이 미끄러짐·guard-mark·피해 팝 `popDelay`도 같은 값을 본다 — 타이밍 상수가 두 벌이 되면
  인과가 다시 어긋난다. 공격 포즈(`pose(…, "attack", 350)`)는 돌진 시작과 같이 건다 — 나가는 동안
  공격 프레임이 돈다.
- `hitSource === "card"`(번개 등 비접촉)는 지금 파티클 그대로 둔다. 몸이 가는 것은 `attack`뿐이다.

### 2. 적 순차 공격 (같은 effect)

- 공격자 목록은 이미 있다(`prevAttackers`). 동시 20px 대신 **`index × 520ms`씩 어긋나게** 각자
  병사 앞까지 돌진·타격·복귀한다. 거리는 1과 같은 칸 규칙(부호만 반대), 포즈·플래시·셰이크·타격음도
  공격자마다 자기 도착 시점에 낸다.
- 피해 팝은 관측이 합산 하나만 실으므로 **첫 도착에 한 번** 띄운다(`PlayerActor`의 `DamagePop`에
  적과 같은 `delay` prop을 연결). 공격자별 분해는 엔진을 갈라야 하므로 안 한다 — 매 도착의
  플래시·셰이크가 「여러 대」를 말하고 숫자는 합계 하나면 족하다.
- 「내 턴」 배너 700ms(`combat.tsx:365-369`)는 직전 공격자 수만큼 늦춘다
  (`700 + (n−1) × 520`) — 마지막 적이 복귀하기 전에 배너가 서면 순서가 거꾸로 읽힌다.
- 타이머는 전부 기존 `timers` 배열에 넣는다 — 정리 경로가 이미 있다.

### 3. 승패 아웃트로 (`app.tsx` + `combat.tsx`)

- `answer()`에서 전투를 떠나는 두 갈래를 잡는다: `leftWonCombat`(이미 있음)과
  `leftLostCombat = step.done && !step.value.won && 전투 phase`. 잡히면 즉시 `show`/`setResult`하지
  않고 **`outro: "won" | "lost"` state를 세우고 1.3초 뒤에** 넘긴다(타이머 하나).
- 아웃트로 동안 `answer()`는 첫 줄에서 `outro`면 return — 멈춘 화면의 카드·버튼이 이미 지나간
  결정에 답하면 안 된다(들어온 문은 `options` 검사가 있지만 제너레이터는 이미 전진해 있다).
- `CombatScreen`에 `outro` prop 하나를 더한다:
  - `"won"` — 적 배열을 빈 것으로 그린다 → 남은 적 전원이 기존 exitPop(사망 2프레임, 500ms)으로
    쓰러진다. 승리 = 전원 사망이므로 누가 막타였는지 알 필요가 없다. `sweepBanner("승리")`.
  - `"lost"` — `PlayerActor`에 `data-pose="death"`를 세운다(배선은 `motion.css:111`에 이미 있고
    한 번도 안 쓰였을 뿐이다). `sweepBanner("패배")`.
  - 배너 문구는 「내 턴」과 같은 키워드 표기다 — 문장을 만들지 않는다(WRITING.md).
- 화면 전환 자체는 App 한 곳 규칙(UI.md) 그대로: `slow` 판정에 「combat에서 나가며 outro였던
  전환」을 더해 leave 0.2 → 0.5초, 들어오는 reward/result는 기존 enter를 쓴다. 전환 쌍마다 새
  연출을 만들지 않는다.

### 4. 줄인 모션

- 돌진·순차 지연·아웃트로 홀드 전부 0 — 지금처럼 즉시 숫자·상태로 말한다. 정보(피해 팝 still,
  guardLine, 결과 화면)는 연출 없이 이미 다 있다(UI.md).
- e2e 드라이버가 아웃트로 1.3초에 걸려 헛돌지 않는지 본다 — 걸리면 줄인 모션과 같은 문으로 뺀다.

## 최소 검증

- 공격 카드를 내면 병사가 맞을 적 앞까지 갔다 돌아오고, 피해 팝·플래시가 도착 순간에 뜬다.
- 적 둘 이상이 공격하는 턴에 하나씩 순서대로 나와서 때리고, 「내 턴」 배너가 마지막 복귀 뒤에 선다.
- 대신 맞기(P-64)가 여전히 읽힌다 — 지킴이 도착 전에 숫자가 안 뜬다.
- 마지막 적을 잡으면 사망 프레임 → 「승리」 → 천천히 보상/결과. 아웃트로 동안 입력이 안 먹는다.
- 패배 시 병사 사망 프레임 → 「패배」 → 천천히 결과.
- 줄인 모션에서는 홀드·돌진 없이 지금과 같다.
- 확인은 `aside` CLI로 한다.

```bash
npx tsc --noEmit
npm test
npm run build
npm run e2e
git diff --check
```

- 엔진·데이터를 안 만지므로 밸런스 게이트와 무관하다. e2e 소요 시간이 늘면 원인을 리뷰에 남긴다.

## 설명

### 왜 공격자별 피해 분해를 안 하는가

관측의 `hits`는 출처별 합산이고(`sim/engine.ts:399-417`), 공격자별로 가르려면 엔진이 적 턴을
공격자 단위로 끊어 기록해야 한다. 순차 연출의 핵심은 「누가 나와서 때렸나」이고 그것은 UI가 이미
아는 사실(`prevAttackers`)로 충분하다. 숫자 분해는 연출값 대비 엔진 변경이 크다 — 필요해지면
`hits`에 선택 필드 하나 얹는 후속으로 미룬다.

### 왜 아웃트로가 엔진 관측이 아니라 App의 홀드인가

「막타 뒤 combat 관측 한 번 더」는 리플레이 형식과 e2e의 「반출 → CLI 재생 일치」를 건드린다
(`app.tsx:206` 주석이 남긴 바로 그 자리). 승리 = 전원 사망이라는 사실 덕에, 직전 관측에서 적만
비우면 화면이 알아야 할 것이 다 나온다 — 게임 상태가 아니라 화면 상태이므로 App이 든다.
