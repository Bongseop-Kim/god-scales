# P-39 · 티어 — 융합이 최강이 아니다

`plans/39-tier.md` · [◀ P-38](38-patron.md) · [색인](../reviews/00-index.md)

**크기** 중간~큼(카드 15장 신규 설계가 대부분이다) · **착수 조건** 없음. [P-38](38-patron.md)과 파일이 안 겹친다(그쪽은 `ui/`, 이쪽은 데이터·게이트·보상 한 함수). **세 번째 지역을 붙일 계획이면 그쪽이 먼저다** — §3의 깊이 규칙이 「지상이 마지막」을 전제한다

카드 129장이 사실상 **한 등급**이다. `expectedValue` 밴드가 patron 카드를 `[4, 8]`에 가두고(`tools/value.ts:83`) 실측은 4.0~7.5, 신별 평균 4.98~5.46이다. 보상 3택1이 「무엇을 고를까」가 아니라 「셋 중 아무거나」인 이유고, 12층을 걸어도 덱이 세지는 느낌이 없는 이유다.

**티어는 이미 절반 있다.** `isValueAllowed`가 융합에만 `[6, 10]`을 주고 나머지에 `[4, 8]`을 준다 — 하드코딩된 2티어다. 은혜 쪽은 한 발 더 가서 `graceBand(tier)`가 tier로 밴드를 기울인다(`:76`). 이 계획은 **그 하드코딩을 `tier` 필드로 일반화하고, 겹치는 두 밴드 위에 안 겹치는 칸을 쌓는다.**

그리고 실측 하나를 고친다. **융합 10장 중 여덟이 새 tier3 하한(10) 아래고, 그중 여섯은 patron 밴드 안(8 미만)이다:**

| 융합 | 값 | | 융합 | 값 |
|---|---:|---|---|---:|
| 아레스+아르테미스 | 10.0 | | 아테나+포세이돈 | **7.9** |
| 아르테미스+제우스 | 10.0 | | 아테나+제우스 | **7.5** |
| 아르테미스+포세이돈 | 9.9 | | 아레스+아테나 | **7.5** |
| 아르테미스+아테나 | 9.0 | | 아레스+포세이돈 | **6.4** |
| | | | 포세이돈+제우스 | **6.4** |
| | | | 아레스+제우스 | **6.0** |

patron 카드 최고가 7.5(아르테미스)다. **아레스+제우스 융합(6.0)은 평범한 카드보다 약하다** — 은혜 둘을 모아 여는 보상이 그것이다.

## 완료 정의

**티어가 값의 계단이고, 융합이 그 꼭대기고, 깊이 들어갈수록 높은 티어가 나온다.**

```bash
npx tsc --noEmit && npm test
npm run validate                         # 129 + 신규가 반려 0 — 밴드가 겹치지 않는다
npm run tune                             # 조합 승률 하한 0.05
npm run e2e
```

| 항목 | 판정 기준 |
|---|---|
| 계단 | tier1 `[4, 8)` **불변** · tier2 `[8, 10)` · tier3(융합) `[10, 13]`. 반개구간이라 경계값이 한쪽에만 든다 |
| 배포된 129장 | **한 줄도 재분류하지 않는다.** 119장 전부 tier1이고 `validate` 반려가 0으로 유지된다 |
| 융합이 꼭대기 | 융합 10장이 전부 10 이상. **여덟 장을 올린다** |
| 신별 tier2 | 다섯 신이 tier2를 **3장씩**, 전량 신규. 조합에 따라 고티어가 없는 신이 없다 |
| 획득 | 저승 tier1만 · 지상 일반 전투 3택1 중 **한 자리** tier2 · 정예·보스 **전부** tier2 |
| 풀 게이트 | `poolValueMax`가 티어별로 갈린다. 새 게이트가 아니라 있는 게이트의 일반화다 |
| 밸런스 | `tune` 하한 하나. 티어가 승률을 올리면 다이얼은 tier2 자리 수다 (CLAUDE.md) |

## 설계

### 1 · 티어는 위로 쌓는다 — 있는 카드를 재분류하지 않는다

처음엔 tier1 `[4, 6]` · tier2 `[6, 8]`로 자르고 값 6 초과 14장을 tier2로 올리려 했다. **실측이 그것을 막았다:**

```
값 6 초과 14장:  6.1 6.1 6.1 6.2 6.2 6.3 6.5 6.5 6.5 6.5 6.5 7.0 7.0 7.5   평균 6.50
값이 정확히 6.0인 카드:  18장
```

tier1 상한과 tier2 후보가 **0.1~0.5 차이로 붙어 있고**, 경계 6.0에 18장이 걸터앉는다. 그 계단은 등급이 아니라 반올림이다.

**밴드를 위로 쌓는다. 아래 칸은 손대지 않는다.**

```ts
// tools/value.ts — isValueAllowed를 대체한다. 반개구간이라 경계값이 한쪽에만 든다
const bands: [number, number][] = [[4, 8], [8, 10], [10, 13]];
export const cardTier = (card: Card): number => card.patron_pair ? 3 : card.tier ?? 1;
export const isValueAllowed = (card: Card): boolean => {
  const [low, high] = bands[cardTier(card) - 1];
  const value = expectedValue(card);
  return value >= low && (cardTier(card) === 3 ? value <= high : value < high);
};
```

- **tier1 `[4, 8]`은 지금 밴드 그대로다.** 배포된 119장이 한 줄도 안 바뀌고 `validate` 반려가 0으로 남는다 — 승률이 움직이면 그건 티어가 아니라 **획득 규칙(§3)**이 민 것이다. 두 원인을 섞지 않는 유일한 방법이다
- `Card.tier?: 1 | 2`. **융합은 안 적는다** — `patron_pair`가 곧 3이고, 두 곳에 적으면 어긋난다
- tier1 실측 최고가 7.5라 **8이 진짜 문턱**이다. tier1 평균 5.28 대비 tier2(8~10)는 1.7배 — 이건 계단으로 읽힌다
- **tier2는 전량 신규다.** 신별 3장 × 5신 = 15장을 값 8~10으로 설계한다

### 2 · 융합 여덟 장을 올린다 — 이 계획의 알맹이이자 최대 리스크

tier3 밴드 `[10, 13]`을 넘는 것은 지금 **두 장뿐**이다(아레스+아르테미스 10.0 · 아르테미스+제우스 10.0). 나머지 여덟 장을 올린다. **값만 올리는 게 아니라 조합의 정체성이 보이게 올린다** — 아레스+제우스 6.0이 가장 낮은 것은 출혈과 감전이 서로를 안 읽기 때문이다.

- 평균 8.06 → 11이면 **네 런에 한 번**(합성률 0.25, [R-28](../reviews/28-boon.md)) 덱에 들어오는 카드가 크게 세진다. **P-39에서 `tune`을 깨뜨릴 가능성이 가장 높은 항목이 이것이다**
- 상한 13은 지금 최고 10.0 위 세 칸이다. 밴드를 넓히려는 게 아니라 **10.0짜리 두 장이 상한에 붙어 있으면 손댈 여지가 없어서**다
- **하한 10이 너무 세면 다이얼은 tier3 밴드다** — `[9.5, 12]`로 내리면 올릴 카드가 여덟에서 일곱으로 줄고 폭도 준다. 카드 값을 깎아 게이트를 통과시키지 않는다(CLAUDE.md)
- 융합을 tier3으로 못 올릴 조합이 나오면 **그 조합의 토큰 축이 안 맞는다는 신호**다. 억지로 숫자를 붙이지 말고 리뷰에 적는다

### 3 · 획득은 깊이가 정한다 — 정예·보스 전용이 아니다

정예는 **지상 3·4층에만** 편성이 있고(`data/map.json`), 층마다 갈래 셋 중 하나만 밟으므로 한 런의 정예는 **0~2회**다. 보스는 2회. 「정예·보스 전용」이면 저승 여섯 층이 고티어를 한 번도 못 보고 노출이 런당 2~4회에 그친다.

**깊이로 잠근다.** 함수 하나다:

```ts
// 3택1 중 tier2가 차지하는 자리 수
const tier2Slots = (depth: number, path: MapNodeType): number =>
  path === "elite" || path === "boss" ? 3 : depth >= floorsPerRegion ? 1 : 0;
```

| 자리 | tier2 자리 | 런당 기대 |
|---|---:|---:|
| 저승 일반 전투 | 0 | — |
| 지상 일반 전투 | 1 / 3 | 3~4회 |
| 정예 | 3 / 3 | 0~2회 |
| 보스 | 3 / 3 | 2회 |

`rewardOffer`(`sim/engine.ts:67`)가 인자 하나를 더 받고, 후보를 티어로 갈라 뽑는다. **뽑기 순서는 tier2 먼저** — 나중에 뽑으면 같은 난수열에서 tier1 결과가 흔들려 옛 replay가 깨진다.

- 저승이 tier1뿐인 것이 곧 난이도 곡선이다. 지역 전환이 「강해졌다」로 읽히는 유일한 자리
- **「후보가 셋보다 적으면 던진다」 가드(`:70`)를 티어별로도 건다.** 지금은 조합 전체로만 센다 — 정예·보스가 tier2 세 자리를 요구하는데 조합 두 신의 tier2 합이 셋 미만이면 **무한 루프**다(`while (offer.length < 3)`)
- 신별 tier2가 3장이라 지상 보상에서 같은 카드가 반복해 뜬다 — `rewardOffer`의 중복 배제는 **한 판 안**이므로 그대로 둔다. 3장이 적다고 느껴지면 늘리는 것은 실측 뒤다
- **맵을 늘려도 이 규칙은 산다** — `depth >= floorsPerRegion`이 상수를 읽으므로 지역당 층수가 6→8이 되면 저절로 따라간다. **세 번째 지역을 붙이면 다시 짜야 한다**(「지상」이 더 이상 마지막이 아니다). 3지역 안이 예정돼 있으면 그쪽을 먼저 놓는 게 싸다

### 4 · 풀 게이트를 티어로 가른다 — 새 게이트가 아니다

`poolValueMax = 5.5`는 신별 풀 **평균값** 상한이다(`tools/validate.ts:408`). 지금 평균이 제우스 5.46 · 아르테미스 5.44 · 아테나 5.27 · 아레스 5.17 · 포세이돈 4.98로 **둘이 천장에 붙어 있다.** 값 8~10짜리 세 장을 같은 풀에 넣으면 그 자리에서 `pool_ratio` 반려다.

재분류를 안 하므로(§1) **tier1 평균은 지금 값 그대로 빡빡하다** — 여유는 안 생긴다. 상한을 올리는 게 아니라 **평균을 티어별로 낸다:**

- tier1 상한은 **5.5 그대로**. 배포된 119장이 지금 통과하는 그 숫자다
- tier2 상한은 **9.0** — 밴드 `[8, 10]`의 가운데다. 세 장뿐인 풀의 평균이므로 상한이 곧 「세 장 다 최고값은 안 된다」
- `poolRatioMax = 0.3`(완화 비율)은 **티어를 안 가른다.** 완화 비율은 신의 성격이지 등급이 아니고, 가르면 tier2 세 장으로 재는 비율이 되어 잡음만 커진다. **다만 tier2 세 장은 tier1 풀의 비율 계산에서 빠져야 한다** — 안 그러면 완화형 tier2 한 장이 그 신의 비율을 통째로 밀어 올린다

### 5 · `graceBaseline`은 tier1로 못 박는다 — 한 줄이다

`graceBaseline = 3.06`은 **「배포된 119장 실측 평균」**이고(`tools/value.ts:70`) 은혜 45줄의 밴드가 전부 여기서 나온다. 재분류를 안 하니 이 값은 **저절로 안 움직인다** — 위험은 나중에 누가 「배포된 카드 평균」을 다시 잴 때 tier2 15장이 모수에 섞이는 것뿐이다.

**주석에 「tier1 풀만」을 적고 끝낸다.** 값을 다시 계산하지 않는다 — `expectedValue` 평균 ×0.5는 전체 2.64 · tier1 2.56으로 **둘 다 3.06이 아니다.** 3.06이 어떤 계산에서 나왔는지 모르는 채로 재정의하면 은혜 45줄이 조용히 흔들린다.

## 함정

- **밴드를 겹치게 두면 티어가 이름뿐이다.** 지금 융합 `[6, 10]`이 patron `[4, 8]`과 6~8에서 겹쳐 「최강」이 거짓이 됐다. 지금 판정이 `>= low && <= high`(`tools/value.ts:84`)라 경계값이 두 밴드에 다 든다 — **반개구간으로 바꾸고 테스트로 못 박는다**. 값이 정확히 8.0·10.0인 카드를 설계하면 그 자리가 첫 시험이다
- **경계에 카드가 몰려 있다.** 값 6.0이 18장, 4.0이 4장이다. 밴드 경계를 옮기는 제안이 나오면 **먼저 몇 장이 걸터앉는지 세고** 나서 옮긴다 — §1이 그 계산 때문에 통째로 바뀌었다
- **`graceBaseline`을 다시 재면 은혜가 인플레된다.** §5가 그것 하나만 막는 절이고, 재계산이 아니라 주석이 답이다
- **tier2 뽑기를 나중에 하면 옛 replay가 깨진다.** 같은 `createRng(seed * 1000 + nodeSeed)` 스트림을 쓰므로 소비 순서가 곧 결과다
- **보스 보상이 12층에서 낭비된다.** 지금도 그렇지만(런이 그 자리에서 끝난다) tier2 3택1을 주면 눈에 띄게 무의미해진다. **이번에 고치지 않는다** — `offerReward` 호출을 빼면 e2e의 428결정 기준선이 움직인다. 리뷰에 적는다
- **봇에게 3택1이 자명해진다.** tier2가 섞이면 `expectedValue` 정렬이 언제나 그것을 고르므로 실측은 「항상 고티어를 집는 사람」의 승률이다 — 사람 승률의 **상한**이다(P-36의 하한과 반대 방향이다. 리뷰에 그렇게 적는다)
- **융합 상향이 합성 조합만 밀어 올린다.** 여덟 장을 평균 8.06 → 11로 올리는 것이 이 계획에서 가장 큰 값 변화다. 합성률 0.25라 네 런에 한 번이고 그 한 번이 조합 행렬의 특정 셀에 몰린다. 최저 셀(0.208)이 안 오르면 티어는 편차를 **키운** 것이다 — 그때 다이얼은 tier3 밴드(`[9.5, 12]`로 내린다)와 tier2 자리 수다
- **포세이돈 tier2 세 장이 완화로 막힌다.** 포세이돈은 완화 여유가 0.6밖에 없다([R-28](../reviews/28-boon.md)) — `soaked`·`displace`가 둘 다 완화라 값 8~10짜리를 만들면 비율 상한을 바로 넘는다. **`poolRatioMax`를 건드리는 게 아니라 포세이돈 tier2를 비완화(피해·연쇄)로 만든다**
- **기존 119장은 한 줄도 안 바뀐다 — 그게 이 계획의 대조군이다.** 승률이 움직이면 원인은 둘뿐이다: 획득 규칙(§3)과 융합 상향(§2). 재분류를 섞었다면 셋이 되어 어느 쪽이 밀었는지 못 가른다
- **tier2 15장이 신규 설계다.** 「값 8~10 카드 15장」은 이 계획에서 제일 오래 걸리는 작업이고, `duplicateFailure`(지문 겹침)가 마지막에 몰아서 반려한다 — 신 하나를 끝낼 때마다 `validate`를 돌린다

## 다음 자리 — 이 계획이 안 하는 것

1. **자유 모드**(P-40) — 시작 덱을 사람이 고른다. 고를 값이 생긴 뒤라야 결정이 된다. 밸런스 게이트는 고정 덱만 재고 자유 모드는 제외하되, 반출 파일에 모드가 남아야 재생이 안 어긋난다([P-38](38-patron.md)의 `patrons`와 같은 자리)
2. **저승 정예.** 편성이 없어서 빠진 칸이다(`group_under_forcing`) — 정예가 저승에 서면 §3의 깊이 규칙을 단순화할 수 있다
3. **tier3 patron 카드.** 융합만 3인 이유는 「조합을 완성한 보상」이라는 자리 때문이다. 신 하나로 tier3에 닿는 길을 열면 융합의 값이 다시 흐려진다
4. **12층 보상 제거.** e2e 기준선과 함께 움직인다
