# P-65 · 결과 화면 정리 · 다시 시작과 이탈 확인

관련 [R-54](../reviews/54-statusbar.md) 상태 바 · [R-53](../reviews/53-overlays.md) `<dialog>` 셸 ·
[R-52](../reviews/52-ui-split.md) · `tools/e2e.ts` 계약 · [WRITING.md](../WRITING.md) · [UI.md](../UI.md)

## 배경

**하나.** 결과 화면 오른쪽 절반이 개발자 로그다 — `result.log.slice(-10)`(`ui/screens/result.tsx:57`)이
`node=3:1 play card_zeus_04 → enemy_...` 꼴 열 줄을 `ui-monospace`로 깐다. 런을 마친 사람이 볼 것이 아니다.
그 옆의 「런 JSON 반출」은 **주요 버튼(`.primary`) 자리**를 차지하고 있어서, 다시 하고 싶은 사람의 눈이
먼저 닿는 것이 파일 반출이다.

**둘.** 런을 버리고 처음부터 하는 길이 **결과 화면에만** 있다. 3층에서 그만두려면 새로고침뿐인데,
새로고침은 아무것도 안 묻고 런을 지운다.

## 확인한 사실 — e2e가 이 화면을 읽는다

이 화면은 `tools/e2e.ts`의 마지막 관문이고, **B-0 4번(반출한 JSON을 CLI가 그대로 재생한다)의 증명이
반출 버튼 클릭 하나에 걸려 있다.** 지우면 그 증명이 통째로 사라진다. 읽는 자리 전부:

| 자리 | 읽는 쪽 |
|---|---|
| `.result-layout .actions button.primary` → 반출 | `e2e.ts:159` |
| `.result-layout .actions button:not(.primary)` → 다시 시작 | `e2e.ts:225` |
| `.result-layout h1` 텍스트 `승리` | `e2e.ts:214`·`:271` |
| `.result-layout .eyebrow` — `제우스 + 아테나 · 12/12층` 꼴 | `e2e.ts:215`·`:352` |
| `.summary-grid article > small`·`strong` | `e2e.ts:206`·`:358`·`:359` |

- 「다시 시작」은 **setup으로 돌아간다**(`e2e.ts:226`이 `[data-phase='setup']`을 기다린다). `reset()`
  (`app.tsx:98`)이 이미 그렇게 되어 있다.
- 상태 바는 `pending`이 있을 때만 그려진다(`app.tsx:206`) — **런 중에만 서는 자리**라 「다시 시작」이
  살 집으로 맞다. `.status-bar > div`는 `1fr auto 1fr` 격자고 왼쪽 칸이 `.vitals` flex다(`style.css:318`).
- 오버레이는 네이티브 `<dialog>` 셸 하나를 넷이 공유한다(`ui/shared/overlay.tsx:15`) — Esc·바깥 클릭·×가
  전부 `onClose` 하나다. 확인 창은 그 셸을 그대로 쓴다.
- **새로고침은 우리 창으로 못 막는다** — 브라우저가 `beforeunload`에 자기 문구를 띄운다. 앱이 할 수
  있는 것은 「물어보게 만드는 것」까지다.

## 단계

### 1. 결과 화면을 한 줄기로 (`ui/screens/result.tsx` · `ui/style.css`)

지금 2열(`.result-columns`, `.8fr 1.2fr`)에서 위에서 아래로 쌓는 한 줄기로 바꾼다:

```
머리글   조합 · N/12층  +  승리/패배
요약     최종 체력 · 전투 횟수 · 신 둘의 호의        (그대로 — e2e가 읽는다)
지도     저승 · 지상 (걸어온 길)
카드     마지막에 낸 셋
버튼     다시 시작 (주요)                            · 런 JSON (구석)
```

- **로그 열 줄 삭제** — `.combat-log`와 그 CSS(`style.css:614`)가 같이 죽는다. `result.log`는 관측·리포트에
  그대로 남는다(CLI·시뮬이 읽는 자리다).
- **`.outcome` 배지 삭제**(「균형 유지」·「저울 붕괴」) — `h1`의 「승리/패배」와 같은 말이다.
- eyebrow 문구는 **한 글자도 안 바꾼다** — e2e가 정규식으로 층수를 뽑는다.
- 요약 넷도 그대로다 — 라벨이 곧 e2e의 키다.

### 2. 반출 버튼을 구석으로

지우지 않고 **강등**한다. `.primary`를 「다시 시작」에 주고, 반출은 `.ghost`(작은 글씨·40% 불투명·
가리키면 또렷)로 같은 줄 오른쪽 끝에 선다 — `.fullscreen`(`style.css:131`)과 같은 꼴, 같은 이유다.

`tools/e2e.ts` 두 줄을 같이 고친다:

- `:159` → `.result-layout .actions button.ghost`
- `:225` → `.result-layout .actions button.primary`

**이 두 줄이 이 계획에서 e2e를 만지는 전부다.**

### 3. 「다시 시작」을 상태 바 왼쪽 끝에 (`ui/shared/header.tsx`)

`.vitals`의 **첫 자식**으로 작은 버튼 하나. 격자(`1fr auto 1fr`)는 안 건드린다 — flex 줄 안에 하나가
느는 것뿐이다. 런 중에만 뜨는 것은 `StatusBar` 자체의 조건이 이미 준다.

`StatusBar`에 `onRestart: () => void` 하나가 는다. 상태는 App이 든다(오버레이 넷과 같은 자리).

### 4. 확인 창 (`ui/shared/overlay.tsx` · `ui/app.tsx`)

`OverlayKind`에 `"restart"`를 더하고, `Overlay` 셸 안에 문장 하나 + 버튼 둘:

> 진행 중인 런을 버립니다. 처음부터 시작할까요?

버튼은 「다시 시작」(주요)·「취소」. 문체는 UI 시스템 텍스트 — **합니다체·능동·한 문장**(WRITING.md).
승인하면 `reset()`, 취소하면 닫기. Esc·바깥 클릭은 취소다(셸이 이미 그렇게 되어 있다).

**`confirm()`을 안 쓴다** — 커서 넷·픽셀 서체·청동 틀이 전부 죽고, 게임 안에서 유일하게 OS가 말하는
자리가 된다.

### 5. 새로고침도 한 번 묻는다 (`ui/app.tsx`)

```
런이 도는 동안에만(`pending`이 있을 때) `beforeunload`에 preventDefault 하나.
```

- **결과·시작·타이틀 화면에서는 안 건다** — 거기서는 버릴 것이 없다. e2e는 결과 화면에서 탭을 닫고
  「다시 시작」으로 setup에 가므로 **둘 다 `pending`이 없는 순간이라 안 걸린다.**
- 문구는 브라우저 것이다. 우리가 못 바꾸는 자리라 시도하지 않는다.

## 하지 않는 것

- **반출 기능 삭제 없음.** 버튼을 지우면 e2e가 증명하던 「반출 → CLI 재생 동치」가 사라진다.
  가리는 것과 없애는 것은 다르다.
- eyebrow 문구·요약 라벨·`h1` 텍스트 변경 없음 — 셋 다 e2e의 계약이다.
- `result.log` 생성 삭제 없음 — 화면에서만 내린다. 리포트·CLI가 계속 쓴다.
- 자동 저장·이어하기 없음. 「다시 시작」은 버리는 길이지 저장하는 길이 아니다.
- 「다시 시작」을 시작 화면·타이틀에 두지 않는다 — 거기서는 이미 처음이다.
- 규칙·값·데이터·봇 불변.

## 완료 정의

- 결과 화면에 로그 줄이 없고, 남은 것은 승패·요약 넷·지도 둘·카드 셋뿐이다.
- 주요 버튼이 「다시 시작」이고 반출은 구석에서 흐리게 선다.
- 런 중 어느 화면에서든 좌상단 「다시 시작」이 보이고, 누르면 **확인 뒤에** 시작 화면으로 간다.
- 런 중 새로고침·탭 닫기가 브라우저 확인을 한 번 거친다. 런 밖에서는 안 묻는다.
- `npm run e2e`가 두 줄 수정만으로 그대로 완주한다 — 반출물·재생 검사가 전부 살아 있다.
