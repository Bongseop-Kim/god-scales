## 완료 정의

브라우저에서 **카드를 직접 내며** 1런을 완주하고, 반출한 JSON을 `--replay`가 재생해 같은 결과를 낸다.

```bash
npm run dev
#   → 카드 클릭으로 1런 완주 → 반출 → logs/human/run-play-1.json
npm run sim -- --replay logs/human/run-play-1.json
#   → 브라우저 런과 승패 · 도달 층 · 최종 호의가 일치
```

반출 JSON의 `actions`에 `card` 항목이 있어야 한다. `path`만 있으면 아직 봇이 싸운 것이다.

## 산출

```
ui/combat.tsx   손패 · 에너지 · 적 HP와 의도 · 타겟 선택 · 턴 종료

```

## 범위

| 이 세션 | 이 세션 밖 |
|---|---|
| 카드 클릭 · 타겟 클릭 · 턴 종료 | 요구 선택 — 엔진이 자동 처리한다. 선택지로 올리는 것은 규칙 작업 |
| 휴식 종류와 제거 카드 | 은총 카드 선택 — `applyMilestones`가 신의 첫 카드로 고정 |
| 적 의도 표시 (봇이 이미 읽는 값이다) | 신 조합 선택 — 제우스+아테나 고정 |
| 1440×900 좌측 쏠림 레이아웃 | 새 연출 · 새 에셋 (P-18 · P-21에서 끝) |

**최소 범위** — 손패에서 카드를 골라 낼 수 있고 턴을 넘길 수 있으면 된다. 시간이 부족하면 휴식은 봇에게 맡기고(action log 부분 덮어쓰기가 이것을 허용한다) 전투만 사람이 한다.

---

## 지시

- **`ui/`는 게임 상태를 갖지 않는다**(I-3). React가 드는 것은 제너레이터 핸들 하나(`useRef`)와 "지금 어느 phase인가"뿐이다. HP·에너지·손패는 매 yield마다 엔진이 준 값을 그린다
- 카드를 낼 수 없는 상황(에너지 부족)은 **버튼을 비활성화**해서 막는다. 엔진에 못 내는 카드를 보내고 예외를 받지 않는다
- 반출 형식은 `{seed, actions, replay_mode: "action_log"}` 그대로다(P-22에서 `actions`만 넓혔다)
- **클라이언트 저장소를 쓰지 않는다**(T-1.1)
- 연출은 P-18에서 정한 것을 재사용한다. 카드 진입에 새 애니메이션을 만들지 않는다

## 검증은 aside repl로

`aside exec`는 모델을 써서 크레딧에 걸린다. `aside repl`은 안 쓴다.

```bash
open -a Aside   # 앱이 떠 있어야 확장이 붙는다
aside repl "const p = await openTab('http://localhost:5173/'); ..."
```

완주 E2E는 **이 세션에서 처음 짠다.** P-19 시점에 짜지 않은 이유는 그때 화면이 갈림길 4클릭뿐이어서 여기서 전부 다시 짜야 했기 때문이다.
