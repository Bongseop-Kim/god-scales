## 완료 정의

`bot_policy_version`과 `global_param_version`이 v1로 찍히고 리포트에 기록된다. 그 이전에 아래 네 항목이 전부 끝나 있다.

```bash
npm run play          # 사람 런 6~10회 (여러 사람)
npm run sim -- --runs 2000 --stratified
#   → hp_curve, block_efficiency 확인 후 상수 확정
```

## 동결 전에 해야 할 일

### 1. 사람 플레이테스트 6~10런

`npm run play`(P-12)로 3~5명이 각 2런씩 돈다. **전역 파라미터 조정의 유일한 정당한 근거이며**(T-6 ⑤ 3번), 동결 이후에 하면 그 조정이 이전 회차를 전부 무효로 만든다. 인원은 미리 섭외되어 있어야 한다(A-4).

물어볼 것은 통계로 나오지 않는 것들이다 — 상충 요구에서 어느 쪽을 왜 택했는지, 역린이 회복 불가능하게 느껴진 시점이 있었는지, 휴식과 전투 사이 선택이 실제로 고민이었는지.

**사람 런도 계측에 남긴다**(T-9.3). 통계가 되지 않는 런 수지만, 기록하지 않으면 난이도 조정의 근거가 문서에 존재하지 않게 된다.

### 2. HP 예산 확정

P-09의 `hp_curve` 실측과 사람 런을 함께 보고 R-8.3의 값을 확정한다. **룰 봇 승률은 이 판단의 근거가 되지 못한다**(T-6 ⑤).

### 3. `block_efficiency` 확인

0.8~1.2 대역 안인지 본다(P-11). 벗어나면 **지금** 봇 정책을 고친다 — 동결 후에는 고칠 때마다 이전 회차가 폐기된다.

### 4. 룰 봇 승률이 분별 대역 안인지 확인

15~70%(T-6). 벗어나면 그것은 난이도 신호가 아니라 **측정 불능 신호**다. 0%에 가까우면 모든 런이 같은 곳에서 끝나 카드별 델타가 나오지 않고, 100%에 가까우면 어떤 카드를 넣어도 이겨서 역시 델타가 나오지 않는다. 대역 안으로 되돌리는 조정은 3번에 해당하므로 사람이 판단하고 계측에 남긴다.

## 구현 노트

**이 게이트를 세우지 않으면 회차를 돌리는 내내 파라미터를 만지게 되고, 3회차가 끝났을 때 비교 가능한 데이터가 하나도 없다.** 시드 문서들이 여러 곳에서 "이전 회차가 무효가 된다"고 경고하지만 그 경계를 **언제** 세울지는 정하지 않았다. 여기다.

**계기의 절대 성능보다 계기의 불변성이 중요하다**(T-6). 정책을 개선하면 이전 회차의 밸런스 결론이 전부 근거를 잃는다. 서투른 채로 고정된 계기가 똑똑하지만 흔들리는 계기보다 낫다.

**동결 이후에 이 값들을 바꾸려면** — 사람이 명시적으로 바꾸고, 버전 번호를 올리고, `human_intervened`에 사유와 함께 남기고, **이전 회차 데이터를 폐기한다.** 반쯤 섞어 쓰지 않는다.

**참조** — T-6 ⑤ (조정 순서와 주체), T-6 (승률 분별 대역, 정책 버전), T-9.1 (버전 필드), T-9.3 (정직성 요건)
