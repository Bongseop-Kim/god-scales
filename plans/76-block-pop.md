# 76 — 막은 피해도 화면에 선다: 방어 흡수 팝

완전히 막힌 공격은 지금 **아무 연출이 없다.** `recordHits`(`sim/engine.ts:401`)가 HP가 깎인 것만 `hits`에 넣으므로, 방어가 피해를 전부 흡수하면 `hitSeq`가 안 올라 피격 파이프라인(돌진·플래시·셰이크·사운드·팝, `combat.tsx:304`)이 통째로 스킵된다 — 버그로 읽힌다. 엔진은 `dealDamage`(`core/rules.ts:214`)에서 `blocked`를 이미 계산하고 버린다.

**관측 확장 + 기존 팝에 한 갈래다** — 새 연출 시스템, 새 지표, 밸런스 수치 변경 없음(승률 게이트에 닿을 일 자체가 없어야 한다).

표기 문법: **델타는 팝, 총량은 칩.** 머리 위 팝이 이번 타격의 델타(피해 −N, 흡수 🛡N)를 말하고, 남은 방어 총량은 발밑 칩 `방어 N`(`combat.tsx:640,705`)이 이미 말한다. 「방어가 몇 감소했는가」를 따로 애니메이션하지 않는다 — 팝의 🛡N이 그 값이다.

---

## 1. 엔진: `hits`에 `blocked`, 막기만 한 프레임도 seq를 올린다

`sim/engine.ts`

1. `CombatObservation.hits`(`:289`) → `{ id: string; amount: number; blocked?: number }`.
2. `recordHits(before, source, blockBefore?)` — 세 번째 인자로 액터별 방어 스냅샷 `Map<string, number>`을 **선택적으로** 받는다. 액터별 `spent = max(0, blockBefore − blockNow)`를 계산해:
   - `lost > 0 || spent > 0`이면 항목을 넣는다(`amount: lost, blocked: spent`).
   - 항목이 하나라도 있으면 `hitSeq += 1`. `hitSource`도 지금처럼.
   - `turnTargets`·`damage_taken` 집계는 **지금처럼 `lost > 0`만** — 요구(과업) 사실은 안 바뀐다.
3. `blockBefore`를 넘기는 곳은 **카드 프레임(`:517`)과 적 턴 프레임(`:546`) 둘뿐**이다. 방어 흡수가 실제로 나는 자리가 거기다.
   - **power 프레임(`:468`)에는 절대 넘기지 않는다** — 스냅샷이 `startTurn`의 방어 리셋(`core/combat.ts:134`)을 가로지르므로, 넘기면 매 턴 남은 방어 전량이 가짜 「흡수」 팝으로 뜬다.
   - favor 프레임(`:477`)도 안 넘긴다 — 개입 피해의 흡수까지 구분해 보여줄 가치가 팝 하나 값이 안 된다. 필요해지면 그때.
4. `max(0, …)`인 이유: 같은 프레임에 방어가 **늘** 수도 있다(적 패턴의 block, curl 패시브). 순증은 0으로 눌려 팝이 안 뜬다 — 맞는 동작이다. curl은 피해가 뚫렸을 때만 발동하므로(`rules.ts` `amount > 0` 분기) 「전부 막음」 팝과는 안 겹친다.
5. `blockAbsorbed`(`:549`) 집계는 그대로 둔다 — 기존 리포트 필드고, 이 플랜은 관측만 늘린다.

## 2. UI: `DamagePop` 확장 + 막기만 한 타격의 소리·셰이크

`ui/screens/combat.tsx`

1. **`DamagePop`(`:39`)** — `!amount`면 `null`이던 것을 `!amount && !blocked`로. 표기:
   - 뚫림만: 지금처럼 붉은 `-7`
   - 일부 막음: `🛡5 -7` — 방패(`#icon-guard`, 이미 있음) + 흡수량을 피해 앞에
   - 전부 막음: `🛡8`만
   - 방패+숫자는 발밑 칩 `.shield`와 **같은 색**이다 — 「파란 숫자 = 방어」를 학습 한 번으로 끝낸다. 줄인 모션 still 분기(`:46`)도 같은 내용을 렌더한다(연출은 장식, 정보는 아님 — UI.md).
2. **피격 파이프라인(`:304`)** — `hits`에 막기만 한 항목이 실리므로 돌진·플래시는 공짜로 재생된다. 갈래 둘만:
   - 프레임의 모든 hit이 `amount === 0`이면 사운드는 `hit` 대신 `guard`(이미 있음, `:310`의 P-64 것과 같은 파일).
   - `impact()`(`:345`)에서 `amount === 0`인 대상은 **셰이크를 뺀다** — 막았으니 안 밀린다. 플래시는 유지(맞긴 맞았다).
3. **`aria-label`** — `EnemyButton`·`PlayerActor`의 라벨은 이미 `방어 N` 총량을 읽는다. 팝은 `aria-hidden` 유지, 추가 작업 없음.

`ui/style.css` — `.damage-pop`(`:527`) 안 방패 갈래 색 지정 한 줄. 레이아웃 규칙은 기존 그대로(absolute 층, transform/opacity만 — UI.md 제1규칙).

`guarded`(대신 맞기 P-64)의 `guard-mark`와는 별개 개념이다 — 같은 아이콘을 쓰지만 guard-mark는 액터 중앙, 팝은 머리 위(inset 다름). 겹치는 프레임(지킴이가 대신 맞고 방어로 막음)을 `aside`로 한 번 눈으로 확인한다.

## 3. 테스트

- `test/steps.test.ts`(또는 hits를 검증하는 기존 자리)에 엔진 케이스 셋:
  1. 방어가 피해를 전부 흡수 → `hits`에 `{ amount: 0, blocked: N }`이 서고 `hitSeq`가 오른다.
  2. 일부 흡수 → `amount`·`blocked` 둘 다 양수.
  3. 턴이 넘어가며 남은 방어가 리셋돼도(power 프레임) 가짜 hit이 **안** 선다.
- `test/ui.test.ts`에 `DamagePop` 표기 케이스: 전부 막음이면 방패만, 일부면 둘 다.
- `vitest run` 전체 통과 — 수치를 안 건드렸으니 밸런스 게이트는 당연히 통과해야 하고, 아니면 뭔가 잘못 만진 것.

## 완료 기준

- 방어로 전부 막은 적 턴에 guard 사운드 + 플래시 + `🛡N` 팝이 뜬다 — `aside`로 육안 확인(플레이어 피격·적 피격 양쪽).
- 완료 후 `reviews/76-block-pop.md` 작성, 이 플랜 삭제.

## 이 플랜이 안 하는 것

- deflect(되받아침) 연출 — 반사 피해가 공격자 쪽에 팝을 이미 만든다. 맞은 쪽 표기는 별도 논의.
- 개입(favor)·파워 피해의 흡수 구분 — 위 §1-3.
- 토큰(bulwark·shell)이 자른 양의 표기 — 방어와 문법을 나누기 시작하면 팝이 명세서가 된다. 필요가 보이면 별도 플랜.
