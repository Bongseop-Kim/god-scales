## 완료 정의

```bash
npm run sim -- --runs 200
```

가 승률 하나를 출력하고, **같은 시드 집합으로 재실행하면 승률이 소수점까지 동일하다.**

추가로 `npm run sim -- --runs 1 --log`가 전투 로그를 사람이 읽을 수 있는 형태로 출력한다 — 어느 적에게 무엇이 들어갔는지, 어느 토큰이 몇 스택인지가 읽혀야 한다.

## 산출

```
sim/runner.ts         1런 실행 → 로그
sim/bots/rule.ts      룰 봇 (전투 판단만)
sim/report.ts         최소 집계 (승률, 런 길이)
sim/log.ts            전투 로그 텍스트 렌더
```

**이 세션의 룰 봇은 전투 판단만 실장한다** — 맵·호의·요구는 아직 없다.

| 판단 | 정책 (T-6) |
|---|---|
| 카드 사용 순서 | 기대 가치 내림차순 = 예상 피해 + 예상 방어 환산 + 토큰 기대 이득 |
| 대상 선택 | 이번 턴 처치 가능한 적 → 복수면 의도 피해 큰 적 → 없으면 최저 HP |
| 광역 판단 | 생존 적 2체 이상이면 `all_enemies` 기대 가치에 적 수를 곱해 비교 |
| 방어 판단 | 공개된 의도를 합산해 그만큼만 block. 초과 방어는 낭비로 계산 |
| 치사 대응 | 합산 피해 ≥ 현재 HP면 모든 판단 무시하고 방어 최대화 |
| `exhaust` 취급 | 기대 가치에 0.6을 곱해 순서 결정 |
| 탐색 깊이 | 1턴 그리디. 다중 턴 탐색 없음 |

## 구현 노트

**이 세션이 끝나면 계측이 존재한다.** 이전까지는 코드였고 여기부터는 계기다.

**전투 로그 가독성을 여기서 함께 만든다**(B-5). UI가 P-17까지 없으므로 읽히는 로그가 유일한 디버깅 수단이다. 나중에 붙이면 이미 로그 없이 디버깅하는 습관이 든 뒤다. B-5는 이것을 "폴리시가 아니라 전달의 문제"라고 분류한다.

**봇은 측정 대상이 아니라 측정의 렌즈다**(T-6). 정책이 명시되지 않으면 승률 수치가 무엇의 함수인지 정의되지 않는다. **정책이 단일 전략인 것은 결함이 아니라 정의다** — 서투른 채로 고정된 계기가 똑똑하지만 흔들리는 계기보다 낫다.

**아직 `bot_policy_version`을 찍지 않는다.** 정책은 P-09(경로·휴식)와 P-11(대상 선택 검증)에서 더 붙고, 동결은 P-13에서 한다.

**참조** — T-6 (룰 봇 정책 정의), T-2 (`sim/` 디렉터리), B-5 (전투 로그 가독성)
