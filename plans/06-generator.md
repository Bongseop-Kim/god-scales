## 완료 정의

한 바퀴가 돈다.

```bash
# 1. 생성 — Claude Code 세션이 prompts/card-v1.md 를 읽고 staging/ 에 쓴다
# 2. 게이트
npm run validate -- staging/cards-zeus.json
#      → pass_rate 와 failure_breakdown 출력, 통과분만 data/cards.json 에 반영
# 3. 시뮬
npm run sim -- --runs 200
#      → 그 카드로 200런이 돈다
```

`pass_rate`가 **0%도 100%도 아닐 것.** 낮은 통과율은 실패가 아니라 정상 작동이다(T-6).

**그리고 반송분을 같은 프롬프트로 재생성해 두 번째 바퀴가 돈다.** 한 바퀴만 도는 것은 파이프라인이 아니라 일회성 생성이다.

## 산출

```
prompts/card-v1.md       카드 생성 프롬프트 (사람이 쓰는 유일한 콘텐츠 산출물)
data/gods.json           손으로 쓰는 유일한 데이터
staging/                 세션 출력이 게이트를 통과하기 전 머무는 곳
data/cards.json          통과분
logs/generation/         생성 세션 트랜스크립트
tools/validate.ts        --apply 옵션 추가 (통과분을 data/ 에 반영)
```

`data/gods.json`은 5신의 `id` `name` `tokens` `ops` `rivals` `stage_effects` `demands`만 담는다. **호의 상수·단계 경계·마일스톤은 여기 없다** — 전부 `core/favor.ts` 상수다(T-3.2).

## 구현 노트

### 여기서 프로젝트가 갈린다

이 시점 이후 모든 실패는 게임의 문제이고, 이전 실패는 논지의 문제다. **세 회차를 돌릴 시간이 없더라도 이 한 바퀴는 반드시 완주한다.**

### 생성 수단은 구독 토큰이다 (A-6)

`tools/generate.ts`는 만들지 않는다. 카드를 쓰는 것은 Claude Code 세션이고, `tools/`가 하는 일은 **게이트와 반영**뿐이다.

**논지의 경계는 API 호출이 아니라 사람의 개입 지점이다.** I-5는 사람의 개입을 "스키마·임계값·프롬프트 수정"으로 한정한다. 생성이 스크립트에서 나오든 세션에서 나오든 그 경계는 같은 자리에 있다. **사람이 카드 내용을 손으로 고치는 순간에만 I-5가 깨지고, 그때는 `human_intervened`에 남긴다.**

### 반송 경로

```
프롬프트 → 세션이 30장 생성 → staging/
  → npm run validate → 18장 통과, 12장 반송 + failure_breakdown
  → 반송 사유를 세션에 그대로 다시 넣는다 → 재생성
  → npm run validate → ...
```

**두 번째 바퀴가 완료 정의에 들어 있는 이유가 이것이다.** 반송이 실제로 다음 생성을 바꾸는지가 파이프라인의 전부다. 한 번 생성하고 끝내면 게이트는 필터일 뿐 루프가 아니다.

**리포트에 "루프가 자동으로 돌았다"고 쓸 수 없다.** "게이트가 반송하면 반송 사유와 함께 재생성했다"가 실제로 일어난 일이고, T-9.3이 요구하는 정직성이 그것이다.

### 트랜스크립트가 증거다

생성 세션의 트랜스크립트를 `logs/generation/`에 저장하고 커밋한다. **API 로그를 대체하며 오히려 더 강한 증거다** — 무엇을 요청했고 무엇이 돌아왔는지가 그대로 보인다.

### 구조화 출력이 없다

`output_config.format`은 API 기능이다. 세션 출력은 JSON 형식이 강제되지 않으므로 **`dsl_parse` 반송률이 API 경로보다 높게 나올 것을 예상한다.** 대응 둘 —

1. 프롬프트에 스키마 예시를 그대로 넣고 "이 형식 외의 텍스트를 출력하지 마라"를 명시한다
2. 게이트가 파싱 실패를 정확히 어느 줄에서 났는지 보고하게 한다. 그 메시지가 다음 바퀴의 입력이다

**ajv 게이트가 더 중요해졌다.** 구조화 출력이 있었다면 형식만은 보장됐겠지만, 어차피 값 범위(`cost: 0~3`, `stacks`, 배열 길이)는 잡아주지 않았다(A-6.2). 게이트의 역할은 그대로고 부담만 늘었다.

### 생성 지침

- **목표 수량의 5~10배를 과잉 생산한다**(T-6). 통과율이 낮은 것은 정상이다
- 프롬프트에 해당 신의 토큰 어휘와 성향만 노출한다. 컨텍스트가 좁아지고 정합성이 오른다
- 한 세션 안에서 한 신을 끝낸다. 세션이 바뀌면 출력 성향이 미묘하게 달라진다
- 프롬프트는 `prompts/` 아래 파일로 관리하고 버전을 매긴다. **이 이력이 본선 산출물의 기반이다**(B-1)
- 통과율이 0%에 가까우면 **임계값이 아니라 프롬프트를 고친다.** 임계값을 풀면 게이트가 무력해지고 파이프라인이 형식만 남는다

### 헤드리스 자동화는 나중에

Claude Code의 비대화형 실행 모드로 반송 루프를 자동화할 수 있을지도 모른다(A-6.4). **먼저 소규모로 확인하고, 이 세션의 완료 정의는 반수동 경로로 채운다.** 자동화는 세션 왕복이 회차 수를 제약하는 것이 관측된 뒤에 한다.
