# P-46 · 신이 보이게 한다 — 컷인이 말을 하고, 호의가 급변한다

`plans/46-presence.md` · [◀ P-45](45-fx.md) · [색인](../reviews/00-index.md) · 후속 [P-47](47-wrath.md)

**크기** 큼 · **착수 조건** [P-45](45-fx.md) — 단계 넷의 그림이 없으면 §4가 설 자리가 없다. [P-44](44-cards.md)와는 직교한다(저쪽은 카드 데이터, 이쪽은 호의·개입·화면)

신은 **개입하고 있다.** 안 보일 뿐이다. 600런 층화 실측이 원인을 셋으로 가른다:

| 사실 | 숫자 |
|---|---:|
| 조우가 **평온**인 비율 | **0.680** |
| 평온·분노에 `on_encounter_start` 줄이 있는 신 | **0/5** |
| 평온의 매 턴 개입 값 | 전부 **1** (조우 9.9턴 → 3회 → 총 6포인트) |
| 헌신 신이 하나라도 선 조우 | 0.187 |
| 컷인 그림이 덮는 단계 | 4단계 → **3장** (평온·분노가 같은 `burst`) |

세 조우 중 둘은 신이 값 1짜리를 세 번 한다. 그리고 그 세 번에 **같은 그림이 뜬다** — 화면은 「신이 뭔가 했다」까지만 말하고 무엇을 했는지, 도와준 건지 방해한 건지는 말하지 않는다.

이 계획은 여섯을 한다 — 설계 절 §1~§6과 하나씩 짝이다.

1. **호의 100을 두 신에게 배분하고 시작한다** — 런의 첫 결정이 하나 는다. 조합이 「누구와」라면 배분은 「얼마나」다
2. **컷인이 무엇을 했는지 말한다** — 문장은 `ui/header.tsx`에 이미 있다. 에셋 0장
3. **개입이 대상 위에서 터진다** — 누가 맞았는지가 보인다. 에셋 0장
4. **단계 넷이 다른 얼굴을 갖는다** — 신 5 × 단계 4 = 20장을 그리지 않는다. 그림 4 × CSS 색 5
5. **평온의 침묵을 깬다** — 다섯 신 평온에 조우 시작 한 줄. 조우의 68%가 이 자리다
6. **호의가 급변한다** — 전투 중 2택 「신탁」 하나. 한 조우에 단계가 바뀌면 §2~§4가 즉시 보상받는다

## 완료 정의

**100:0으로 시작한 런의 첫 조우에서, 한 신이 헌신이고 한 신이 진노임을 화면만 보고 알 수 있다.**

```bash
npx tsc --noEmit && npm test
npm run art -- --check      # 대조 위반 0 — P-45가 놓은 fx 여섯이 다 배선됐다
npm run size                # 위반 0
npm run validate -- data/gods.json
npm run tune                # 조합 승률 하한 0.05 — 이 계획의 유일한 밸런스 판정 (CLAUDE.md)
npm run e2e
```

| 항목 | 판정 기준 |
|---|---|
| 배분 | 시작 화면에서 100을 두 신에게 나누고(합이 항상 100) 그 값으로 런이 시작된다 |
| 기본값 | 손대지 않으면 **50:50** — 지금 값이다 |
| 재생 | `favor` 필드가 **없는** 기존 replay가 지금 그대로 재생된다(50/50) |
| 시뮬 | `npm run tune`이 **50:50으로 지금과 같은 값**을 낸다 — 배분은 시뮬 축이 아니다 |
| 컷인 문장 | 개입 컷인에 **신 이름 · 단계 · 한 일**이 뜬다. `prefers-reduced-motion`에서도 남는다 |
| 단계 구분 | 평온과 분노가 **다른 그림**이다. 진노가 신 일러다 |
| 대상 표시 | 개입이 때린/붙인 대상 위에서 파티클이 터진다 |
| 평온 | 다섯 신 전부 `on_encounter_start` 한 줄을 갖는다 — 68%의 침묵이 깨진다 |
| 신탁 | 전투 중 2택이 뜨고 호의를 ±12 움직인다. 행동 로그에 들어가 재생된다 |
| 게이트 | 조합 승률 하한 0.05 하나. 새 지표·밴드를 만들지 않는다 |

## 설계

### 1 · 호의 100을 배분하고 시작한다 — 런의 첫 결정

**저울이 이 게임의 이름이다.** 지금 시작 화면이 묻는 것은 「신 둘을 고르라」 하나고, 호의는 둘 다 50에서 자동으로 시작한다. 여기에 축 하나를 더 준다: **총합 100을 두 신에게 나눈다.**

```
   제우스 ◀━━━━━━━━━━━━━━●━━━▶ 아테나
     70 · 헌신              30 · 평온
```

슬라이더는 **하나**다. 한쪽을 정하면 나머지가 정해진다 — 둘을 두면 합을 100으로 맞추는 일이 플레이어 몫이 되고, 그건 결정이 아니라 산수다.

배분이 곧 시작 단계다:

| 배분 | 왼쪽 | 오른쪽 | 런이 어떤 모양이 되는가 |
|---|---|---|---|
| 50:50 | 평온 | 평온 | 지금 그대로. 둘 다 조용히 시작해 요구로 갈린다 |
| 70:30 | **헌신** | 평온 | 1조우부터 개입이 온다. 감쇠 −3이 곧 70을 깎으므로 유지는 카드가 한다 |
| 80:20 | **헌신** | **분노** | 한 신이 적을 회복시킨다. 헌신이 그 값을 넘겨야 이득이다 |
| 100:0 | **헌신**(상한) | **진노** | 1조우부터 신이 **적으로 합류**한다. 헌신 쪽은 감쇠 여유가 가장 크다 |

**0은 잘 안 올라온다.** `shiftFavor`가 0에서 자른다(`core/favor.ts:73`)는데 감쇠가 조우마다 −3이고 카드는 조우당 +5 상한이다 — 버려진 신을 끌어올리려면 그 신 카드로 덱을 채워야 하고, 그러면 다른 신을 버리게 된다.

그리고 진노의 `join`은 **조우마다** 다시 터진다. `applyFavorStageEffects`가 조우마다 돌고(`sim/engine.ts:285`) `queueEnemy`의 중복 방지는 한 전투 안에서만 산다(`createCombat`이 조우마다 `pending`을 새로 만든다). **100:0은 「런 내내 매 조우 신 하나가 더 선다」**는 뜻이고, 그게 이 축의 대가다.

지금 그 신은 hp 60이라 잡졸 한 마리 반이다 — **대가가 축을 지탱하지 못한다.** 스펙·보상·화해는 [P-47](47-wrath.md)이 짓는다. 이 계획은 **문을 열기만** 한다.

이 하나가 조사에서 나온 숫자 셋을 정면으로 푼다:

| 문제 | 배분이 하는 일 |
|---|---|
| 조우의 68%가 평온 | 플레이어가 시작부터 평온을 벗어날 수 있다 |
| 헌신 도달에 10조우 (런은 7.5조우) | **0조우**에 도달한다 |
| 진노 도달률 0.005 | 100:0을 고르면 **1.000**이다 |

[R-30](../reviews/30-intervention.md)이 진노 도달률을 못 열고 남긴 부채가 여기서 닫힌다 — 봇이 요구를 구조적으로 거절하던 자리를 **사람의 선택**이 우회한다.

덤으로 §2~§4를 만들면서 확인할 수단이기도 하다. 지금은 진노 컷인을 눈으로 보려면 200조우를 돌려야 한다.

#### 코드

`runSteps`의 초기 호의는 지금 리터럴이다(`sim/engine.ts:433`):

```ts
favor: { [patrons[0]]: graced ? 70 : 50, [patrons[1]]: 50 },
```

인자 하나를 뒤에 붙인다. **기본값이 지금 값이므로 시뮬·튠·기존 replay는 한 줄도 안 바뀐다.**

```ts
export const favorPool = 100;

export function* runSteps(
  seed: number,
  scenario?: Scenario,
  patrons: PatronPair = ["zeus", "athena"],
  startingDeck: string[] = ruleDeck(patrons),
  /**
   * `patrons[0]`이 가진 몫. 나머지(`favorPool - split`)가 `patrons[1]`이다 — **한 숫자가 둘을 정한다.**
   * 값을 둘 받으면 합이 100이 아닌 상태가 표현 가능해지고, 그러면 그것을 막는 검사가 화면·엔진·게이트
   * 세 곳에 생긴다. 배분은 **시작값만** 정한다: 시작 뒤에는 감쇠·카드·요구·신탁이 각자 민다
   *
   * **`scenario`를 늘리지 않는다** — 시나리오는 시뮬이 재는 고정 상태 셋이고 이건 사람이 시작 화면에서
   * 돌리는 축이다. 둘을 한 자리에 놓으면 `--scenario split_80`류가 끝없이 붙는다
   */
  split: number = favorPool / 2,
)
```

화면은 `<input type="range" min="0" max="100">` **하나**다. `ui/app.tsx`의 setup 화면에 시드 입력이 이미 있고 그 옆이다. 양 끝 라벨이 신 이름 · 값 · **단계 이름**을 든다 — `favorStage`가 이미 계산하므로 「70 · 헌신」이 슬라이더를 미는 동안 실시간으로 바뀐다. 그 라벨이 이 축을 가르치는 유일한 문서다.

**슬라이더는 폼 컨트롤이므로 라이브러리를 안 쓴다.** 색·눈금은 `ui/style.css`의 `--{id}`와 미터가 쓰는 단계 색을 그대로 얹는다. 트랙에 단계 경계 넷(70·30·10)을 눈금으로 새긴다 — 어디를 넘으면 무엇이 바뀌는지가 미는 동안 보여야 결정이 된다.

replay는 선택 필드 하나를 더 든다 — `patrons`·`deck`과 같은 자리다(`sim/replay.ts:21`):

```ts
export type ReplayFile = { seed: number; actions: ReplayAction[]; replay_mode: "action_log"; patrons?: PatronPair; deck?: string[]; split?: number };
```

없으면 50이다. **배포된 replay는 필드가 없으므로 지금 그대로 재생된다.**

#### 밸런스는 어떻게 판정하나

**게이트는 늘리지 않는다** (CLAUDE.md). `npm run tune`은 50:50으로 지금과 **완전히 같은 값**을 내고, 조합 승률 하한 0.05 하나가 그대로 판정한다. 배분은 봇이 고르는 축이 아니다 — 시뮬은 이 인자를 안 넘긴다.

그렇다고 안 재고 내보내지는 않는다. 착수 시 **한 번** 손으로 잰다:

```bash
npm run sim -- --runs 600 --stratified              # 50:50 — 기준선
npm run sim -- --runs 600 --stratified --split 100  # 극단
```

`--split`은 러너 플래그 하나고 게이트가 아니다. **이 숫자로 값을 깎지 않는다** — 극단이 지배 전략이면 그건 이 계획이 아니라 다음 회차가 볼 자리고, 계획은 잰 값을 리뷰에 적는 것까지 한다.

### 2 · 컷인이 무엇을 했는지 말한다 — 에셋 0장

지금 컷인(`ui/combat.tsx:118-130`)은 그림 한 장을 480ms 띄웠다 지운다. **그림은 「신이 뭔가 했다」까지만 말한다.**

그런데 무엇을 했는지의 문장은 **이미 있다.** `godStageText(god, stage)`가 `{ start, turn }`을 돌려주고 미터 툴팁이 그것을 쓴다(`ui/header.tsx:20`):

```
「적 하나에게 피해 8」 · 「나에게 방어 3」 · 「전 적군을 2 회복」
```

`playSprite`에 라벨 하나를 붙인다 — `ui/fx.ts`가 19줄에서 25줄이 된다:

```ts
export async function playSprite(host: HTMLElement, source: string, kind: "cut" | "spark" = "cut", label?: string): Promise<void>
```

컷인이 뜨는 자리에 `{신 이름} · {단계} — {한 일}`을 얹는다. 신 색은 `--{id}`, 단계 색은 미터가 쓰는 것을 그대로 쓴다.

**모션 밖에도 남긴다.** `reducedMotion`이면 지금 컷인이 통째로 `return`인데(`combat.tsx:120`), 그러면 그 플레이어는 신이 무엇을 했는지 **알 방법이 아예 없다.** 문장은 애니메이션이 아니라 정보다 — 모션을 끄면 페이드 없이 3초 머무는 정적 배너로 남는다. 접근성은 간소화 대상이 아니다.

### 3 · 개입이 대상 위에서 터진다 — 에셋 0장

컷인은 화면 가운데다. **누가 맞았는지가 안 보인다.**

개입이 만든 변화는 이미 관측에 들어간다 — `recordHits(beforeAura)`가 개입 직후에 돈다(`sim/engine.ts:349`). 그 `hits`를 화면이 읽어 대상 엘리먼트에 파티클을 쏜다. 카드가 이미 쓰는 경로 그대로다:

```ts
void playSprite(host, particleArt[...], "spark");
```

**파티클 엔진도 풀도 만들지 않는다** — `ui/fx.ts`의 주석이 이미 그렇게 적어 뒀다.

개입 op → 그림 한 줄. **`strike.webp`가 위에서 내려오는 국소 이펙트**라 신 개입이 카드와 한눈에 갈린다(카드 파티클은 제자리에서 터진다):

| op | 그림 | 색 |
|---|---|---|
| `damage` | `fx/strike` + `particle/slash_01` | 신 색 |
| `block` | `fx/strike` + `particle/window_01` | 신 색 |
| `heal` | `particle/magic_01` | 대상이 적이면 경고색 |
| `apply_token` | `particle/magic_01` | 토큰 색(`ui/tokens.tsx`가 이미 든다) |
| `join` | 신 일러 `art/gods/{god}.webp` → 스프라이트 `enemy_god_{god}` | — |

### 4 · 단계 넷이 다른 얼굴을 갖는다 — 그림은 [P-45](45-fx.md)가 만든다

지금 매핑이 4 → 3이었다(`ui/combat.tsx:26`) — 평온과 분노가 같은 `burst`라 도와주는 것과 방해하는 것이 화면에서 구별되지 않았다. **P-45가 그 표를 없앤다:**

```ts
// 단계 이름이 곧 파일 이름이다 — 매핑 테이블이 없으면 어긋날 자리도 없다
const cutFor = (stage: FavorStage) => fxArt[`../art/fx/${stage}.webp`];
```

이 절이 쓰는 것은 전부 P-45가 놓고 간 것이다:

| 자리 | 파일 |
|---|---|
| 단계 컷인 넷 | `art/fx/{devotion,calm,anger,wrath}.webp` |
| 개입 대상 위 | `art/fx/strike.webp` |
| 세기 올리는 공용 레이어 | `art/fx/burst.webp` |
| 진노의 합류 | `art/gods/{god}.webp` · `art/sprites/enemy_god_{god}.webp` (둘 다 이미 있다) |

**신 5 × 단계 4 = 20장을 그리지 않는다.** 신은 색으로 가른다 — `--{id}` 다섯이 이미 CSS에 있다. 그림은 모양(무슨 일이 벌어지는가)이고 색은 출처(누가)다.

화려함은 에셋 수가 아니라 연출에서 온다 — `art/fx/burst.md`가 이미 5단으로 적어 뒀다(**상징 스윕 → 신 일러 슬라이드인 → 화면 플래시 → 오버레이 → 컬러 그레이드**). 전부 CSS·WAAPI이고 새 의존이 없다:

- **단계마다 다른 진입** — 헌신은 위에서 내려오고 진노는 화면이 붉게 찢긴다(`clip-path` + `filter`)
- **화면 흔들림** — 피해 개입에 `translate` keyframes 200ms. 진노만 크게
- **호의 미터 펄스** — 이미 있다(`crossed`). 신탁이 단계를 넘기는 순간이 그 자리다
- **진노는 신 일러가 화면을 반쯤 덮는다** — 「신이 적으로 합류」는 판이 뒤집히는 사건이고 480ms 페이드로 지나가면 안 된다

에셋 규격·프롬프트·변환은 전부 [P-45](45-fx.md)에 있다. 이 절은 **배선만** 한다.

### 5 · 평온의 침묵을 깬다 — 이건 이펙트가 아니라 콘텐츠다

§2~§4를 다 해도 **평온 조우의 1턴에는 띄울 것이 없다.** 다섯 신 다 평온에 `on_encounter_start`가 비어 있고, 그게 조우의 68%다.

다섯 신 평온에 조우 시작 한 줄씩 넣는다. 매 턴 값이 1인 것은 그대로 둔다 — 조우당 1회는 3회보다 여섯 배 싸고, [P-34](../reviews/34-tempo.md)가 주기를 다이얼로 쓴 이유(`core/favor.ts:43`)가 여기 안 걸린다.

| 신 | 평온 · 조우 시작 (후보) |
|---|---|
| 제우스 | 앞 적에게 `shock` 1 |
| 포세이돈 | 전 적군에 `soaked` 1 |
| 아테나 | 나에게 방어 4 |
| 아레스 | 나에게 `frenzy` 1 |
| 아르테미스 | 앞 적에게 `mark` 1 |

값은 `npm run tune`이 정한다. **하한 0.05를 못 넘는 값을 테스트에 넣지도 깎지도 않는다**(CLAUDE.md) — 넘을 때까지 값을 내린다.

게이트 `stageEffectScopeFailure`(`tools/validate.ts:291`)가 이미 셋을 잠근다: 소모 경로 없는 토큰, 오타 난 대상, 헌신 개입의 기대값 ≤ 0. 평온은 세 번째 조건 밖이다(헌신만 본다) — **그대로 둔다.** 평온은 순이득일 필요가 없다.

### 6 · 호의가 급변한다 — 「신탁」 하나

지금 호의를 움직이는 것은 셋뿐이다:

| 경로 | 크기 | 빈도 |
|---|---:|---|
| 그 신 카드를 낸다 | +1 (조우당 5 상한) | 매 턴 |
| 조우가 끝난다 | −3 (안 쓰면 −5) | 조우마다 |
| 요구를 수락한다 | patron +12~ · 상대 −9~−18 | 조우 앞 |

앞의 둘이 상쇄되어 **조우당 순증 +2**다. 50 → 70이 10조우인데 런에 전투가 7.5조우다 — **카드만으로는 헌신에 도달할 수 없다.** 요구만이 미터를 움직이고, 그래서 미터가 조우 **안에서는** 절대 안 움직인다. 전투 중에 신의 얼굴이 바뀌는 일이 없다.

**신탁(oracle) — 전투 중에 한 번 뜨는 2택.**

```
[개입 턴] 아테나가 저울을 내민다.

  ① 방패를 내려놓아라   → 이번 조우 내 방어 0 · 아테나 +12
  ② 나는 내 손으로 선다 → 아테나 −12 · 카드 한 장 뽑기
```

왜 이 모양인가:

- **훅이 이미 있다** — 개입 턴(`intervenesOnTurn`)이 그 자리다. 새 시점을 만들지 않는다
- **결정 프레임이 이미 있다** — `Decision`을 yield하고 화면이 답한다. `DemandScreen`과 같은 모양이고 행동 로그에 들어가 그대로 재생된다
- **±12가 단계를 넘길 수 있다 — §1의 배분이 출발점을 경계 12 이내에 놓았을 때다.** 50:50에서는 신탁 하나(62나 38)로 아무 경계도 못 넘고, 조우당 한 번이라 한 조우 안 왕복도 없다. 65나 40처럼 경계 근처에서 시작해야 신탁이 그 조우의 컷인 얼굴(§2~§4)을 바꾼다 — 배분 없이는 이 절이 밋밋한 이유고, §1이 먼저인 이유다
- **§1과 축을 나눠 갖는다** — 배분은 **시작 위치**를 정하고 신탁은 **런 중에** 민다. 70:30으로 시작한 플레이어가 신탁 둘로 82:18까지 갈지 58:42로 되돌릴지가 결정이고, 배분이 없으면 그 결정에 출발점이 없다
- **진노 도달률을 연다** — [R-30](../reviews/30-intervention.md)이 못 연 자리다. 봇이 요구를 구조적으로 거절하는 이유(순수한 처벌에 보상이 안 붙는다)가 여기엔 없다. 신탁은 **양쪽 다 값이 붙은 저울**이라 거절할 「거절」이 없다

한 조우에 **한 번**이다. 개입 턴이 셋이므로 첫 개입 턴에만 띄운다 — 셋 다 띄우면 요구·신탁·카드가 같은 전투에서 다섯 번 묻고, 그건 결정이 아니라 클릭이다.

RNG는 **`nodeSeed` 계열의 새 스트림**에서 뽑는다. 전투·셔플·보상 스트림에 얹으면 신탁을 켜는 것만으로 적 뽑기까지 흔들려 기존 replay가 통째로 어긋난다 — ε 동전이 이미 같은 이유로 갈라져 있다(`sim/engine.ts:437` 주석).

봇은 `sim/bots/rule.ts`에 `chooseOracle` 하나를 갖는다. `chooseDemandAnswer` 옆이고 같은 모양이다.

#### 나머지 이벤트 후보 — 지금은 안 만든다

신탁 하나로 「호의가 조우 안에서 움직인다」가 서는지부터 잰다. 안 서면 아래를 얹는다. **서면 안 얹는다.**

| 이름 | 언제 | 무엇 | 왜 나중인가 |
|---|---|---|---|
| **시샘** | 한 신이 헌신에 닿는 순간 | 상대 신 −10 | 코드 3줄인데 신탁과 같은 축을 민다 — 둘을 같이 켜면 어느 쪽이 미터를 움직였는지 못 가른다 |
| **제물** | 조우 시작, 체력 40% 아래 | 최대 체력 −5를 내고 호의 +15 | 요구의 선불 대가(`payDemandCost`)와 같은 것이다. 어휘가 겹치면 화면에 두 이름이 선다 |
| **변덕** | 진노 단계의 개입 | 낮은 확률로 개입이 뒤집힌다 | 게이트가 「뒤집힌 개입」을 이미 반려한다(R-30 사후 수정). 규칙을 먼저 갈라야 한다 |
| **징조** | 지도 | `omen` 칸이 요구 대신 호의를 직접 건다 | `omen`은 이미 요구를 건다. 칸 하나에 두 뜻을 주는 것은 P-28의 `state.grace` 부채와 같은 실수다 |
| **연쇄 신탁** | 신탁을 같은 방향으로 두 번 | 세 번째가 커진다 | 상태를 하나 더 든다. 신탁 한 번이 재밌은 뒤에 |

## 함정

- **`prefers-reduced-motion`에서 정보가 사라진다.** 지금 컷인은 통째로 `return`이다. 문장은 모션이 아니다 — §2가 이걸 고치지 않으면 접근성 설정 하나가 신을 다시 투명하게 만든다
- **컷인 셋이 겹친다.** 조우 시작에 후원 둘 + 신탁이 같은 480ms에 뜨면 아무것도 안 읽힌다. 큐를 만들지 말고 **순서를 강제한다** — 조우 시작 컷인은 신 하나씩 220ms 어긋나게, 신탁은 컷인이 끝난 뒤에 묻는다
- **배분이 `scenario`를 오염시킨다.** `--scenario split_80` 같은 것이 붙기 시작하면 시뮬이 재는 고정 상태와 사람이 시작 화면에서 고르는 축이 한 자리에 앉는다. 인자를 나눠 둔 이유가 그것이다
- **100:0이 지배 전략일 수 있다.** 헌신 개입은 게이트가 순이득임을 강제하는데(`stageEffectScopeFailure`) 진노의 대가는 적 하나가 느는 것이다 — 그것도 hp 60이라 잡졸 1.5마리다. 착수 시 `--split 100`을 한 번 재서 리뷰에 적는다. **재되 그 숫자로 값을 깎지 않는다** — 대가를 키우는 것은 [P-47](47-wrath.md)이 맡는다
- **합이 100이 아닌 상태를 표현 가능하게 만들지 않는다.** 값을 둘 받는 순간 그것을 막는 검사가 화면·엔진·게이트 세 곳에 생긴다. 인자는 `split` 하나다
- **§5가 §6과 같은 방향으로 민다.** 평온 개입을 키우면서 신탁으로 헌신 도달을 열면 승률이 두 번 오른다. **§5를 먼저 재고 통과시킨 뒤 §6을 얹는다** — 한 번에 켜면 어느 쪽이 밴드를 깼는지 모른다
- **P-45 없이 착수하면 §4가 빈다.** 그림 넷이 없으면 컷인 매핑을 다시 3장으로 접게 되고, 그건 지금 상태다
- **재생 결정론.** 신탁은 **결정**이지 난수가 아니다 — 행동 로그에 들어가야 `npm run e2e`의 「반출 → CLI 재생 일치」가 선다

## 안 하는 것

- **신 5 × 단계 4 = 20장을 그리지 않는다.** 그림 4 × CSS 색 5다
- **파티클 엔진·스프라이트 풀을 만들지 않는다.** `playSprite` 한 함수가 계속 전부다
- **애니메이션 라이브러리를 더 넣지 않는다.** CSS keyframes와 WAAPI로 끝난다 — `ui/fx.ts`가 이미 WAAPI다
- **새 밸런스 지표를 만들지 않는다.** 판정은 `npm run tune`의 조합 승률 하한 0.05 하나다 (CLAUDE.md)
- **배분을 시뮬 축으로 만들지 않는다.** 10조합 × 배분 N개는 회차 비교를 부르는 격자다. 봇은 50:50만 돈다
- **배분을 런 중에 다시 묻지 않는다.** 시작값만 정한다 — 도중에 미는 것은 §6의 신탁이 맡는다
- **진노 신 다섯의 콘텐츠를 만들지 않는다.** [R-30](../reviews/30-intervention.md)이 정한 순서 그대로 — 도달률이 먼저다. 신탁이 그것을 열면 그다음 계획이다
