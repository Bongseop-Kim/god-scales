# P-68 · 과업은 맵에서 받고, 개입은 전투에서 자동

## 핵심

### 한 줄 결론

**전투 시작 선택을 없애고, 맵의 `과업` 노드에서만 다음 전투의 도전을 고른다.**

```text
과업 노드: 신 A / 신 B / 지나간다
                    ↓
다음 판정 가능한 전투: 그 한 판에서 조건 한 줄만 추적
                    ↓
달성 확정: 신 컷인 · 결과 잠금
달성 후 전투 승리: 호의 +12 · 기본 카드 1장 + 과업 카드 1장
미달성 후 전투 승리: 호의 보상 없음 · 기본 카드 1장
```

### 플레이 시나리오 · 아테나의 과업

#### 1. 맵에서 과업 칸을 고른다

```text
갈 수 있는 칸

[ 전투 ]    [ 과업 ]    [ 쉼터 ]
                ↑ 선택
```

과업 칸은 전투를 시작하지 않는다. 다음 전투에 걸 도전 하나만 고르고 맵으로 돌아온다.

#### 2. 두 신 중 하나를 고른다

```text
아테나의 과업
조건: 받는 피해를 8 이하로 막습니다.
기한: 다음 전투 한 판
달성: 아테나 호의 +12 · 아테나 카드 후보 3장 중 1장을 선택합니다.
선택: 제우스 호의 -9

[ 아테나를 따른다 ]

제우스의 과업
조건: 6턴 안에 전투에서 승리합니다.
기한: 다음 전투 한 판
달성: 제우스 호의 +12 · 제우스 카드 후보 3장 중 1장을 선택합니다.
선택: 아테나 호의 -9

[ 제우스를 따른다 ]    [ 지나간다 ]
```

플레이어가 아테나를 고른다. 제우스 호의가 즉시 9 내려가고, 맵 상단 상태 영역에 진행 중인 과업을 표시한다.

```text
진행 중인 과업 · 아테나 · 받는 피해 8 이하
```

#### 3. 다음 전투는 바로 시작한다

전투 시작 전에 다른 선택 화면은 뜨지 않는다. 전투 상단에서 조건과 현재값만 확인한다.

```text
과업 · 아테나    받은 피해 0 / 허용 8    개입 · 2턴 뒤
```

피해를 받을 때마다 `0 / 8 → 4 / 8 → 6 / 8`처럼 바뀐다. `개입` 칸은 다음 개입까지 남은 턴을 세고,
2·5·8턴에는 선택 화면 없이 현재 호의 단계에 맞는 두 신의 개입이 자동으로 일어난다.

#### 4-A. 5턴에 피해 6으로 전투에서 이기면 과업을 달성한다

```text
[ 아테나 컷인 ]
과업 달성
받은 피해 6 / 허용 8
아테나 호의 +12

전투 승리 보상
[ 제우스 카드 ]  [ 아테나 카드 ]  [ 제우스 또는 아테나 카드 ]
→ 1장 선택

[ 과업 보상 ]
[ 아테나 카드 ]  [ 아테나 카드 ]  [ 아테나 카드 ]
→ 1장 선택
```

컷인은 기존 신 연출을 재사용하고 입력을 요구하지 않는다. 기본 카드 한 장과 과업 카드 한 장을 고르면
총 두 장을 얻고 맵으로 돌아간다. 과업은 끝난다.

#### 4-B. 조건을 지키지 못하면 미달성으로 확정한다

```text
과업 미달성
받은 피해 11 / 허용 8

전투는 계속 진행
전투 승리 뒤 호의 보상 없음

[ 전투 승리 보상 ]
[ 제우스 카드 ]  [ 아테나 카드 ]  [ 제우스 또는 아테나 카드 ]
→ 1장 선택
```

받은 피해처럼 되돌릴 수 없는 조건은 한계를 넘는 순간 미달성으로 잠근다. 전투는 그대로 계속하며,
이후 전투에서 이겨도 과업 보상은 받지 않는다.

기본 카드 한 장만 고르고 맵으로 돌아간다. 과업 컷인과 과업 카드 보상은 없으며,
최대 체력이나 카드를 추가로 잃지 않는다.

#### 예외 · 아직 판정할 수 없는 전투

포세이돈의 `한 턴에 적 2명 공격`을 골랐는데 다음 전투의 적이 하나라면 과업을 판정하지 않는다.
그 전투에는 진행도를 띄우지 않고, 적이 둘 이상 나오는 다음 전투까지 맵 상단의 과업 상태를 유지한다.

### 플레이 규칙

| 순간 | 규칙 |
|---|---|
| 일반 전투 진입 | 선택 화면 없이 바로 전투 |
| 과업 노드 | 두 신 중 하나를 고르거나 지나감 |
| 신 선택 즉시 | 다른 신의 호의 −9, 라이벌이면 −18 |
| 전투 중 과업 | 새 선택은 없고, 받아 둔 조건 하나만 추적 |
| 과업 유지 | 판정 가능한 전투 한 번용 과업 하나만 유지. 여러 조건은 겹치지 않음 |
| 제한 | 기한은 판정하는 전투 한 판. 공통 턴 카운터는 없음 |
| 판정 | 조건을 실행할 수 있는 다음 전투 한 번에서 달성·미달성을 확정 |
| 달성 | 조건 충족 · 신 컷인 · 결과 잠금 |
| 달성 후 승리 | 호의 +12 · 기본 카드와 과업 카드 총 2장 획득 |
| 미달성 후 승리 | 기본 승리 보상 카드 1장만 획득 |
| 전투 중 개입 | 두 신이 2턴째부터 3턴마다 자동 행동 · HUD가 다음 개입까지 남은 턴을 셈 |

포세이돈처럼 적 둘이 필요한 조건은 적 하나 전투에서 소모하지 않는다. 화면에도 그 과업을 띄우지 않고,
조건을 판정할 수 있는 다음 전투까지 유지한다.

### 없애는 것

- 전투마다 뜨는 `신 A / 신 B / 관망` 화면
- 승부 카드 선택
- 최대 체력 8 판돈
- 조건 실패 시 카드 보상 몰수
- 전투 중 호의를 ±12 움직이는 신탁 선택
- 과업 보상으로 신 카드 전체를 펼치는 페이지 UI

### 남는 이름 둘

- **과업**: 맵에서 고르는 다음 전투 도전
- **개입**: 전투 2·5·8턴에 자동으로 일어나는 신의 행동

기존 전투 중 선택 이벤트였던 `신탁`은 삭제하며, 이 이름을 다른 시스템에 재사용하지 않는다.

`요구`·`내기표`·`승부 카드`·`판돈`은 플레이어 UI에서 쓰지 않는다.

### 완료 모습

```text
맵에서 과업 칸 선택
→ 신 하나 또는 지나가기
→ 맵으로 복귀
→ 일반 전투는 즉시 시작
→ 상단에 과업 조건·현재값과 다음 개입 카운트다운 표시
→ 2·5·8턴 자동 개입
→ 달성하면 신 컷인
→ 기본 보상 3택 1장
→ 달성했으면 선택한 신의 보상 3택 1장 추가
```

## 구현

### 1. 동시에 과업 하나만 든다

- `sim/engine.ts`의 `quests: Bet[]`를 단일 선택 상태로 줄인다.
- 맵의 `omen`에서만 `demand` 결정을 낸다. 엔진 id는 바꾸지 않고 화면 이름만 `과업`으로 쓴다.
- 과업 화면은 두 신과 `지나간다` 셋만 보여 준다.
- 이미 과업이 있으면 새 선택이 교체한다. 지나가면 기존 과업을 유지한다.
- 선택 즉시 기존 `takeSide`로 다른 신의 호의를 내린다. 새 비용 규칙은 만들지 않는다.

하나만 유지하는 것은 한 신을 런 끝까지 따른다는 뜻이 아니다. HUD에 조건 여러 개가 쌓이고 한 전투에서
보상 선택이 반복되는 것을 막는 슬롯 제한이다. 판정이 끝나면 비우며 다음 과업 노드에서 다른 신을 고를 수 있다.

### 2. 과업은 다음 판정 가능한 전투 한 번만 산다

- `demandEnemies`로 현재 적 수에서 조건을 판정할 수 있는지 확인한다.
- 판정할 수 없으면 전투 HUD와 정산에서 빼고 다음 전투로 넘긴다.
- 판정할 수 있으면 해당 전투 안에서 달성·미달성을 확정하고, 전투가 끝나면 과업을 비운다.
- 전투 HUD에는 `과업 · 신 이름 · 조건 · 현재/목표` 한 줄만 둔다.
- 달성은 기존 `demandSatisfied`, 미달성은 이미 있는 `demandSettled`의 `broken` 경로를 정산에 연결해 판정한다.
  현재 정산(`sim/engine.ts`의 과업 완료 판정)은 `demandSatisfied`만 보고 있어 실패 경로가 죽어 있다.
- 새 DSL·기한 카운터·퀘스트 종류는 만들지 않는다.

### 3. 기한은 판정하는 전투 한 판이다

- 공통 턴 제한 상수(`taskTurnLimit`)·기한 카운터·HUD 남은 턴 표시를 만들지 않는다.
  턴을 재는 조건은 제우스 요구 데이터의 `6턴 안에 승리`(`data/demands.json`) 하나뿐이며 그대로 둔다.
- `>=`·`>` 조건은 목표에 닿는 순간 달성으로 잠근다.
- `<=` 조건은 한계를 넘는 순간 미달성으로 잠근다. 전투 종료까지 지키면 달성한다.
- 전투 종료까지 어느 쪽도 확정되지 않은 조건은 종료 시점의 사실로 판정한다.
- 한 번 확정한 결과는 전투가 계속돼도 뒤집지 않는다.
- 달성이 확정되는 순간 기존 신 컷인과 `과업 달성`을 흐름 밖 오버레이로 한 번 재생한다.
- `prefers-reduced-motion`에서는 움직임 없이 같은 신 그림과 문구를 보여 준다.

### 4. 기본 보상과 과업 보상을 차례로 준다

- 모든 승리 전투는 지금처럼 두 신의 카드 후보 3장 중 한 장을 기본 보상으로 준다.
- 과업을 달성한 상태로 전투에서 이기면 기존 `offerQuestReward`를 이어서 한 번 연다.
- 과업 보상은 선택한 신의 카드 후보 3장 중 한 장이다. 지금처럼 전체 카드를 페이지로 펼치지 않는다.
- 따라서 과업 달성 전투에서는 기본 보상 한 장과 과업 보상 한 장, 총 두 장을 얻는다.
- 과업 보상 화면 상단에는 이미 확정한 `과업 달성` 결과 한 줄만 남긴다. 컷인을 다시 재생하지 않는다.
- 같은 자리에서 선택한 신의 호의 +12를 적용한다.
- `rewardOffer`의 patron 인자만 두 신 고정쌍에서 `readonly string[]`로 넓혀 기본 보상과 과업 보상이 같은 추첨을 쓴다.

과업 미달성 전투는 기본 보상 한 장만 받는다. 과업 보상 화면과 컷인은 열리지 않는다.

### 5. 일반 전투의 내기를 통째로 삭제한다

- `sim/engine.ts`: `askBet`·`askBetCard`·`BetCard`·`BetDecision`·`BetSettlement`·`betCandidates` 삭제.
- 첫 손 카드 고정, 마무리 일격 판정, 최대 체력 예치·반환, 승부 카드 강화 경로 삭제.
- `core/demands.ts`: `betDeposit`·`payDeposit` 삭제.
- `sim/bots/rule.ts`: `chooseBetCard`와 일반 전투 요구 선택 경로 삭제.
- `sim/replay.ts`: `bet_card` action 삭제. 제거한 phase의 별칭은 남기지 않는다.
- `ui/screens/choices.tsx`: `BetSheet`·`BetScreen` 삭제.
- `ui/style.css`·`ui/motion.css`: 내기표·판돈·승부 정산 스타일 삭제.

카드를 실제로 잃는 판돈도 만들지 않는다. 약한 카드 제거가 보상이 되는 역전을 막으려면 카드 가치 제한이나
별도 잠금 상태가 필요하다. 이 시스템은 그 비용을 들일 만큼 핵심이 아니다.

### 6. 기존 전투 중 신탁 선택을 삭제한다

- `core/favor.ts`: `oracleSwing` 삭제.
- `sim/engine.ts`: `OracleDecision`·전용 RNG·`askedOracle`·`oracle` yield·±12 호의 이동 삭제.
- `sim/bots/rule.ts`, `sim/replay.ts`, `ui/screens/choices.tsx`, `ui/app.tsx`의 oracle 분기 삭제.
- 첫 개입 턴에도 선택 없이 바로 `applyFavorStageEffects(..., "on_turn_start")`를 실행한다.
- 현재 단계별 개입 데이터·컷인·파티클은 그대로 둔다.
- 상태 바의 시점 설명 문구 대신 전투 HUD에 `개입 · N턴 뒤` 카운트다운 한 줄을 둔다.
  `intervenesOnTurn`(`core/favor.ts`)에서 남은 턴을 계산하며, 새 상태나 타이머는 만들지 않는다.
- `core/favor.ts:43` 주석의 평균 조우 턴 `5.8`을 최신 실측 `6.65`(`reviews/59-bets.md`)로 갱신한다.

### 7. 화면과 문서를 정리한다

- `ui/screens/map.tsx`: `예고`를 `과업`으로 바꾼다.
- 과업 선택지는 `즉시 다른 신 호의 감소`, `조건`, `달성 시 호의 +12와 카드 보상`만 적는다.
- 도움말은 `과업`과 `개입` 두 항목만 설명한다.
- 전투 약속 칩과 저널의 `퀘스트` 표기를 `과업`으로 통일한다.
- README 결정 표에서 일반 전투 요구·승부 카드·전투 중 신탁을 삭제하고 새 흐름을 적는다.
- 한글은 `WRITING.md`, 고정 높이와 버튼 배치는 `UI.md`를 따른다.

## 최소 검증

- 과업 없는 전투의 첫 결정이 `card`다.
- 과업 선택 뒤 조건을 판정할 수 없는 전투에서는 과업이 남는다.
- 다음 판정 가능한 전투에서 달성·미달성과 무관하게 과업이 끝난다.
- 코드에 공통 과업 턴 제한 상수가 없다. 턴을 재는 조건은 제우스 요구 데이터뿐이다.
- 달성·미달성으로 잠긴 결과는 같은 전투에서 바뀌지 않는다.
- 조건을 어긴 과업이 `broken`으로 정산되고 과업 보상이 열리지 않는다.
- 과업 HUD가 조건·현재값을 한 줄에 표시한다.
- 전투 HUD에 다음 개입까지 남은 턴이 표시된다.
- 달성 전투는 기본 보상 한 장 뒤에 선택한 신의 보상 한 장을 추가로 얻는다.
- 미달성 전투는 기본 보상 한 장만 얻고 과업 보상 화면이 열리지 않는다.
- 과업 보상 화면에는 선택한 신의 카드 후보 3장과 `과업 달성` 결과 한 줄이 함께 보인다.
- 한 런의 결정 phase에 `bet_card`·전투 중 `oracle`이 없다.
- 2턴 시작에 선택 화면 없이 자동 개입이 적용된다.

## 설명

### 현재 카드 선택이 이해되지 않는 이유

현재 승부 카드는 실제 판돈이 아니다. 첫 손에 들어오고 그 카드로 마지막 적을 처치하면 강화되지만,
실패해도 카드는 남는다. 잃는 것은 카드 보상과 최대 체력 8이다. `카드를 건다`는 말과 실제 위험이 다르므로
설명을 더 붙여도 직관적이 되기 어렵다.

### 현재 신탁이 호의 조절을 쉽게 만드는 이유

카드 사용은 신당 조우당 최대 호의 +5다. 전투 중 신탁 한 번은 한 신 +12, 다른 신 −12라 두 신의 간격을
24 바꾼다. 카드 운용보다 버튼 한 번이 저울에 더 크게 작용한다. 게다가 모든 조우의 2턴째에 한 번씩 오므로
예외 사건이 아니라 반복 메뉴가 됐다.

기존 전투 중 신탁 선택을 없애도 신은 사라지지 않는다. 호의 단계가 조우 시작과 2·5·8턴의 자동 개입을 결정하므로,
플레이어가 맵에서 한 선택과 전투에서 쓴 카드가 실제 신의 행동으로 이어진다.

### 왜 공통 6턴 제한을 두지 않는가

최신 실측 평균 전투 길이가 6.65턴이다(`reviews/59-bets.md`). 모든 과업에 6턴 컷을 걸면 승리형 조건은
평균 전투 길이와 컷이 겹쳐 동전 던지기가 되고, `받는 피해 8 이하` 같은 유지형 조건은 잴 시간이 줄어
오히려 자동 달성에 가까워진다. 기한은 판정하는 전투 한 판으로 충분하며, 전투 자체가 이미 기한이다.
턴을 재고 싶은 요구는 제우스처럼 조건 안에 직접 적는다.

### 왜 개입에 카운트다운을 붙이는가

2·5·8턴 주기는 규칙이 있지만 플레이어에게는 예고가 없어 임의로 느껴진다. Into the Breach가 보여 줬듯
임의성의 해독제는 발동 규칙 변경이 아니라 사전 표시다. Wildfrost도 발동 자체는 기계적인 카운터지만
숫자가 붙어 있어 아무도 규칙이 없다고 느끼지 않는다. 주기는 그대로 두고 남은 턴만 보여 준다.

### 왜 과업을 맵에만 두는가

맵의 `omen`은 이미 별도 위험·보상 선택을 받을 자리다. 일반 전투는 전투를 하고, 과업 노드는 도전을 고른다.
노드의 역할이 갈리므로 플레이어는 언제 결정을 요구받는지 예측할 수 있다.

과업을 한 전투로 끝내면 조건·기한·정산도 한 줄씩이다. 현재처럼 달성할 때까지 여러 전투에 남거나 두 개를
겹치면 HUD와 저널이 다시 퀘스트 관리 화면이 된다.

### 조사에서 가져온 원칙

- [Slay the Spire 개발자 인터뷰](https://www.gamedeveloper.com/game-platforms/road-to-the-igf-mega-crit-games-i-slay-the-spire-i-): 맵 경로 선택 자체가 적은 복잡도로 위험·보상과 계획을 만든다. 전투마다 별도 계약 화면을 더할 필요가 없다.
- [Hades · Chaos Boons](https://hades.fandom.com/wiki/Chaos/Boons_%28Hades%29): 전용 게이트에서 단기 불이익을 받고, 정해진 전투 수를 버티면 장기 보상으로 바뀐다. 선택 장소·기간·보상이 한 계약 안에 있다.
- [Dead Cells 공식 위키 · Curse](https://deadcells.wiki.gg/wiki/Curse): 위험은 하나이고 해제 조건은 적 처치 수 하나다. 진행도를 즉시 읽을 수 있어 별도 설명표가 필요 없다.
- [Into the Breach 개발자 인터뷰](https://www.gamedeveloper.com/game-platforms/road-to-the-igf-subset-games-i-into-the-breach-i-): 실패 이유가 명확해야 플레이어가 통제감과 학습 가능성을 느낀다. 과업의 조건과 자동 개입 시점을 전투 전에 읽을 수 있어야 한다.
- [Wildfrost · 카운터 메커니즘](https://dood.gg/en/wildfrost/guides/frost-mechanics/): 발동은 기계적인 카운터지만 유닛 옆 숫자로 항상 예고된다. 고정 주기라도 카운트다운을 보여 주면 임의성으로 읽히지 않는다.

이 사례를 그대로 복제하지 않는다. 현재 코드에 이미 있는 `omen`·`demandSatisfied`·`rewardOffer`·`offerQuestReward`·단계별 개입을
한 줄로 이어 새 시스템 없이 같은 효과를 낸다.
