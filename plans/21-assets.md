# P-21 · 에셋 투입 — 동결 후

`plans/21-assets.md` · [◀ P-20](20-rounds.md) · [색인](00-index.md)

**크기** 제작 시간에 좌우됨 · **착수 조건** P-20 (콘텐츠 동결)

**이 세션은 코드 세션이 아니다.** 배선은 P-18에서 끝났고 여기서는 만든 것을 넣는다. 코드 쪽 작업은 누락 확인과 최적화뿐이다.

---

## 완료 정의

```bash
npm run art -- --check
#   → 누락 목록이 비어 있거나, 남은 것이 의도된 우선순위 밖이다
npm run build && npm run size
#   → 에셋 투입 후 번들·자산 총량이 목표 안
npm run dev
#   → 1런 완주 후 반출 → npm run sim -- --replay  → 일치
```

**재생 일치가 여기서도 검증 대상이다.** 에셋이 붙었다고 UI가 상태를 갖기 시작하면 안 된다.

---

## 왜 여기인가

**카드는 회차마다 자동 조정되고 3회 조정 후에도 임계값을 벗어나면 폐기·재생성되며 id도 바뀐다**(T-6 ⑤). P-20 이전에 만들면 **만든 것의 일부가 존재하지 않는 카드의 것이 된다.**

이 규칙은 카드 일러스트만이 아니라 **직접 제작하는 셋 전부에 적용된다** — 스프라이트 이펙트는 카드 효과에 붙고, 사운드는 사건에 붙는다.

```bash
npm run art -- --list
#   → id · 이름 · 귀속 신 · 효과문 · 태그  →  작업 목록 CSV
```

## 1. 카드 일러스트 (~70장)

`art/cards/{card_id}.webp` — 파일을 넣는 것으로 끝난다. 코드 변경 없음(A-2.3).

**시연이 급하면 우선순위가 있다.**

| 순위 | 대상 | 장수 | 근거 |
|---|---|---|---|
| 1 | 시작 덱 카드 (신별 4장 × 5신) | 20 | 모든 런의 1턴부터 화면에 있다 |
| 2 | 합성 카드 | 10 | 절정이고 조합당 1장뿐이라 기억된다 |
| 3 | 그 외 | ~40 | 픽률(`pick_rate`) 높은 순 |

**30장이면 화면에 뜨는 빈도의 대부분을 덮는다.** 나머지는 placeholder로 두어도 시연이 성립한다.

3순위 순서는 `pick_rate`로 정한다 — 회차 데이터가 이미 어떤 카드가 자주 뽑히는지 알고 있다.

---

## 2. 스프라이트 시트 이펙트

**저빈도 극적 연출에만 만든다**(A-2.6). 고빈도 UI 피드백은 P-18의 CSS 연출로 끝나 있다.

| 대상 | 런당 | 우선순위 |
|---|---|---|
| 합성 카드 획득 | 0~1 | **1** — 절정 |
| 역린 개입 (신별 5종) | 0~5 | 2 |
| 보스 등장 | 2 | 3 |
| 총애 전역 효과 (신별 5종) | ~10 | 4 |

**규격**(A-2.8) — `transform: translateX()` + `steps()`. `background-position`은 paint를 유발하므로 쓰지 않는다. 처음부터 2x로 만들고 CSS에서 반으로 줄인다. 12프레임 × 256px = 3072px 폭이면 모바일 텍스처 한계에 근접하니 세로로 감거나 나눈다.

**프레임 수는 12 안팎이면 충분하다.** 손그림 애니메이션이 12fps로 도는 것과 같은 이유이며, 프레임을 늘려도 480ms 예산 안에서는 체감이 크게 달라지지 않는다.

## 3. 사운드 (~10종)

`audio/{event}.webm` (또는 `.m4a`) — P-18의 `ui/sfx.ts`가 받는다.

| 사건 | 런당 | 지침 |
|---|---|---|
| 카드 사용 | ~100 | **아주 짧고 미묘하게.** 여기서 실패하면 3분 만에 끄고 싶어진다 |
| 피격 · 회복 | ~200 | 짧게. 피해량에 따라 피치를 살짝 |
| 토큰 부여 | ~80 | 거의 들리지 않을 정도 |
| 요구 제시 | ~7 | 신의 개입임이 들리게 |
| 역린 개입 | 0~5 | 크게 |
| 합성 획득 | 0~1 | **가장 크게** |
| 승 · 패 | 1 | 런의 마침표 |

**빈도 규칙이 소리에는 시각보다 가혹하다.** 100회 반복되는 소리는 100회 반복되는 애니메이션보다 훨씬 빨리 거슬린다.

**배경 음악은 만들지 않는다**(A-3.3). 루프 하나가 시연 내내 도는 것은 SFX보다 빨리 거슬리고, SFX가 먼저다.

**음소거 스위치는 P-18에서 이미 있다.** 여기서는 소리를 넣고 스위치가 여전히 도는지만 확인한다.

## 4. 최적화

에셋이 붙으면 번들이 아니라 **자산 총량**이 문제가 된다.

| 항목 | 목표 |
|---|---|
| 카드 일러스트 70장 | WebP, 장당 40KB 이하 → ~3MB |
| 스프라이트 시트 | WebP, 시트당 200KB 이하 |
| 사운드 10종 | 짧은 SFX, 종당 30KB 이하 |

- **첫 화면에 필요한 것만 즉시 로드하고 나머지는 지연 로드한다.** 신 선택 화면에 카드 일러스트 70장이 필요하지 않다
- 카드 일러스트는 `loading="lazy"` + 손패에 들어올 때 프리페치
- 스프라이트 시트는 해당 연출이 처음 발생하기 전에 프리페치 — 발생 시점에 로드하면 첫 재생이 끊긴다

**배포 URL이 여전히 즉시 열려야 한다**(T-1). 자산이 늘어 첫 로드가 느려지면 그 자체가 시연 손실이다.
