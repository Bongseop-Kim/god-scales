# P-64 · 대신 맞기가 보이게 · 빈 손패가 판을 안 흔들게

관련 [P-60](60-poses.md) 스프라이트 포즈(**먼저 돈다**) · [R-58](../reviews/58-flourish.md) 피격 연출 ·
[R-55](../reviews/55-battle-stage.md) 칸 배치 · [R-25](../reviews/25-enemies.md) guard 도입 · [UI.md](../UI.md)

## 배경

**하나.** 지킴이(`guard`)가 앞에서 대신 맞는다(`core/rules.ts:327`). 화면에서 벌어지는 일은 「내가 고른
적이 아니라 옆 적의 체력이 줄었다」뿐이다 — 지킴이는 제자리에 서 있고, 대신 맞았다는 신호가 하나도
없다. 능력 칩에 「보호 2」가 적혀 있지만 그것이 **방금 발동했다**는 것을 화면이 말하지 않는다.

**둘.** 손패를 다 내면 `.fan`(`ui/style.css:579`)의 높이가 0이 되고 `.combat-bottom` 격자가 통째로
당겨 올라온다. 「턴 종료」와 에너지 젬은 `absolute`(`:510`·`:518`)라 제자리지만 무대·힌트 줄이 내려앉는다 —
UI.md 제1규칙 위반이고, 마지막 카드를 낸 바로 그 순간에 판이 덜컥인다.

## 확인한 사실

- 재지정은 **플레이어 카드에서만** 일어난다 — `guardFor`를 부르는 자리는 `executeCard`의
  `card.target === "enemy"` 피해 한 줄뿐이다(`rules.ts:387`). 적의 공격은 재지정되지 않는다.
- **관측에 「누가 대신 맞았나」가 없다.** `hits`(`sim/engine.ts:271`)는 체력이 줄어든 쪽만 싣는다 —
  체력바 비교로 만들기 때문이다(`recordHits`). 화면이 「내가 고른 대상」과 대조해 추측할 수는 있지만,
  연쇄·전체 카드가 섞이면 그 추측이 틀린다.
- 재지정은 **한 카드에 여러 번** 날 수 있다 — `all_enemies`·`chain`은 대상마다 `guardFor`를 지난다.
- `guard` 스택은 소모된다(`guard.passives.guard -= 1`) — 그래서 능력 칩의 숫자가 줄어드는 것은 이미
  화면에 나온다. 없는 것은 **그 순간의 연출**이다.
- 적의 x 위치는 `--slot`이 정한다(`style.css:464`, 칸 간격 180px) — **두 적 사이 거리를 DOM 측정 없이
  칸 차이 × 180으로 계산할 수 있다.** 관측이 `slot`을 싣는다.
- 피격 연출은 `view.hitSeq` 이펙트(`combat.tsx:282`)가 WAAPI로 건다 — `translate`·`filter` 속성이라
  motion의 `transform`과 안 싸운다. **P-60 §3이 이 같은 이펙트에 포즈를 얹는다** — 그래서 P-60이 먼저다.
- `.fan`은 카드 높이를 그대로 받는 flex다 — 세로를 정하는 규칙이 없다.

## 단계

### 1. 재지정을 사실로 남긴다 (`core/state.ts` · `core/combat.ts` · `core/rules.ts`)

`CombatState`에 한 칸:

```ts
/** 이번 카드가 재지정한 피해. `playCard` 진입에서 비운다 — 한 번의 클릭이 만드는 사실이다 */
guarded: { by: string; from: string }[];
```

`turnPlays`(`state.ts:74`)와 같은 꼴의 **파생 기록**이다 — 규칙이 이걸 읽고 분기하지 않는다.

- `playCard`(`combat.ts:151`) 진입에서 `state.combat.guarded = []`.
- `executeCard`(`rules.ts:387`)의 그 한 줄에서 `guardFor`의 결과가 원래 대상과 다르면 밀어 넣는다.
  `guardFor` 자체는 안 바꾼다 — 반환값 비교로 이미 알 수 있다.

### 2. 관측에 싣는다 (`sim/engine.ts`)

`hits` 옆에 `guarded: { by, from }[]`. `hitSeq`가 이미 「새 피해」를 세므로 **새 seq를 만들지 않는다** —
가드는 언제나 피해와 같은 프레임에 온다. 빈 배열이면 아무 일도 없었다는 뜻이다.

### 3. 연출 — 800ms짜리 한 동작 (`ui/screens/combat.tsx`)

`view.hitSeq` 이펙트 안, 피격 연출 **앞**에 붙는다. 지킴이가 원래 대상 앞으로 나갔다가 돌아온다:

| 구간 | 길이 | 하는 일 |
|---|---:|---|
| 전진 | 260ms | 지킴이가 `(from.slot − by.slot) × 180px`만큼 미끄러진다. 목표 칸 **앞**에서 멈춘다(−40px) |
| 버팀 | 240ms | 그 자리에서 흰 플래시 + 원래 대상 위에 「보호」 자국(guard 글리프 페이드) |
| 복귀 | 300ms | 제자리로 |

- **맞은 쪽 플래시·셰이크·피해 팝은 260ms 늦춘다** — 지킴이가 도착한 뒤에 맞아야 인과가 읽힌다.
  타이머는 지금 컷인 이펙트가 쓰는 `timers` 배열과 같은 꼴로 cleanup이 걷는다.
- 이동은 WAAPI `translate`다 — motion의 `layout`(칸 이동)과 채널이 갈린다(P-58과 같은 이유).
- **글로도 남긴다** — 힌트 줄(`role="status"`, `combat.tsx:384`)에 「〈이름〉이 대신 맞았습니다.」
  (UI 시스템 텍스트: 합니다체·능동·한 문장, WRITING.md). 연출이 꺼져도 정보가 안 사라진다(UI.md).
- `prefers-reduced-motion`에서는 이펙트가 초입에서 반환하므로 이동이 안 붙고 **문장만 남는다.**
- 재지정이 둘 이상이면 지킴이 하나가 여러 번 나가는 것이 아니라 **한 번 나가서 한 번 버틴다** —
  같은 지킴이가 두 대상 몫을 받는 것이 규칙이고, 화면도 한 동작이면 족하다.

### 4. 빈 손패가 자리를 지킨다 (`ui/style.css`)

```css
/* 손을 다 내도 자리가 남는다 — 카드가 사라지며 아래가 당겨 올라오면 안 된다(UI.md 제1규칙) */
.fan { min-height: <실측 카드 높이 + 회전 여백>px; }
```

숫자는 aside로 잰 값 하나를 박고 **어디서 온 값인지 주석에 남긴다**(`--card-w`가 고정이라 이 높이도
고정이다). 무대로 한 장이 빠지는 경우는 이미 남은 카드가 높이를 들고 있어 여기 안 걸린다 — 걸리는 것은
0장뿐이다.

## 하지 않는 것

- **적의 공격에는 재지정이 없다** — 규칙이 그렇다. 화면에 없는 것을 그리지 않는다.
- `guardFor`의 규칙 변경 없음: 1회 재지정 · 사거리 안 · 광역 제외 그대로. 값·데이터·봇 불변.
- 새 `seq` 필드 없음 — `hitSeq` 하나로 족하다.
- 지킴이 전용 스프라이트·아이콘 생성 없음. 「보호」 글리프는 `icons.svg`의 `guard`가 이미 있다.
- 재지정 로그·저널 없음. 이 사건은 그 프레임에 보이면 끝이다.
- `.combat-bottom`의 격자 구조 변경 없음 — 고칠 것은 빈 `.fan` 하나다.

## 완료 정의

- 지킴이가 있는 편성에서 뒷칸을 때리면 **지킴이가 앞으로 나와 대신 맞고 제자리로 돌아간다.**
- 그 순간 힌트 줄에 「〈이름〉이 대신 맞았습니다.」가 뜬다 — 줄인 모션에서도 뜬다.
- 피해 팝이 지킴이 도착 **뒤에** 뜬다.
- 손패를 다 내도 무대·힌트·부채꼴 자리가 한 픽셀도 안 움직인다.
- 규칙 결과가 안 바뀐다 — `npm run sim` 기준선 그대로.
