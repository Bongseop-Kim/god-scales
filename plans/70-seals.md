# P-70 · 은혜는 카드에 새기고, 두 신의 인장이 모이면 융합한다

P-69 완료 뒤에 착수한다. 둘 다 `cardEffects`를 만지므로 순서를 겹치지 않는다.

## 핵심

### 한 줄 결론

**은혜를 슬롯(태그 전체)이 아니라 덱의 카드 한 장에 인장으로 새기고, 한 카드에 두 신의 인장이 모이면
그 자리에서 융합 카드로 변한다.**

```text
헌신 승리 → 은혜 3택 1 → 덱에서 대상 카드 1장 선택
        ↓
그 카드에 인장이 붙어 은혜 효과를 카드가 직접 낸다 (신당 카드당 1개)
        ↓
같은 카드에 반대 신의 인장이 또 붙으면
        ↓
카드가 그 조합의 융합 카드로 즉시 변신 · 원본과 인장은 사라진다
```

### 플레이 시나리오

제우스·아테나 조합. 아테나 헌신으로 전투에서 이긴다.

```text
아테나의 은혜 3택 1
→ 「방벽 은혜」 선택
→ 덱이 펼쳐진다: 어느 카드에 새길까
→ 제우스의 `작은 번개`를 고른다        ← 다른 신의 카드에도 붙는다

작은 번개  피해 5 · 방어 1  [아테나 인장]
```

몇 전투 뒤 제우스 헌신으로 이기고, 제우스 은혜를 같은 카드에 새긴다.

```text
작은 번개 [아테나 인장] + [제우스 인장]
→ 융합: 아이기스 뇌광
```

카드가 덱의 그 자리에서 `아이기스 뇌광`(tier3)으로 바뀐다. 원본 카드와 두 인장 효과는 사라진다 —
융합 카드가 그 값이다.

### 플레이 규칙

| 순간 | 규칙 |
|---|---|
| 은혜 획득 | 3택 1 뒤 덱에서 대상 카드 1장을 고른다 |
| 대상 | 아무 신의 카드나 가능. 신당 카드당 인장 1개 |
| 인장 효과 | 그 카드가 은혜 효과를 자기 효과 뒤에 이어서 낸다 |
| 인장 세기 | 새길 때 그 신의 은혜 누계로 tier 결정(2·4·6 마일스톤 유지) |
| 융합 | 한 카드에 두 후원 신의 인장이 모이는 순간 자동 · 그 조합의 융합 카드로 교체 |
| 융합 횟수 | 제한 없음 — 비용이 이미 은혜 2개(헌신 승리 두 번)다 |
| 강화 | 인장은 강화를 따라간다. 융합 카드는 지금처럼 강화 불가면 그대로 |

### 없애는 것

- 슬롯 은혜 전부: `graceSlots`·`GraceHeld`·`takeGrace`의 슬롯 tier 승계·`graceOffer`의 빈 슬롯 우선 정렬
- `canFuse`와 정산 시 융합 카드 자동 덱 추가(`sim/engine.ts:800-805`), 런당 1회 `fused` 플래그
- `cardEffects`의 `graceSlots` 참조 — 인장은 카드 자신이 든다

### 완료 모습

```text
헌신 승리 → 은혜 3택 1 → 대상 카드 선택
→ 카드에 인장 표시 · 호버에 은혜 문구
→ 반대 신 인장이 겹치면 즉시 융합 연출과 카드 교체
→ `토큰과 기호` 사전에 인장·융합 항목
```

## 구현

### 1. 인장은 카드 id가 든다 — 강화가 간 길 그대로

- 덱 항목의 정체성은 id 문자열이고 강화가 이미 id를 갈아 끼운다(`upgradeId`, `core/rules.ts:78`,
  `base+level`). 인장도 같은 길이다: 새기면 덱의 그 항목을 인장 달린 파생 id로 바꾸고, 파생 카드는
  원본 효과 뒤에 은혜 효과를 이어 든다.
- 같은 id 두 장 중 한 장에만 새겨도 강화와 똑같이 id가 갈라져서 문제가 없다. 인장 상태를 따로 드는
  맵·인덱스를 만들지 않는다 — 덱 배열이 유일한 진실이다.
- 파생 id는 `cardLevel`·`upgradeId`의 `+level` 파싱을 깨지 않는 자리에 둔다. 강화 접미사와 공존하는
  왕복(`인장 → 강화`, `강화 → 인장`) 테스트를 한 줄 남긴다.
- 신당 카드당 인장 1개. 이미 그 신의 인장이 있는 카드는 대상 후보에서 뺀다.

### 2. 은혜 흐름에 대상 카드 선택을 더한다

- `grantGrace`(`sim/engine.ts:607`)의 3택 1 뒤에 `grace_card` 결정을 하나 더 낸다 — 휴식의
  `rest → rest_card` 2단계(`sim/engine.ts:316`)와 같은 문법이다.
- 후보는 현재 덱 전부에서 그 신의 인장이 이미 있는 카드만 뺀 것.
- 봇(`sim/bots/rule.ts`): 반대 신의 인장이 있는 카드가 있으면 그 카드(융합 진행), 없으면 후보 중
  비용이 가장 높은 카드. 두 줄이면 된다.
- `sim/replay.ts`에 `grace_card` action을 더한다.
- tier는 지금처럼 그 신의 은혜 누계(`graceTier`)가 정하고, 새길 때 그 tier 줄의 효과를 든다.
  슬롯이 없으므로 `slotTier` 승계는 삭제한다.

### 3. 융합은 인장 두 개의 즉시 결과다

- 새긴 직후 그 카드에 두 후원 신의 인장이 모였으면, 덱의 그 항목을 조합의 융합 카드 id로 바꾼다.
  `canFuse`·정산 훅·`fused` 플래그를 전부 삭제한다.
- 원본 카드와 인장 효과는 사라진다. 융합 카드(tier3)가 보상이고, 무엇이 될지는 화면에 미리 적는다.
- 횟수 제한을 두지 않는다. 은혜 상한이 신당 6이므로 이론상 최대도 낮고, 비용이 헌신 승리 두 번이다.
  같은 융합 카드 여러 장이 게이트를 흔들면 원인을 리뷰에 남긴다.

### 4. 인장의 생김새 — 심볼 하나, 색으로 가른다

- `art/icons.svg`에 인장 심볼 하나(`icon-seal`)만 더한다. 신 식별은 새 그림 다섯 개가 아니라
  기존 신 색 변수(`--zeus`처럼 `speak`가 이미 쓰는 것)로 배지를 물들여서 한다 —
  심볼 1개 × 색 5개로 다섯 신을 다 덮는다.
- 배지는 카드 우상단 모서리 고정 위치. 인장 둘이면 나란히 두 개. 자리는 인장이 없어도 예약해서
  배지가 생겨도 카드 안 요소가 밀리지 않는다(UI.md 제1규칙).
- 호버 툴팁은 그 은혜의 신 대사 + 효과를 명사형 한 줄로 — 토큰 칩 문법(`ui/shared/tokens.tsx:96`)
  그대로.
- 대상 카드 선택 화면은 기존 덱 오버레이(`ui/app.tsx:27`)의 펼침을 재사용한다. 새 페이지를 만들지
  않는다. 후보 카드에는 새겨질 배지를 미리 반투명으로 보여 주고, 반대 신 인장이 이미 있는 카드에는
  `융합 · 아이기스 뇌광`처럼 결과를 적는다.
- `토큰과 기호` 사전에 **인장**과 **융합** 항목을 더한다(P-69가 더한 훼방·파워 옆).
- 플레이어 UI 용어는 `인장`으로 쓴다. 한글은 `WRITING.md`를 따른다.

### 5. 융합 연출 — 두 신이 나란히 서는 유일한 화면

융합은 헌신 승리 두 번을 모아야 나오는 이 런 최대의 보상이고, 저울 위에서 내내 경쟁하던 두 신이
**함께 서는 순간은 게임 전체에서 융합뿐이다**. 그 사실이 연출의 뼈대다: 저울 양쪽에 있던 둘이
가운데 카드에서 만난다. 전용 오버레이 하나를 만들되 재료는 전부 기존 것이다 — 신 초상
(`art/gods/*.webp`), 신 색 변수, 발화(`speak`), 신별 파티클 스트립, 융합 효과음 1개(`ui/shared/sfx.ts`
기존 체계).

시퀀스 (fx 층의 전용 오버레이, 약 2.5초, 전부 `transform`·`opacity`):

1. **어두워지고 카드가 중앙에 선다** — 인장을 새긴 그 카드가 화면 가운데로 확대된다.
2. **두 신이 좌우에서 들어온다** — 저울 양쪽 자리 그대로, 두 초상이 각자의 신 색 기운을 두르고
   좌·우에서 카드를 향해 선다. 두 인장 배지가 카드에서 떠올라 가운데서 맞닿는다.
3. **섬광, 교체** — 배지가 맞닿는 순간 짧은 섬광(`opacity`)과 융합 효과음, 원본 카드가 융합 카드로
   바뀐다. 두 신의 파티클 스트립이 카드 위로 동시에 내려온다 — 「두 신이 함께 내렸다」.
4. **두 신이 한 마디씩** — `gods.json`에 신당 `fuse` 대사 한 줄을 더하고(신별 목소리 표 준수),
   두 신이 320ms 어긋나게 말한다 — 발화 겹침 규칙(P-46) 그대로.
5. **카드가 제자리로** — 융합 카드가 덱의 자리로 돌아가며 오버레이가 걷힌다.

규칙:

- 입력을 요구하지 않는다. 클릭은 넘기기만 하고 기록되지 않는다 — 발화와 같은 「화면 상태지 게임
  상태가 아니다」 규칙. 봇·리플레이·e2e에 결정이 늘지 않는다.
- 층 질서는 fx(3) < voice(4) 그대로. 새 층을 만들지 않는다.
- `prefers-reduced-motion`: 움직임 없이 같은 장면의 정지 구도 하나 — 두 초상 사이에 결과 카드와
  `융합 · 카드 이름` 문구. 정보는 연출 없이도 다 보인다(UI.md).

## 최소 검증

- 은혜 선택 뒤 `grace_card` 결정이 오고, 후보에 그 신의 인장이 있는 카드가 없다.
- 인장 카드는 원본 효과 뒤에 은혜 효과를 이어서 낸다 — 엔진 집계와 손패 표시가 같은 값을 읽는다.
- 같은 id 두 장 중 한 장에 새기면 그 한 장만 바뀐다.
- 인장 카드를 강화해도 인장이 남고, 강화 카드에 새겨도 강화가 남는다.
- 두 후원 신의 인장이 모이는 순간 그 항목이 융합 카드로 바뀌고, 원본·인장 효과는 남지 않는다.
- `canFuse`·자동 덱 추가·`graceSlots` 참조가 코드에 없다.
- 카드의 인장 표시에 호버하면 은혜 문구가 보이고, 배지가 생겨도 카드 안 요소가 밀리지 않는다.
- 융합 시 전용 오버레이에 두 신 초상과 `fuse` 대사가 뜨고, 어떤 입력도 결정으로 기록되지 않는다.
- 줄인 모션에서는 두 초상과 결과 카드·문구가 정지 구도로 보인다.

```bash
npx tsc --noEmit
npm test
npm run validate -- data/graces.json data/cards.json
npm run build
npm run tune
npm run e2e
git diff --check
```

- 밸런스 판정은 조합 승률 하한 하나만 본다. 새 지표·밴드·회차 비교를 만들지 않는다.
- 하한이 깨지면 게이트를 낮추거나 값을 테스트에 맞춰 깎지 않는다. 실패 조합과 원인을 리뷰에 남긴다.
- 은혜가 덱 전체 강화에서 카드 한 장 강화로 줄어드는 큰 너프다 — 하한이 깨지면 은혜 효과 수치가
  후보 다이얼이고, 그 판단 근거를 리뷰에 남긴다.
- 완료 뒤 `reviews/70-seals.md`를 작성하고 이 파일을 삭제한다.

## 설명

### 카드 단위 은혜는 한 번 기각된 방향이다 — 왜 지금은 다른가

`core/grace.ts:6-9` 주석이 남긴 대로, 카드 한 장에 붙는 은혜(`multi` 슬롯)는 P-28이 걷어낸 옛
마일스톤과 같다는 이유로 기각됐다. 그때의 카드 단위 은혜는 스탯 버프 하나가 전부였다. 지금은 인장이
**융합의 재료를 겸한다** — 어느 카드에 새길지가 어떤 카드를 tier3로 바꿀지의 선택이고, 은혜 하나가
버프이자 융합 진행 절반이다. 가치가 두 겹이라 한 장에 붙어도 결정이 가볍지 않다.

### 왜 융합이 자동이고 즉시인가

두 인장을 한 카드에 모으는 것 자체가 두 번의 명시적 선택이다. 세 번째 확인 버튼은 이미 한 결정을
다시 묻는 것이라 두지 않는다. 무엇으로 변할지는 대상 카드 선택 화면에 미리 적어, 모으기 전에 결과를
알고 고르게 한다.

### 왜 원본 카드와 인장 효과가 사라지는가

융합 카드는 tier3다. 원본 효과나 인장 효과까지 얹으면 값을 다시 재야 하는 별도 카드가 조합마다
생긴다. 「인장 두 개 = 융합 카드 한 장」의 교환이 한 줄로 읽히고, 융합 카드 데이터 10장을 그대로 쓴다.

### 왜 저울 왕복이 그대로 남는가

인장을 새기려면 여전히 그 신의 헌신(70+) 승리가 필요하다. 융합에 두 신의 인장이 필요하므로
「저울을 양쪽으로 한 번씩 기울여야 융합이 열린다」는 기존 구조는 그대로고, 달라지는 것은 융합이
자동 지급에서 플레이어의 조합 선택으로 바뀌는 것뿐이다.
