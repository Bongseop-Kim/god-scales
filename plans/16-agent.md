## 구현 노트

### 에이전트는 전략만 판단한다

**전투 내 카드 순서와 대상 선택은 룰 봇 v1에게 맡긴다.** 에이전트가 판단하는 것은 이것뿐이다.

| 판단 지점 | 런당 횟수 |
|---|---|
| 신 조합 선택 | 1 |
| 조우 진입 전략 — 요구를 만족시킬 것인가, 어느 신을 밀 것인가, 합성을 노릴 것인가 | 8~12 |
| 상충 요구 선택 | 0~2 |
| 층 경로 선택 (3·5층) | 4 |
| 휴식 선택 (회복 / 카드 제거) | 0~4 |
| 전투 보상 선택 | 8~12 |
| 은총 마일스톤 대상 선택 | 0~3 |
| | **합 ~30** |

원래 설계는 런당 ~100 판단이었고 전투 조작이 그 대부분이었다. 구독 토큰으로는 그 규모가 성립하지 않는다(A-6.3).

### 그런데 이 축소가 측정을 개선한다

**T-6이 에이전트에게 묻는 질문은 "판단이 필요한 상태에 도달할 수 있는가, 선택이 선택인가"이지 "카드를 잘 쓰는가"가 아니다.** `fusion_rate` 격차는 전략 판단 — 합성을 노릴 것인가, 어느 신을 밀 것인가 — 에서 나오지 전투 조작에서 나오지 않는다.

**전투를 룰 봇에 맡기면 두 주체가 같은 `bot_policy_version`을 공유하게 되고, 차이가 전략 층에만 남아 격차의 원인이 깨끗하게 분리된다.** 원래 설계에서는 격차가 "전략이 좋아서"인지 "카드를 잘 써서"인지 섞여 있었다.

### 이 축소의 대가

**에이전트가 더 이상 사람 플레이 전체를 근사하지 않는다.** T-8은 에이전트를 "세 층 중 사람의 판단을 근사하는 유일한 층"이라 부르는데, 이제 전략 층만 근사한다.

**대가를 사람 플레이테스트가 메운다.** 전투 층의 체감은 P-13과 P-18의 사람 런이 답하고, 전략 층의 도달 가능성은 에이전트가 답한다. 두 층이 나눠 맡는 구조이며, **이 분담을 리포트에 명시한다** — 에이전트가 사람을 대체한다고 쓰면 거짓이 된다.

**특권 정보 문제는 없다**(T-8). 에이전트는 사람보다 더 적게 보지 더 많이 보지 않는다. T-8이 막으려던 것은 특권이지 입도가 아니다.

### 파일 핸드셰이크

러너가 판단 지점에서 멈추고 상태를 파일로 쓴다. Claude Code가 그것을 읽고 답을 파일로 쓴다. 러너를 이어서 실행한다.

```
decisions/001/
  pending.json    { turn, phase, observation, options[] }
  answer.json     { choice, reason }
  log.jsonl       판단 전체 누적
```

**`observation`은 사람이 보는 정보 범위로 직렬화한다**(T-8) — 호의 수치와 단계, 적별 의도, 제시된 요구, 남은 층, 현재 덱. 전투 내부 상태는 이 층에서 보이지 않는다.

**부수 이득 — `decisions/`가 그대로 재현 기록이 된다.** `replay_mode: action_log`로 표시하고 이 디렉터리를 보관하면 I-2의 요건이 자동으로 충족된다.

**폴백** — 파싱 실패, 무효 선택, 응답 없음이면 룰 봇 판단으로 대체하고 `agent_fallbacks`를 올린다.

### 한 회차는 한 세션에서

`effort`나 `thinking`을 지정할 수 없으므로(A-6.2) 판단의 일관성이 세션 설정에 묶인다. **한 런은 한 세션 안에서 끝낸다.** 세션이 바뀌면 그 런의 판단 성향이 중간에 달라지고, 그 런은 비교 대상에서 빼야 한다.

### 런 수

**10런이 T-6의 "수십"의 하단이다.** 부족한 부분은 시나리오 주입으로 보완한다 — `fused_deck` `grace_6` `both_devotion`이 이미 있고(P-10), 그것이 T-6이 애초에 시나리오 시뮬을 둔 이유다.

**늘려야 하면 API로 전환한다**(A-6.5). 모델을 낮추지 않는다 — 에이전트에게 묻는 질문은 약한 모델이 답할 수 없다.

### 물어야 할 것

**호의 관리의 체감이다**(T-8). 상충 요구에서 어느 쪽을 왜 택했는지, 역린이 회복 불가능하게 느껴진 시점이 있었는지, 휴식과 전투 사이 선택이 실제로 고민이었는지는 통계로 나오지 않는다. `answer.json`의 `reason` 필드가 그것을 담는다.

### T-9.2의 핵심 지표

`fusion_rate`가 룰 봇에서 0에 가깝고 에이전트에서 유의하게 높으면, 그것이 **"판단할 수 있는 주체에게만 열리는 경로가 실재한다"는 유일한 직접 증거**다. 두 주체에서 비슷하면 합성 조건이 너무 쉬워 우연히 달성되고 있다는 뜻이며, 조건을 조여야 한다.

라이벌 조합의 승률 격차가 두 주체에서 좁혀지는지도 같은 곳에서 나온다. 좁혀지지 않으면 R-4의 고위험 고상한 설계가 실패한 것이다.
