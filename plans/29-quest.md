# P-29 · 요구를 시련으로

`plans/29-quest.md` · [◀ P-28](28-boon.md) · [색인](../reviews/00-index.md) · [P-26 ▶](26-hud.md)

**크기** 중간 · **착수 조건** P-28 완료 (걸 판돈이 있어야 한다)

**실패 시 행동** 두 단이 안 갈리면(한쪽이 75% 넘게 쏠리면) **3단으로 늘리지 말고 대가·보상 폭을 벌린다.** 벌려도 안 갈리면 시련 단을 지우고 지금 요구로 되돌린다 — 갈리지 않는 선택지는 화면 한 칸을 낭비하는 것이다.

---

## 완료 정의

**요구가 지금 무언가를 빼앗고 나중에 갚는다.** 수락/거절이 아니라 값을 치를지 고르는 자리가 된다.

```bash
npm run validate                            # demand_axis 위반 0
npm run sim -- --runs 2000 --stratified
#   → 선택지 셋(수락·시련·거절)이 각각 25% 이상 선택된다 (하나로 쏠리면 실패)
#   → 단별 지킴률이 수락 0.55~0.70 / 시련 0.15~0.35
#   → 시련 도중 사망률이 전체 패배의 20%를 넘지 않는다
```

**쏠리면 쏠렸다고 쓴다.** 하나가 언제나 옳으면 선택지가 아니라 장식이고, 그게 이 항목의 결과다.

### 왜 3단이 아니라 2단인가

원래 셋이었다 — 대가 없음 / 토큰 대가 / 지속 대가+은혜. 요구 6개 × 3단 = 18줄, 단조 규칙 3종 × 3쌍, 봇 정책 하나, 그리고 이 계획 자신이 「선택 쏠림이 기본값이다」라고 쓴다.

**두 단이 갈리는 것부터 확인한다.** 2단이면 분포 게이트가 「셋 다 25% 이상」으로 서고, 단조 검사가 1쌍으로 줄고, 5층 금지 규칙은 그대로다. 두 단이 실제로 갈린 뒤에 가운데를 끼우는 것이 순서다 — 안 갈리면 3단은 장식 둘이 된다.

## 지금 상태

`ui/choices.tsx:72` `DemandScreen`은 버튼 두 개다.

```
수락  → 다음 전투에서 지키면 호의 +12 (라이벌 −18 / 그 외 −9)
거절  → 아무것도 움직이지 않는다. 벌금 없음
```

**거절에 대가가 없으므로 계산이 필요 없다.** 지킬 만하면 수락, 아니면 거절. 그리고 판돈은 호의 숫자 하나뿐인데, 호의는 그 자체로 쓸모가 아니라 단계 효과와 은총으로 가는 중간재다.

요구 6개의 축은 셋뿐이다 (`data/demands.json`):

| 축 | 요구 |
|---|---|
| `target_spread` | 제우스 +2 / +3, 포세이돈 −1 |
| `damage_taken` | 아테나 ≤6, 아레스 >10 |
| `token_load` | 아르테미스 한 턴 6스택 |

## 조사 — 카오스의 시련

하데스의 카오스 보온은 **저주 + 축복 두 짝**이다. 저주가 무작위 조우 수(2~5회) 동안 붙어 있다가, 만료되면 **런이 끝날 때까지 남는 축복으로 변한다.** 보스가 가까우면 저주는 그 전에 안 걷힌다.

전략 해설이 그 값을 이렇게 정리한다 — 「축복은 런 전체를 가고 일반 보온보다 크게 스케일하므로 **쉬운 조우 구간에 저주 값을 치르는 것**이 강한 거래다. 다만 축복이 오기 전에 죽을 저주라면 값어치가 없다.」

**결정이 성립하는 이유가 여기 있다.** 지금 우리 요구는 값이 전부 나중에 있다 — 지키면 받고 못 지키면 아무 일 없다. 위험이 없으니 계산도 없다. 카오스는 **값을 앞에 놓는다.** 그러면 "지금 내 체력·덱·다음 조우로 이 값을 감당할 수 있나"가 문제가 되고, 그건 화면에 이미 다 있는 정보다.

설계 분석이 같은 것을 다르게 말한다 — 「완벽하지 않은 해법: 카드는 '피해는 크지만 덱에 상처를 넣는다' 같은 단점을 갖거나, 즉시가 아니라 서서히 오는 이득이어야 한다.」

## 설계

요구 하나에 **2단**. 축은 그대로, 선불 대가와 보상만 벌린다.

```json
{
  "id": "demand_athena_safe",
  "patron": "athena",
  "axis": "damage_taken",
  "polarity": "-",
  "tiers": [
    { "condition": "damage_taken <= 12", "cost": null,
      "reward": { "favor": 8 } },
    { "condition": "damage_taken == 0",  "cost": { "maxHp": -8, "encounters": 3 },
      "reward": { "grace": 1 } }
  ]
}
```

- **수락** 대가 없음, 작은 보상 — 지금 요구와 같다
- **시련** 조우 3회 동안 지속되는 선불 대가, 보상은 은혜. **P-28이 없으면 이 줄이 못 선다**

거절은 남긴다. **세 번째 버튼이 아니라 두 단을 다 안 받는 것**이다.

라이벌 벌금(`rivalDemandPenalty` −18)은 단에 비례해 나눈다. 지금은 수락 한 번에 정액이다.

### 대가는 새 기제를 안 만든다

`cost`가 쓸 수 있는 것은 이미 있는 것뿐이다.

| 대가 | 기존 경로 |
|---|---|
| 해로운 토큰 | `applyFavorStageEffects`(`core/favor.ts:50`)의 조우 시작 부여 |
| 최대 체력 | `state.combat.player.maxHp` |
| 호의 | `shiftFavor` |
| 에너지 −1 | `ENERGY_PER_TURN` 런 변수화 |

호의 하락 대가는 [P-30](30-intervention.md)이 같이 쓴다 — 진노 도달률이 0.000이라 **플레이어가 스스로 떨어뜨리는 길**이 필요하고, 시련 대가가 그 길 중 셋째다. P-30이 앞에서 두 경로(라이벌 요구 빈도·`recordCardFavor` 상한)로 갈 수 있는 데까지 갔으므로, **여기서 그 부족분만큼 호의 대가의 크기를 잡고 wrath_ratio 0.05를 다시 잰다.** P-30이 얼마를 남겼는지는 `reviews/30-intervention.md`에 있다.

`encounters` 카운터 하나만 새로 든다 — 카오스의 2~5 대신 **고정값**을 쓴다. 무작위 지속은 다이얼이 하나 더 늘고, 우리는 재생 결정론이 걸려 있다.

## 게이트

`demandFailure`가 지금 **요구 하나당 축·polarity 중복**을 잰다. 2단으로 늘리면 규칙 셋이 는다 — 검사 대상은 단 한 쌍이다:

1. **임계 단조** — polarity `-`면 내려가고 `+`면 올라간다
2. **보상 단조** — 쉬운 단이 더 주면 시련을 아무도 안 고른다
3. **대가 단조** — 그리고 대가는 `expectedValue`로 환산해 보상 증가분보다 작아야 한다. 아니면 시련은 항상 손해다

셋 다 `demand_axis`로 잡는다. **키를 늘리지 않는다.**

지킴률 대역 0.17~0.65는 P-22에서 정한 값이다. 이제 **단별로** 잰다. 시련이 0.05 밑이면 도달 불가라 선택지가 아니다.

**`demand_zeus_solo`는 지운다.** 지킴률 0.738로 대역 위고, 제우스만 요구가 둘이라 조이는 대신 지우는 것이 맞다 — `reviews/00-index.md`가 지목한 부채다. 2단화 전에 지워야 6개가 아니라 5개를 두 배로 만든다.

## 함정

- **선불 대가가 사망을 만든다.** 카오스도 「축복 전에 죽을 저주면 값어치가 없다」고 알려져 있고, 하데스는 보스 앞에서 저주가 안 걷히게 막는다. 우리도 같은 보호가 필요하다 — **6층 보스 직전(5층)에는 시련을 제안하지 않는다.** 사망률 게이트가 이걸 잡는다
- **선택 쏠림이 기본값이다.** 둘의 기대값이 같으면 봇은 위험 낮은 수락만 고른다. 시련 보상(은혜)이 호의 대비 얼마인지 **P-28의 기대값 환산으로 먼저 재고** 임계를 잡는다
- **재생 호환은 요구하지 않는다.** 옛 로그는 [P-27 §재생](27-map.md)이 아카이브했다. `"accept"`를 별칭으로 남기지 않고 `"tier1"`·`"tier2"`·`"reject"` 셋으로 깔끔하게 간다
- `demandOutcomes` 관측(`sim/engine.ts:430`)이 지킴/미지킴 이진값이다. 단과 대가 정보를 실어야 리포트가 단별 지킴률과 시련 중 사망을 낼 수 있다. **시련 중 사망은 P-25의 `defeatContext`와 같은 자리에서 읽는다**
- **아르테미스는 여전히 `rivals: []`다.** 지켜도 상대 신이 화나지 않아 설계상 공짜다 — P-22가 축은 고쳤지만 이건 남았다. 시련 보상이 은혜면 공짜가 더 커진다. 라이벌을 주거나 시련을 호의로 묶는다
- **P-25의 패시브와 겹친다.** `spite`(비공격 카드 처벌)를 가진 적 앞에서 아테나 시련(무피해)은 거의 불가능하다. 조합이 사고가 아니라 설계이려면 P-27의 층 표를 보고 요구 등장 층을 정해야 한다
