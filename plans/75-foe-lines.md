# 75 — 적별 신 대사: 조우 대사가 세계를 보게 한다

현행 조우 대사(`encounter`)는 플레이어 상태(호의 단계)만 보고 눈앞의 적을 안 본다. 신과 적 사이의 신화적 관계를 대사에 싣는다. **연출·데이터만이다** — 호의 증감, 엔진, 밸런스는 손대지 않는다.

공통 제약
- 밸런스 게이트는 `test/matrix.test.ts`의 조합 승률 하한 하나뿐. 이 작업은 게이트에 닿을 일 자체가 없어야 한다(수치 변경 0).
- 대사는 난수를 안 당긴다 — 기존 `n % lines.length` 방식 유지(`ui/shared/header.tsx:22`, P-46 §6). replay 불변.
- 한글 대사는 `WRITING.md`의 신별 목소리 표를 따른다. 시스템 용어 금지, 신마다 어미 고정.

---

## 1. 설계 규칙: 언제 적 대사가 이기는가

적별 대사는 **헌신·평온에서만** 단계별 조우 대사를 대체한다. 분노·진노는 기존 단계별 대사 유지.

이유 둘:
- 서사: 신이 플레이어에게 화가 나 있으면 화제는 적이 아니라 플레이어다. "네가 버린 것" 이야기를 하는 신이 옆에서 니케 안부를 묻으면 이상하다.
- 기능: 진노 조우 대사는 경고("하늘은 닫았네")다. 이 정보를 스토리 대사로 덮으면 플레이어가 진노 개입을 예고 없이 맞는다.

적 하나당 대사 배열 하나(단계 구분 없음). 편성에서 대사를 가진 적이 둘 이상이면 **칸 번호가 낮은 적** 하나만 — 조우 시작 발화는 신당 한 마디라는 현행 규칙 그대로.

## 2. 데이터: `data/gods.json`에 `lines.foes`

```jsonc
"lines": {
  "encounter": { ... },   // 기존 유지 — 폴백
  "foes": {
    "enemy_surface_support": ["니케… 내 곁에 서던 날개예요.", "..."]
  },
  ...
}
```

새 파일을 만들지 않는다. 신의 입에서 나오는 말은 전부 `gods.json` `lines` 아래 한 곳이다.

### 대사를 쓸 짝 (신화 근거가 있는 곳만 — 전 조합 15×5를 채우지 않는다)

| 신 | 적 | 근거 |
|---|---|---|
| 아테나 | 타락한 니케 | 니케는 아테나의 동반자(아테나 니케 신전) |
| 아레스 | 스파르토이 방패병 | 아레스의 용 이빨에서 태어난 전사들 |
| 제우스 | 잠들지 않는 아르고스 (보스) | 헤라의 감시자, 제우스가 헤르메스를 시켜 죽인 구원 |
| 제우스 | 사자 가죽의 파수병 | 네메아 사자 가죽 = 아들 헤라클레스의 전리품 |
| 아르테미스 | 델포이의 무녀 | 오라비 아폴론의 신탁 |
| 아르테미스 | 마르시아스의 고행자 | 아폴론에게 도전했다 벗겨진 자의 추종자 |
| 아르테미스 | 켄타우로스 습격자 | 사냥·야생의 영역 침범 |
| 포세이돈 | 레테의 익사자 | 물에 죽은 자 — 자기 영역의 끝 |
| 전원(5) | 케르베로스 (보스) | 하데스의 개 — 올림포스 신들에게 남의 집 문지기 |

케르베로스·아르고스는 보스라 런당 한 번의 큰 자리다 — 다섯 신 모두 케르베로스 대사를 갖는 것이 지하 보스전의 값을 한다. 나머지는 표의 짝만. 대사는 짝당 2개 이상(같은 뜻 둘 금지 — WRITING.md).

## 3. 코드: 조회 한 줄 + 호출부 한 곳

1. **`ui/shared/header.tsx`** — `godLine`에 폴백 한 단 추가. 시그니처를 늘리기보다 별도 소함수가 깔끔하면 그쪽으로:
   ```ts
   export const godFoeLine = (god: string, enemies: string[], n: number): string
   ```
   `lines.foes`에서 칸 순서대로 첫 매칭 적의 배열을 찾고 `n % length`. 없으면 빈 문자열.
2. **`ui/screens/combat.tsx:211`** — 조우 시작(`start`)이고 단계가 헌신·평온일 때 `godFoeLine(god, view.enemies.map(({id}) => id), view.depth)`이 비지 않으면 그걸 말하고, 비면 기존 `godLine(god, "encounter", ...)`. 개입(`intervene`) 쪽은 손대지 않는다.
3. `GodLines` 타입(`header.tsx:10`)에 `foes?: Record<string, string[]>` 추가. `core/favor.ts`의 `lineTriggers`에는 **넣지 않는다** — foes는 "모든 신이 반드시 가져야 하는 트리거"가 아니라 선택 데이터라, 게이트의 "빈 트리거 반려" 규칙과 결이 다르다.

## 4. 게이트: `tools/validate.ts`에 검증 하나

`godLineFailure` 옆에 소검사 추가: `lines.foes`가 있으면 (a) 모든 키가 `data/enemies.json`에 실존하는 적 id, (b) 각 배열이 비지 않은 문자열들. 오타 난 적 id는 조용히 침묵하는 대사가 되므로 게이트가 잡아야 한다. 새 지표·밴드가 아니라 기존 데이터 정합 검사의 연장이다.

## 5. 테스트

- `test/ui.test.ts`(또는 대사 조회를 검증하는 기존 자리)에: foes에 있는 적이 편성에 서면 그 대사가, 없으면 encounter 폴백이 나온다 — 순수 함수 `godFoeLine` 단위 케이스 2개.
- `vitest run` 전체 통과(밸런스 게이트 포함 — 수치를 안 건드렸으니 당연히 통과해야 하고, 아니면 뭔가 잘못 만진 것).

## 이 플랜이 안 하는 것

- 호의 증감·`favor_shift` 연결 — 스토리→호의는 과업(`demand_offer` 계열, 현재 미사용) 쪽에서 별도 플랜으로.
