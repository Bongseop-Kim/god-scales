# 75 — 적별 신 대사와 런 단위 비반복: 신이 같은 말을 되씹지 않는다

현행 대사는 `data/gods.json` 기준 신마다 32줄, 전부 160줄이다. 그중 실제 화면에서 호출되는 것은 신마다 29줄이고, `encounter`는 단계당 2줄·`intervene`는 단계당 3줄이라 한 런 안에서도 같은 말이 반복된다. 먼저 현재 발화 풀을 넓히고 **한 번 실제로 나온 문장은 그 런에서 다시 고르지 않게** 한 뒤, 신과 적 사이의 관계를 조우 대사에 싣는다.

**연출·데이터 작업이다.** 호의 증감, 엔진, 전투 수치, 봇, replay 형식은 손대지 않는다.

공통 제약
- 밸런스 게이트는 `test/matrix.test.ts`의 조합 승률 하한 하나뿐. 수치 변경 0, 새 지표·밴드·회차 비교 0.
- 대사는 난수를 당기지 않는다. 기존 `n % lines.length`를 후보 배열의 시작점으로만 쓰고, 그 뒤 아직 말하지 않은 문장을 순서대로 찾는다. replay RNG 불변.
- 한글 대사는 먼저 `WRITING.md`의 신별 목소리 표를 따른다. 시스템 용어 금지, 신마다 어미 고정, 같은 뜻의 바꿔쓰기 금지.
- 한 런에서 후보를 다 썼으면 반복하지 않고 침묵한다. 고갈을 숨기려고 단계가 다른 대사나 다른 신의 대사를 빌리지 않는다.

## 1. 선행 데이터: 실제로 들리는 기존 대사를 넓힌다

`data/gods.json`의 **현재 호출되는 트리거만** 늘린다. 아직 UI 호출부가 없는 `demand_offer`·`demand_kept`·`demand_broken`은 이번 작업에서 문장만 쌓지 않는다.

신마다 다음 최소 풀을 갖는다.

| 트리거 | 현재 | 변경 |
|---|---:|---:|
| `encounter` | 단계당 2 | 단계당 **5** |
| `intervene` | 단계당 3 | 단계당 **8** |
| `cross` | 단계당 1 | 단계당 **3** |
| `tear` | 2 | **4** |
| `join` | 1 | **3** |
| `reconcile` | 1 | **3** |
| `fuse` | 1 | **3** |

이로써 실제 호출되는 일반 대사는 신마다 29줄 → 77줄, 다섯 신 합계 145줄 → 385줄이 된다. 아래 적별 대사 48줄까지 합치면 새로 들을 수 있는 풀은 433줄이다. 숫자를 채우기 위한 동의어 교체는 실패다. 각 배열 안에서 소재 축과 발화 의도가 달라야 한다.

## 2. 런 단위 비반복: 실제로 나온 문장만 기억한다

게임 상태나 replay에 `seenLines`를 넣지 않는다. 대사는 이미 게임 결정 밖의 화면 상태이므로 `ui/shared/fx.ts`가 런 동안만 기억한다.

1. **`ui/shared/header.tsx`**
   - `godLine`을 후보 하나가 아니라 결정적인 후보 순서를 돌려주는 `godLines(god, trigger, n, stage?)`로 바꾼다.
   - 원 배열을 `n % length`에서 시작하도록 회전할 뿐 난수는 쓰지 않는다.
   - 빈 데이터면 빈 배열을 돌려준다.
2. **`ui/shared/fx.ts`**
   - `speak`의 `text`를 `string | readonly string[]`로 넓힌다.
   - 모듈의 `Set<string>` 하나에 `${god}\0${text}`를 저장한다. 같은 신이 다른 트리거에서 같은 문장을 가져도 한 런에는 한 번만 나온다.
   - 높은 레벨 발화가 서 있어 실제로 표시하지 못한 후보는 사용 처리하지 않는다. 우선순위 검사를 지난 뒤 후보 중 첫 미사용 문장을 골라 DOM에 붙일 때만 기록한다.
   - 후보가 전부 사용됐으면 빈 발화로 끝낸다. 다시 첫 줄로 순환하지 않는다.
   - `resetSpokenLines()` 한 함수를 함께 내보낸다. 별도 저장소·컨텍스트·클래스는 만들지 않는다.
3. **`ui/app.tsx`**
   - 새 런을 확정하는 `start()`에서 `resetSpokenLines()`를 한 번 호출한다. setup으로 돌아가는 `reset()`이 아니라 실제 시작 시점이 경계다.
   - `godLine`을 쓰던 `fuse` 호출도 후보 배열을 넘긴다.
4. **나머지 호출부**
   - `ui/shared/header.tsx`의 `cross`, `ui/screens/combat.tsx`의 `encounter`·`intervene`·`join`·`tear`·`reconcile`가 모두 후보 배열을 `speak`에 넘긴다.
   - `과업 달성 · 현재 / 목표`처럼 직접 넘기는 단일 문자열도 같은 Set을 지나므로 같은 신·같은 문장이 한 런에 재등장하지 않는다.

이 Set은 화면 상태라 반출 JSON에 넣지 않는다. 같은 replay를 새로 열면 빈 Set에서 시작하며, 발화 표시 여부와 무관하게 엔진 결과와 RNG 소비는 달라지지 않는다.

## 3. 적 대사가 이기는 조건

적별 대사는 **헌신·평온에서만** 단계별 조우 대사를 대체한다. 분노·진노는 기존 단계별 대사를 유지한다.

- 서사: 신이 플레이어에게 화가 나 있으면 화제는 적이 아니라 플레이어다.
- 기능: 진노 조우 대사는 경고다. 적 이야기로 덮으면 진노 개입을 예고 없이 맞는다.
- 적 하나당 대사 배열 하나, 단계 구분 없음.
- 편성에서 대사를 가진 적이 둘 이상이면 **칸 번호가 낮은 적 하나**만 고른다. 신당 조우 시작 한 마디라는 현행 규칙은 유지한다.
- 적별 후보도 일반 후보와 같은 런 Set을 지나며, 다 썼으면 일반 `encounter` 후보로 되돌아가지 않고 침묵한다. 같은 조우 관계를 본 뒤 갑자기 일반 인사를 덧붙이지 않는다.

## 4. 데이터: `data/gods.json`의 `lines.foes`

```jsonc
"lines": {
  "encounter": { ... },
  "foes": {
    "enemy_surface_support": ["...", "...", "..."]
  }
}
```

새 데이터 파일을 만들지 않는다. 신의 말은 전부 `gods.json`의 `lines` 아래 둔다. 짝마다 **서로 다른 각도의 3줄**을 쓴다.

### 대사를 쓸 짝

| 신 | 적 | 근거와 대사 각도 |
|---|---|---|
| 아테나 | 타락한 니케 | 아테나 니케 숭배 — 승리의 동반자·잃은 날개 |
| 아테나 | 복수의 에리니스 | 오레스테스 재판 뒤 분노를 설득해 도시에 들임 — 판결·옛 합의 |
| 아테나 | 마르시아스의 고행자 | 아테나가 버린 피리를 마르시아스가 집음 — 버린 것을 탐한 수 |
| 아레스 | 스파르토이 방패병 | 아레스의 샘을 지킨 용의 이빨에서 무장한 채 솟은 전사들 |
| 제우스 | 잠들지 않는 아르고스 (보스) | 헤라의 감시자, 헤르메스가 잠재워 죽임 — 수하에게 맡긴 옛 처리 |
| 제우스 | 사자 가죽의 파수병 | 아들 헤라클레스의 첫 과업과 전리품 |
| 제우스 | 청동 탈로스 파편 | 에우로페에게 준 청동 수호자 전승 — 깨진 옛 선물 |
| 아르테미스 | 델포이의 무녀 | 쌍둥이 오라비 아폴론의 델포이 신탁 |
| 아르테미스 | 마르시아스의 고행자 | 오라비에게 겨뤄 벗겨진 자의 추종자 — 경고를 못 읽은 표적 |
| 아르테미스 | 켄타우로스 습격자 | 직접 일화가 아니라 사냥·야생의 영역을 어지럽힌 침입자 |
| 포세이돈 | 레테의 익사자 | 직접 일화가 아니라 바다와 지하 망각의 물을 대비 |
| 전원(5) | 케르베로스 (보스) | 하데스의 문지기. 제우스·아테나는 헤라클레스의 저승행, 나머지는 각자 영역에서 본 지하의 문으로 갈라 쓴다 |

총 16짝, 48줄이다. 직접 전승과 영역 대비를 표에서 구분했으므로 대비를 혈연·소유 관계처럼 단정하지 않는다. 전 조합 15×5를 억지로 채우지 않는다.

## 5. 적별 조회와 호출

1. **`ui/shared/header.tsx`**
   ```ts
   export const godFoeLines = (god: string, enemies: string[], n: number): string[]
   ```
   `lines.foes`에서 칸 순서대로 첫 매칭 적의 배열을 찾고, `n % length`부터 회전한 후보 배열을 돌려준다. 없으면 빈 배열.
2. **`ui/screens/combat.tsx` 조우 시작 호출부**
   - `start`이고 단계가 헌신·평온이면 `godFoeLines(god, view.enemies.map(({ id }) => id), view.depth)`를 먼저 본다.
   - 적별 후보가 있으면 그것만 `speak`에 넘기고, 데이터 자체가 없을 때만 `godLines(god, "encounter", ...)`를 폴백으로 넘긴다.
   - 개입(`intervene`) 쪽은 적별 분기를 만들지 않는다.
3. **타입**
   - `GodLines`에 `foes?: Record<string, string[]>`를 추가한다.
   - `core/favor.ts`의 `lineTriggers`에는 `foes`를 넣지 않는다. 모든 신에게 같은 키를 요구하는 트리거가 아니라 선택 데이터다.

## 6. 게이트

`tools/validate.ts`의 `godLineFailure` 옆 기존 `line_coverage` 검사만 확장한다.

- 실제 호출 트리거가 §1의 최소 개수를 만족한다.
- 신 하나의 모든 `lines`와 `lines.foes`를 펼쳤을 때 공백을 제외한 완전 동일 문장이 중복되지 않는다. 런 Set이 중복 데이터를 가려 주게 두지 않는다.
- `lines.foes`의 모든 키가 `data/enemies.json`에 실존한다.
- 각 foe 값은 비지 않은 문자열 배열이며 3줄 이상이다.

새 failure key, 점수, 밴드, 통계는 만들지 않는다. 전부 기존 `line_coverage`의 데이터 정합성이다.

## 7. 테스트

- `test/ui.test.ts` 또는 기존 대사 조회 자리:
  - `godLines`가 `n`부터 회전한 결정적 후보 순서를 돌려준다.
  - 같은 신의 후보를 두 번 고르면 두 번째는 다음 미사용 문장, 전부 소진하면 빈 문자열이다.
  - `resetSpokenLines()` 뒤에는 첫 후보를 다시 고른다.
  - 다른 신의 같은 문자열은 서로 막지 않는다.
  - 높은 레벨 발화 때문에 화면에 못 선 후보는 사용 처리되지 않는다(필요하면 후보 선택 소함수를 `fx.ts`에서 직접 검증).
  - foes에 있는 적이 서면 적별 후보, 없으면 `encounter` 후보가 나온다.
