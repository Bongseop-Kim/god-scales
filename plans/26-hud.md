# P-26 · 토큰·우호도 HUD

`plans/26-hud.md` · [◀ P-29](29-quest.md) · [색인](../reviews/00-index.md) · [P-32 ▶](32-art.md)

**크기** 중간 · **착수 조건** P-25·P-31·P-27·P-30·P-28·P-29 완료 — **화면을 여는 계획이 전부 끝난 뒤**

**실패 시 행동** 1440×900에 다 안 들어가면 **우호도 미터를 접는다**(patron 둘만 상시, 나머지 셋은 숨김). 토큰 줄과 패시브 배지는 접지 않는다 — 그 둘이 대상 선택의 근거다.

---

## 왜 맨 뒤인가

원래 P-25 다음이었다. 그런데 화면을 여는 계획이 다섯 더 있다:

| 계획 | 화면 |
|---|---|
| P-31 | 토큰 9종 → 10종(`thorns`), 파워가 전투 내내 붙어 있다 |
| P-27 | 지도 화면이 통째로 새로 든다 |
| P-30 | 신의 개입이 자동으로 터진다 — 무엇이 왜 일어났는지 |
| P-28 | `GraceScreen`이 카드 목록에서 은혜 3택1 + 슬롯 교체로 |
| P-29 | `DemandScreen`이 버튼 둘에서 수락·시련·거절로 |

앞에 두면 **레이아웃을 다섯 번 다시 연다.** 뒤에 두면 한 번이다.

**대신 둘은 P-25가 떼어 갔다** — `intentLabel` 복합 반환과 적 이름 옆 패시브 배지. 없으면 대상 선택이 도박이 되어 P-25의 정책 행렬 자체가 뜻을 잃기 때문이다. 여기서는 그 둘의 **배치와 색**을 맡는다.

---

## 완료 정의

**전투 화면만 보고 다음 턴을 계산할 수 있다.** 다키스트 던전 2의 규칙 그대로 — 상태는 스탯이 아니라 배우 위에 붙은 물건이다.

```bash
npm run build && npx tsc --noEmit
npm run e2e -- --dist
open -a Aside
aside repl "..."   # 토큰 3종·패시브 2종이 걸린 턴에서 스크린샷
```

확인할 것 여섯:

1. 토큰이 배우 **위**에 뜬다 — 텍스트 줄 안에 섞여 있지 않다
2. 토큰의 **진영**(이로움/해로움)이 색으로 갈린다
3. **패시브**가 적 이름 옆에 상시 표시된다 — `guard`·`shell`을 모르면 대상 선택이 도박이다
4. **의도**가 복합 행동을 그린다 — 「공격 10 + 아군 강화」가 「대기」로 뭉개지지 않는다
5. 후원 두 신의 **우호도**가 플레이어 위에 항상 있다
6. **여덟 화면이 한 눈금을 쓴다** — 전투·지도·보상·휴식·은총·요구·개입이 같은 여백과 글자 크기다. 다섯 계획이 각자 뼈대만 세워 놓은 것을 여기서 맞춘다

## 지금 상태

**시스템은 있고 배치와 관측이 없다.**

| 항목 | 어디에 | 화면 |
|---|---|---|
| 토큰 10종 | `core/state.ts:3`, `core/rules.ts:59` | `ui/tokens.tsx:33` — 적 버튼 `.badges` 안, 플레이어는 `player-bar` 텍스트 사이 |

| 패시브 | P-25 | P-25가 배지까지 했다 — **색과 자리가 남았다** |
| 파워 | P-31 `CombatState.powers` | **없다.** 전투 내내 일하는데 화면에 흔적이 없다 |
| 우호도 | `core/favor.ts`, `state.favor` | **없다** |

우호도가 없는 이유는 `RunView`(`sim/engine.ts:104`)가 `favor`를 안 실어서다. 헤더는 체력·조합·위치만 받는다(`ui/header.tsx:24`).

## 조사 — 색은 신이 아니라 진영이다

다키스트 던전 2는 **노랑 = 이로움, 파랑 = 해로움**으로 나눈다. 위키가 「토큰이 해당하는지 판별하는 가장 쉬운 방법은 색을 보는 것」이라고 못박는다. 세부 계열은 그 위에 얹힌다 — 짙은 파랑 = 약화, 옅은 파랑 = 스킬 기제, 빨강 = 처형 카운트.

우리는 지금 **신별로** 색을 준다(`ui/tokens.tsx:5` — `shock`은 제우스색, `bulwark`는 아테나색). 출처는 읽히지만 **이로운지 해로운지가 안 읽힌다.** 전투 중에 급한 정보는 후자다.

> 색 = 진영, 아이콘 = 신. 신 색은 아이콘 테두리로 남긴다.

집합은 P-25가 만드는 `harmfulTokens`를 읽는다. `selfTokens`에서 파생되므로 목록이 늘지 않는다.

슬레이 더 스파이어의 의도는 **7갈래 + 복합**이다 — 공격(피해 구간 7단) / 방어 / 디버프 / 버프 / 이탈 / 수면 / 기절 / 미지. 복합은 공격+방어, 공격+디버프, 방어+버프. 무기 아이콘이 피해 구간에 따라 커진다.

DD2는 토큰에 **지속과 스택 상한**을 명시한다(대부분 3턴·2~3스택). 우리 지속은 세 갈래뿐이다.

## 엔진 변경 — 한 개

`RunView`에 `favor`와 `grace`를 추가한다.

export type RunView = {

## 화면

### 토큰 줄

`.enemy` 버튼과 새 `.player-actor` 블록에 배우 상단 절대 위치. `TokenRow`를 그대로 쓰고 컨테이너만 옮긴다.

`TokenBadge`에 셋을 붙인다:

**진영** — 이로움/해로움 배경색. `harmfulTokens`에서 읽는다.

**지속** — 세 가지뿐이다. 근거는 코드다:

| 지속 | 토큰 | 근거 | 표시 |
|---|---|---|---|
| 이번 턴 | `shock` | `core/combat.ts:105`에서 지운다 | 테두리 점선 |
| 1회 소모 | `deflect`·`crit`·`frenzy`·`soaked`·`displace`·`bleed`·`bulwark` | `consumeToken`을 탄다 | 기본 |
| 전투 내내 | `mark` | 소모되지 않는다 (`core/rules.ts:74`) | 테두리 실선 강조 |

**상한** — P-25의 `tokenLimits`. 상한에 닿으면 숫자를 강조한다. 더 걸어도 낭비라는 걸 화면이 말해야 한다.

`title={token}`이 지금 영문 id다(`ui/tokens.tsx:24`). 한글 이름 + 효과 한 줄로 — `tokenName()`이 이미 한글을 갖고 있다.

### 의도와 패시브 — 배치만

P-25가 `intentLabel` 복합 반환과 배지를 이미 붙였다. 여기서는 자리와 색이다. 피해 구간별 아이콘 크기는 넣지 않는다 — 숫자가 이미 있고 우리 조우는 최대 3인이라 훑을 양이 적다.

### 파워

플레이어 배우 옆 작은 줄. 파워는 카드가 손을 떠난 뒤 **전투 내내 매 턴 일하는데** 지금 화면에 흔적이 없다 — 「턴 시작 광란 1」을 두 장 냈는지 한 장 냈는지 플레이어가 세고 있어야 한다. 토큰 배지를 그대로 쓰고 트리거를 툴팁에 적는다.

### 우호도 미터

플레이어 배우 위. 단계 경계는 `favorBoundaries`(`core/favor.ts:9` — 헌신 70 / 평온 30 / 분노 10 / 진노 0)를 읽는다. **UI에 숫자를 다시 박지 않는다.**

**후원 둘만 상시로 그린다.** 다섯 칸 × 미터에 은총 점 6개씩이면 30개가 전투 화면에 얹힌다 — 나머지 셋은 숫자 하나로 접고, 진노에 가까워지면 그때 편다. 진노는 경고색이어야 한다: `applyFavorStageEffects`(`:50`)가 진노에서 조우 시작에 **적을 하나 더 부르므로**(P-30) 플레이어가 그 전에 알아야 한다.

은총 점은 후원 둘 옆에만. P-28이 은혜 슬롯 넷을 만들었으므로(공격·방어·유틸·토큰) **슬롯 표시가 은총 점을 대체하는지 먼저 본다** — 둘 다 그리면 같은 사실이 두 곳에 있다.

## 함정

- **화면이 넘친다.** 적 3인 × (토큰 + 패시브 + 의도) + 플레이어 + 파워 + 우호도가 한 화면이다. 토큰 4개를 넘으면 접어서 「+N」으로 — DD2도 그렇게 한다. 그래도 안 되면 위 「실패 시 행동」
- **`aria-label`.** 적 버튼이 이미 `${name} 체력 ${hp} ${intent}`를 읽는다(`ui/combat.tsx:69`). 패시브·토큰을 넣되 배지마다 읽히면 안 된다 — 컨테이너에 요약 한 문장
- **색만으로 진영을 말하면 안 된다.** 이로움/해로움을 색에만 실으면 색각 이상에서 사라진다. 테두리 모양(채움/외곽)을 같이 준다
- **1440×900.** P-19에서 본문이 좌측에 몰리고 우측이 비었다. 여덟 화면 전부를 여기서 한 번에 본다 — 앞 다섯 계획이 뼈대만 세워 놓고 넘긴 자리다
- **`aside repl`만 쓴다.** `aside exec`는 모델을 써서 크레딧(402)에 걸린다
- 애니메이션을 새로 만들지 않는다. `ui/motion.css`와 `pop`/`damagePop` 상수를 재사용하고 `prefers-reduced-motion`을 지킨다
