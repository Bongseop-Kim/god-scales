# P-17 · UI 골격

`plans/17-ui.md` · [◀ P-16](16-agent.md) · [색인](00-index.md) · [P-18 ▶](18-motion.md)

**크기** 김 · **착수 조건** P-12 (게임 규칙이 전부 있어야 화면이 정해진다)

**이 세션은 골격만 만든다.** 에셋과 연출은 P-18이다. 여기서 검증하는 것은 **UI가 상태를 갖지 않는가**뿐이며, 그것을 먼저 통과시켜야 P-18에서 연출을 붙여도 깨지지 않는다.

---

## 완료 정의

브라우저에서 1런을 완주하고, **런 종료 시 반출한 JSON을 `npm run sim -- --replay`가 재생해 같은 결과를 낸다.**

```bash
npm run dev
#   → 브라우저에서 1런 완주 → 반출 버튼 → logs/human/run-*.json
npm run sim -- --replay logs/human/run-*.json
#   → 브라우저 런과 승패 · 도달 층 · 최종 호의가 일치
```

**재생 일치가 이 세션의 진짜 검증이다.** UI가 상태를 몰래 바꾸면(I-3 위반) 재생이 어긋난다. 화면이 예쁜지는 검증 대상이 아니다.

## 구현 노트

### 범위 — 골격만

**8개 화면의 구조와 배선.** 에셋 없이, 연출 없이, 신 색만으로 만든다.

| 이 세션 | 다음 세션 (P-18) |
|---|---|
| 화면 구조와 전환 | 아이콘 · UI 프레임 |
| `core/` 읽기와 action dispatch | 전투 연출 |
| 반출 버튼 | 카드 일러스트 자리와 placeholder |
| 신 색 5종 | 배지 아이콘, `ATTRIBUTION.md` |

토큰은 임시로 한 글자만(감 지 침 벽 반 혈 광 표 치), 노드도 글자 하나(전 · 휴 · 보)로 둔다. P-18에서 아이콘이 얹힌다.

**S-4의 1번은 UI를 가장 먼저 버리라고 하지만, 산출물이 둘이므로 UI 없이는 제출이 성립하지 않는다**(S-1). 축소 대상은 세션이 아니라 범위다. 시작할 때 남은 시간이 이틀 미만이면 전투 화면만 만들고 맵은 텍스트 목록으로 끝낸다.

### 화면 구조

A-2의 표가 화면별 구성 요소 전체다. 이 세션에서는 그 요소들이 **자리를 잡고 올바른 값을 읽는지**까지만 한다.

### I-3을 지키는 법

`ui/`는 `core/`를 읽고 action을 dispatch한다. **그 외의 권한이 없다.** UI가 자체 상태를 갖는 순간 반출한 action 로그가 화면에서 일어난 일을 재현하지 못하고, 완료 정의가 깨진다.

React 상태는 "현재 어느 화면인가" 같은 표현 상태만 갖는다. 게임 상태는 전부 `core/`에 있다.

**이 경계를 여기서 통과시켜야 P-18이 성립한다.** 연출을 붙이면 "지금 무엇이 날아가는 중인가"라는 상태가 생기는데, 그것이 게임 상태로 새면 재생 일치가 깨진다. 골격 단계에서 경계가 이미 흐리면 연출을 붙인 뒤에는 원인을 찾을 수 없다.

### 반출 형식

P-12의 CLI 플레이가 이미 확정했다. 같은 형식을 쓴다.

```ts
// ponytail: 서버 없음. 런 로그는 파일로 나가고 사람이 logs/human/에 넣는다
const blob = new Blob(
  [JSON.stringify({ seed, actions, replay_mode: 'action_log' })],
  { type: 'application/json' })
```

**클라이언트 저장소를 쓰지 않는다**(T-1.1). localStorage · IndexedDB · 쿠키 어느 것도 쓰지 않는다 — 브라우저에 남길 상태가 없다. 새로고침 복구가 필요해지면 B-5에서 꺼낸다.

**참조** — I-3 (UI는 상태를 변경하지 않는다), T-1.1 (저장소와 반출), A-2 (시각 자산), R-8.2 (노드), R-3.1 (호의 단계 표시)
