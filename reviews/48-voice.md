# R-48 · 신이 말을 건다 — 그리고 요구가 읽힌다

[색인](00-index.md) · 계획 `plans/48-voice.md`(삭제됨) · [◀ R-47](47-wrath.md) · 형제 [R-46](46-presence.md)

## 결론

**통과 · 완료 정의 일곱 전부 충족.** 계획을 설계 그대로 지었다 — 되돌린 값이 하나도 없다. 이 계획이 판 위의 값을 안 건드리므로 **밸런스 영향이 실제로 0이다**: `npm run tune`이 R-47과 **같은 숫자**를 낸다(승률 55.1% · 최저 셀 athena+ares 7.0% · ⚠ 2).

| 완료 정의 | 결과 |
|---|---|
| 조건 | ✅ 요구 화면이 문장 **아래에** 조건을 한글 한 줄로 적는다. 열 줄 다 |
| HUD | ✅ 전투 화면 상단에 약속 한 줄 — 신 · 사람 말 조건 · 현재값/목표 |
| 확정 | ✅ 성공·실패가 **그 순간** L2로 뜬다. 조우 끝이 아니다 |
| 대사 | ✅ 트리거 아홉 × 신 다섯. **155줄** · 빈 트리거는 게이트가 반려한다 |
| 레벨 | ✅ 발화가 셋으로 갈리고 셋 다 입력을 안 받는다 — `Decision`이 안 늘었다 |
| 재생 | ✅ `n % lines.length`. e2e 시드 **727 그대로** · 232결정 · substituted 0 |
| 게이트 | ✅ 하한 0.05 통과 · **R-47과 수치가 한 자리도 안 다르다** |

## 1 · 확정 — 새 상태를 하나도 안 만들었다

계획 §1의 뿌리(사실 넷이 단조 비감소)가 코드에서 그대로 섰다. `core/demands.ts`에 세 줄이 붙었고 **전부 파생값이다**:

```ts
parseCondition(condition)        // 조건 문자열의 정본 파서 — 셋이 같은 한 줄을 읽는다
ruleText(condition)              // "이 조우에서 잃은 체력 8 이하"
demandSettled(tier, facts)       // "kept" | "broken" | undefined
```

`demandSatisfied`가 자기 정규식을 들고 있던 자리를 `parseCondition`으로 바꿨다 — 조건 파싱의 정본이 하나가 됐다. `demandSettled`는 **비교 연산자로만** 가른다(계획 지시대로 `polarity`를 안 읽는다): `>=`·`>`는 처음 넘는 순간 `kept`, `<=`는 처음 넘는 순간 `broken`, `==`는 끝까지 미정이다.

`CombatObservation.promises`는 매 yield마다 `facts`에서 다시 푼다. **상태를 안 든다** — 그래서 화면이 「지켰다」고 적은 뒤에 호의가 다르게 움직일 자리가 없다. 테스트가 그 둘을 같은 자리에 세운다: 배포된 열 단 × 사실값 아홉에 대해 `demandSettled`가 값을 내면 `demandSatisfied`가 그것과 같아야 한다.

## 2 · 레벨 셋 — CSS 세 벌과 함수 하나

`ui/fx.ts`에 `speak(level, god, text, portrait?)` 하나가 붙었다(~35줄). 새 의존 0 · 새 에셋 0 · WAAPI와 CSS뿐이고 `playSprite`와 같은 자리에 산다.

| 레벨 | 화면 | 머무는 시간 | 트리거 |
|---|---|---:|---|
| **1** 속삭임 | 판 아래 자막. 배경 안 어둡게 · `pointer-events: none` | 1.2s | 개입 턴 |
| **2** 말 | 화면 중앙 · 배경 `.34` · 신 색 | 2.0s | 조우 시작 · 단계 경계 · 요구 확정 |
| **3** 외침 | 배경 `.72` + 신 일러 슬라이드인 + 1.5rem + 흔들림 220ms | 3.0s | 찢기 · 합류 · 화해 |

**겹침은 큐가 아니라 순서다.** `speak`가 자기보다 낮은 레벨의 `.voice`를 지우고 선다(`data-level` 비교 한 줄). 같은 레벨은 호출자가 220ms 어긋나게 낸다 — P-46의 컷인과 같은 규칙, 같은 상수다.

`prefers-reduced-motion`에서는 페이드도 흔들림도 슬라이드인도 빠지고 **문장만 제 시간만큼 머문다.** P-46이 컷인에서 고친 것과 같은 규칙이다.

### 컷인 위에 앉는다 — 두 층을 안 합쳤다

`.fx`가 `z-index: 3`, `.voice`가 4다. **그림은 신이 무엇을 했는지고 말은 신이 무엇을 말하는지다** — 합류 조우 시작에 둘이 다 뜬다:

```text
fx   cut   아테나 · 진노 — 적 전체에게 방벽 5 · 아테나가 적으로 합류   (480ms)
voice L3   네 방벽이 이제 내 것이다.                                  (그 뒤 3s)
```

L3만 **480ms 늦게** 낸다. 같이 내면 L3의 `.72` 배경이 「무엇을 했는가」를 덮는다 — 브라우저에서 그 순서를 실측했다(아래).

### 컷인이 안 서는 자리에서도 말한다

P-46의 컷인은 `godStageText`가 빈 문자열이면 아예 안 섰다(「이 신은 지금 아무 일도 안 한다」). **말은 거기서도 나온다** — 제우스의 분노처럼 `on_encounter_start`가 없는 단계에서도 신은 조우 시작에 한 마디 한다. 그래서 `if (!text) return undefined` 한 줄이 타이머 안쪽의 `if (text && source)`로 내려갔다.

## 3 · 요구가 읽힌다

`DemandOffer`에 `rule` 필드 하나가 붙었고 엔진이 `ruleText(tier.condition)`으로 채운다 — **화면이 `condition`을 다시 파싱하지 않는다.** 요구 화면은 문장 아래에 `.rule` 한 줄을 따로 세운다:

```text
시련 · 대가 아테나 호의 −18 즉시
  한 번의 벼락으로 셋을 쳐라. 흩어진 적에게 자비를 두지 마라.
  한 턴에 맞힌 적 3 이상                       ← 새로 선 줄
  지키면 제우스의 은혜 1개 · 아테나 호의 −18
```

같은 화면에 **신 일러와 대사창**을 세웠다(`art/gods/{god}.webp` · 에셋 0장). 지금까지 요구 화면은 글자만 있었다 — 신이 직접 말을 거는 자리인데 누가 말하는지가 화면에 없었다.

`Choice`의 `detail`이 `string`에서 `React.ReactNode`가 됐다. 요구 하나 때문이고 다른 다섯 화면은 문자열 그대로다.

## 4 · 약속이 전투 화면에 산다

머리글 바로 아래, 판보다 위에 한 줄:

```text
⚖ 제우스   한 턴에 맞힌 적 2 이상                        0 / 2
```

| 상태 | 표시 |
|---|---|
| 미정 | 신 색 · 현재값/목표 |
| `kept` | 초록 |
| `broken` | 회색 · 취소선 |

**`omen`이 걸어 둔 약속도 같은 줄에 선다.** 계획의 타입은 `promise?` 하나였는데 배열(`promises`)로 지었다 — 엔진이 이미 `[promise, carried]` 둘을 같은 사실로 판정하므로(`sim/engine.ts`), 하나만 실으면 화면이 판정에 드는 약속 하나를 안 보여 준다. 전투 화면은 0~2줄을 그린다.

`playEncounter`가 인자 하나를 더 받는다(`promised: DemandPromise[] = []`). 기본값이 빈 배열이라 다른 호출자가 없다.

## 5 · 대사 데이터 — 155줄, 트리거가 키다

`data/gods.json`의 신마다 `lines`. 신당 31줄 × 다섯이다:

```text
encounter · intervene · cross   → 단계 넷으로 갈린다 (2·3·1줄)
demand_offer · demand_kept · demand_broken · tear · join · reconcile → 한 벌 (1·1·1·2·1·1줄)
```

`intervene`이 단계당 셋인 이유는 계획 §2의 빈도표다 — 런당 약 49회 뜨는 자리다. 목소리는 §7의 표를 그대로 따랐다(제우스는 명령하고 · 포세이돈은 되묻고 · 아테나는 평가하고 · 아레스는 부추기고 · 아르테미스는 센다).

**고르는 것은 난수가 아니다.** `ui/header.tsx`의 `godLine(god, trigger, n, stage?)`이 `n % lines.length`고 `n`은 그 자리의 턴 수나 조우 수다. e2e가 그것을 증명한다 — 시드 727이 **그대로** 재생되고 반출 순서가 232결정 내내 안 어긋난다.

### 게이트 셋

`tools/validate.ts`에 반려 사유 하나(`line_coverage`)와 검사 셋:

| 검사 | 잡는 것 |
|---|---|
| 트리거 아홉이 다 있고 각각 최소 한 줄(빈 문자열도 반려) | 그 자리에서 신이 **침묵한다** |
| `encounter`·`intervene`·`cross`는 단계 넷이 다 있다 | 평온 줄이 없으면 대부분의 조우에서 신이 말을 안 한다 |
| 요구 조건의 좌변이 `factName`에 있다 | 오타 하나가 화면에서 **빈 줄**이 된다 |

셋 다 실제로 무는 것을 확인했다 — `lines.encounter.calm`을 비우면 `line_coverage`, `tear`를 지우면 `line_coverage`, `hit_targets_in_trun`으로 오타를 내면 `demand_axis`.

**`required.god`에는 `lines`를 안 넣었다.** 넣으면 다른 필터를 재는 신 픽스처 셋(15·18·21)이 전부 `schema`에서 먼저 걸려 「깨진 픽스처 하나가 자기 필터로 간다」가 깨진다. 없는 `lines`는 `godLineFailure`가 더 정확한 이름으로 잡는다.

## 실측 — 브라우저(`aside`)로 트리거 여덟을 다 봤다

100:0 시드 1·3·9·17과 50:50 시드 727을 실제로 클릭해서 화면에서 읽은 줄이다:

| 트리거 | 레벨 | 실제로 뜬 줄 |
|---|---|---|
| `encounter` | L2 | `가라. 하늘이 열려 있다.`(제우스 헌신) · `네 방벽은 내가 세운 것이었다.`(아테나 진노) — 220ms 어긋나 둘 다 |
| `intervene` | L1 | 2턴에 `길을 텄다.`(제우스 헌신) · `무너져라.`(아테나 진노) |
| `cross` | L2 | 2턴 `이제 내 이름으로 쳐라.`(제우스 헌신 진입) · 9턴 `실망했다고 적어 두겠다.`(아테나 분노 진입) |
| `demand_offer` | 화면 | 요구 화면에 일러와 함께 `들어라. 두 번 말하지 않는다.` |
| `demand_broken` | L2 | 10턴 `예상한 결과다.` — 같은 프레임에 약속 줄이 `broken 25 / 20`이 됐다 |
| `tear` | L3 | `손해다. 알고도 했다면 더 나쁘다.` · `그것을 버리는 것이 계산인가?`(두 줄이 `n % 2`로 갈렸다) |
| `join` | L3 | 컷인 480ms **뒤에** `네 방벽이 이제 내 것이다.` |
| `reconcile` | L3 | 신을 꺾은 뒤 `이 정도면 다시 이야기해 볼 만하다.` — 시드 3·9·17에서 다 |

요구 화면의 조건 줄도 같이 봤다: `한 턴에 맞힌 적 2 이상` · `한 턴에 맞힌 적 3 이상`. 전투 화면의 약속 줄은 `제우스 · 한 턴에 맞힌 적 2 이상 · 0 / 2`.

**확정 발화는 한 번만 뜬다** — 약속 줄이 `broken`으로 남아 있는 동안 `예상한 결과다.`는 화면에 한 번만 나왔다(`useRef` 한 벌이 `{depth}:{종류}:{키}`로 본 것을 적는다).

## 남은 것

- **`demand_kept`만 브라우저에서 못 봤다.** `demand_broken`과 같은 삼항의 반대편이고 단위 테스트가 두 갈래를 다 잰다 — 봇 없이 사람 정책으로 클릭하는 드라이버가 조건을 지키는 판을 못 만들었다(「거절이 선택지가 아니다」와 같은 자리다: 봇도 요구를 향해 플레이를 안 바꾼다)
- **화해 발화가 엔진보다 한 프레임 이르다.** 화면은 신이 판에서 사라지는 순간에 말하고 엔진은 조우를 **이긴 뒤에** 호의를 30으로 놓는다(`felled`) — 신을 꺾고 그 조우에서 지면 화해는 없는데 말은 이미 나갔다. 사람이 보는 사건은 신이 쓰러지는 그 프레임이라 이쪽을 골랐다
- **`encounter`·`cross`가 전투 화면에서만 뜬다.** `cross`는 `FavorMeter`가 들고 있어서고, 그래서 요구 보상·신탁이 전투 **밖에서** 넘긴 경계는 조용하다. 미터가 전투에만 있는 것이 원인이고 그건 R-26이 정한 자리다
- **`intervene`이 런당 약 49회다.** 계획이 L1으로 내린 이유고 실제로 자막은 판을 안 가리지만, 155줄 중 60줄이 그 자리라 반복은 결국 눈에 띈다. 늘릴 자리는 데이터뿐이고 코드는 안 바뀐다
- **합류 L3의 480ms 지연이 타이머 하나를 정리 안 한다.** 개입 타이머는 `clearTimeout`으로 걷는데 그 안에서 다시 건 짧은 타이머는 안 걷는다 — 480ms고 `document.body`만 만진다
- **대사가 `RunResult`에도 반출에도 안 들어간다.** 전부 UI 층이라 CLI 재생에는 없다 — 계획대로다(대사는 게임 상태가 아니다)
