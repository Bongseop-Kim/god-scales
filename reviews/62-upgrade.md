# R-62 · 강화 표현과 바뀐 수치 강조

[P-62] 수행 결과. 규칙·값은 한 글자도 안 바뀌었고 화면만 만졌다 — `npm run sim` 기준선이
`win_rate=0.545`로 계획 전후 같다(실측 대조).

## 한 일

### 1. `attackPreview` — 공격자 쪽 보정 넷을 한 함수로 (`core/rules.ts`)

`dealDamage` 안의 넉 줄을 순수 함수로 뽑고 **`dealDamage`가 그것을 쓴다.** 소모(`consumeToken`)는
`dealDamage`에 남고 산술만 옮겼다 — 셋은 서로 다른 키라 소모 순서가 상태를 안 바꾸고 위력은 읽기만
한다. 화면은 소모 없이 플레이어의 현재 토큰을 그대로 넘긴다.

동치 테스트는 `test/combat.test.ts`에 한 줄이다(토큰 8벌 × 값 4개). 두 벌이면 「화면에 11이 적힌
카드가 9를 내보내는」 자리가 생기고, 그 어긋남을 잡는 것이 이 테스트의 전부다.

### 2. 카드 면 — 「원래 값 → 지금 값」 (`ui/shared/card.tsx`)

`Effect`가 값 하나를 그리던 자리에 규칙 하나를 더했다: **원래 적힌 값과 지금 나갈 값이 다르면 원래
값이 취소선으로 앞에 선다.** 원래 값은 `data/cards.json`의 base 카드에서 읽는다 — `cardFace`가 이미
그 파일을 읽고 있어 새 경로가 아니고, 규칙을 다시 계산하는 것이 아니라 **원문을 읽는 것**이라 두 번째
진실이 아니다. 지금 값은 `CardView`의 값(강화 반영)에 `attackPreview`(피해·연쇄만)를 태운 것이다.

중간 단계는 안 적는다 — 5 → 7 → 12를 다 적으면 140px 카드가 숫자 밭이 된다. 은혜는 `cardEffects`가
**뒤에 잇는** 것이라 앞에서부터 인덱스로 맞고, 뒤에 남는 조각은 자기 값이 곧 원문이다.

`GameCard`에 `boost?: Tokens`가 하나 늘었고 넘기는 자리는 **전투 화면의 손패·무대 둘뿐**이다.
`effectText`·`cardCaption`도 같은 값을 받는다 — 화면이 12를 세우는데 스크린 리더가 5를 읽으면
그것이 채널 어긋남이다.

### 3. `+N` 배지

이름 끝의 `+1`을 캡션에서 떼어 등급 칩과 **같은 줄, 다른 슬롯**에 세웠다(`.card-up`). 등급은 카드가
태어난 계단이고 강화는 이 런에서 키운 것이라 직교한다. 프레임색은 안 건드렸다 — 그 색은 신의 것이고
배지는 이로움(`--boon`)이다. `aria-label`에는 `작은 번개+1`이 그대로 남는다.

### 4. 쉼터 미리보기

`RestScreen`이 `upgrading` 하나를 받는다 — App이 `actions.at(-1)?.choice`로 넘기는 직전 `rest` 답이고
**새 상태가 아니다.** 강화일 때 고를 수 있는 카드가 `upgraded(base, level + 1)`로 선다: 같은 규칙
함수라 재구현이 없고, 고르기 전과 고른 뒤가 같은 얼굴이다. 못 고르는 칸(상한·융합)은 지금 얼굴
그대로다 — 거짓 약속을 안 한다.

**`data-card`·`data-cost`·`data-damage` 셋은 덱에 실제로 있는 카드의 값 그대로다.** 미리보기가 그
셋까지 바꾸면 e2e 드라이버가 없는 id를 고르고, 무엇보다 계약이 조용히 깨진다.

## 실측에서 고친 것 하나

**픽셀 서체(Galmuri11)의 `line-through`는 이 크기에서 아무것도 안 그린다.** aside로 찍어 12배로
확대해 보고서야 알았다 — 색은 맞게 나오는데 선이 없어서, 남는 채널이 색 하나뿐이었다. 그대로 뒀으면
R-26의 「색만으로 말하지 않는다」를 정확히 어긴 채 통과했을 것이다. `s::after` 1px로 직접 긋는다.

마크업 단언(`test/ui.test.ts`)은 이 결함을 **못 잡는다** — `<s>5</s>`는 두 경우 다 같다.
카드 면처럼 「그려졌는가」가 곧 기능인 자리는 실측이 테스트를 대신할 수 없다는 자리가 하나 늘었다.

| | |
|---|---|

| `npm test` | 24파일 183개 통과 (동치 테스트 1 · UI 마크업 테스트 2 추가) |

| aside 실측 | 위력 2가 붙은 손패 `~~5~~ 7` · 쉼터 강화 후보 `~~4~~ 6`·`~~3~~ 5` + `+1` 배지 · 덱 오버레이의 `card_zeus_28+1` |

실측은 편집기로 「축적된 전하」 5 + 「작은 번개」 5를 짜서 돌았다 — 위력이 실제로 붙은 손패는 규칙
덱으로는 시드를 골라도 잘 안 나온다.

## 안 한 것

- 대상 쪽 보정(감전·표식)은 카드에 안 적는다 — 대상을 고르기 전에는 거짓이다.
- 중간 값 삼단 표기 없음 · 쉼터 정렬·필터·토글 없음 · 강화 애니메이션 없음.
- 비용이 내려가는 19장의 「원래 비용 → 지금 비용」 표기는 안 만들었다. 젬은 지금 값 하나를 든다 —
  효과 줄이 이미 대조를 들고 있고, 젬까지 둘로 갈리면 좌상단이 숫자 둘이 된다.

## 남은 자리

강화가 **스택·뽑기만 올리는 카드**(「축적된 전하」 등)는 배지 말고는 화면에 아무 변화가 없다. 규칙이
`damage·block·heal·chain` 넷만 올리므로 그것이 사실이고, 화면이 없는 변화를 그리지 않는 것이 맞다 —
`upgrade` 델타를 그런 카드에 더 적는 것은 밸런스 쪽 결정이지 표현 쪽 결정이 아니다.
