# R-42 · 지도를 걷는다 — 격자가 유일한 조작 면이다

[색인](00-index.md) · 계획 `plans/42-mapwalk.md`(삭제됨) · [◀ R-41](41-cardface.md) · [R-27](27-map.md) · [R-37](37-wire.md)

## 결론

**통과 · 완료 정의 일곱 전부 충족 · 규칙·값·데이터·엔진은 한 줄도 안 건드렸다.** 경로 화면에서 오른쪽 패널(`.decision-panel` + `.choice` 셋)이 사라지고 격자 칸이 `<button>`이 됐다 — **런의 경로 화면 열 개 전부에서 `.decision-panel`·`.choice`가 0개**다(실측). 누르면 마커가 그 칸으로 240ms 걸어가고 **그 다음에** 화면이 넘어간다.

**마커가 안 뜨던 두 화면이 시작 칸 하나로 닫혔다.** `here.depth`가 저승 1층에서 −1, 지상 1층에서 5(저승 보스)라 격자에 자리가 없던 것이고, 계획대로 조건 하나(`here.depth`가 이 지역 밖)가 둘을 다 막았다. **경로 화면은 런당 열이다** — 6층·12층은 보스라 갈래를 묻지 않는다(계획의 「12화면 중 둘」은 열 중 둘이 맞다). 열 화면 전부에서 마커가 칸 **안에** 서는 것을 한 런으로 확인했다.

| 완료 정의 | 판정 |
|---|---|
| 한 패널 | ✓ 경로 화면 열 개 전부 `.map-panel` 1 · `.decision-panel`+`.choice` **0**. `run-layout`을 빼서 `measure()`가 `.shell`로 폴백한다 |
| 시작 칸 | ✓ 1층 「시작」 · 7층 「지하에서」에 행이 서고 마커가 그 칸의 자식이다. 열 화면 10/10 마커 |
| 이동 | ✓ 클릭 → 마커 240ms(x축 실측 237ms) → `onLayoutAnimationComplete` → 결정 전송 → 화면 전환. `setTimeout` 없음 |
| 되돌릴 수 없음 | ✓ 이동이 시작되면 전 칸 `disabled`(실측 `allLocked: true`). **이동 중 같은 칸을 두 번 더 눌러도 `data-step`은 하나**만 오른다 |
| 접근성 | ✓ `<button>` + `aria-label="왼쪽 · 전투 · 보상을 노리고 위험을 감수합니다."`. 탭으로 닿는 칸은 **열린 셋뿐**(실측 3) — 잠긴 칸은 `disabled`라 순서에서 빠진다. 설명 줄이 **hover와 focus 둘 다**에 반응한다(실측) |
| 전환 | ✓ 퇴장 120 / 등장 160 · `y: 8 → 0 → −6` · 시작·결과만 320. reduced-motion에서 CSS 리프트가 `none`(실측) · 시간은 `reducedMotion ? { duration: 0 }` |
| 게이트 | ✓ `overflowX` false ×8 · `halfEmpty` false ×8 · 12/12층 완주 · 반출 재생 일치(`diverged: -1`, 330결정) |

`npx tsc --noEmit` 통과 · `npm test` **134**통과(22파일) · `npm run build` 통과 · `npm run e2e` 통과(시드 371 · 330결정 · 12층 완주 · 최종 체력 10 · 여덟 화면 1440px). **밸런스는 안 쟀다** — 규칙·값·데이터·봇 무변경이므로 [R-26](26-hud.md)·[R-41](41-cardface.md)과 같은 자리다(`globalParamVersion`·`botPolicyVersion` 불변).

## 실측 — 클릭에서 화면이 넘어가기까지

`advance`의 대기 한도는 1000ms다(`tools/e2e.ts`, 40 × 25ms). 계획이 「보는 숫자」로 지정한 값이라 한 런의 경로 클릭을 쟀다 — 기록에 남은 것은 아홉 값이다.

| 자리 | 값 |
|---|---|
| 클릭 → `data-step` 증가 | **382 · 383 · 384 · 385 · 385 · 386 · 387 · 389 · 405ms** (아홉 값 · 평균 **387ms**) |
| 한도 대비 여유 | **613ms** |
| 마커 이동(x축이 목표에 닿는 시각) | **237ms** (선언 240ms) |
| 마커가 그 뒤 6px 더 오르는 것 | 화면 **퇴장의 `y: -6`**이다 — 섹션 transform이 마커를 같이 들어올린다. 마커의 애니메이션이 아니다 |
| 남는 ~150ms | 퇴장 120ms + 콜백·프레임 몫 |

계획의 예산(240 + 120 = 360ms)과 실측(387ms)이 맞는다. **이동 시간을 늘릴 때 보는 숫자가 613ms다.**

`layoutId`가 처음에 300ms로 보인 것은 이 6px 때문이었다 — `transition={{ layout: … }}`으로 감싸도 같은 값이 나와, 맨 `transition`이 이미 걸려 있다는 것이 확인됐다(그 우회를 되돌렸다).

## 만든 것

### 지도가 곧 조작 면이다 — 프롭 둘로 갈린다

```
┌─ 지하 6층 × 3갈래 ────────────────┐   1440×900 · 패널 520px 가운데
│  6층    ·    [👑보스]     ·      │   칸 130 × 48px (전 30px)
│  5층  [쉼터]  [전투]   [예고]     │   잠긴 칸 opacity .5
│  1층  ╔전투╗  ╔전투╗  ╔전투╗      │   열림 = 금색 테두리 + hover 2px 리프트
│ 시작    ·    [ ▪🚩 ]    ·        │   점선 = 마커의 집
│  문이 등 뒤에서 닫혔다. …          │   가리킨 칸 설명 / 없으면 view.text
└──────────────────────────────────┘
```

`MapPanel`은 `onEnter`가 오면 걷는 격자, 안 오면 읽는 그림이다. **결과 화면 두 패널에는 `<button>`이 하나도 안 생기고 크기도 30px 그대로다** — 크기·이름 글자·설명 줄이 전부 `.walkable`에만 붙는다(테스트가 `not.toContain("<button")`으로 잠근다).

`open` prop을 `{ lanes: number[] }` → `{ options: string[] }`으로 바꿨다. 칸에서 `"lane:type"`을 되만들면 그 꼴이 두 곳에 적히므로 **엔진이 준 문자열을 그대로 들고 있다가 그대로 보낸다.**

### 시작 칸 — 조건 하나가 구멍 둘을 막는다

```tsx
const start = here && (here.depth < base || here.depth >= base + floorsPerRegion) ? here : undefined;
```

| 자리 | `here.depth` | 행 라벨 | 실측 |
|---|---|---|---|
| 저승 1층 | −1 | 「시작」 | ✓ `map-node here` 안에 마커 |
| 지상 1층 | 5 (저승 보스) | 「지하에서」 | ✓ 같음 |
| 그 외 여덟 | 지역 안 | 행 없음 | ✓ `startRow: false` |

**라벨은 「저승에서」가 아니라 「지하에서」다** — `regionName`이 지역 이름의 정본이고 화면 어디에도 「저승」이 없다. 계획 산문의 「저승」을 코드 어휘로 옮긴 것 하나가 다르다.

칸 위치가 분기 없이 같은 이유는 계획이 적은 그대로다 — 보스가 `bossLane`에 수렴하고 런 시작 `lane`도 `bossLane`이다(`core/map.ts:20`). 갈리는 것은 라벨 문자열 하나다.

### 이동 — 좌표를 계산하지 않는다

마커는 `<m.span layoutId="run-marker">` 하나고, `moving`(= `"lane:type"`)이 그것을 **다른 칸의 자식으로 옮기기만** 한다. 실측 궤적은 (807,513) → (669,451)이고 그 사이를 `motion`이 잇는다 — 좌표도 keyframes도 없다.

끝나는 신호는 `onLayoutAnimationComplete`다. 실제로 도는지 확인이 필요한 자리였는데(안 돌면 런이 그 자리에서 멈춘다) **330결정 완주가 그 답이다** — 경로 결정 열 번이 다 이 콜백으로 넘어갔다.

`moving`과 `pointed`를 **`MapScreen`이 아니라 `MapPanel`이 든다**(계획 §6은 `MapScreen`에 뒀다). 위로 올리면 `moving`·`onPoint` 두 prop이 더 필요하고, 설명 줄도 격자가 아는 사실이라 패널 안에 있는 편이 짧다. `MapScreen`은 이제 프롭을 넘기는 것 말고 하는 일이 없다.

### 화면 전환 — 방향은 축 하나다

| 전환 | 시간 | 실측 |
|---|---|---|
| 조우 ↔ 보상 ↔ 경로 (런당 ~36회) | 퇴장 120 / 등장 160 | ✓ 전환 한 번 360 → **280ms** |
| 시작 진입 · 결과 (런당 1회) | 320 | ✓ `screen === "setup" \|\| "result"`가 양쪽(등장·퇴장)에 걸린다 |

`mode="wait"`는 남겼다 — 빼면 두 `.shell`이 겹치고, `tools/e2e.ts:82`의 「퇴장 중인 옛 화면도 눌린다」 방어가 그 자리다.

### 계획에 없던 것 — `y`가 배경을 접는다

`m.section`에 `y`를 붙이면 **transform이 있는 동안 `fixed`의 기준이 뷰포트가 아니라 그 섹션이 된다.** `.backdrop`은 `.shell` 바깥의 `position: fixed`라(R-37이 세운 자리) 전환 160ms마다 배경이 본문 높이로 접혔다 펴진다. 런당 36번 도는 자리라 깜빡임으로 읽힌다.

`.backdrop`에 `height: 100vh`를 못 박아 닫았다. 실측으로 두 상태를 다 봤다:

| | `transform` | 배경 상자 |
|---|---|---|
| 전환 중 | `matrix(1,0,0,1,0,8)` | 1425 × **900** (섹션 기준 · 높이는 지켜진다) |
| 정지 | **`none`** | 1440 × 900 (뷰포트 기준) |

`motion`이 정지 상태에서 transform을 아예 `none`으로 되돌리므로 **일반적으로는 원래대로 `fixed`다** — 못 박은 높이는 전환 중 160ms만 일한다.

### e2e — 계획대로 하드로 깨졌고 같은 커밋에서 고쳤다

```js
? [document.querySelector("button.map-node.open.rest") ?? enabled("button.map-node.open")[0]]
```

**`.rest` 우선을 남겼다.** `driver.rests`가 쉼터 방문 횟수로 첫 쉼터에서만 다른 선택지를 고르므로, 우선순위가 바뀌면 런의 모양이 바뀌고 CLI ↔ 브라우저가 다른 경로를 비교하게 된다. 시드 371은 그대로 330결정·12층 완주다.

`halfEmpty`(`view.twoColumn && view.cols.length < 2`)는 계획이 지목한 대로 클래스를 빼서 통과시켰다 — 게이트는 안 건드렸다. 경로 화면의 측정값은 `map-panel 520`이고 `twoColumn: false`다.

## 계획과 어긋난 것

| 계획 | 실제 | 왜 |
|---|---|---|
| 마커 240ms를 `ui/motion.css`에 | **`ui/app.tsx`의 `markerTransition`** | `motion`의 layout은 JS 보간이라 CSS로 시간을 줄 수 없다. `motion.css`에는 칸 hover와 reduced-motion만 넣었다 — 시간은 여전히 한 곳에만 적혀 있다 |
| `moving`·설명 줄은 `MapScreen` | **`MapPanel`** | 위로 올리면 prop 둘이 더 붙는다. 설명 줄도 격자가 아는 사실이다 |
| 행 라벨 「저승에서」 | **「지하에서」** | `regionName`이 정본이고 화면 어디에도 「저승」이 없다 |
| (없음) | **`.backdrop { height: 100vh }`** | `y`가 섹션에 transform을 붙이는 동안 `fixed`가 섹션 기준이 된다 |
| `open: { lanes }` | **`open: { options }`** | 칸에서 `"lane:type"`을 되만들지 않기 위해서다(계획의 「엔진 꼴 그대로」) |
| 시작 칸은 「종류 없음」 | **점선 테두리** | 48px에서 실선이면 「누를 수 있는 칸」으로 읽히고, 아무것도 없으면 마커가 허공에 뜬다 |
| `test/ui.test.ts` — 이동 중 전 칸 잠김 | **브라우저에서 봤다** | vitest 환경에 DOM이 없어(jsdom 없음) 클릭을 못 보낸다 — R-41과 같은 벽이다. 실측으로 `allLocked: true` · 삼중 클릭에 결정 하나 |
| reduced-motion 「전부 0ms」 | **CSS만 실측** | `aside`의 CDP 프록시가 `Emulation.setEmulatedMedia`를 막는다(R-41). reduce 규칙을 미디어 밖에 다시 붙여 칸 리프트가 `none`이 되는 것은 봤고, JS 쪽(`reducedMotion ? { duration: 0 }` 셋 + 이동 건너뛰기)은 **읽어서만 확인했다** |

## 남은 것

1. **마커가 어둡다.** 16×16 자산(420B)이 48px 칸의 모서리에 붙는데 실루엣의 위쪽 밝은 부분만 읽힌다. `art/ui/marker.md`가 확대를 금지하므로(16px이 곧 원본 규격) 눈에 더 들어오게 하려면 **자산을 다시 찍는** 자리다 — 코드로 할 일은 없다
2. **시작 칸이 130px 빈 상자다.** 종류가 없어야 맞지만 「문」 같은 글리프 하나가 그 자리를 설명할 수 있다(`art/icons.svg` 28개에 후보가 없어 새로 받는 일이다)
3. **`.walkable` 520px 고정이라 1040px 중 절반이 빈다.** 계획의 「다음 자리 3 · 두 지역을 한 화면에」가 그 폭을 쓸 자리다 — 12층을 다 깔면 세로가 두 배지만 지금 문서가 900px로 딱 맞아 여유가 없다
4. **지나온 길이 경로 화면에는 아직 없다**(계획 다음 자리 1). `taken` prop은 이미 있고 결과 화면만 넘긴다 — `state.map.completed`에 값이 있으므로 배선 한 줄이다
5. **칸 hover에 조우 미리보기가 없다**(계획 다음 자리 2). 설명 줄이 이제 그 문장을 놓을 자리를 만들어 뒀다 — `mapSlots`의 `groups`가 실려 있다
6. **`.node-hint`가 `min-height` 두 줄을 늘 잡는다.** 문장이 한 줄인 화면에서 38px이 비는데, 안 잡으면 훑을 때마다 패널 아래가 흔들린다. 문장 길이를 데이터에서 맞추는 쪽이 다음 자리
