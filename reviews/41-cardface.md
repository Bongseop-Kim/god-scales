# R-41 · 카드 면 · 부채꼴 · 발동 두 단

[색인](00-index.md) · 계획 `plans/41-cardface.md`(삭제됨) · [◀ R-39](39-tier.md) · [R-26](26-hud.md) · [R-33](33-icons.md) · [R-36](36-shove.md)

## 결론

**통과 · 완료 정의 열 하나 전부 충족 · 규칙·데이터·봇은 한 줄도 안 건드렸다.** 비용이 149장 전부 같은 픽셀(좌상단 젬)에 있고, 효과 숫자가 카드에서 제일 큰 글자고, 아이콘은 [R-33](33-icons.md)의 시트 28개에서 그대로 꺼냈다(**그린 것 0 · 요청 0회**). 손패가 부채꼴 한 줄로 서고 — 열 장이어도 한 줄이다 — 대상을 고르는 카드는 무대에서 기다린다.

**계획에 없던 것 하나가 가장 큰 소득이다: `npm run e2e`가 120초 벽에 붙어 있었다.** 낸 카드가 퇴장 애니메이션 160ms 동안 **눌리는 상태로** DOM에 남아, 드라이버가 그것을 첫 후보로 골라 **클릭마다 1초를 버렸다**(실측 78회). `useIsPresent()` 한 줄로 같은 런이 **96초 → 17초**가 됐다. 그 전까지는 `aside repl`의 서버측 120초 상한에 걸려 「데몬이 안 뜬다」로 실패했다 — [R-39](39-tier.md)가 「데몬 미가동으로 못 돌렸다」고 적은 것이 이것이었을 가능성이 높다.

## 만든 것

### 카드 면 — 채널 넷

```
┌───────────────┐  140px 고정
│ ⟨2⟩     [파워] │  좌상단 젬 · 우상단 예외 배지(파워 6 · 전체 14, 안 겹친다)
│   일러 4:3     │  프레임색 = 신 (R-37 그대로)
├───────────────┤
│ ▮▯▯▮ ⚔6 ⚡2 연쇄4│  아이콘 18px + 숫자 1.05rem  ← 카드의 본체
│ 상급 감전 연쇄   │  0.78rem 캡션 (등급 배지는 P-39)
└───────────────┘
```

`GameCard`의 `caption: string`이 `card?: CardView`가 됐다. 값은 여전히 **엔진이 준 관측**이고(은혜가 붙은 뒤의 효과), `data/cards.json`에서 읽는 것은 **종류**뿐이다 — 그림·프레임색·파티클 태그·이름·`power` 태그.

**`effectText`는 그대로 뒀다.** `ui/header.tsx`(개입문)와 `ui/choices.tsx`(은혜)가 문자열로 쓰므로 구조화는 카드 면 안에서만 했다. 그 대신 그 함수가 **스크린 리더 문장**의 재료가 됐다(아래).

### 계획의 채널 표에 없던 것을 남겼다 — 사거리 네 칸

계획 §1의 표는 사거리를 안 적었다. 그대로 지우면 [R-35](35-range.md)가 붙인 「어느 칸에 닿는가」가 카드에서 사라진다 — **마스크를 적은 카드가 26장**이고, 그것이 없으면 `▮▯▯▮ 양 끝`을 왜 못 내는지 화면에 근거가 없다. 효과 줄 맨 앞에 네 칸 그림만 세우고 한글 이름은 `title`이 든다.

`reachText`를 `reachBars` + 이름으로 쪼갰다(`test/range.test.ts`의 단언 넷은 그대로 통과한다) — 칩은 막대만, 툴팁은 전체 문장이다.

### 숫자만 남으면 「6 2 4」로 읽힌다 — 문장은 `aria-label`이 든다

화면을 채널 넷으로 가르면 텍스트 노드에는 숫자만 남는다(아이콘은 `aria-hidden`인 `<svg>`다). 그래서 옛 캡션을 **버리지 않고 자리를 옮겼다**:

```
aria-label="감전 연쇄 · 2 에너지 · ▮▯▯▮ 양 끝 · 피해 6 · 감전 2 · 연쇄 4"
```

`cardCaption`은 이제 보이는 글이 아니라 읽히는 글이다. 이름을 앞에 붙인 것 하나가 달라졌다.

### 부채꼴 — 두 겹, 그리고 축을 계획 값에서 옮겼다

바깥 래퍼가 **자세**(회전·겹침·`z-index`)를, 안쪽 카드가 **모션**(hover 리프트 140ms)을 든다. 이 분리의 유일한 이유는 `ui/motion.css`의 한 줄이다:

```css
@media (prefers-reduced-motion: reduce) { button:active, .choice:hover, .game-card:hover { transform: none; } }
```

한 겹이면 이 줄이 부채꼴을 통째로 편다. **실측으로 확인했다** — 시트에 실린 reduce 규칙 여섯을 미디어 밖에 다시 붙여 보니 래퍼는 `matrix(0.978148, -0.207912, …)`(= `rotate(-12deg)`)로 **그대로**고, 카드의 `transition-property`만 `transform, border-color` → `opacity, border-color, background-color`로 바뀌었다. 체력 채움은 `transform` → `none`, 스프라이트는 `sprite` → `none`. (`aside`의 CDP 프록시가 `Emulation.setEmulatedMedia`를 막아 미디어 에뮬레이션은 못 쓴다 — 규칙을 꺼내 다시 붙이는 쪽이 같은 상태를 만든다.)

기하는 전부 CSS다. React가 넣는 것은 `--i`(인덱스)와 `--n`(손패 수) 둘뿐이다.

**`transform-origin`을 계획의 `50% 320%`에서 `50% 150%`로 옮겼다.** 축이 멀수록 회전이 카드를 **옆으로** 민다(중심 이동 = 축까지의 거리 × sinθ). 320%면 그 거리가 약 420px이라 다섯 장짜리 손패의 양쪽 끝이 ±87px씩 벌어진다 — `.decision-panel`(607px)을 넘어 28px gap을 건너 적 패널을 덮는다. 150%면 거리가 156px이라 ±33px이고, 실측 span은 179~829px(패널 200~807px)로 양쪽 22px씩만 흘러나온다. **호를 만드는 것이 회전 하나라는 계획의 발상은 그대로다** — 그 호의 반지름만 열 폭에 맞춰 줄였다.

겹침은 열 폭에서 역산한다(`max(18px, (--card-w × --n − 100%) / (--n − 1))`). 열 장을 세워 재니 **한 줄**이고 카드 간격 59px, 세로 186px, `overflowX` false다. 격자(`repeat(auto-fill, minmax(96px, 1fr))`)였을 때 열 장은 두 줄 262px이었다.

### 발동 두 단 — 코드 경로는 하나다

```
손패 클릭 → 무대(200ms) → 다음 decision이 target이면 그 자리에서 정지, 아니면 이미 발동
```

`view.card`(id)로 손패에서 그 카드를 찾아 **한 장만 빼고** 무대에 세운다. 손패 키를 `id-index`에서 `id#몇번째사본`으로 바꾼 이유가 이것이다 — 인덱스 키는 한 장이 빠지면 뒤 카드의 키가 전부 밀려 남은 카드가 통째로 퇴장·재등장한다.

**파티클은 「발동하는 클릭」에 튄다.** 클릭 시점에는 어느 쪽인지 모르므로(적이 하나여도 target 단계가 선다 — 실측으로 확인했다) 낸 카드를 `useRef`에 들고, 다음 `decision`이 target이 **아닐 때** 튄다. `card.target`으로 미리 갈라보지 않으므로 엔진과 두 번째 진실이 안 생긴다.

계획이 「무대 대기에 루프 애니메이션을 넣지 마라」고 두 번 적었다 — 넣지 않았다. 정지가 「너를 기다린다」다.

**힌트에서 id가 사라졌다.** 화면에 `card_zeus_01 · 대상을 고르세요`가 뜨던 자리는 이제 무대 카드가 무엇인지 말하고 문장은 「대상을 고르세요」만 남는다. 같은 종류의 버그가 결과 화면에도 있었다 — 「낸 카드」 셋이 `card_athena_02`를 제목으로 달고 있었고, `cardFace`에 이름을 한 줄 넣어 「전하 방벽」이 됐다.

### `popLayout`은 ref 없이 조용히 아무 일도 안 한다

적 퇴장에 `mode="popLayout"`을 걸었는데 실측 `position`이 `relative`였다 — **한 번도 안 돌았다.** `framer-motion`의 `PopChild`가 `cloneElement(children, { ref })`로 노드를 재는데, `EnemyButton`이 그 ref를 안 받으면 측정 대상이 null이라 스타일 주입을 건너뛴다. 경고도 없다.

`ref?: Ref<HTMLButtonElement>`를 받아 `m.button`에 넘긴 뒤 다시 재니 퇴장 중인 노드만 `absolute`다. 그게 없으면 시체가 빈 칸 자리와 **나란히** 서서 패널이 한 줄 늘었다 줄어든다 — 계획이 없애려던 「덜컥」이 두 번 나는 셈이었다.

### 퇴장 중인 버튼은 눌리지 않는다 — 여기서 e2e의 78초가 나왔다

계획의 함정 10은 적 버튼만 적었다. **같은 함정이 손패에도 있었고 그쪽이 훨씬 비쌌다.** 퇴장 애니메이션 중인 노드는 마지막 렌더의 props를 그대로 들고 있다 — 방금 낸 카드는 그때 눌릴 수 있었으니 160ms 동안 `disabled`가 아니다. `tools/e2e.ts`의 드라이버는 「비용이 가장 높은 카드」를 고르므로 **직전에 낸 그 카드**를 다시 집어 클릭하고, 엔진이 안 움직이므로 40틱(1초)을 세고 나서야 다음 후보로 넘어간다.

| 실측(시드 371, 같은 정책) | 결정 | 재시도 | 걸린 시간 |
|---|---:|---:|---:|
| 고치기 전 | 255에서 중단 | **78** | 96초(완주 못 함) |
| `useIsPresent()` 한 줄 뒤 | **330 완주** | **0** | **17초** |

사람에게도 같은 값이다 — 흐려지는 카드를 눌러도 아무 일이 안 일어나던 자리다. 적 버튼과 카드 둘 다 `useIsPresent()`로 막았고, 그것 하나 때문에 `EnemyButton`·`FanCard`를 컴포넌트로 뽑았다(훅은 `AnimatePresence`의 자식 안에서만 부를 수 있다).

### e2e가 화면 문구를 안 읽는다

```js
const cardCost = (button) => Number(button.dataset.cost ?? -1);
const cardDamage = (button) => Number(button.dataset.damage ?? 0);
```

계획의 함정 2 그대로다. 옛 정규식(`/^(\d+) 에너지/`)은 비용이 젬으로 옮겨간 순간 149장 전부 `-1`을 돌려주고도 **실패하지 않는다** — 통과한 게이트가 다른 것을 재고 있게 된다. 값은 `ui/card.tsx`가 관측에서 얹으므로 두 벌이 아니다(`data-damage`는 옛 정규식과 같은 정의: 「피해」+「연쇄」의 합).

선택자도 `.hand button.game-card` → `button.game-card`로 넓혔다. 전투 손패가 `.fan`으로 갔고 무대 카드는 `<article>`(누를 수 없다)이라 버튼만 걸린다.

### 죽은 CSS 규칙을 쓰지 않고 지웠다

계획 §5.1은 `ui/motion.css`의 `.token-badge { transition: transform 160ms, opacity 160ms }`를 「이 절이 비로소 쓴다」고 적었다. **반대로 지웠다.** 그 두 속성을 이제 `motion`이 매 프레임 쓰므로, CSS transition을 같이 걸면 라이브러리가 쓰는 값마다 160ms 지연이 붙어 등장·퇴장이 뭉개진다. 한 속성에 두 주인을 두지 않는다 — reduced-motion 목록에서도 같이 뺐다(배지는 `useReducedMotion()`으로 스스로 멈춘다).

## 계획과 어긋난 것

| 계획 | 실제 | 왜 |
|---|---|---|
| `transform-origin: 50% 320%` | **`50% 150%`** | 320%는 다섯 장 손패를 ±87px 벌려 적 패널을 덮는다. 호를 회전 하나로 만드는 발상은 그대로다 |
| 사거리는 채널 표에 없다 | **효과 줄 맨 앞에 남겼다** | 마스크를 적은 26장이 「어느 칸에 닿나」를 잃는다([R-35](35-range.md)) |
| 죽은 `.token-badge` transition을 쓴다 | **지웠다** | 같은 속성에 `motion`과 CSS transition 두 주인이 붙으면 뭉개진다 |
| 손패 재배치 200ms(`layout`) | **안 붙였다** | 계획의 함정 13이 같은 문서에서 금지한다 — 래퍼의 `rotate`와 `layout`의 transform이 같은 요소에서 겹친다. 부채꼴은 CSS가 즉시 다시 눕고, 등장·퇴장만 흐린다 |
| `test/ui.test.ts` — 퇴장 중인 적 버튼이 `disabled` | **브라우저에서 봤다** | vitest 환경이 node뿐이라(jsdom 없음) 퇴장 수명주기를 렌더할 수 없다. 대신 실제 런에서 죽음 3회·시체 관측 18회 전부 `disabled`(그리고 `position: absolute`)를 확인했다 |
| 「효과문에서 「에너지」가 사라진다」 | **비용 앞머리만 사라졌다** | `energy` op 10장의 「에너지 2」는 **얻는 값**이다. 비용은 젬 하나뿐이므로 두 표기가 겹치지 않는다 |

## 남은 것

1. **결과 화면이 105px 스크롤된다.** 낸 카드 셋이 140px 고정 폭이 되며 `.used-cards`가 `repeat(3, 1fr)` 격자에서 `flex-wrap`으로 바뀌었다(계획 함정 4) — 1040px에서는 세 장이 한 줄에 들어가지만 카드가 50px 높아졌다. 요약 칸·지도 둘·기록이 이미 875px을 쓰는 화면이라 다음에 손대는 쪽은 카드가 아니라 그 배치다
2. **열 장 손패의 오른쪽 끝이 적 패널 테두리를 6px 덮는다**(span 841 vs 패널 835). 카드가 위에 그려지고 `overflowX`는 false다. 손이 열 장까지 가는 것이 흔해지면 총 각도(`34deg`)를 줄이는 자리
3. **열 장 손패에서 이름이 잘린다** — 겹침이 116px이라 젬과 첫 효과 숫자만 남는다. 계획의 「다음 자리 3 · 카드 확대 보기」가 그 근거를 얻었다
4. **효과 넷인 카드 4장(융합)은 효과 줄이 두 줄로 접힌다.** 그 카드만 이웃보다 ~20px 길어 부채꼴에서 아래로 처진다. 융합은 런당 한 장이라 그대로 뒀다
5. **`aside repl`에 서버측 120초 상한이 있다.** 이번에 17초로 내려왔지만 결정 수가 두 배가 되면 다시 만난다 — 그때는 드라이버를 `window.__e2e`에 심어 둔 채 `aside repl`을 여러 번 부르는 쪽으로 쪼개면 된다(탭은 호출 사이에 살아 있다)
6. 계획의 「다음 자리」 넷은 그대로 남는다: 드래그로 내기 · 공격/스킬 타입 칩 · 카드 확대 보기 · **적 턴이 한 프레임에 끝난다**(가장 큰 학습비용이고 연출로는 못 고친다 — `playEncounter`가 적 행동 사이에 `yield`를 안 한다)
