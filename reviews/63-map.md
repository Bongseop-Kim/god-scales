# R-63 · 지도 화면 — 확대 · 마커 · 군더더기 제거

[P-63] 수행 결과 · 관련 [R-42](42-mapwalk.md) · [R-54](54-statusbar.md) · [art/ui/marker.md](../art/ui/marker.md)

## 결론

**통과 · 완료 정의 전부 충족.** 판이 520 → 760px, 칸 48 → 72px, 마커 16 → 32px이 됐고 화면에
남은 글자는 층 번호와 칸 이름뿐이다. 규칙·값·데이터·봇·관측 불변 — 만진 것은 CSS 여덟 줄과
`map.tsx`의 화면 조립뿐이다. **계획에서 한 곳 벗어났다**(§주의 1: `<h2>`를 통째로 못 지운다).

## 한 일

### 1. 판을 키웠다 (`ui/style.css` — `.walkable`만)

| 자리 | 지금 | 실측 |
|---|---:|---:|
| `.map-panel.walkable` 폭 | 760 | 760 |
| `.map-wrap` 폭 | 760 | 760 |
| 칸 | 72px 높이 | 200×72 |
| 칸 아이콘 | 28 | 28 |
| 칸 이름 글자 | .74rem | — |
| 층 번호 열 | 64 | — |
| 마커 | 32(정수 2배) | 32×32 |

`.prop.boss-signal`의 `right`는 **`-72px` → `-56px`**이다. 판이 커지며 좌우 여백이 260 → 140px로
줄어 `-72px`면 신호 프롭이 `.prop.flank.right`(셸 끝 36px, 96px 스프라이트)와 가로로 겹친다.
`-56px`이면 둘의 왼쪽 끝이 1108px로 같고 세로가 갈린다(신호 202~250 · 원경 342~438).

`art/ui/marker.md`의 「주의」 첫 줄은 **두 크기를 다 적도록** 고쳤다 — 결과 화면은 여전히 16px
원본이고 경로 화면만 32px이다. 2배·3배 외 배율 금지도 같이 적었다(1.5배는 `pixelated`로도 뭉갠다).

### 2. 글자 셋을 뺐다 (`ui/screens/map.tsx`)

- **`.node-hint` 줄 삭제** → `text` prop · `pointed` 상태 · `onPointerEnter/Leave/Focus/Blur` 넷이
  같이 죽었다. `style.css`의 `.node-hint` 규칙도 지웠다. `view.text`는 엔진에 그대로 남는다
  (**관측 불변**) — 화면이 그것을 안 읽을 뿐이다.
- **`nodeDetail` 표는 남았다** — `aria-label`이 계속 「왼쪽 · 쉼터 · 체력을 회복하거나 카드를
  지웁니다」를 읽는다. 접근성은 안 깎았다.
- 화면에 남은 글자를 실측으로 셌다: `6층|보스|5층|예고|전투|쉼터|…|1층|전투|전투|전투|시작`.
  제목 줄도 설명 줄도 없다.

### 3. 지나온 자리는 막힌 자리가 아니다

`.map-node:disabled { cursor: default; }` 한 줄. 실측 `disabledCursor: "default"` — 지금 서 있는
칸·시작 칸·잠긴 칸 전부에서 금지 커서가 안 뜬다. `disabled` 자체는 그대로 뒀다(테스트·e2e 계약).

### 4. 화려하게 — 새 에셋 0

판에 `.decision-panel.solo`와 **같은** 케니 청동 9-slice(`panel-border-007-bronze.png`)를 둘렀다.
열린 칸 셋은 `box-shadow` 1px inset → **청동 2px inset + 14px 바깥 발광**이다(실측
`rgb(198,169,105) 0 0 0 2px inset, rgba(198,169,105,.38) 0 0 14px`). 종류별 색은 그대로고,
칸이 커진 만큼 저절로 더 보인다. 연결선·미니맵·스크롤은 안 만들었다.

### 5. 마커를 천천히 걷게 했다

`markerTransition` `0.24s` → `0.5s`. 곡선은 그대로다.

## 벗어난 곳 · 남긴 것

### 주의 1 — `<h2>`는 **읽는 격자에만** 남겼다 (계획과 다름)

계획 §2는 「`<h2>` 삭제」다. 그런데 그 `<h2>`는 `MapPanel` 안에 있고 **결과 화면이 같은
`MapPanel`을 두 번 쓴다**(`result.tsx:49`). 통째로 지우면 결과 화면의 두 격자가 나란히 선 채
**이름을 잃는다** — 어느 쪽이 저승인지 말할 것이 그 줄뿐이다. 계획의 완료 정의(「결과 화면의 두
격자는 눈에 띄는 변화가 없다」)와 정면으로 부딪친다.

그래서 `{!onEnter && <h2>…</h2>}`로 걸었다. 경로 화면(`walkable`)에서는 사라지고 결과 화면에서는
**한 글자도 안 바뀐다**. 실측: 결과 격자 둘이 `지하 6층 × 3갈래` · `지상 6층 × 3갈래`, 폭 197px,
칸 30px, `walkable` 없음 — 계획 전과 같다.

### 주의 2 — hover가 「밝기만」이 아니다 (판단 필요)

계획 §4는 「hover는 밝기만 올린다」고, 근거로 「지금 `box-shadow` 1px inset뿐이다」를 든다.
**그 전제가 틀렸다.** `ui/motion.css:116`이 이미 `.map-node:not(:disabled):hover`에
`translateY(-2px)`를 걸고 있다 — `.choice`·`.game-card`와 **한 규칙을 나눠 쓰는** 줄이고,
`@media (hover: hover) and (pointer: fine)` 안이다.

계획이 든 이유(「크기·여백을 바꿔 이웃 칸을 밀지 않는다」)는 그 2px이 **이미 만족한다** —
`transform`이라 레이아웃을 다시 안 잡는다. 실측으로 확인했다: hover 중 이웃 칸 스무 개의
`getBoundingClientRect`가 한 픽셀도 안 움직이고, 움직이는 것은 가리킨 칸의 `transform` 하나다
(UI.md 「hover 반응은 `transform`만」이 정확히 이 꼴이다).

**그래서 2px을 안 지웠다.** 지우면 지도만 게임의 다른 클릭 면과 다른 반응을 하게 되고, 그것은
계획이 몰랐던 사실 위에서 내리는 새 디자인 결정이다. 지금은 **청동 밝기 1.3 + 기존 2px**이다.
「정말로 밝기만」이 맞으면 `motion.css:116`의 선택자에서 `.map-node:not(:disabled):hover`만
빼면 된다 — 한 줄이다.

### 죽은 단언 하나를 지웠다

`test/ui.test.ts`의 「결과 화면에 `node-hint`가 없다」는 이제 **어디에도** `node-hint`가 없어
영원히 통과한다. 같이 붙은 주석도 없어진 「설명 줄」을 가리키고 있었다. 단언을 빼고 주석을
크기 이야기로 고쳤다 — 남은 `walkable` 단언이 「결과 격자는 30px 그대로」를 계속 지킨다.

**마커 0.5s가 완주 시간에 미치는 영향: +2.5초** (0.24s에서 24.6초 → 0.5s에서 27.2초, 같은 기계
연속 측정). 층당 0.26초 × 12층 = 3.1초라는 계획의 예측과 맞고, e2e에 시간 여유가 있다.

1440×900 실측에서 판은 `left 340 · right 1100`, `overflowX: false`, 세로도 안 넘친다(저승 1층이
가장 높은 화면이고 시작 줄까지 624px).
