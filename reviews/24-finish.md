# P-24 리뷰 · 공개 배포 완주와 마감

`reviews/24-finish.md` · [◀ P-23](23-round6.md) · [색인](00-index.md)

판정: **완주는 됐다. 공개 URL 갱신과 "매일"은 안 됐다.**

배포 산출물(`dist/`)을 브라우저로 **12층 완주**하고 반출 → CLI 재생 일치까지 통과했다. B-0 4번의 실질은 여기서 닫혔다. 남은 두 조각은 커밋·푸시 금지 지침과 Aside 앱 의존 때문에 이번 턴에 못 한다 — 아래에 그대로 적는다.

## 완주 — 정책부터 바꿔야 했다

기존 `tools/e2e.ts`는 시드 56에서 "누를 수 있는 **마지막** 카드"를 눌렀다. P-19가 이미 "자동 클릭은 최악의 정책"이라고 적었고, P-22로 콘텐츠가 바뀐 뒤에는 **400시드 중 완주가 하나도 없었다.** 완주하지 못하면 결과 화면과 반출 버튼을 지나지 못하므로 그 E2E는 B-0 4번을 증명할 수 없다.

정책을 화면에 적힌 것만 쓰는 최소한의 규칙으로 바꿨다. **룰 봇을 브라우저로 옮겨 심지 않았다** — 두 번째 진실이 생긴다.

| 결정 | 규칙 | 화면에서 읽는 것 |
|---|---|---|
| 갈림길 | 쉼터가 있으면 쉼터 | `button.choice.rest` |
| 휴식 | 첫 번째만 카드 제거, 이후 회복 | 버튼 순서 |
| 요구 | 수락 | 첫 버튼 |
| 표적 | 체력이 가장 낮은 적 | `.hp small` |
| 카드·보상·은총·제거 | 비용 최대 → 표시 피해 최대 → 카드 id | 캡션 `"2 에너지 · 피해 9 · 방어 3"` |

동점 처리를 카드 id까지 내려 전순서로 만들었다 — DOM 순서에 기대면 재현이 깨진다.

이 정책으로 400시드 중 완주가 **다섯**이다(51 · 69 · 141 · 162 · 291). 가장 짧은 141을 골랐다.

## `--dist` — dev 번들로는 반쪽이었다

기존 E2E는 `npx vite`(dev 서버)를 띄웠다. B-0 4번은 "**배포본**으로 1런 완주"라 공개 URL에 올라가는 것과 같은 파일을 눌러야 한다. `--dist`를 붙여 `vite preview`로 `dist/`를 띄우게 했다.

**dev와 dist 결과가 완전히 같다** — 503결정, 최종 체력 16, 호의 [34, 92]. 번들링이 게임을 바꾸지 않는다는 증거다.

## 1440×900 레이아웃 — 실제 결함이 있었다

P-19가 "본문이 좌측 컬럼에 몰리고 우측이 비어 있다"고 적어둔 자리를 쟀다.

Aside가 CDP `Emulation.setDeviceMetricsOverride`를 막아 뷰포트를 강제할 수 없었다. 앱 창이 마침 1440×900이라 그대로 쟀고, `.shell`이 `min(1040px, 100% - 32px)`로 고정되므로 **뷰포트가 1072px 이상이면 안쪽 배치는 폭과 무관하게 같다.**

별도 스크립트를 만들지 않았다 — E2E 드라이버가 이미 여덟 화면을 다 지나므로 거기서 한 번씩 기하를 재게 했다(단독 스크립트는 한 evaluate가 30초 CDP 한도를 넘어 죽었다).

| 화면 | 전 | 후 |
|---|---|---|
| card · target | enemy-panel 405 · decision-panel 607 | 그대로 |
| path | map-panel 405 · decision-panel 607 | 그대로 |
| demand · rest · rest_card · grace | decision-panel 1040 | 그대로 |
| **reward** | **decision-panel 405** | **1040** |

`RewardScreen`이 `shell run-layout`(2열 격자)에 패널을 하나만 놓아 **오른쪽 607px가 통째로 비어 있었다.** 휴식·요구·은총과 같은 1열(`shell`)로 고쳤다. 클래스 한 단어다.

폭 0짜리 자식은 없으므로 처음 만든 검사는 이걸 놓쳤다. `twoColumn && cols.length < 2`를 추가해 잡는다 — 이제 여덟 화면의 가로 넘침과 빈 칸이 E2E 게이트다.

## 안 한 것 — 그리고 왜

- **공개 URL 갱신.** 지금 올라간 번들은 P-21 시점이라 6회차 콘텐츠(P-22의 카드·요구·신 어휘)가 없다. 200은 반환하지만 **그 화면으로 도는 완주는 옛 게임의 완주다.** `main` 푸시가 워크플로를 돌리는데 커밋·푸시는 사용자가 그 턴에 지시할 때만 한다(CLAUDE.md)
- **"매일 재확인".** 최종 게이트가 Aside 앱을 요구해 GitHub Actions에서 못 돈다. 지금은 배포 직전 수동 실행이다. **매일 돌지 않으므로 매일 돈다고 쓰지 않았다.** 자동화하려면 헤드리스 브라우저를 붙이거나, 매일 도는 것을 브라우저 없는 `npm run sim -- --replay`로 낮춰야 한다
- **반출 런을 `logs/human/`에 넣기.** DEPLOY.md가 그렇게 적어뒀지만 넣지 않았다 — 그 폴더는 사람 플레이테스트 집계이고 E2E는 자동 클릭 정책이다. 섞으면 전역 파라미터 조정의 근거가 오염된다. DEPLOY.md에 그 구분을 적었다
- **스프라이트·사운드·일러스트 15장.** 다른 장비에 있어 이번 범위 밖(사용자 지시)
