# R-64 · 대신 맞기가 보이게 · 빈 손패가 판을 안 흔들게

[P-64] 수행 결과. 규칙·값·데이터는 한 글자도 안 바뀌었다 — `npm run sim` 기준선이 `win_rate=0.545`로
계획 전과 같다. `guardFor`의 세 규칙(1회 재지정 · 사거리 안 · 광역 제외)도 그대로다.

## 한 일

### 1. 재지정을 사실로 남긴다 (`core/state.ts` · `core/combat.ts` · `core/rules.ts`)

`CombatState`에 `guarded: { by, from }[]` 한 칸. `playCard` 진입에서 **새 배열로 갈아 끼우고**(비우지
않는다 — 관측이 지난 배열을 그대로 들고 있다), `executeCard`의 피해 한 줄이 `aim()`을 지난다.
`aim`은 `guardFor`를 부르고 **반환값이 원래 대상과 다르면** 기록한다 — `guardFor` 자체는 안 건드렸다.

`turnPlays`와 같은 꼴의 파생 기록이다. 규칙이 이것을 읽고 분기하는 자리는 없다.

### 2. 관측에 싣는다 (`sim/engine.ts`)

새 `seq`는 안 만들었다 — 재지정은 언제나 피해와 같은 프레임에 온다.

**계획에 없던 한 줄이 여기 붙었다.** `hits`는 새 피해가 날 때까지 프레임에 남으므로, 관측이
`state.combat.guarded`를 그대로 실으면 **적 턴 피해 프레임에 지난 카드의 재지정이 따라온다** —
화면이 적의 공격에 지킴이를 내보낸다. 그래서 `recordHits` 안에서 출처가 `attack`·`card`일 때만 싣고
나머지 출처(`favor`·`enemy`)에서는 빈 배열이다. 재지정이 플레이어 카드에서만 난다는 사실이
관측 쪽에도 한 번 적힌 셈이다.

### 3. 연출 — 800ms 한 동작 (`ui/screens/combat.tsx`)

`view.hitSeq` 이펙트 안, 피격 연출 **앞**이다. 전진 260 · 버팀 240 · 복귀 300.
거리는 `(from.slot − by.slot) × 180 − 부호 × 40`이다 — 칸 간격이 CSS 상수라 DOM을 안 잰다.
「보호」 글리프(`icons.svg`의 `guard`)는 원래 대상 판에 `absolute`로 붙였다 지운다(`playSprite`와 같은 꼴).

맞은 쪽 플래시·셰이크·피해 팝은 재지정이 있을 때만 260ms 늦는다. 힌트 줄에 「〈이름〉이 대신
맞았습니다.」가 서고 — 이름이 데이터에서 오므로 조사는 받침으로 고른다 — `prefers-reduced-motion`에서는
이펙트가 초입에서 반환하므로 **문장만 남는다.**

재지정이 둘 이상이어도 한 번 나가서 한 번 버틴다(`view.guarded[0]`).

### 4. 빈 손패가 자리를 지킨다 (`ui/style.css`)

`.fan { min-height: 206px }`. 206 = 카드 높이 180 + 위아래 여백 26이다.

## 실측에서 고친 것 · 알게 된 것

**하나. 셰이크가 미끄러짐과 같은 채널이다.** 피격 셰이크(`translate: -4px → 4px → 0`)를 나가 있는
지킴이에게도 걸면 뒤에 시작한 애니메이션이 이겨 **버팀 200ms 동안 제자리로 튕긴다**(실측:
버팀 시점 translate가 287px에서 −2.9px로). 지킴이만 셰이크를 뺐다 — 계획의 「그 자리에서 흰 플래시」가
글자 그대로 맞는 자리였다.

**둘. 카드 높이가 하나가 아니다.** 계획은 `--card-w`가 고정이니 높이도 고정이라고 봤지만, 효과문이
한 줄이면 157 · 두 줄이면 180이다(3판 364프레임에서 이 둘뿐). 그래서 min-height를 **최댓값**으로 박았다 —
0장 붕괴만이 아니라 「짧은 손 ↔ 긴 손」 23px 흔들림도 같이 닫혔다. 손패 5·6·8장 어디서나 부채꼴은 206이다.

**셋. 피해 팝이 이 빌드에서 안 뜬다 — P-64 이전부터다.** `.damage-pop`은 DOM에 서고 값(-3)도 맞는데
인라인 `opacity: 0`에 `getAnimations()`가 0이고 800ms를 그대로 있는다. **`delay`를 뺀 원래 줄
(`transition={damagePop}`)로도 같다** — 재지정 없는 평범한 타격에서도 같으므로 이번 변경의 것이 아니다.
같은 페이지에서 다른 motion 애니메이션은 돈다(부채꼴 래퍼 opacity 0 → 1, `document.getAnimations()` 12).
그래서 「피해 팝이 지킴이 도착 뒤에 뜬다」는 **배선만 확인했고 화면으로는 못 봤다**(아래 남은 자리).

실측은 지킴이 편성(`enemy_under_guardian`@1 · `enemy_under_pressure`@2 · `enemy_under_zealot`@3)을
브라우저에서 실제로 만나 뒷칸을 때려서 봤다:

- 지킴이 `translate` 41px(140ms) → 288px(320ms, 목표 칸 40px 앞) → 110px(620ms, 복귀 중), 800ms 하나.
- 「보호」 글리프는 **원래 대상 판 안**이다(`markParent=enemy_under_zealot`), 48×53에 대상 칸 중앙,
  버튼 위 92px, 520ms에 opacity 1.
- 힌트 줄 「스파르토이 방패병이 대신 맞았습니다.」 · 능력 칩이 보호 2 → 1.
- 부채꼴: 카드 있을 때와 없을 때 `.fan` 206 · `.hint` top 647 · `.stage-field` bottom 647 — **한 픽셀도 안 움직인다**
  (고치기 전에는 180px 밀렸다).

카드 하나로는 안 나온다는 것도 실측이 알려줬다 — 첫 시도가 `card_zeus_18`(사거리 `03`)이라 칸 1의
지킴이를 **지나갔다.** 사거리 규칙이 화면에서 그대로 보이는 자리다.

## 안 한 것

- 적의 공격에는 재지정이 없다 — 규칙이 그렇다. 화면에 없는 것을 그리지 않았다.
- 새 `seq`·재지정 로그·저널·전용 스프라이트 없음. `.combat-bottom` 격자 구조도 그대로다.
- 피해 팝 자체는 고치지 않았다 — P-58의 자리고 이 계획의 범위가 아니다.

## 남은 자리

- **피해 팝이 안 뜬다**(위 §셋). motion 키프레임 배열 + `key` 리마운트 조합이 의심되지만 좁히지
  않았다. 이것이 살아나면 P-64의 260ms 지연도 같이 보인다.
- **쓰러진 지킴이는 안 나선다.** 대신 맞고 죽으면 관측의 `enemies`에서 빠져 칸을 못 구하므로 미끄러짐이
  붙지 않는다(퇴장 연출과 힌트 줄만 남는다). 죽는 프레임에 800ms를 더 얹는 것이 더 나쁘다고 봤다.
- **이동 중에는 체력바·칩이 이웃과 겹친다.** 배우 판 전체가 움직이므로 800ms 동안 앞칸의 바와 겹쳐
  선다. 스프라이트만 떼어 움직이려면 배우 판을 두 겹으로 갈라야 하고, 그건 P-55의 칸 배치를 다시 여는 일이다.
