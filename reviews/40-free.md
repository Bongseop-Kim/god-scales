# R-40 · 자유 모드

[색인](00-index.md) · 계획 `plans/40-free.md`(삭제됨) · [◀ R-39](39-tier.md) · [◀ R-38](38-patron.md)

## 결론

**통과 · 완료 정의 전부 충족.** 시작 덱 열 장을 사람이 짜고, 그 런이 반출·재생되며, `tune`은 그 모드를 한 번도 안 본다.

격리의 증거는 계획이 요구한 그대로 **`tune` 수치가 P-39와 한 자리도 안 움직였다**는 것이다:

| 지표 | R-39 배포본 | 이번 회차 |
|---|---:|---:|
| 승률(3000런 층화) | 0.424 | **0.424** |
| 조합 표준편차 | 0.188 | **0.188** |
| 변동계수 | 0.444 | **0.444** |
| 최저 셀(ε=0) | 0.140 | **0.140** (athena+ares) |
| 하한 0.05 | 통과 | 통과(최저 0.060) |
| ⚠ 평평한 조합 | 0 | 0 |

한 자리도 안 움직인 이유는 코드에 분기가 없어서다. **엔진에 모드 플래그를 안 만들었다** — `runSteps(seed, scenario, patrons, startingDeck?)`의 넷째 인자가 전부고, 안 넘기면 기본값이 규칙 덱이다. `tune`·`sim`·`heatmap`이 그 인자를 안 넘기므로 **호출부가 곧 제외**다. `--free` CLI 옵션도 안 만들었다: 만드는 순간 누군가 그걸로 게이트를 돌린다.

| 완료 정의 | 판정 |
|---|---|
| 편집 | ✓ 열 장. 중복 허용·상한 없음·신 무관. 아홉 장이면 「런 시작」 `disabled`(e2e가 실제로 지난다) |
| 기본값 | ✓ 편집기가 규칙 덱으로 차 있다. e2e가 슬롯 열 칸을 읽어 `ruleDeck(["zeus","athena"])`와 대조한다 |
| 격리 | ✓ `tune` 여섯 지표 불변(위 표). `sim` 200런 `win_rate=0.385`, 동결 버전 `v8`/`v9` 그대로 |
| 반출·재생 | ✓ 자유 덱 런의 JSON에 `deck`이 실리고 CLI가 `substituted=0`으로 재생한다. `deck` 없는 옛 파일은 규칙 덱으로 돈다 |
| 입력 검증 | ✓ `readReplay`가 던진다 — 길이·미지의 id·융합·tier2·배열 아님 여섯 경우 |
| 게이트 | ✓ 하한 하나 그대로. 자유 모드용 지표를 **하나도 만들지 않았다** |

## 계획과 다르게 한 것 셋

### 1 · 「119장」이 아니라 **tier1 124장**이다

계획 §2가 「배포된 patron 카드 119장 안에서만」이라 적었는데 실측은 다르다: patron 카드는 **139장**(tier1 124 + tier2 15)이고 융합이 10, 합이 149다. 119는 P-35·P-36의 자리 조건 카드 5장과 P-39의 tier2 15장이 빠진 옛 숫자다([R-39](39-tier.md)가 이미 「계획은 119라 적었다 — 124다」로 고쳐 뒀다).

계획이 예고한 대로 P-39가 선 지금은 그 문장이 **곧 「tier1만」**이다. 필터 한 줄이 셋을 동시에 만족한다:

```ts
cards.filter((card) => card.patron === god && (card.tier ?? 1) === 1)
```

- `card.patron`이 융합 10장을 뺀다 — 융합에는 `patron`이 없고 `patron_pair`만 있다
- `(card.tier ?? 1) === 1`이 tier2 15장을 뺀다
- **`rewardOffer`가 쓰는 것과 같은 표현이다**(`sim/engine.ts`) — 등급 규칙이 두 벌이면 「보상에는 나오는데 편집기에는 없다」가 생긴다

`cardTier`(`tools/value.ts`)를 안 부른 이유는 인자 모양이 다르기 때문이다. 그쪽은 **원시 데이터**의 `patron_pair`(스네이크)를 읽는데 엔진의 카드는 이미 `patronPair`(카멜)로 변환된 뒤다 — 그대로 넘기면 융합 열 장이 조용히 tier1로 읽혀 시작 덱에 들어간다. 값 밴드가 아니라 소속을 묻는 자리라 필터가 맞다.

### 2 · 열한째 장은 **가장 오래된 것을 밀어낸다** — 「먼저 빼세요」가 아니다

계획은 상호작용을 안 적었다. 처음엔 「열 장이 차면 목록 전체를 `disabled`」로 짰는데, 그러면 한 장 바꾸려고 슬롯을 먼저 눌러야 하고 화면 절반이 회색이 된다. [P-38](38-patron.md)의 조합 토글이 이미 같은 문제를 풀어 뒀다 — 「셋째를 누르면 가장 오래된 것이 빠진다」. 같은 꼴을 그대로 쓴다:

```ts
onSelect={(id) => onChange([...deck, id].slice(-deckSize))}
```

부수 효과가 둘 있다. 덱은 **언제나 열 장 이하**라 `disabled`가 붙는 자리는 시작 버튼 하나로 남고(`test/ui.test.ts`의 「이 화면에서 `disabled`가 붙는 자리는 그것 하나뿐이다」가 그대로 산다), e2e가 같은 카드를 열 번 눌러 「중복 열 장」을 한 동작으로 증명한다.

### 3 · e2e는 「첫 전투까지」가 아니라 **1층에서 끝나는 런**이다

계획 §5는 「첫 전투까지만 가고 → 반출」이라 적었는데 **그 순서로는 못 짠다**: 반출 버튼은 결과 화면에만 있다. 전투 도중에 반출할 방법이 없으므로 「완주는 안 한다」와 「반출을 본다」를 같이 만족하는 유일한 길은 **빨리 끝나는 런**이다.

열 장을 아테나 「꿰뚫는 창」(사거리 `12` — 앞뒤 칸에 못 닿는다)으로 채우면 시드 371이 1층에서 끝난다. **24결정**이고, 같은 시드의 고정 모드 완주는 330결정이다. 「12층을 두 번 걷지 않는다」는 지켜졌다.

같은 브라우저 세션에서 「다시 시작」으로 돌아가 이어 붙였다 — `aside repl`을 두 번 띄우지 않으므로 e2e 전체 시간이 사실상 안 늘었다. 드라이버는 페이지의 `window.__e2e`에 남아 있고 `restart()`가 결정열만 비운다.

카드 id를 브라우저 스크립트에 박지 않고 **Node에서 `deckOk`로 먼저 검사한 뒤 주입**한다. 데이터가 그 카드를 지우거나 tier2로 올리면 브라우저를 띄우기 전에 던진다 — 조용히 다른 것을 재는 대신.

## 저울은 한 줄도 안 썼다 — 화면이 그 규칙을 처음 적는다

계획 §3이 옳았다. 「조합을 맞출까 좋은 카드를 넣을까」의 대가는 이미 코드에 있다:

- `recordCardFavor`는 어느 신의 카드든 그 신에게 +1을 주지만, 은혜·개입·합성이 전부 `patrons`만 읽는다(R-26) — **조합 밖 신의 호의는 아무것도 움직이지 않는다**
- `finishCombatFavor`가 조우마다 후원 신 호의를 −3 하고, 그 조우에 한 장도 안 쓴 신에게 −2를 더 깎는다

즉 이방 카드로 채우면 조우마다 −5씩 새고 은혜가 안 온다. **규칙 코드는 한 줄도 안 바뀌었다.** 이 계획이 한 일은 그 문장을 편집기에 적고(`ui/app.tsx`의 힌트 한 문단), 조합 밖 신의 슬롯에 「호의 안 오름」을 붙인 것뿐이다 — 색이 아니라 글자다(R-26의 채널 규칙).

## 배선

| 자리 | 무엇 |
|---|---|
| `sim/engine.ts` | `deckSize` · `ruleDeck(patrons)` · `startableCards`(신별 tier1) · `deckOk` · `runSteps`/`run`에 `startingDeck?` |
| `sim/replay.ts` | `ReplayFile.deck?` · `readReplay`가 `deckOk`로 던진다 |
| `sim/runner.ts` | `--replay`가 `replay.deck`을 같이 넘긴다 |
| `ui/export.ts` | 규칙 덱과 **순서까지** 같으면 `deck`을 안 적는다 |
| `ui/app.tsx` | `DeckEditor`(접힌 `<details>` · 슬롯 10 · 신 탭 다섯 · 이방 표시 · 시작 가드) · `cardIndex` |

| `tools/e2e.ts` | 자유 모드 체크포인트 · `exportReplay`/`restart` 추출 · 접힌 시작 화면 높이 |
| `test/free.test.ts` | 여섯 |

**엔진 규칙·데이터·봇·게이트·동결 버전은 한 줄도 안 바뀌었다.** `data/`는 손대지 않았고 `globalParamVersion=v9`·`botPolicyVersion=v8` 그대로다.

### 새 컴포넌트 0

카드는 `CardRow`/`GameCard`를 그대로 쓴다 — 보상 화면과 같은 그림이다. 접힘은 `<details>`, 신 탭은 조합 선택의 `.god-legend` 버튼 줄을 재사용했다. **그 재사용이 e2e를 한 번 깼다**: `.god-legend button` 다섯을 세던 조합 선택 검사가 열을 세고 편집기의 활성 탭까지 「고른 신」으로 읽었다. 접근 이름(`[aria-labelledby='patron-pick']`)으로 좁혀 고쳤다 — 클래스가 아니라 의미로 집는다.

### 값의 출처

시작 화면에는 관측이 없다. UI가 `data/cards.json`을 직접 읽으면 같은 사실에 두 경로가 생기므로(`ui/card.tsx`의 규칙), **엔진이 `CardView`로 내보낸 `startableCards`**를 쓴다. 신별로 갈라 내보내는 이유는 편집기가 다섯 탭이어서다 — 화면이 다시 `patron`으로 나누면 그것이 두 번째 진실이다.

## 검증

```
npx tsc --noEmit          통과
npm test                  22파일 134테스트 통과 (새 6)
npm run tune              하한 0.05 통과 · P-39와 여섯 지표 전부 동일
npm run sim               200런 win_rate=0.385 · v8/v9
npm run e2e               고정 330결정 완주 + 자유 24결정, 전부 ok
```

e2e가 새로 잠근 여섯 줄:

```
ok  조합 선택 = {"gods":5,...,"tall":false}          ← 접힌 편집기가 지키는 한 눈금(1440×900)
ok  편집기 기본값 = {"collapsed":true,"ruled":[...]}  ← 접힘 기본 + 슬롯 열 칸이 규칙 덱
ok  열 장이 아니면 시작 못 함 = {"count":9,"blocked":true}
ok  짠 덱 = {"deck":[꿰뚫는 창 ×10],"ready":true}
ok  고정 모드 반출에 deck 없음 = undefined            ← 기준선이 안 움직이는 이유
ok  자유 덱 재생 = {"substituted":0,"won":false}
```

`test/free.test.ts` 여섯: 열 조합 × 자유 덱 시작(이방 카드 열 장 포함) · 규칙 덱을 손으로 넘기면 결과 객체가 통째로 같다 · `deck` 없는 옛 파일은 규칙 덱 · 반출→재생 왕복과 「같으면 안 적는다/순서가 다르면 적는다」 · 잘못된 덱 여섯 경우 반려 · **파워 카드 덱이 1층에서 안 터진다**.

마지막 것이 계획의 함정 하나였다. 규칙 덱은 attack·defend·utility 태그만 뽑으므로 파워가 시작 덱에 든 적이 없다 — `firePowers`가 1층부터 도는 경로가 이번에 처음 열렸다. 배포된 파워 카드 전부를 열 장씩 채워 돌렸고 크래시는 없다.

## 남은 자리

1. **획득의 자유.** 보상 풀은 여전히 `patrons`만 본다 — 자유는 **시작 덱뿐**이다. 여는 순간 조합 선택이 장식이 되므로, 저울(§3)이 실제로 결정을 만드는지 본 뒤다
2. **덱 프리셋.** 만들지 않았다. 반출 JSON이 이미 덱을 들고 있으므로 그 파일이 곧 프리셋이다
3. **자유 모드 통계.** 만들지 않는다. 게이트를 하나로 두는 이유가 그것이다(CLAUDE.md)
4. **CLI 자유 모드.** `sim/play.ts`는 시드만 묻는다 — 덱을 물으면 파이프 입력의 자리 수가 바뀌어 기존 스크립트가 다 깨진다
5. **편집기는 `data/cards.json`의 카드 수에 비례해 무거워진다.** 지금은 탭 하나에 23~31장이라 문제가 없지만, 신별 카드가 두 배가 되면 목록 가상화가 필요해진다. 그때까지는 `loading="lazy"` 하나로 충분하다
