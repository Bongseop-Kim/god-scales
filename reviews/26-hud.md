## 결론

**통과 · 완료 정의 여섯 중 여섯 · 체크리스트 둘은 근거가 없어 안 만들었다.** 전투 화면이 이제 토큰을 배우 위에 얹고, 진영을 색과 채움으로 갈고, 패시브를 이름 옆에 세우고, 파워와 후원 둘의 우호도를 상시로 든다. 여덟 화면이 같은 머리글 눈금을 쓰고 1440×900에서 세로가 **975px → 900px**로 들어왔다.

| 확인할 것 | 결과 |
|---|---|
| 1 · 토큰이 배우 위에 뜬다 | 통과 — `.actor-tokens`가 적 버튼 첫 행과 `.player-actor` 첫 줄이다. 텍스트 줄에서 빠졌다 |
| 2 · 진영이 색으로 갈린다 | 통과 — 테두리·채움이 `harmfulTokens`에서 온다(해로움 파랑 채움 / 이로움 노랑 외곽) |
| 3 · 패시브가 이름 옆에 상시 | 통과 — `.enemy .name` 안 알약 배지 |
| 4 · 복합 의도 | 통과 — 토큰 이름을 한글로 바꿨다(영문 id였다). 한 줄에 붙어 선다 |
| 5 · 후원 둘의 우호도 | 통과 — 미터 둘 상시, 경계는 `favorBoundaries`, 진노는 경고색 |
| 6 · 여덟 화면 한 눈금 | 통과 — `.run-header` 하나로 여덟이 같은 제목·여백을 쓴다(`npm run e2e -- --dist`가 여덟을 다 잰다) |

`npx tsc --noEmit` 통과 · `npm test` **91**통과(19파일) · `npm run build` 통과 · `npm run e2e -- --dist` **완주**(시드 170, **428결정**, 12층, 여덟 화면 1440px, 반출 → CLI 재생 일치, 대체 0) · 1440×900 세로·가로 넘침 없음.

**밸런스 게이트는 재지 않았다** — 규칙도 데이터도 안 건드렸다. 근거는 e2e가 그대로 재생된 것이다: 428결정·최종 체력 93·호의 [59,61]이 변경 전 런과 같은 값이다. `npm run size` 위반 1(`art/fx/open.webp`)은 P-32·P-21 자리고 이 계획 밖이다.

## 엔진 — 계획의 한 개가 셋이 됐다

계획은 `RunView`에 `favor`·`grace` 하나였다. `EnemyView.passives`는 P-25가 이미 실어 놨다. 둘이 늘었고 둘 다 화면이 거짓말을 하던 자리다:

```ts
// sim/engine.ts
export type RunView = { …; favor: Record<string, number>; grace: Record<string, number> };
type PowerView = { trigger: Trigger; card: CardView };   // 파워 줄이 읽을 것이 없었다
hand: state.combat.hand.map((id) => {
  const card = cardMap.get(id)!;
  return { ...cardView(card), effects: cardEffects(state, card) };   // 은혜가 붙은 뒤의 효과
}),
```

**손패 캡션이 카드 원문만 적고 있었다.** 공격 슬롯에 은혜가 걸리면 그 카드는 실제로 다른 일을 하는데(`cardEffects`) 캡션은 데이터 원문이었다 — 「화면만 보고 다음 턴을 계산할 수 있다」가 그 자리에서 깨진다. 고친 곳은 관측 한 줄이고 UI는 손대지 않았다. 낼 때 도는 목록과 같은 함수를 읽으므로 두 번째 진실이 생기지 않는다.

**대가를 재 봤다.** e2e의 클릭 정책은 캡션의 숫자로 카드를 고르므로 캡션이 바뀌면 정책이 흔들릴 수 있었다(시드 170의 완주가 끊기면 600개를 다시 훑어야 한다). 실측은 **불변**이다 — 428결정, 체력 93, 호의 [59,61]. 은혜가 슬롯에 붙는 뒤쪽 층에서도 같은 카드가 뽑혔다.

## 배지 — 테두리에 셋이 얹히는 문제를 채널 넷으로 갈랐다

P-33이 「테두리 하나에 진영·지속·색각 대체가 다 얹힌다, P-26이 정하라」고 되돌려 놓은 자리다. **결정:**

| 채널 | 무엇 | 어디 |
|---|---|---|
| 진영 | 이로움/해로움 | 테두리 **색** + 배경 **채움**(해로움만 채운다 — 색각 대체가 이것이다) |
| 신 | 출처 | 안쪽 고리 `box-shadow: inset`, 아이콘 글리프는 뒤에서 .4로 남는다 |
| 지속 · 이번 턴 | `shock` | 테두리 **점선** |
| 지속 · 전투 내내 | `mark`·`thorns` | 바깥 고리 `outline` + `outline-offset` |

1회 소모는 기본형이다(장식 없음). `outline`을 쓴 이유는 `box-shadow`가 이미 신 색을 들고 있어서다 — 넷이 한 속성에서 부딪히지 않는다. 색 hex 둘(`--boon`·`--bane`)은 `:root`에 있고 신 색 다섯은 그대로다.

**지속 표는 `ui/tokens.tsx`에 뒀다.** 근거는 코드다 — `shock`은 `endTurn` 맨 끝에서 지워지고(`core/combat.ts:152`) `mark`·`thorns`는 `consumeToken`을 아예 타지 않는다. `core/state.ts:9`가 「분류를 표로 두면 읽는 코드가 없어 주석과 다를 게 없다」고 적어 둔 표를, 이제 읽는 코드가 생겨서 UI 쪽에 세웠다. `Record<TokenName, …>`이라 토큰을 새로 만들면 컴파일이 막힌다.

계획의 **`thorns`가 표에서 빠져 있었다**(전투 내내 칸에 `mark`만 적혀 있다). 코드는 둘 다 소모하지 않으므로 둘 다 「전투 내내」로 넣었다.

## 화면

**의도** — `intentLabel`이 토큰을 `${action.token}`으로 적고 있었다. 배지는 「감전」인데 의도는 `shock`이라 같은 것이 두 이름을 갖고 있었다. `tokenName()`을 통과시켰다. 자리는 이름 옆 그대로 두고 `white-space: nowrap`을 줬다 — 접히는 쪽을 이름으로 바꿨다. 스크린샷에서 「공격 4」가 **한 글자씩 세로로** 접혀 있었다.

**패시브** — `.badges`에서 `.name` 안으로 옮겼다. 옮기면서 알약 스타일이 통째로 날아갔다: 규칙이 `.enemy .badges em.passive`로 **컨테이너에 묶여** 있었다(R-25 사후 수정 2가 만든 자리). `.enemy .passive`로 풀었다. `.badges`에는 이제 `방어 N`만 남는다.

**파워** — 이름 알약 + 트리거·효과 툴팁, 같은 파워 두 장이면 `×2`. 파워는 상한이 없으므로(`playCard`가 낸 만큼 등록한다) 세는 쪽이 화면이어야 한다.

**우호도** — 후원 둘, 미터 + 단계 이름 + 은총 수. 눈금선은 `favorBoundaries`를 그대로 `left: N%`로 깐다(UI에 70/30/10을 다시 박지 않는다). 진노는 테두리·배경·글자가 다 경고색이다.

**개입 표시(P-30 마감)** — 미터의 툴팁과 `aria-label`이 그 신이 **이 단계에서 조우 시작에 하는 일**을 적는다: 「진노 · 조우 시작에 나에게 감전 2」. `data/gods.json`의 `stage_effects`를 `godStageText()`가 읽고 효과문은 카드와 같은 `effectText`를 탄다. 계획이 「진노는 적을 하나 더 부른다(P-30)」고 적었는데 **그건 사실이 아니다** — `applyFavorStageEffects`가 지원하는 op은 damage·block·heal·apply_token 넷뿐이고 다섯 신의 진노는 전부 자기에게 붙는 토큰이다(R-30 §2가 「신이 적으로 합류」를 아직 안 만들었다). 그래서 경고 문구를 데이터에서 읽게 했다 — 화면이 없는 규칙을 말하지 않는다.

**여덟 화면 눈금** — `RunHeader`에 `run-header` 클래스 하나. 제목 5rem → 2.3rem, 머리글 여백 34 → 16px, `.shell:has(.run-header)` 안쪽 여백 64 → 28px, `.decision-panel .hint` 위 여백 0(칸 사이는 격자 `gap` 하나로만 띈다). 세로 975 → 900px. 설정·결과 화면은 `run-header`가 없어 그대로다.

**접근성** — 배지마다 읽히면 적 하나가 문장 여섯이 된다. 적은 버튼 `aria-label` 한 문장에 이름·체력·의도·패시브·토큰을 다 싣고(`tokenSummary`), 플레이어 줄과 파워 줄·미터는 `role="img"` + `aria-label`로 컨테이너가 한 번 읽는다. `prefers-reduced-motion`에 미터 채움 전환을 껐다(`.favor .meter i`).

## 안 만든 것 둘 — 근거가 없다

### 1 · 상한 강조 — `tokenLimits`가 코드에 없다

계획은 「P-25의 `tokenLimits`. 상한에 닿으면 숫자를 강조한다」고 했다. **그 상수는 없다.** R-25 §재측정 1이 2000런으로 재고 아무것도 남기지 않았다 — `frenzy 3`은 승률을 한 자리도 안 바꾸고(손패가 셋을 넘겨 쌓지 못한다), 감전·출혈·침수까지 자르면 0.018이 날아간다. `addToken`에도 상한이 없다.

없는 규칙을 화면이 말하면 「더 걸어도 낭비」가 **거짓말**이 된다. UI에 숫자를 박는 것은 계획이 금지한 것이기도 하다. 상한이 생기면 배지가 그것을 읽는다 — 자리는 `tokenStyle` 옆이다.

### 2 · 나머지 셋 우호도 접기 — 접을 칸이 없다

`state.favor`는 런 내내 **조합 둘만** 든다. 뒤진 결과:

- 초기값이 `{ [patrons[0]], [patrons[1]] }` 둘뿐이다(`runSteps`)
- 호의를 움직이는 경로 전부가 patron 아니면 상대 patron이다 — `recordCardFavor`·`finishCombatFavor`·`finishRestFavor`·`resolveDemand`·`payDemandCost`
- `favor_shift`에 신을 이름으로 박은 카드는 둘뿐이고(`card_zeus_retry_06`·`card_poseidon_16`) **둘 다 자기 patron**이다
- 조합 밖의 신은 `favorStage(50) = calm`이라 `applyFavorStageEffects`가 건너뛴다

그래서 셋을 그리면 영원히 「50 · 평온」인 칸 셋이고, 진노에 가까워지는 일도 없다. 계획의 「실패 시 행동」(patron 둘만 상시, 나머지 셋은 숨김)이 그대로 옳은 답이었다 — 자리가 없어서 접은 것이 아니라 **사실이 없어서** 안 그렸다. 조합 밖 신의 호의를 움직이는 규칙이 생기면 그때 칸이 생긴다.

## 은총 점과 슬롯 표시 — 겹치지 않았다

계획은 「P-28이 슬롯 넷을 만들었으므로 슬롯 표시가 은총 점을 대체하는지 먼저 본다」고 했다. 확인 결과 **P-28은 전투 화면에 슬롯을 아무것도 안 그린다**(`GraceScreen`의 `replaces` 한 줄이 전부다). 겹칠 것이 없었다.

정리한 방식:

| 사실 | 어디 | 왜 거기 |
|---|---|---|
| 받은 은혜 **수** | 미터 옆 `은총 N` | 다음 은혜의 tier이자 합성 전제(`graceTier`·`canFuse`) — 값 하나다 |
| 슬롯에 **걸린** 은혜 | 손패 카드 캡션 | 그 은혜는 카드가 하는 일을 바꾼다. 결정하는 자리에 값이 있어야 한다 |

점 6개 × 둘을 그리지 않았다 — 숫자 하나가 같은 것을 말한다. 슬롯 패널도 만들지 않았다: 캡션이 이미 효과를 적으므로 패널은 같은 사실의 두 번째 자리가 된다.

## 함정 — 실제로 걸린 것

- **스크린샷이 토큰 3종에 못 닿았다.** 계획은 「토큰 3종·패시브 2종이 걸린 턴」을 요구했다. 브라우저 클릭 정책(토큰 카드 우선 + 비용 내림)으로 시드 170을 200결정까지 훑어 최대가 **2종 + 2종**이다(결정 52). 제우스+아테나에서 플레이어에 남는 토큰이 방벽·반사·가시고 셋 다 맞으면 소모되므로 한 턴에 셋이 겹치기 어렵다. 대신 셋으로 나눠 잠갔다 — 3종이 걸린 마크업은 `test/ui.test.ts`가 고정하고(진영 둘 · 지속 셋 · 파워 ×2 · 진노 개입문 · 경계), 열 배지의 진영·지속은 설정 화면 범례 스크린샷이 한 장에 보여 준다
- **적 3인 × 배지가 넘치는 것**은 `TokenRow`의 `limit = 4`로 접는다(`+N`). 실제로 넘친 적은 없어 눈으로는 확인 못 했다
- **`aside repl`의 벽 두 개.** 한 호출이 ~90초를 넘으면 데몬이 연결을 끊는다(200결정 ≈ 80초). 그리고 세션이 끝나면 열었던 탭이 닫혀 **호출 사이에 상태가 안 남는다** — 긴 런의 스크린샷은 「1차로 걸으며 번호를 찾고, 2차로 같은 정책으로 그 번호까지 다시 걷는다」 두 호출로 나눠야 한다. `tab.screenshot({path})`은 세션 디렉터리 밖을 거부하므로 반환 버퍼를 base64로 받아 node가 쓴다. `Emulation.setEmulatedMedia`는 노출돼 있지 않다(애니메이션을 못 끈다)
- 애니메이션은 하나도 새로 만들지 않았다 — `pop`·`damagePop`·`.token-badge` 전환을 그대로 쓴다

## 남은 것

- **손패 캡션이 길어졌다.** 은혜가 붙은 카드는 효과가 다섯 줄이 되고 카드가 좁다(96px). 접거나 툴팁으로 미는 것은 카드 디자인이고 P-32 자리다
- **`+N` 접기와 상한 강조가 화면에서 검증되지 않았다.** 토큰 5종이 한 배우에 걸리는 런을 못 찾았다 — 조우가 커지거나(P-25·P-27) 은혜가 토큰 슬롯을 채우면 걸린다
- **파워 줄이 트리거로 묶이지 않는다.** 지금은 카드별 알약이라 파워 넷이면 알약 넷이다. 「턴 시작」끼리 묶는 것은 파워가 다섯을 넘으면 본다
- **P-33이 아이콘 33개를 넣을 때 채널 넷을 지켜야 한다** — 위 §배지 표가 그 계약이다. 글리프는 신의 **모양**이고 색은 신 색이며, 진영은 테두리·채움이 든다
