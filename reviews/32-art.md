## 계획에서 코드를 뺐다

에셋 83개가 다 있어도 **화면에는 아무것도 안 뜬다.** 붙이는 코드가 없다.

| 자리 | 남은 일 |
|---|---|
| `.enemy` 버튼 | 96px 스프라이트 열 (`grid-template-columns: 96px 1fr auto`) |
| `ui/card.tsx:57` | `{cardId}.webp` 없으면 `{patron}_{tag}.webp`로 떨어지는 폴백 |
| `tools/art.ts:22` | 위 폴백을 필수 판정이 인정하게 |
| `ui/fx.ts:1` | `playSprite` 호출부 — 정의만 있고 아무도 안 부른다. 오버레이 3 · 신 일러 5가 여기에 붙는다 |
| `result` 화면 | 주인공 일러 슬롯 |
| `ui/app.tsx:37` | `godColors` 삭제 — **hex는 §3 표가 정본이고 이미 확정이다.** 코드 정리만 남았다 |

`.player-actor`와 전투 좌우 스왑(`combat-layout`)은 이미 있다.

**그림 쪽 결정은 다 끝나 있으므로 코드 계획은 규격만 받으면 된다** — §1 「방향」(병사 오른쪽 봄 · 적 왼쪽 봄), §3 팔레트 hex 다섯, §0 화면 크기.

## `required_missing`은 에셋 상태를 재지 않는다

```
npm run art -- --check   →  cards=129 present=10 required_missing=15
```

이 숫자를 완료 정의로 쓰면 **영원히 통과하지 못한다.** `tools/art.ts:22`가 카드당 1장(`{cardId}.webp`, 129장)을 세는데 §3이 그 구조를 `{patron}_{tag}.webp` 30장으로 줄였다. 30장이 다 있어도 15가 나오고, 0이 되는 조건은 위 표의 폴백 코드다.

계획의 완료 정의를 `identify` 기반 게이트로 바꾼 이유가 이것이다.

## 게이트가 두 번 새어 나갔다 — 목록을 눈으로 훑었기 때문이다

원래 게이트는 「파일과 크기를 나열하고 사람이 본다」였다. 두 번 통과시켰다.

**1 · 오버레이 3장이 크기는 맞고 완전 불투명이었다.** `open.webp`가 1536×960으로 규격을 만족하는데 `min-alpha=1` — 투명 픽셀이 한 점도 없었다. 그대로 붙이면 컷인이 화면 전체를 덮는 판이 된다. **폴백보다 나쁘다** — 없으면 아무 일도 안 일어나지만 이건 게임을 가린다.

원인 둘:

- **생성기가 「Transparent background」를 무시한다.** `art/_src/fx/*.png` 셋 다 `alpha=Undefined`로 나왔다
- **변환에 알파를 만드는 단계가 없었다.** 옛 `open.md`에 있던 `#ff00ff` 크로마키 제거를 `OVERLAY_CONVERT`로 통합할 때 crop만 남겼다 — 이 리뷰 세션에서 만든 회귀다

고친 방법은 **마젠타 크로마키**다. 프롬프트가 배경을 `#ff00ff`로 칠하게 하고 변환이 벗긴다. 초록 키를 안 쓴 이유는 창백한 빛을 갉아먹기 때문이고, `-fx` 조건이 「r·b 높고 g 낮음」이라 `block`의 탁한 붉은 테두리(`#9b2226` 계열, b가 낮다)는 안 먹는다.

**2 · 카드 30장이 512×384였다.** 개수가 30/30이라 완료로 봤다 — **파일이 있다는 것과 규격대로라는 건 다른 얘기다.** 크기를 재지 않았다.

지금 게이트는 **위반만 출력한다.** 통과하면 빈 출력이다. 검사 범위에서 `art/cursor-pixel/`(220장)·`art/particle/`(81장)을 뺐다 — 외부 팩이고 83개가 아니다. 개별 프레임(`*_idle_N` 등)도 스트립에서 갈라진 것이라 스트립만 센다.

## 카드는 512×384로 확정했다 — 유일한 축소 허용 자리

원본 소실을 발견했을 때 30장 재생성이 기본안이었다. **그러지 않기로 했다.**

| 근거 | 값 |
|---|---|
| `.card-art` 슬롯 | 약 89×67 |
| DPR 2에서 필요한 화소 | 178×134 |
| 512×384 | 그것의 **2.9배** |
| 실측 용량 | 30장 합계 517KB, 평균 17KB, 최대 29KB |

[R-21](21-assets.md)의 「장당 22~31KB」가 실측과 맞는다. **89px 썸네일은 화소가 값이 아니다** — 화면을 꽉 채우는 배경·컷인·일러와 반대다. 그게 카드만 예외인 이유고, 그 하나 때문에 원본 보존 규칙 전체를 흔들지 않는다.

**감수한 것:** `art/_src/cards/`가 비어 있으므로 팔레트나 구도를 바꾸려면 재생성밖에 없다. 30장이 이미 톤이 맞고 89px에서 읽히니 그 대가를 지불한다 — **재생성 비용이 얻는 것보다 크다.**

`art/_src/zeus_attack-1448.png`(1448×1086) 한 장만 남아 있다. 30장 중 1장이다.

## 세로로 뽑힌 배경 넷 — 지시가 프롬프트 밖에 있었다

`map-under`·`map-surface`(1024×1536) · `surface-boss`(1122×1402) · `surface-combat`(1231×1278)이 세로거나 정사각이었다.

**「가로로 뽑는다」가 생성 지시에만 있고 프롬프트 본문에는 없었다.** `open.webp`만 본문에 `Wide landscape 16:10` 문장이 있어서 혼자 가로를 지켰다 — 그게 증거다.

문장을 배경 6 · fx 3 · hero 3 **열두 장 전부**에 박았다. 그리고 지도 둘은 프롬프트가 `vertical cross-section`이라 가로 지시와 싸웠다 — 「넓은 절벽 단면에 세 갈래가 나란히」·「스위치백이 좌우로 오간다」로 소재를 다시 썼다.

**crop으로 고치지 말라**는 경고를 사이드카에 넣었다. 1024×1536을 16:10으로 자르면 그림의 절반이 버려진다.

## 원본 보존 순서가 실제로 작동했다

`art/fx/`·`art/hero/` 6장이 1440×900으로 깎이고 원본이 없었던 게 이 계획의 시작점이었다. 재생성 때 **「생성물을 `art/_src/{경로}/`에 먼저 저장하고 나서 변환한다」**를 사이드카 명령에 박았고, 결과가 남았다:

```
art/_src/bg 4 · fx 3 · gods 5 · hero 3 · player 9 · ui 3   = 27장
```

이제 팔레트나 배율을 바꿔도 원본에서 다시 줄이면 된다. `cards`만 예외다.

## 프롬프트 정본이 세 장을 안 덮고 있었다

`art/_src/gen-docs.mjs`가 정본이고 사이드카를 손으로 고치면 다음 재생성이 덮는다 — 그런데 **`open.md`·`under-combat.md`가 생성기에 없었다.** 정본이 안 덮으니 이 둘만 수정을 못 받았고, `open`은 재생성 대상 셋 중 하나였다. 둘 다 생성기에 넣었다.

**아직 정본 밖인 사이드카 9장:** `zeus_{tag}` 4 · `under_chain` · `player` · `enemy_under_{pressure,attrition,boss}`. 다 완성된 에셋이라 급하지 않지만, 프롬프트를 고칠 일이 생기면 이 아홉은 생성기가 안 덮는다. `zeus_*` 4장은 손 작성 확정본이라 그 사실을 문서 머리에 적어 뒀다.

`ROOT`가 `/Users/gimbongseob/...` 하드코딩이라 다른 기계에서 안 돌던 것도 고쳤다 — 스크립트 위치 기준이다.

## 남은 부채

- **에셋이 화면에 안 붙어 있다.** 위 표 여섯 줄. 이게 붙기 전에는 `aside` 스크린샷·`npm run e2e -- --dist`·「위쪽 빛이 한 줄의 상승으로 읽히는지」를 확인할 방법이 없다
- **`godColors`가 아직 `ui/app.tsx:37`에 있다.** hex 정본은 §3 표로 확정됐고 카드 30장도 그것으로 그렸다 — 코드에서 지우는 것만 남았다
- **정본 밖 사이드카 9장**
- **카드 원본이 없다.** 감수한 값이지만 되돌릴 수 없다는 사실은 남는다
- **`art/cards/` 아트가 89px에서 실제로 갈리는지 안 봤다.** 사이드카의 통과 기준(같은 신 4장을 89×67로 줄여 나란히 놓고 형태가 갈리는지)은 붙이는 코드와 무관하게 지금 할 수 있다 — 하지 않았다
