## 결론

**통과 · 완료 정의 다섯 전부 충족 · 그런데 밀림 자체의 승률 부호가 0이다.** `displace`가 이름대로 일한다 — 밀린 적은 그 턴을 쉬고 **뒤로 한 칸 간다.** 뒤에 적이 있으면 맞바꾸고, 뒤가 비어 있어도 맞바꾼다(구멍을 만들지 않는다), 맨 뒤(칸 3)면 불발이다. `slot(target)` 조건이 서고 그것을 읽는 카드가 신별로 한 장씩 다섯 장 붙었다.

**계획 A안(이동 + 스킵 유지)을 그대로 골랐다.** 값 표·`mitigationTokens`·`botPolicyVersion`이 한 줄도 안 움직였고 카드 5장 재가격도 없었다 — 밀어내기는 순수한 상향이다.

**기여를 갈라 재보니 상향은 밀림이 아니라 카드 다섯이었다**(3000런 층화, `npm run tune` 같은 판):

## 만든 것

### 밀림은 `endTurn` 앞에서 역순으로 한 번 돈다

`takeEnemyTurn`을 지웠다. 그 함수에서 `displace` 분기를 빼면 남는 것이 `patternIndex += 1` 한 줄이라 함수일 이유가 없다 — 호출부(`endTurn`)로 인라인했다. 대신 `shoveDisplaced` 하나가 섰다:

```ts
export function shoveDisplaced(combat: CombatState): Set<ActorState> {
  const shoved = new Set<ActorState>();
  for (let slot = combat.enemies.length - 1; slot >= 0; slot -= 1) {
    const enemy = combat.enemies[slot];
    if (enemy.hp <= 0 || !consumeToken(enemy, "displace")) continue;
    shoved.add(enemy);
    if (slot + 1 < combat.enemies.length) [combat.enemies[slot], combat.enemies[slot + 1]] = [combat.enemies[slot + 1], combat.enemies[slot]];
  }
  return shoved;
}
```

세 결정이 이 여덟 줄에 다 들어 있다:

- **역순(칸 3 → 0).** 정순이면 앞칸이 비켜 준 자리로 올라온 적을 같은 턴에 다시 만난다 — 그 적의 밀림은 소모되지도 않고, 한 카드가 두 칸을 움직이는 판이 된다. `test/range.test.ts`의 「never moves one enemy two slots in a turn」이 정순과 역순의 결과가 실제로 다른 판(앞칸 둘이 같은 턴에 밀린다)으로 그것을 못 박는다
- **맞바꿈.** 뒤가 비어 있어도 이동이 아니다. 「뒤가 비면 이동」으로 슬쩍 바꾸는 순간 앞에 구멍이 생기고, `admitPending`이 **가장 앞 빈 칸**을 쓰므로 밀어내기가 「진노한 신을 전열로 불러오는 카드」가 된다
- **집합의 키가 id가 아니라 배우 그 자체다.** 계획은 「밀린 적 id를 모아」라고 적었는데, 편성 데이터는 같은 적 id를 두 칸에 적는 것을 막지 않는다(`groups[].with`에 게이트가 없다). 그러면 한쪽의 밀림이 둘의 턴을 지운다. 동일성으로 세면 그 자리가 없어지고 코드는 같은 길이다

`firePowers("turn_end")` **뒤**에 둔다 — 턴 끝 파워가 붙인 밀림도 이번 턴에 값을 해야 한다(카드로 붙인 밀림이 그 턴에 소모되는 것과 같은 자리).

**맞바꿈이 `patternIndex`를 데려간다**는 계획의 예상은 맞았다. 배열 요소를 통째로 바꾸므로 상태·토큰·패턴 진행이 전부 따라가고, `definitions.get(enemy.id)`는 id로 읽으므로 무해하다.

### 자리 조건은 정규식 두 줄이다

```ts
match = expression.match(/^slot\(target\) (>=|<) (\d+)$/);
if (match) return compare(context.state.combat.enemies.findIndex((enemy) => enemy === context.target), match[1], Number(match[2]));
```

칸은 배열 인덱스라는 P-35의 결정이 여기서 값을 한다 — `EnemyState`에 `slot`이 없으므로 조건이 판을 직접 읽는다. 게이트에는 두 줄이 붙었다: `conditionPatterns` 한 줄, 그리고 **`target: self` 카드의 자리 조건은 반려**한다(사거리에 이미 같은 규칙이 있다 — 자기 대상 카드의 대상은 플레이어고 플레이어에게는 칸이 없다. `findIndex`가 −1을 주므로 `< 2`가 조용히 참이 된다).

계획의 「사거리와 자리 조건을 같은 카드에 붙이지 않는다」를 지켰다 — 다섯 장 다 사거리가 없다(전체).

| 카드 | 신 | 효과 | 기대값 |
|---|---|---|---:|
| 후열 낙뢰 `card_zeus_24` | zeus | 피해 6 · **뒷줄이면** 연쇄 5 | 4.25 |
| 해안 파쇄 `card_poseidon_18` | poseidon | 피해 8 · **앞줄이면** 침수 3 | 4.60 |

신마다 성격이 갈린다(계획 §2 그대로): 아르테미스는 뒷줄 저격, 아테나는 앞을 받아내고, 아레스는 앞칸을 더 세게 친다. 계획이 정하지 않은 둘은 어휘로 정했다 — 제우스는 뒷줄을 치면 벼락이 갈라지고(`chain`), 포세이돈은 파도가 앞줄을 적신다(`soaked`).

이름 둘은 고쳤다. **`card_zeus_17` 「고압 감전」이 제일 나쁜 자리였다** — `감전`은 이 게임의 토큰 이름(`shock`)인데 그 카드가 붙이는 것은 `displace`다. 「폭풍 압박」이 됐고 `card_zeus_08` 「마비 벼락」은 「충격 밀침」이 됐다. **문구는 고칠 것이 없었다** — 카드에는 이름 말고 텍스트 필드가 없다(캡션은 `effectText`가 효과에서 만든다).

`gods.json`의 토큰 어휘는 안 건드렸다(계획 지시) — 제우스에게서 `displace`를 빼면 `shock` 하나만 남고 `tokenScopeFailure`·`pool_ratio`·풀 생성기가 다 그 표를 읽는다.

### 화면 — 키가 칸이 아니라 적이다

```tsx
<m.button key={enemy.id} layout={!reducedMotion} transition={transition} className="enemy" …>
```

**키를 바꾸는 것이 이 한 줄의 절반이다.** 옛 키는 칸 번호라 자리가 맞바뀌어도 DOM 노드는 제자리에 있고 **내용만** 바뀐다 — 플레이어는 자리가 바뀐 것이 아니라 「적이 바뀐 줄」 안다. 키가 적 id면 React가 노드를 옮기고 `layout`이 그 사이를 미끄러진다.

`ui/app.tsx`의 `LazyMotion features`를 `domAnimation` → **`domMax`**로 올렸다. `domAnimation`에는 layout 기능이 없어서(`features-max.mjs`가 `domAnimation` + `drag` + `layout`이다) 그대로 두면 `layout` prop이 **조용히 아무 일도 안 한다.** `npm run size`는 에셋만 세므로 이 JS 증가는 게이트에 안 잡힌다(2.43MiB 불변).

밀림 배지 툴팁은 「다음 행동을 건너뛰고 뒤로 한 칸 밀린다」다 — 옛 문구는 스킵만 말했다.

**눈으로 본 것과 안 본 것을 갈라 적는다.** `npm run e2e`가 시드 589로 12층을 완주하며 여덟 화면을 1440px에서 다 재고 가로 넘침 0을 확인했다(적 패널 405px 불변). 하지만 **미끄러짐 자체는 사람이 안 봤다** — 밀림이 실제로 나는 조우까지 브라우저를 몰아야 하고, 160ms 전환은 스크린샷으로 증명되지 않는다. 확인한 것은 배선의 세 조각(feature 번들에 layout이 들었다 · prop이 붙었다 · 키가 적을 따라간다)과 줄인 모션에서 `layout={false}`로 갈라지는 것뿐이다.

## 계획이 못 본 것

### 완료 정의의 게이트 명령이 애초에 통과할 수 없었다

계획은 `npm run validate -- data/cards.json`에 **반려 0**을 요구했다. HEAD에서 그것을 돌리면 **48장이 `duplicate`로 반려된다.** `duplicateFailure`의 비교 대상은 「같은 배치의 앞선 후보」뿐이라(색인의 부채 항목에 이미 적혀 있다) 배포된 풀을 한 배치로 넣으면 풀이 **자기 자신과** 겹친다. 계획 탓이 아니라 게이트의 설계고, P-36이 만든 것도 아니다.

그래서 게이트는 **후보 파일**로 돌렸다 — `staging/cards-slot.json`(새 5장 + 이름 고친 2장)을 `npm run validate`에 넣고 `--apply`로 배포했다. 이것이 `staging/` 31개 파일이 쓰던 그 흐름이다. 반려 0 · `pass_rate` 1 · 신 다섯 풀 전부 상한 안:

| 신 | 장수 | 장당 기대값(≤ 5.5) | 완화 비율(≤ 0.30) |
|---|---:|---:|---:|
| zeus | 31 | 5.424 | 0.274 |
| poseidon | 22 | 4.962 | 0.288 |
| athena | 23 | 5.249 | 0.287 |
| ares | 24 | 5.139 | 0.133 |
| artemis | 24 | 5.394 | 0.139 |

제우스가 5.424로 상한에 가장 붙어 있어 **새 카드의 기대값 상한이 6.6이었다** — 후열 낙뢰(4.25)는 그 안이다.

### 밀림의 3분의 1은 벽에 부딧힌다

| | 3000런 |
|---|---:|
| 소모된 `displace` | 14,132 |
| 자리를 옮긴 것 | 9,348 (66.1%) |
| **칸 3 불발** | **4,784 (33.9%)** |
| 산 적과 맞바꾼 것 | 1,388 (9.8%) |

불발이 3분의 1인 이유는 **밀림이 누적되기 때문**이다. 혼자 선 적을 세 번 밀면 칸 3에 붙고, 그 뒤의 모든 밀어내기는 「그냥 턴 스킵」으로 돌아간다. 조우의 89%가 1~2인이라(위 분포) 그 벽에 금방 닿는다. 산 적과의 맞바꿈 — 편성의 앞뒤가 실제로 뒤집히는 유일한 경우 — 은 열 번에 한 번뿐이다.

이것이 「밀림의 승률 부호가 0」의 절반이다. 나머지 절반은 봇이다.

「밀림만」 열에서 읽을 것 하나: **`athena+ares`·`athena+artemis`·`ares+artemis` 셋은 소수점까지 같다.** 그 세 조합은 `displace` 카드를 아예 못 든다 — 그 토큰은 제우스와 포세이돈의 어휘다. 움직인 넷은 전부 그 둘이 든 조합이고 폭은 ±1%p, 예외는 `poseidon+athena`(−2.6%p)뿐이다. **규칙이 데이터를 통해서만 승률을 움직인다**는 R-35의 줄이 한 번 더 확인된 자리다.

셀 단위 차이는 **귀속하지 않는다.** `tools/tune.ts`가 스스로 적어 둔 대로 조합당 300런에서 두 승률 차의 95% 노이즈가 ±0.07이고, 위 표의 셀 차이는 대부분 그 안이다. 게다가 풀에 카드를 더하면 `rewardOffer`가 뽑는 **인덱스가 통째로 밀려** 같은 시드가 다른 보상을 제안한다 — 셀 차이에는 「새 카드의 세기」와 「보상 열의 재배치」가 섞여 있다. 믿을 것은 전체(+1.4%p)와 변동계수(0.541 → **0.489**)다.

**변동계수가 내려간 것은 이번 회차의 유일한 B-0 3번 방향 움직임이다.** P-35가 0.437 → 0.541로 올려놓은 것을 카드 다섯이 0.489로 되돌렸다. 최저 셀도 0.127 → 0.147로 올랐다.

### 조건 카드는 보상에서 거의 안 뽑힌다

3000런에서 실제로 낸 횟수(전체 639,403회):

| 카드 | 낸 횟수 |
|---|---:|
| 전열 받아치기(athena) | 873 |
| 해안 파쇄(poseidon) | 549 |
| 선봉 도끼(ares) | 302 |
| 후열 낙뢰(zeus) | **28** |
| 후열 저격(artemis) | **12** |

이유는 R-35가 사거리에서 만난 것과 같은 구조다. `chooseReward`는 **기대값 순으로만** 고르고, `expectedValue`는 `when` 붙은 효과를 `conditionRate = 0.5`로 깎는다 — 조건 카드는 밴드(4~8) 바닥에 앉고, 3택1에서 조건 없는 카드가 옆에 있으면 절대 안 뽑힌다. 그 다섯 장이 **데이터에는 있고 플레이에는 거의 없다.**

같은 자리에서 하나 더 드러났다: **`card_zeus_08`(충격 밀침)은 3000런에서 한 번도 안 나온다.** 기대값 4.0으로 밴드의 정확한 바닥이라 보상에서 절대 안 뽑히고 시작 덱에도 없다. P-36이 만든 것이 아니라 이름을 고치면서 발견한 배포본의 사문이다.

### 시험 픽스처 둘을 다시 골랐다

콘텐츠가 바뀌면 갱신하게 되어 있는 자리 둘이 실제로 갱신을 요구했다.

- **`test/demands.test.ts`의 시드 22 → 10.** 「첫 요구를 지키는 시드」다(주석에 25 → 57 → 70 → 4 → 6 → 94 → 4 → 22의 이력이 있다). 조건이 **다섯**이라 400시드를 훑어 가장 앞을 다시 골랐다 — 곡선이 갈라지고, 보상·벌금이 그 자리에 정확히 들어가고, 전부 거절하면 편이 상대로 넘어가고, `demand_zeus_multi:tier1`의 지킴률이 0과 1 사이여야 한다. 「수락해도 안 바뀌는 시드」는 4 → **2**다(시드 4가 이번에 지켜지는 쪽으로 넘어갔다)
- **`tools/e2e.ts`의 시드 170 → 589.** 170은 여전히 브라우저에서 끝까지 굴러가지만 **헌신에 못 닿아 `grace` 화면을 안 지난다**(454결정 대신 200결정에서 끝난다). `tools/e2e.ts`의 클릭 정책을 CLI로 흉내내 600시드를 훑었고 완주 시드는 다섯이다(56·241·546·589·595) — 가장 짧은 589를 골랐다. 브라우저 실행으로 여덟 화면·반출 재생·완주를 다 확인했다

### 밴드 하나를 고쳤다 — 「이긴 런은 6번 싸운다」는 밴드가 아니었다

`test/map.test.ts`가 이긴 런의 조우 수를 `>= 6`으로 잠그고 있었는데 이번 판에서 5조우 완주가 하나 나왔다(시드 267). **HEAD에서도 그 런은 5조우로 12칸을 걸었다 — 이기지 않았을 뿐이다.** 즉 하한 6은 「그 길로 이긴 런이 아직 없었다」는 우연이고, 격자가 정하는 하한은 **지역당 보스 하나**다(층 5는 쉼터가 보장되고 층 1~4는 넷 다 예고가 될 수 있다).

그래서 값을 5로 깎지 않고 **구조가 정하는 값**으로 바꿨다 — `encounters >= 2 && encounters <= mapDepth`. 한 칸 더 내려온 우연을 다음 회차가 다시 만나지 않는다.

## 남은 부채

- **밀림이 승률을 못 움직인다(+0.1%p) — 봇이 자리를 안 읽기 때문이다.** `chooseTarget`은 사거리 안의 「체력 낮은 놈」이고 `chooseCard`는 「앞칸 지킴이를 밀면 `012` 카드가 뒤에 닿는다」를 모른다. 실측 승률이 사람 값의 하한인 것은 R-35에도 있었지만, 이번엔 **그 격차가 기여의 전부**다. 정책 넷에 자리 항을 붙이는 것이 다음 자리고, 그것 없이는 밀어내기 상향의 크기를 영원히 못 잰다
- **밀림의 33.9%가 칸 3 불발이다.** 누적으로 벽에 붙기 때문이고, 조우의 89%가 1~2인이라 빨리 붙는다. 「당기기」(뒷칸을 앞으로)가 계획의 다음 자리로 적혀 있는데, 그것이 이 벽의 답이기도 하다 — 새 토큰이 필요하다
- **조건 카드 다섯 중 둘이 사문에 가깝다**(28회 · 12회). `chooseReward`가 기대값 순이고 `when`은 ×0.5로 깎이므로 조건 카드는 3택1에서 구조적으로 진다. 게이트의 밴드(4~8)가 통과시킨 카드를 봇 정책이 거른다 — 「기대값이 곧 채택률」이 아닌 자리다
- **`card_zeus_08`은 3000런에서 0회다.** 기대값 4.0으로 밴드 바닥이라 보상에서 안 뽑힌다. 밴드 하한에 앉은 카드가 몇 장 더 있는지 세어 본 적이 없다
- **저휴식 클리어가 0.134 → 0.154로 올랐다**(상한 0.24). 계획의 함정 넷째 줄이 예고한 방향 그대로다 — 승률이 오르면 상한(0.7)이 아니라 이쪽이 먼저 움직인다. 3000런 층화로는 0.240이고 그 상한은 **기본 조합 500런**에 걸린 값이라(R-34) 두 모집단을 섞어 읽으면 안 된다. 다음 상향이 여기를 먼저 깨뜨린다
- **미끄러짐을 눈으로 안 봤다.** 배선 세 조각은 확인했지만 밀림이 실제로 나는 조우를 브라우저로 지나며 전환을 본 적은 없다. `data-projection-id` 같은 관측 가능한 흔적이 이 버전의 motion에는 없어 자동 확인 경로도 없다
- **편성 데이터가 같은 적 id를 두 칸에 적는 것을 게이트가 막지 않는다.** `shoveDisplaced`는 동일성으로 세서 그 자리를 피했지만, `guardFor`·`resolveTargets`·`admitPending`은 여전히 id로 읽는다. 배포된 편성 12개에는 중복이 없다
