# R-71 · 타격은 몸이 가서 하고, 승패는 한 박자 세운 뒤 넘어간다

[P-71] 수행 결과. 엔진·리플레이·봇·데이터를 건드리지 않고 기존 `hits`·`hitSource`·`hitSeq` 관측과
WAAPI·스프라이트 포즈 배선만으로 전투 타격과 승패 아웃트로를 연결했다.

## 한 일

- 병사의 `attack`은 첫 피격 적의 칸 앞까지 280ms 동안 돌진하고, 도착 순간 피해 팝·플래시·셰이크·
  타격음을 낸 뒤 돌아온다. 여러 적을 때리면 앞 칸까지 한 번만 나가며 `card` 출처는 제자리에 남는다.
- 직전 공격 의도를 가진 적들은 520ms 간격으로 병사 앞까지 차례로 왕복한다. 각 도착마다 타격 연출을
  내고 합산 피해 팝은 첫 도착에 한 번만 띄운다. 「내 턴」 배너도 마지막 공격자 뒤로 미뤘다.
- 대신 맞기의 도착과 모든 타격 표시가 같은 280ms를 보도록 맞췄다. 위치는 기존 칸 간격만 사용하고
  DOM 크기를 재지 않는다.
- 전투 승패를 App의 `outro` 화면 상태로 1.3초 붙든다. 승리는 남은 적의 기존 death/exit 프레임,
  패배는 병사의 이미 배선된 death 프레임과 「승리」·「패배」 배너를 보인 뒤 0.5초 퇴장한다.
- 아웃트로 중에는 답을 막고, 다음 화면을 열 때 잠금도 함께 해제한다. 줄인 모션에서는 이동·순차 지연·
  홀드가 모두 0이다. Aside 드라이버는 `data-outro`가 사라질 때까지 기다려 지나간 결정을 다시 누르지 않는다.

E2E는 아웃트로마다 실제 1.3초 홀드를 기다려 약 40초가 걸렸다. 처음에는 새 보상 화면이 뜨는 순간에도
잠금이 남아 첫 카드 선택을 삼켰고 시드 623이 패배했다. 아웃트로 해제와 화면 이탈을 한 상태 전환으로
묶은 뒤 기준선인 329결정·12층 승리로 돌아왔다. 정적 UI 검사는 승리 때 적 DOM이 비고 패배 때 병사에
`data-pose="death"`가 붙는 것을 고정한다.

규칙·수치·데이터가 불변이므로 밸런스 게이트는 돌리지 않았다.
