## 결론

P-01~P-21의 코드·데이터·자동 검증은 구현됐다. N-01~N-05에서 엔진을 스텝화하고 여덟 종류 결정을 전부 사람에게 넘겼다 — **UI에 남은 자동화는 없다.** N-06에서 죽어 있던 규칙 셋(토큰 4종·헌신·진노 오라·요구 조건 판정)을 살렸다. P-19의 공개 URL과 배포본 일일 런은 커밋·푸시 금지 지침 때문에 외부 완료되지 않았다.

## 최종 검증

- `npm test`: 18파일, 59테스트 통과
- `npm run build`, `npx tsc --noEmit`: 통과
- 32,000런 5회차: 승률 37.7%, 조합 표준편차 28.79%p, 블록 효율 0.655, 합성률 6.1%
- 조합 행렬 최저 셀 0.000 → **0.034** (0%짜리 셀 여섯이 없어졌다)
- 회차 분산: 기준선을 두 번 갈아엎어 비교 대상이 없다 — 6회차부터 판정
- 브라우저: `aside repl`로 시드 6 완주, 요구가 전투 앞에 뜨는 것과 정수 수치 확인

## 남은 작업

- **신별 풀 구성을 제한하는 게이트 규칙.** `pairing_win_stddev` 0.288은 그때까지 덮은 숫자다 — 카드 한 장의 기대값 밴드로는 "완화에 다 써서 이기는 신"을 못 잡는다. 근거는 [06-tokens.md](06-tokens.md)의 「닫지 못한 것」
- 제우스가 아테나 없이는 못 이긴다(≤0.050). 진단만 되어 있다
- `demand_artemis_mark`는 조건을 10으로 올려도 지킴률 0.997 — 축을 바꿔야 한다
- 시작 덱 15장 일러스트, 스프라이트, 사운드
- 사용자가 별도 턴에 지시하면 커밋·푸시하고 GitHub Pages 공개 URL 1런을 확인한다
