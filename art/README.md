# `art/` — 파일은 원본 해상도로 둔다

[P-32](../plans/32-art.md) · **이 규칙이 없어서 원본 해상도가 한 번 소실됐다.** 아래가 그 재발 방지다.

## 사고 경위

사이드카 문서가 `**규격** 480×300 PNG`, `**규격** 32×32 PNG` 라고 적고 그 아래에 이런 명령을 함께 놨다:

```
magick in.png -filter box -resize 480x300! ... art/bg/under-combat.png
```

**「규격」이 화면에서 보이는 크기였는데 파일 크기 지시로 읽혔다.** 게다가 입력이 `in.png`라 입력과 출력이 같은 파일이 되면 `-resize`가 원본을 그 자리에서 깎는다. 그래서 생성 원본이 남지 않았다.

## 규칙

**1 · `art/**`는 생성 원본 해상도를 유지한다. 축소하지 않는다.**

변환은 알파·크로마키 정리까지만 한다. `-resize`, `-colors`, `-filter box`를 원본에 걸지 않는다.

**2 · 문서의 크기 숫자는 두 종류고 섞어 쓰지 않는다.**

| 항목 | 뜻 | 파일에 하는 지시인가 |
|---|---|---|
| `**파일**` | 디스크에 있어야 하는 것 | **그렇다** — 원본 해상도, 무손실 |
| `**화면**` | CSS가 그 크기로 보여준다 | **아니다** — 구도를 잡을 때 쓰는 참고값이다 |

`32×32`·`480×300`·`89px`는 전부 `**화면**` 쪽이다. **그 숫자로 파일을 만들지 않는다.**

**3 · 변환 명령의 입력과 출력은 다른 경로다.**

```
magick art/_src/{경로}/{name}.png  ...  art/{경로}/{name}.png
```

`in.png` 같은 익명 입력을 쓰지 않는다 — 그게 원본을 덮어쓴 경로다. 생성 원본을 먼저 `art/_src/`에 넣고 그다음 변환한다.

**4 · `art/_src/`는 작업 중간물 자리다.**

생성 직후 원본, 스트립 조립용 포즈별 파일, 크로마키가 아직 붙어 있는 것. 게임에 안 들어간다 — Vite가 `art/cards/*.webp`만 glob한다(`ui/card.tsx:5`).

## 화면 크기는 왜 그렇게 작은가

뷰포트가 P-19에서 **1440×900**으로 굳었고 `.shell`이 `min(1040px, 100% - 32px)`다(`ui/style.css:21`). 카드 아트 슬롯이 약 89×67px인 것도 `.hand`가 `repeat(auto-fill, minmax(96px, 1fr))`(`:132`)이기 때문이다.

**전부 CSS px이다.** 코드에 `devicePixelRatio`를 쓰는 곳이 없으므로 DPR 2 화면에서 실제 필요한 화소는 두 배다:

| 자리 | 화면 CSS | DPR2 실제 필요 |
|---|---|---|
| 카드 아트 | 89×67 | 178×134 |
| 컷인 오버레이 · 주인공 일러 | 1440×900 | 2880×1800 |
| 픽셀 배경 (3배 확대) | 1440×900 | 확대라 DPR 무관 |

그래서 **원본을 그대로 두는 게 화질 대책까지 겸한다.** 생성기 상한이 `1536×1024`라 그래도 2880×1800은 못 채우지만, 여기서는 **더 깎지 않는 것**까지 한다.

## 픽셀 아트의 미결 사항

픽셀 배경·스프라이트는 `image-rendering: pixelated`로 3배 확대해야 픽셀 아트로 읽힌다. 원본 1024×1536을 브라우저가 96px로 부드럽게 줄이면 그냥 축소된 그림이 된다.

**그 축소는 에셋이 아니라 코드가 맡는다** — 화면에 붙이는 선행 코드 작업(§1·§2)에서 빌드가 만들게 한다. **원본 파일은 건드리지 않는다.** 지금은 아트가 화면에 붙어 있지도 않다 (`art/cards`만 `ui/card.tsx`가 읽고 배경·스프라이트·프롭·컷인은 호출부가 없다).

## 무엇이 깎였는지 확인하는 방법

파일 상태는 작업하면서 계속 바뀌니 표로 박아 두지 않는다. 이걸 돌린다:

```bash
for f in art/*/*.png art/*/*.webp; do echo "$(magick identify -format '%wx%h' "$f")  $f"; done | sort
```

**1000px 미만이면 깎인 것이다.** 생성 상한이 `1536×1024`라 온전한 파일은 네 자리 폭을 갖는다. 예외는 셋뿐이다:

- `props/` 중 직접 찍은 8×8 다섯 개 (`under_wisp`·`under_ash`·`under_droplet`·`under_flies`·`surface_lightning_afterglow`)
- `ui/marker.png` 16×16
- `sprites/player.png` — 조립된 스트립이라 원본이 아니다. 포즈 원본이 `_src/player/`에 있어야 한다

깎인 파일을 찾으면 `art/_src/`에 원본이 있는지 보고, 없으면 그 사이드카 문서의 프롬프트로 **재생성**한다. 프롬프트는 전부 남아 있다 — 소실된 건 화소뿐이다.

**카드는 급하지 않다.** 화면 슬롯이 89px이라 512×384로도 DPR 2에 2.9배 여유가 있다. `fx`·`hero`가 먼저다 — 화면을 꽉 채우는 자리라 축소가 그대로 보인다.
