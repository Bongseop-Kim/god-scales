### A-2.1 토큰 배지 9종

배지는 `아이콘 배경 + 한 글자 오버레이 + 스택 수`로 만든다.

| 토큰 | 글자 | 색 | 검색어 |
|---|---|---|---|
| `shock` | 감 | 제우스 | lightning · electric |
| `displace` | 지 | 포세이돈 | hourglass · time · slow |

| `bulwark` | 벽 | 아테나 | shield · rampart |
| `deflect` | 반 | 아테나 | mirror · reflect · bounce |
| `bleed` | 혈 | 아레스 | bleeding wound · blood |
| `frenzy` | 광 | 아레스 | rage · berserk |

### A-2.3 카드 컴포넌트와 일러스트 규약

```
┌─────────────────┐
│ [코스트]   [태그] │
│                 │
│   ← 일러스트 →   │   art/cards/{card_id}.webp
│                 │   없으면 placeholder
│─────────────────│
│ 카드 이름        │
│ 효과문           │
└─────────────────┘
테두리 = 귀속 신의 색 (합성 카드는 두 색 그라디언트)
```

**카드 스키마는 유지하고 `art/cards/{card_id}.webp` 파일 규약으로 연결한다.** 교체는 파일 드롭으로 끝낸다.

placeholder는 신 색 그라디언트 + 신 아이콘 워터마크로 CSS에서 만든다.

### A-2.4 일러스트 작업 시점

| 시점 | 상태 |
|---|---|
| P-06 ~ P-20 | 카드 id가 바뀐다. placeholder로 둔다 |
| **P-21 (동결 후)** | **id가 확정된다. 여기서 만든다** |

```bash
npm run art -- --list   # id, 이름, 귀속 신, 효과문 → 작업 목록 CSV
npm run art -- --check  # art/cards/ 에 없는 id 나열
```

**우선순위** — 시작 덱 20장 → 합성 카드 10장 → `pick_rate` 높은 순.

### A-2.5 신 색 5종

```css
--zeus:      #D4A017;  /* 뇌전 — 황금 */
--poseidon:  #2E7D8F;  /* 심해 — 청록 */
--athena:    #7A8B5C;  /* 올리브 — 회녹 */
```

가정치다. 검증 기준은 전투 화면에서 두 신의 카드가 손패에 섞였을 때 구분되는가이며, 구분되지 않으면 명도를 벌린다.

### A-2.6 전투 연출

**연출은 반복 빈도에 반비례해서 넣는다.**

| 사건 | 런당 빈도 | 연출 | 목적 |
|---|---|---|---|
| 카드 사용 | ~100 | press `scale(0.97)` 120ms | 피드백 |
| 피해·회복 숫자 | ~200 | 대상 위에 팝, 400ms 후 소멸 | **어느 적에게 들어갔는가** |
| 토큰 부여 | ~80 | 배지 펄스 1회 160ms | 상태 표시 |
| HP·호의 바 변동 | ~150 | `scaleX` 트윈 200ms | 크기 전달 |
| `chain` 파급 | ~20 | 대상마다 60ms stagger | **파급이 몇 체에 갔는가** |
| 조우 전환 | ~10 | 페이드 200ms | 공간적 일관성 |
| 요구 제시 | ~7 | 배너 슬라이드인 250ms | 상태 표시 |
| 역린 개입 | 0~5 | 화면 가장자리 신 색 플래시 | 상태 표시 |
| 은총 마일스톤 | 0~3 | 토스트 + 대상 카드 강조 | 설명 |
| **합성 카드 획득** | **0~1** | **가장 크게** — 두 신 색이 합쳐지는 카드 등장 | delight |

**두 범주로 예산을 나눈다.**

| 범주 | 예산 | 수단 | 무엇 |
|---|---|---|---|
| **UI 피드백** (고빈도) | **300ms 미만** | CSS transition · Motion | 카드 press, 피해 숫자, 배지 펄스, 바 트윈, 화면 전환 |
| **극적 연출** (저빈도) | 480ms+ 허용 | **스프라이트 시트** | 역린 개입, 합성 획득, 보스 등장 |

**규격**

```css
--ease-out:    cubic-bezier(0.23, 1, 0.32, 1);      /* 등장·소멸 */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);     /* 화면 내 이동 */
```

- 등장·소멸은 `ease-out`, 화면 내 이동은 `ease-in-out`을 쓴다
- **`transform`과 `opacity`만 애니메이션한다.** HP 바는 `transform: scaleX()`로 만든다
- 빠르게 반복 트리거되는 것(토큰 배지, 바)은 CSS transition으로 만든다

**연출 중에도 입력을 받고, 다음 입력이 오면 진행 중인 연출을 즉시 완료시킨다.**

**`prefers-reduced-motion: reduce`에서 이동 모션을 제거하고 opacity와 색 전환은 유지한다.**

### A-2.7 라이브러리

| 후보 | 판정 |
|---|---|
| **Motion** (`motion/react`) | **채택** — `AnimatePresence` |
| GSAP | 불채택 |
| canvas-confetti | 불채택 |
| 스프라이트 재생 라이브러리 | 불채택 |

**Motion은 exit 애니메이션에만 쓴다** — 화면 전환 crossfade · 손패 카드 퇴장 · 토스트 · 배너.

**press 피드백, 배지 펄스, 바 트윈은 CSS transition으로 만든다.** 합성 카드 획득 같은 다단계 순차 연출은 WAAPI `await el.animate(...).finished`로 만든다.

Motion 사용 시 부하가 보이면 단축 prop(`x`/`y`/`scale`) 대신 full transform 문자열을 쓴다.

### A-2.8 스프라이트 시트

**`transform`으로 프레임을 넘긴다.**

```css
.fx       { overflow: hidden; width: 256px; height: 256px }
.fx > img { animation: sprite 480ms steps(12) forwards }
@keyframes sprite { to { transform: translateX(-3072px) } }
```

- **처음부터 2x로 만들고 CSS에서 반으로 줄인다**
- 12프레임 × 256px = 3072px 폭이면 모바일 텍스처 한계에 근접하므로 세로로 감거나 시트를 나눈다
- 개별 이미지 시퀀스 대신 시트 하나로 만든다
- 프레임 수는 12 안팎으로 한다

### A-2.9 사운드

**Web Audio 30줄로 만든다.** 버퍼를 한 번 디코드하고 재생마다 `AudioBufferSourceNode`를 만든다. 모바일 autoplay는 첫 `pointerdown`에서 `ctx.resume()`으로 푼다.

| 사건 | 런당 | 지침 |
|---|---|---|
| 카드 사용 | ~100 | 아주 짧고 미묘하게 |
| 피격 · 회복 | ~200 | 짧게. 피해량에 따라 피치를 살짝 |
| 토큰 부여 | ~80 | 거의 들리지 않을 정도 |
| 요구 제시 | ~7 | 신의 개입임이 들리게 |
| 역린 개입 | 0~5 | 크게 |
| 합성 획득 | 0~1 | **가장 크게** |
| 승 · 패 | 1 | 런의 마침표 |

**음소거 스위치를 만든다.** 기본값 켜짐, 첫 화면에서 끌 수 있게 한다.

## A-6. 생성 수단 — 구독 토큰

콘텐츠 생성(P-06, P-08, P-11, P-12)과 에이전트 판단(P-16)은 Claude Code 세션에서 나온다.

### A-6.1 파이프라인 구성

| | 담당 |
|---|---|
| 사람이 쓰는 것 | 스키마 · 임계값 · 프롬프트 |
| 카드를 쓰는 것 | Claude Code 세션 |
| 게이트 | `tools/validate.ts` |
| 반송 경로 | 반송 결과를 세션에 다시 넣는다 |
| 증거 | **생성 세션 트랜스크립트** |

**생성 세션 트랜스크립트를 `logs/generation/`에 저장하고 `prompt_version`과 함께 커밋한다.**

**리포트에는 "게이트가 반송하면 반송 사유와 함께 재생성했다"로 적는다.**

### A-6.2 API 경로와의 차이

| | 대응 |
|---|---|
| 구조화 출력 없음 | `dsl_parse` 반송률 상승을 예상한다. ajv 게이트로 잡는다 |
| 프롬프트 캐싱 제어 없음 | 조립 순서를 신경 쓰지 않는다 |
| `effort` · `thinking` 지정 없음 | **한 회차를 한 세션 안에서 끝낸다** |
| `usage` 계측 없음 | **세션 수와 소요 시간**을 기록한다 |
| 처리량이 한도에 묶임 | A-6.3 |

### A-6.3 규모

**생성** — 1회차 약 130회 요청(카드 45 · 합성 50 · 적 20 · 요구 16). 3회차 총 300회 안쪽.

**에이전트** — 전략 층만 판단해 런당 ~30회, 10런으로 300회(P-16).

에이전트 판단 지점: 신 선택 · 조우 전략 · 상충 요구 · 층 경로 · 휴식 · 보상 · 마일스톤. 전투 내 카드 순서와 대상 선택은 룰 봇이 처리한다.

**T-6의 "수십 런" 하단인 10런으로 두고 부족한 부분은 시나리오 주입으로 보완한다.**

### A-6.4 헤드리스 옵션

Claude Code 비대화형 실행 모드가 구독 인증으로 동작하고 한도 안에 들어오면 `tools/`가 이를 호출해 반송 루프를 자동화한다. **먼저 소규모로 확인한다.** 기본은 A-6.1의 반수동 경로다.

### A-6.5 API 전환 조건

아래 중 하나가 관측되면 API 키를 발급한다. 비용은 총 $45 안팎(생성 $14 + 에이전트 $31).

- 에이전트 런을 20 이상으로 늘려야 한다
- 회차를 5회 이상 돌려야 한다
- 반송 루프의 세션 왕복이 회차 수를 제약한다
