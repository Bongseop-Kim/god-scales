본편에 넣고 싶은 충동이 생기면 여기에 적고 넘어간다. 항목과 착수 조건을 함께 적는다.

## B-0. 승격 조건 (공통)

아래를 **모두** 만족한 뒤에 항목을 본편으로 올린다.

1. 축소 우선순위(S-4)에서 버린 것이 없다
2. 파이프라인 루프가 3회차 이상 완주한다
3. 승률 분산이 회차마다 줄어드는 것이 데이터로 확인된다
4. 배포본으로 1런 완주가 매일 재확인되고 있다

---

## B-1. 본선 대비 (최우선 그룹)

| 항목 | 착수 조건 |
|---|---|
| **주제 무관 코어 분리** — `core/`(T-2)를 신화 소재에서 독립시킨다 | **여유 시간 발생 시 즉시** |
| 디렉팅 명세서 초안 | 프롬프트 버전 이력 3세대 이상 |
| 런타임 LLM 에이전트 — 신을 대화 가능한 존재로 | 사전과제 제출 이후. 별도 브랜치 |
| 에이전트 다중 페르소나 (공격적 / 신중한) | 주체별 `fusion_rate` 격차가 한 번 관측된 뒤 |
| 룰 봇 정책 v2 (다중 턴 탐색) | 콘텐츠 동결 후 더 이상 회차가 필요 없어진 뒤 |

---

## B-2. 게임 확장

| 항목 | 착수 조건 |
|---|---|
| 제3신의 일시적 축복 | 요구 발생 빈도·강도가 시뮬로 확정된 뒤. 조합 정체성과 보상 풀(R-10)을 유지하는 형태로 |
| 신 6~7명으로 확대 | 조합당 런 수를 유지하며 시뮬 처리량을 2배 이상 늘린 뒤 |
| `random_enemy` 대상 추가 | 분산 기준선 확보 후 |
| 무작위 적 패턴 (`pattern_mode: random`) | 분산 기준선 확보 후 |
| 조우당 적 4체 이상 | `enemy_count_dist`와 `target_spread` 안정 후 |
| 유물 카테고리 | 카드 통과율 안정 후 |
| 조우 구성을 `encounters.json`으로 분리 | 조우 편성이 적 정의와 독립 생성될 필요가 관측된 뒤 |
| 토큰의 신 간 교차 공유 | 조합 교락 통제(T-7) 작동 확인 후 |
| 역린 개입의 다단계화 | `wrath_recovery`와 역린 체류 비율 안정 후 |
| 상충 요구의 3축 이상 동시 발생 | `conflict_outcomes` 균형 확인 후 |
| 카드별 개별 업그레이드 효과 | `upgrade_rate`와 카드 단위 델타 안정 후 |
| 휴식 노드 업그레이드 선택 (3택) | `rest_choices`가 2택에서 균형인 것 확인 후 |
| 합성 카드 조합당 2장 이상 | `by_pairing` 통과율이 단일 신 카드 수준에 도달 후 |
| 상점·이벤트·보물 노드 | `path_choices` 균형 확인 후 |
| 3번째 구역 / 난이도 단계 | 시뮬 처리량 여유 확보 후 |
| 층 수 확대 / 분기 폭 확대 | `hp_curve`가 사람 플레이테스트로 검증된 뒤 |
| 신 해금 (런 간) | 사전과제 제출 이후 |
| 신의 요구 다양화, 서사 이벤트 | 게임 체감 개선이 병목이 될 때 |
| 런 중 후원 신 교체 | 승률의 측정 단위를 궤적으로 재정의하고 층화를 다시 설계할 수 있을 때 |
| 메타 프로그레션 | 대표 지표를 승률에서 다른 것으로 바꾸고 01부터 다시 쓸 때 |
