# P-36 · 밀어내기 — 자리를 움직이고 자리를 읽는다

`plans/36-shove.md` · [◀ P-35](35-range.md) · [색인](../reviews/00-index.md) · [R-37 ▶](../reviews/37-wire.md)

**크기** 작음 · **착수 조건** **P-35 완료.** 자리가 없으면 밀 곳이 없다

[P-35](35-range.md)가 자리를 만들면 `displace`의 이름이 비로소 사실이 된다. 지금 「밀려남」은 적의 한 턴을 지우는 것이고(`core/rules.ts:143`), 포세이돈의 **밀쳐내기 · 심해 압력 · 격류 밀침** 셋은 이름과 아무 관계 없는 일을 한다.

이 계획은 어휘를 넓히지 않는다. **있는 토큰 하나의 뜻을 자리에 연결하고**, 카드가 자리를 읽게 한다.

---

## 완료 정의

**밀려난 적이 뒤로 한 칸 가고, 앞뒤가 맞바뀌고, 카드가 그 자리를 읽는다.**

```bash
npx tsc --noEmit && npm test
npm run validate -- data/cards.json      # 반려 0 — 값 표를 안 건드리므로 129장이 그대로 통과해야 한다
npm run tune                             # 조합 승률 하한 0.05
npm run e2e
```

| 항목 | 판정 기준 |
|---|---|
| 밀림 | `displace` 소모가 자리를 하나 뒤로 옮긴다. 맨 뒤(칸 3)면 불발 |
| 맞바꿈 | 뒤칸에 적이 있으면 자리를 **맞바꾼다** — 구멍을 만들지 않는다 |
| 값 표 불변 | `tokenWeights.displace = 6`과 `mitigationTokens`가 그대로다. 카드 5장·은혜·게이트가 안 움직인다 |
| 자리 조건 | `slot(target) >= N` DSL이 서고, 그것을 쓰는 카드가 신별로 있다 |
| 화면 | 자리 이동이 **보인다**. 안 보이면 규칙이 아니라 버그로 읽힌다 |

## 설계

### 1 · 밀림은 자리를 옮기고, 턴 스킵은 그대로 둔다

세 가지 길이 있었다:

| 안 | 뜻 | 대가 |
|---|---|---|
| **A (고른다)** | 뒤로 한 칸 **+ 그 턴 스킵 유지** | 값 표·카드·어휘·게이트가 전부 불변. 순수한 상향 |
| B | 스킵을 빼고 이동만 | 무게 6 → 2, `mitigationTokens`에서 제거, 카드 5장 재가격, `pool_ratio` 재측정 |
| C | 즉시 `shove` op으로 승격 | `gods.json` 어휘 · `dslFailure` · `tokenScopeFailure` · 카드 5장이 같이 움직인다 |

**B와 C는 보스전에서 그 다섯 장을 무가치하게 만든다** — 보스는 혼자 서므로 밀 곳이 없다. 지금 그 다섯 장은 보스의 한 턴을 지우는 카드이고, 그것이 무게 6의 근거다(`tools/value.ts:8`). 스킵을 빼면 밀어내기 카드가 「편성이 둘 이상일 때만 쓰는 카드」가 되고, 값 표는 그 조건부를 못 잰다.

**A는 이동을 얹기만 한다.** 토큰 하나가 두 일을 하지만, 그 둘은 같은 그림이다 — 밀려난 적은 자세를 잃고 자리를 내준다.

```
밀기 전   [지킴이] [탱커] [서포터] [사수]
칸 0 밀림  [탱커] [지킴이] [서포터] [사수]     ← 0과 1이 맞바뀐다. 지킴이는 이번 턴 쉰다
```

- 칸 `i` → `i+1`. **`i+1`에 적이 있으면 맞바꾼다**
- 칸 3은 불발이다 — 토큰은 소모되고 아무 일도 안 한다(연쇄가 혼자인 적에게 아무 일도 안 하는 것과 같은 자리, `core/rules.ts:272`)
- **구멍을 만들지 않는다.** 뒤가 비어 있어도 이동이 아니라 맞바꿈이므로 배열 길이가 안 변한다 — 밀어내기로 빈 칸을 만들 수 있으면 [P-35](35-range.md)의 신 입장 규칙이 「밀어내기로 진노한 신을 불러오는」 길이 된다
- 밀림 처리는 **`endTurn` 앞에서 역순(칸 3 → 0)으로 한 번** 돈다. 정순으로 돌면 방금 앞으로 온 적을 같은 턴에 또 밀어 한 카드가 두 칸을 움직인다. 밀린 적 id를 모아 이어지는 적 행동 루프가 건너뛴다 — `takeEnemyTurn`의 `displace` 분기(`core/rules.ts:143`)는 그 자리로 옮겨간다

**여기서 나오는 결정 하나가 이 계획의 값 전부다.** [P-35](35-range.md) §4에서 `guard`는 사거리 안에서만 재지정한다 — **앞칸 지킴이를 뒤로 밀면 앞 셋(`012`) 카드가 지킴이를 지나 때린다.** 밀어내기가 사거리를 여는 열쇠가 되고, 그 대가로 뒷칸 서포터가 앞으로 끌려 나온다.

### 2 · 카드가 자리를 읽는다 — 조건 하나

`evaluateCondition`(`core/rules.ts:162`)에 패턴 하나를 더한다. 여섯 개가 이미 같은 꼴로 서 있다.

```
slot(target) >= 2    # 뒷줄이면
slot(target) < 2     # 앞줄이면
```

- `core/rules.ts`의 `evaluateCondition`에 정규식 한 줄, `tools/validate.ts:63`의 `conditionPatterns`에 한 줄
- 「추격」(`has_token(target, mark) >= 1`, `card_artemis_14`)이 이미 같은 설계다 — 조건부 두 번째 `damage` 효과
- **신마다 성격이 갈린다**: 아르테미스는 `slot(target) >= 2`에서 추가 피해(저격), 아테나는 `slot(target) < 2`에서 추가 방어(앞을 받아낸다), 아레스는 앞칸에서 추가 피해
- 이 조건은 **사거리와 다른 것**이다. 사거리는 닿는지를 정하고 조건은 닿은 뒤 값을 바꾼다. 좁은 사거리 카드에 자리 조건을 또 붙이면 두 번 좁히는 것이라 값이 죽는다 — **둘을 같은 카드에 붙이지 않는다**

### 3 · 데이터 — 제우스 두 장은 이름이 어긋난다

| 카드 | 지금 | 판정 |
|---|---|---|
| `card_poseidon_06` 밀쳐내기 | `displace 1` + 피해 3 | ✓ 이름 그대로 |
| `card_poseidon_10` 심해 압력 | 피해 7 + `displace 1` | ✓ |
| `card_poseidon_retry_02` 격류 밀침 | `displace 1` + 피해 7 | ✓ |
| `card_zeus_08` 마비 벼락 | `displace 1` + 피해 2 | ✗ 마비는 미는 게 아니다 |
| `card_zeus_17` 고압 감전 | 피해 7 + `displace 1` | ✗ |

**이름과 문구를 고친다.** 제우스에게서 `displace` 어휘를 빼는 쪽이 아니다 — `gods.json`의 토큰 어휘를 줄이면 제우스가 `shock` 하나만 남고, `tokenScopeFailure`·`pool_ratio`·풀 생성기가 다 그 표를 읽는다. **문자열 둘이 제일 싸다**(「충격 밀침」·「폭풍 압박」류).

자리 조건 카드는 **신별 1장씩 5장**으로 시작한다. 아홉 사거리 모양이 이미 덱 결정을 만들고 있으므로, 조건 카드는 그 위에 얹는 소금이다.

### 4 · 화면 — 이동이 보여야 규칙이다

적이 자리를 바꾸는데 화면이 그냥 다시 그려지면 플레이어는 **적이 바뀐 줄 안다.**

- `ui/combat.tsx:79`의 적 버튼에 `motion`의 `layout`을 붙인다 — 자리 순서만 바뀌면 그 사이를 미끄러진다. 라이브러리는 이미 들어 있다(`motion/react`)
- `prefers-reduced-motion`에서는 즉시 이동한다 — 이미 `useReducedMotion`으로 갈라 두는 자리다(`ui/combat.tsx:62`)
- **밀림 배지의 툴팁을 고친다** — 「다음 턴에 쉬고 뒤로 밀린다」. 지금 문구는 스킵만 말한다(`ui/tokens.tsx`)
- 자리 조건 카드의 캡션은 조건문을 그대로 쓴다(「뒷줄이면 +4」) — `effectText`가 이미 `when`을 그리는 자리다

### 5 · 배선

| 자리 | 무엇 |
|---|---|
| `core/combat.ts` `endTurn` | 밀림 역순 루프 + 스킵 집합, `firePowers("turn_end")` 뒤 |
| `core/rules.ts:143` `takeEnemyTurn` | `displace` 분기를 위로 옮긴다 |
| `core/rules.ts:162` | `slot(target)` 조건 |
| `core/favor.ts:19` | `globalParamVersion` **v8** (P-35이 v7) |
| `test/freeze.test.ts` | 버전 문자열 |
| `tools/validate.ts:63` | `conditionPatterns` 한 줄 |
| `ui/combat.tsx` · `ui/tokens.tsx` | `layout` 이동, 밀림 툴팁 |
| `data/cards.json` | 제우스 두 장 이름·문구, 자리 조건 5장 |

**봇 정책은 안 건드린다.** `cardValue`가 `displace`를 `tokenWeights`로 세고 그 무게가 안 바뀌므로 `botPolicyVersion`은 v8(P-35) 그대로다 — 봇이 밀어내기로 지킴이를 치우는 것까지 배우게 하는 것은 이 계획의 일이 아니다. **그래서 실측 승률은 사람이 얻을 값의 하한이다**(리뷰에 그렇게 적는다).

## 함정

- **정순 루프는 한 카드로 두 칸을 민다.** 역순(칸 3 → 0)이 그것을 구조적으로 막는다. 테스트로 못 박는다 — 앞칸 둘이 같은 턴에 밀리는 판이 그 시험이다
- **맞바꿈은 `patternIndex`를 데려간다.** 배열 요소를 통째로 바꾸므로 상태·토큰·패턴 진행이 다 따라간다. `definitions.get(enemy.id)`는 id로 읽으므로 무해하다(`core/combat.ts:129`)
- **`guard`가 앞뒤로 오가면 봇 정렬이 흔들린다.** `chooseTarget`은 체력만 보고 고르므로(`sim/bots/rule.ts:229`) 지킴이 위치 변화를 못 읽는다 — 봇 승률이 사람 승률보다 낮게 나오는 자리이고, 하한을 그것 때문에 못 넘으면 봇을 고치는 게 맞다
- **스킵이 남아 있으므로 밀어내기는 순수한 상향이다.** 승률이 오르면 상한(0.7)이 아니라 `저휴식 클리어` 쪽이 먼저 움직인다 — [R-34](../reviews/34-tempo.md)가 상한 0.24로 잡아 둔 지표다. 다이얼은 `displace` 스택을 주는 카드 수뿐이다
- **자리 조건과 좁은 사거리를 같은 카드에 붙이지 않는다.** 둘 다 좁히므로 `expectedValue`가 통과시킨 값이 실제로는 절반이 된다
- **밀림이 빈 칸을 만들면 진노가 공짜로 등장한다.** 맞바꿈을 쓰는 유일한 이유다 — 「뒤가 비면 이동」으로 슬쩍 바꾸는 순간 [P-35](35-range.md)의 입장 규칙이 뚫린다
