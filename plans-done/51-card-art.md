# P-51 · 카드 179장 전부에 제 그림을 — 카드별 아트

`plans/51-card-art.md` · [색인](../reviews/00-index.md) · 관련 [P-32](../reviews/32-art.md) §3 · [R-41](../reviews/41-cardface.md)

**크기** 큼(에셋 169장 생성) · **착수 조건** 없음. 코드 변경은 `tools/art.ts` 숫자 하나와 주석뿐이다.

지금은 그림 30장이 카드 179장을 덮는다 — attack 5장이 103장(58%)을 덮어, 손패에 같은 신 공격 카드가 여러 장 오면 이름으로만 갈린다. 카드 게임에서 그림은 카드의 얼굴이다. **매핑 규칙은 안 바꾼다**: `cardArtCandidates`(`ui/art-keys.ts:16`)가 id 정확 일치를 이미 첫 후보로 시도하므로, `art/cards/{card_id}.webp`를 놓기만 하면 화면·게이트 양쪽에서 그 그림이 잡힌다. 코드 0줄로 굴러가는 계획이 맞는 계획이다.

- 신규 생성 **169장** = 179 − 융합 10(카드별 아트 이미 완료)
- 기존 `{god}_{tag}` 20장은 **롤아웃 동안 폴백으로 살아 있다** — 다 채운 뒤에만 지운다

## 완료 정의

**전투 손패·보상·덱 화면에서 같은 신 카드들이 그림으로 구분되는 것을 `aside`로 눈으로 확인한다** (브라우저 확인은 `aside` CLI로만 — CLAUDE.md).

```bash
npx tsc --noEmit && npm test
npm run art -- --check      # cards 179/179 · required_missing=0 · 대조 위반 0
npm run size                # 4MiB 상한 통과 — 이 계획의 유일한 빡빡한 게이트
```

| 항목 | 판정 기준 |
|---|---|
| 에셋 | `art/cards/{card_id}.webp` 179장, **320×240** q80 WebP. 원본 PNG(1536×1024)는 전부 `art/_src/cards/`에 남는다 |
| 용량 | 전체 번들 ≤ 4MiB. 계산: 현재 3.22MiB − 카드분 0.51MiB + 179장×~6KB ≈ **3.8MiB**. 장당 10KB를 넘으면 q를 내리지 말고 프롬프트(어두운 면적)를 고친다 |
| 화면 | `--card-w: 140px`(`ui/style.css:35`) → 아트 슬롯 약 124×93, DPR 2에서 248×186. 320×240이 그 1.3배다 — P-32의 512×384(2.9배)에서 줄이는 건 **179장이 4MiB에 앉아야 하기 때문**이고, `aside`로 실기 확인이 판정이다 |
| 스타일 | 기존 30장과 같은 문법 — 태그=형태, 신=색, `#11131a` 배경, 굵은 먹선. 89px 축소에서 형태가 읽힌다 |
| 게이트 | 밸런스 불변(규칙·데이터 무변경). `tools/art.ts:37`의 `made: 30` → `179`만 갱신 |

## 설계

### 1 · 프롬프트 — 문법은 유지하고 주제문만 카드별로 간다

기존 프롬프트는 「주제문 1문단 + 고정 꼬리(구도·스타일·조명·금지)」 구조고, 꼬리는 `art/_src/gen-docs.mjs`의 `CARD_TAIL`·`ONE_HUE`에 이미 있다. **바뀌는 건 주제문뿐이다.**

- `art/_src/cards/subjects.json` 신설: `{ "card_zeus_01": "A single small thunderbolt ...", ... }` 169개. 카드 이름·효과에서 도출한 **영어 한 문단**씩
- `gen-docs.mjs`에 조립 한 단 추가: `data/cards.json`을 읽어 카드별로 `주제문 + CARD_TAIL(ONE_HUE(신 색))`을 뽑는다. 신 색 5종·융합 2색 규칙은 기존 표 그대로
- **구별 규칙**: 같은 신+태그 묶음 안에서 주제문마다 **모티프 명사가 달라야 한다**(번개의 크기·각도 변주는 실패, 번개/사슬/폭풍구름/창공의 균열은 통과). 태그별 형태 어휘는 유지 — attack=타격하는 무기·힘, defend=방벽·수호물, token=낙인·인장, utility=그릇·손·불꽃
- `power` 태그 카드(5장 내외)는 다음 태그의 형태 어휘를 쓴다 — 지금 폴백과 같은 규칙

### 2 · 파일럿 — 제우스 스타터 덱으로 끝까지 완주

`godDecks`(`sim/engine.ts`)의 제우스 스타터 카드들로 생성 → 변환 → `art --check` → `aside` 확인을 먼저 완주한다. 스타터가 게이트의 `required` 집합이라 순서도 이득이다.

파일럿 판정: 손패에서 스타터끼리 그림으로 갈리고, 기존 30장과 **같은 화면에 섞여도 톤이 안 튀면** §3으로. 톤이 튀면(더 밝다/채도가 높다/먹선이 얇다) 멈추고 사용자에게 보고한다 — 169장을 뽑는 것은 그 판단 뒤다.

### 3 · 물결 — 신별 배치로 169장

한 물결 = 신 하나(31~40장). 물결마다:

1. `gen-docs.mjs`가 뽑은 프롬프트로 GPT-image 2.0 `1536×1024` 생성 → `art/_src/cards/{card_id}.png`
2. 변환 — **입력과 출력이 다른 경로다**(art/README.md 규칙 3):
   ```
   magick art/_src/cards/{card_id}.png -gravity center -crop 1365x1024+0+0 +repage \
     -filter Lanczos -resize 320x240! -quality 80 art/cards/{card_id}.webp
   ```
3. 검증 — **`/tmp`에만** 깎아 본다: `magick art/cards/{id}.webp -resize 89x67! /tmp/t.png`. 같은 신 카드들을 나란히 놓고 형태가 갈리면 통과. 신 색 면적 25% 초과·흰 코어·제3의 색은 재생성
4. `npm run art -- --check && npm run size` — 물결마다 돌린다. 중간 상태에서도 폴백 20장이 살아 있어 항상 통과해야 정상이다

### 4 · 마무리 — 폴백 삭제와 융합 재인코딩

179/179가 된 뒤에만:

- `{god}_{tag}` 20장 삭제(webp+사이드카) — id 일치가 항상 먼저 걸려 이미 안 쓰이지만, 지우면 번들 ~0.35MiB가 돌아온다
- 융합 10장도 512×384 → 320×240으로 재인코딩해 규격을 하나로 — 원본이 `art/_src/`에 없으므로(사이드카 명기) **배포 webp를 입력으로 `/tmp` 경유** 재인코딩하고 원본은 안 건드린다
- `tools/art.ts:37` `made: 30` → `179`, `:32` 폴백 주석 갱신. `ui/art-keys.ts:9`·`ui/card.tsx:16`의 「149장→30장」 주석도 실상으로
- 사이드카: 카드별 179장을 손으로 안 쓴다 — `gen-docs.mjs`가 프롬프트·변환 명령을 담아 일괄 생성하고, 손 작성 템플릿(`zeus_attack.md`)은 「20장 규칙」 문서로 이름만 남긴다

### 함정

- **원본 소실** — `art/**`에 `-resize`를 직접 걸거나 입출력을 같은 경로로 쓰면 P-32 사고 재발. 변환 입력은 항상 `art/_src/`
- **`patron_pair` 순서** — 융합은 건드리지 않는다. 순서 뒤집기 폴백을 넣지 않는 결정(R-32)도 그대로
- **4MiB** — 물결 중간에 초과하면 그 물결에서 멈추고 원인(밝은 면적 큰 그림)을 고친다. 상한을 올리는 건 이 계획의 선택지가 아니다
- **커밋 금지** — 사용자가 시킬 때만(CLAUDE.md)
