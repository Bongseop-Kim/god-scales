# P-47 · 진노 — 신을 꺾어 화해한다

`plans/47-wrath.md` · [◀ P-46](46-presence.md) · [색인](../reviews/00-index.md) · 형제 [P-48](48-voice.md)

**크기** 중간 · **착수 조건** [P-46 §1](46-presence.md)(배분) — 배분이 없으면 진노에 닿는 사람이 없다(현행 도달률 0.005). P-46의 §2 이후(화면)와는 병행 가능하다

[P-46](46-presence.md)이 함정으로 남긴 한 줄을 닫는다:

> **100:0이 지배 전략일 수 있다.** 헌신 개입은 게이트가 순이득임을 강제하는데(`stageEffectScopeFailure`) 진노의 대가는 적 하나가 느는 것이다 — 12층 내내 헌신 상한을 유지하는 값이 신 적 하나보다 크면 배분에 결정이 없다

**대가를 키운다.** 그리고 그 대가를 **이길 수 있게** 만들어서 도박으로 바꾼다 — 진노는 처벌이 아니라 **판돈**이다.

---

## 0 · 지금 진노가 무엇인지부터

계획 셋의 전제라 코드로 확인한 것만 적는다.

### 진노 신은 잡졸 1.5마리다

| 적 | hp | 패시브 |
|---|---:|---|
| 잡졸 (`enemy_under_*`) | 35~40 | 하나 |
| **진노 신** (`enemy_god_*`) | **60** | 하나 |
| 저승 보스 케르베로스 | 130 | `ward 2` |
| 지상 보스 아르고스 | 190 | `ward 2` |

**신이 잡졸보다 1.5배다.** 「신이 적으로 합류한다」가 화면에서 사건인데 판 위에서는 잡졸 한 마리 반이다.

### 잡아도 보상이 없다

조우 보상은 **노드 종류**가 정한다 — `tier2Slots(path)`는 `elite`·`boss`에만 3을 준다(`sim/engine.ts:99`). 신을 얹은 `combat` 노드는 여전히 `combat`이라 tier2가 0이다. **신을 잡는 것과 잡졸을 잡는 것의 보상이 같다.**

### 매 조우 또 나타난다 — 호의는 리셋되지 않는다

`applyFavorStageEffects`가 **조우마다** 돌고(`sim/engine.ts:285`) 진노 단계의 `on_encounter_start`에 `join`이 있다. `queueEnemy`의 중복 방지는 `combat.pending`·`combat.enemies`를 보는데(`core/combat.ts:94`) `createCombat`이 조우마다 그 둘을 새로 만든다 — **한 전투 안에서만 막는다.**

그리고 호의 0은 잘 안 올라온다: 감쇠 −3에 카드 +1(조우당 5 상한)이라 그 신 카드로만 덱을 굴려야 조우당 +2다. 0 → 10(분노)이 **다섯 조우**고 그동안 다른 신을 버리게 된다.

**즉 지금 100:0은 「12층 내내 매 조우 잡졸 한 마리 반이 더 붙는다」**이다. 사용자의 의문에 대한 답이고, 이 계획이 바꿀 자리다.

### 90:10은 진노가 아니다

```ts
export const favorBoundaries = { devotion: 70, calm: 30, anger: 10, wrath: 0 } as const;
// favorStage: >= 10 이면 anger
```

**진노는 0~9다.** 10은 분노의 **하한**이고, 90:10은 헌신 + **분노**다. 진노로 시작하려면 **91:9 이상**이다.

## 완료 정의

**100:0으로 시작한 런에서 1조우에 보스보다 강한 신이 서고, 그 신을 꺾은 런이 실제로 존재한다.**

```bash
npx tsc --noEmit && npm test
npm run validate -- data/enemies.json data/gods.json
npm run tune                              # 조합 승률 하한 0.05 — 이 계획의 유일한 밸런스 게이트 (CLAUDE.md)
npm run sim -- --runs 2000 --split 100    # 게이트가 아니다. 아래 「가능성」 한 줄만 본다
npm run e2e
```

| 항목 | 판정 기준 |
|---|---|
| 스펙 | 진노 신 다섯이 지역 보스(130)보다 **위**다 |
| **가능성** | `--split 100` 2000런에 **승리 런이 하나 이상 있다.** 0이면 시드를 바꿔 한 번 재확인하고, 그래도 0이면 되돌린다 |
| 화해 | 진노 신을 쓰러뜨리면 그 신 호의가 **평온 구간으로** 돌아온다 — 다음 조우에 다시 안 선다 |
| 찢기 | 진노인 신의 카드를 내면 **효과는 나가고 그 카드가 덱에서 사라진다** |
| 보상 | 진노 신을 잡은 조우가 **tier2 3장**을 준다 (`elite`와 같은 대우) |
| 대사 | `join`·`reconcile`·`tear` 세 트리거 이름을 [P-48](48-voice.md)에 넘긴다 — 줄은 저쪽이 쓴다 |
| 게이트 | 조합 승률 하한 하나. **`--split 100`의 숫자로 값을 깎지 않는다** |

**「가능성」은 밴드가 아니다.** 「0이 아니다」는 새 지표도 회차 비교도 아니고 **불가능하지 않다는 증명**이다 (CLAUDE.md). 승률이 0.02든 0.08이든 판정은 같다.

## 설계

### 1 · 꺾으면 화해한다 — 반복을 이걸로 끊는다

`join`이 매 조우 반복되는 것을 그대로 두면 100:0은 도박이 아니라 사형이다. 반대로 「한 런에 한 번」 플래그를 두면 상태가 하나 늘고, 그 상태는 replay·화면·게이트 세 곳이 알아야 한다.

**셋 다 아니다. 신을 쓰러뜨리면 호의가 회복된다.**

```ts
/**
 * 진노한 신을 판 위에서 꺾으면 그 신이 물러난다 — 호의가 평온 하한으로 돌아오고 다음 조우에는
 * 다시 서지 않는다. **반복을 끊는 상태를 따로 만들지 않는다**: 반복의 원인이 호의였으므로 호의를
 * 올리는 것이 곧 반복을 끊는 것이다. 플래그를 두면 replay·화면·게이트가 그 플래그를 다 알아야 한다
 */
export const wrathReconcileFavor = favorBoundaries.calm; // 30
```

이 한 줄이 사용자의 요구를 그대로 만든다 — **「해치우면 이후 난이도가 쉬워지는 데 기여한다.」** 개입이 진노(적 회복·신 합류)에서 평온(작은 도움)으로 바뀌는 것이 가장 큰 보상이다.

**30으로 돌린다. 50이 아니다.** 50은 「아무 일도 없었던 것」이고 30은 평온의 **하한** — 감쇠 −3이 열 조우 만에 다시 진노로 데려간다. 화해는 휴전이지 우정이 아니다.

죽음을 잡는 자리는 하나다. `updateOutcome`이 이미 적의 죽음을 거두므로(`core/combat.ts`) 거기에서 `enemy_god_` 접두사를 읽는다 — id 규칙은 `godEnemyId`가 이미 정본이다(`core/favor.ts:63`).

> ⚠ `core/combat.ts`는 `core/favor.ts`를 import할 수 없다 — `favor.ts`가 `queueEnemy`로 그 파일을 이미 읽어 순환이 된다(`core/combat.ts:242` 주석이 같은 이유를 적고 있다). **엔진이 잇는다**: 조우가 끝나면 `playEncounter`가 쓰러진 신 id를 돌려주고 `runSteps`가 `shiftFavor`를 부른다.

### 2 · 스펙을 보스 위로 — 숫자 하나와 패시브 하나

사용자 요구: **최종 보스보다 어렵되 불가능하지 않게.**

숫자만으로 그것을 만들지 않는다. **진노 신은 이미 문맥으로 보스보다 어렵다** — 보스는 12층 덱으로 만나고 진노 신은 **1층 덱 15장으로** 만난다. 같은 hp라도 그쪽이 훨씬 어렵고, 반대로 후반에 만나면 이길 만하다. 그래서 「불가능하면 안 된다」가 자동으로 지켜진다.

그 위에 두 가지를 올린다:

| 항목 | 지금 | 바꿀 값 | 근거 |
|---|---:|---:|---|
| hp | 60 | **140** | 지역 보스 130 **위**, 최종 보스 190 아래. 190을 넘기면 1층에서 산술적으로 못 깎는다 |
| 패시브 | 하나 | **둘** (기존 + `ward 2`) | 보스 둘이 `ward 2`를 공유한다 — 「보스급」의 기존 어휘다 |

#### 카드 찢기 — 진노한 신은 자기 카드를 거둔다

「신을 버려 놓고 그 신의 카드를 쓴다」의 대가다. 100:0으로 시작해 제우스를 0에 두면 제우스 카드가 덱 절반이다(`ruleDeck`이 후원 둘의 카드로 짠다).

```
진노(호의 0~9)인 신의 카드를 낸다 → 효과는 그대로 나간다 → 그 카드가 덱에서 사라진다
```

**효과는 나간다.** 안 나가면 손패를 클릭했는데 아무 일도 안 일어난 것이고, 그건 연출이 아니라 버그로 읽힌다. 신은 힘을 빌려준 뒤 **거둬 간다** — 그게 「찢는다」의 그림이다.

훅은 이미 있다. `sim/engine.ts:399`가 카드를 낼 때 이미 어느 신의 것인지 읽는다(`if (card.patron) recordCardFavor(...)`) — 그 옆에서 `favorStage(favor[card.patron]) === "wrath"`를 보고 덱에서 뺀다. **새 관측도 새 스트림도 없고**, 제거는 결정론이라 replay가 안 흔들린다.

찢기가 이 계획에 있는 이유: **진노 경제의 판돈은 hp·화해·찢기 셋이 한 몸이고, 「가능성」 한 줄이 셋을 한 번에 재야 한다.** 표현 계획(P-48)에 두면 밸런스를 흔드는 규칙이 게이트 없는 계획에 앉는다. 벌은 이것 하나다 — **한 행동에 벌이 둘이면 하나는 안 보인다**(적이 조금 세지는 `frenzy`류는 안 얹는다). L3 「외침」 연출과 `tear` 대사는 [P-48](48-voice.md)이 얹는다.

덱이 줄어드는 것이 100:0의 진짜 판돈이다: **버린 신의 카드를 안 쓰고 이길 수 있는가.**

#### 값은 게이트가 정한다

hp 140·`ward 2`는 **후보**다. `npm run tune`의 조합 승률 하한 0.05는 50:50에서 도는 것이라 이 값에 안 걸린다 — 그러니 걸리는 것은 「가능성」 한 줄뿐이다. **`--split 100`에서 승리 런이 0이면 찢기 → hp 순으로 되돌린다(규칙이 숫자보다 먼저다). 0이 아니면 그 숫자로 더 깎지 않는다.**

### 3 · 보상 — 신을 잡은 조우는 정예다

지금 신을 잡아도 tier2가 0이다. `tier2Slots`가 노드 종류만 보기 때문이다(`sim/engine.ts:99`):

```ts
const tier2Slots = (path: MapNodeType): number => (path === "elite" || path === "boss" ? 3 : 0);
```

**노드 종류를 바꾸지 않는다** — 지도의 칸은 지도가 정하고, 진노는 지도가 모르는 일이다. 인자를 하나 더 받는다:

```ts
/** 신을 꺾은 조우는 정예와 같은 보상을 준다 — 판 위에서 실제로 정예였다 */
const tier2Slots = (path: MapNodeType, feltGod = false): number => (feltGod || path === "elite" || path === "boss" ? 3 : 0);
```

보상 셋:

| 무엇 | 값 |
|---|---|
| 호의 | 0 → **30** (§1) — 개입이 진노에서 평온으로 |
| 카드 | **tier2 3장** 제시 (정예 대우) |
| 은혜 | **주지 않는다** — 은혜는 헌신이 주는 것이고(`awardGrace`) 진노가 은혜를 주면 두 단계가 같은 문을 연다 |

### 4 · 대사는 [P-48](48-voice.md)이 짓는다

진노의 합류·격파·찢기는 신이 가장 말을 해야 하는 자리지만, 그 말은 **여기서 만들지 않는다.** 트리거 아홉 · 레벨 셋 · 신당 29줄이 [P-48](48-voice.md)의 몸통이고, 이 계획이 그중 셋(`join` · `reconcile` · `tear`)만 따로 만들면 대사 데이터가 두 자리에 앉는다.

이 계획이 P-48에 넘기는 것은 **트리거 이름 셋**이다:

| 트리거 | 언제 | 이 계획이 만드는 순간 |
|---|---|---|
| `join` | 진노 신이 판에 선다 | §1의 `queueEnemy` → `admitPending` |
| `reconcile` | 진노 신이 쓰러진다 | §1의 화해 (호의 0 → 30) |
| `tear` | 진노인 신의 카드를 낸다 | §2의 찢기 |

**순서는 어느 쪽이 먼저여도 깨지지 않지만 이 계획이 먼저가 낫다.** P-48이 먼저면 그 세 트리거가 데이터에만 있고 안 터진다(게이트가 「최소 한 줄」만 보므로 통과한다). 이 계획이 먼저면 세 순간이 잠시 말 없이 지나간다 — P-46의 컷인이 그림은 띄우고, P-48이 오면 줄이 산 트리거 위에 앉는다.

### 5 · 배분 슬라이더가 경계를 가르쳐야 한다

진노는 **0~9**고 배분 슬라이더는 0~100이다. 진노 구간이 슬라이더의 **9%**뿐이라 우연히 밟히지 않고, 그건 의도대로다 — 진노는 극단이어야 한다.

다만 P-46 §1의 슬라이더가 그 경계를 **보여줘야** 한다. 이미 계획에 있는 것이고 여기서 값만 못 박는다:

```
제우스 ◀━━━━━━━━━━━━━━━━━━━━━━━━━●▶ 아테나
  91 · 헌신                      9 · 진노
       ╵         ╵      ╵    ╵
      70        30     10    0     ← 눈금 넷
```

라벨이 단계 이름을 실시간으로 든다 — 「9 · 진노」와 「10 · 분노」가 슬라이더를 미는 동안 바뀐다. **그 라벨이 이 축을 가르치는 유일한 문서다.**

## 함정

- **화해가 반복을 못 끊을 수 있다.** 호의 30에서 감쇠 −3이면 열 조우 뒤 다시 0이다. 12층 런에 진노가 **두 번**까지 올 수 있고 그건 의도다 — 세 번 이상 오면 그때 상한을 본다. 지금 값에 상한을 미리 붙이지 않는다
- **`core/combat.ts` → `core/favor.ts` import는 순환이다.** 죽음을 거두는 자리에서 `shiftFavor`를 직접 못 부른다. 엔진이 잇는다 (§1)
- **hp 140이 100:0을 못 이기게 만들 수 있다.** 「가능성」이 그것을 잡는 유일한 검사다. 0이면 **찢기를 먼저** 되돌리고, 그래도 0이면 hp를 내린다 — 규칙이 숫자보다 먼저다
- **「가능성」은 봇의 상한이지 게임의 상한이 아니다.** 봇은 찢긴 카드를 아껴 쓸 줄 모른다 — 사람은 이기는데 봇이 0일 수 있다. 그리고 참 승률이 0.3%면 600런에서 0승이 나올 확률이 17%다. **2000런인 이유고, 0이 곧 롤백이 아니라 시드를 바꿔 재확인이 먼저인 이유다**
- **`--split 100`의 승률을 게이트로 승격시키고 싶어진다.** 하지 않는다 (CLAUDE.md). 「0이 아니다」까지고, 그 위의 숫자는 리뷰에 적는 것이지 판정하는 것이 아니다
- **은혜를 진노에도 주고 싶어진다.** 그러면 헌신과 진노가 같은 문을 열고, 배분의 양 끝이 같은 보상을 준다 — 축이 사라진다

## 안 하는 것

- **진노 전용 조우 밴드를 만들지 않는다.** [R-30](../reviews/30-intervention.md)이 정한 2번 — 게이트가 얹은 뒤의 조우를 `groupStrength`로 합성해서 잰다. 런타임 제약(하한 편성에만 얹는다)을 남기면 플레이어가 갈래 선택으로 처벌을 피하고, 그러면 처벌이 아니다
- **「한 런에 한 번」 플래그를 만들지 않는다.** 반복의 원인이 호의였으므로 호의로 끊는다 (§1)
- **진노 신 다섯의 패턴을 다시 짜지 않는다.** 지금 넷씩 있고 신마다 다르다 — hp와 패시브 둘만 올린다
- **대사를 이 계획이 쓰지 않는다.** 트리거 이름 셋만 넘긴다 — [P-48](48-voice.md)이다
