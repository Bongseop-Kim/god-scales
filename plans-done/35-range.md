# P-35 · 거리 — 적 4칸 · 카드 사거리 · 자리가 정하는 역할 · 빈 자리로 들어오는 신

`plans/35-range.md` · [◀ P-33](33-icons.md) · [색인](../reviews/00-index.md)

**크기** 큼 · **착수 조건** 없음. 규칙·데이터·화면·봇을 한 번에 건드리므로 P-32·P-33(그림)과 겹치지 않는다

**[R-37](../reviews/37-wire.md)이 먼저 끝났다.** `.enemy`에 96px 스프라이트가 이미 서 있다 — **열이 아니라 이름 위 한 줄이다**(405px 칸에서 `nowrap`인 의도가 넘쳐서). 칸을 넷으로 늘릴 때 그 줄을 칸마다 그대로 복제하면 된다. 파일은 `art/sprites/{enemy.id}.webp`고 없는 적은 스프라이트 없이 지금 모양 그대로 뜬다

조우에 **자리**를 만든다. 지금 `combat.enemies`는 순서 없는 목록이고 모든 공격 카드가 아무 적에게나 닿는다 — 대상 선택이 「체력 낮은 놈」 하나뿐인 이유다(`sim/bots/rule.ts:229`).

자리가 생기면 결정이 셋 늘어난다. **어느 칸을 먼저 뚫는가**(앞 탱커냐 뒷 화력이냐), **어떤 사거리를 덱에 넣는가**, 그리고 진노한 신이 **들어설 자리가 있는가**([R-30](../reviews/30-intervention.md) §2, 색인의 「진노 콘텐츠가 없다」).

## 완료 정의

**적이 넷까지 서고, 앞칸은 단단하고 뒷칸은 아프고, 카드가 닿는 칸이 갈리고, 자리가 없으면 신이 문 앞에서 기다린다.**

```bash
npx tsc --noEmit && npm test
npm run validate -- data/enemies.json    # 반려 0
npm run tune                             # 조합 승률 하한 0.05
npm run e2e                              # 12층 완주 + 여덟 화면 1440px
```

| 항목 | 판정 기준 |
|---|---|
| 4칸 | 편성 4인이 최소 한 층에 서고, 다섯째는 `createCombat`이 던진다 |
| 사거리 | 아홉 모양이 데이터에 다 쓰이고, 닿지 않는 적은 대상 목록에 없다 |
| 자리별 역할 | 역할이 자리를 정하고 **게이트가 어긋난 편성을 반려한다** |
| 앞을 뚫는 값 | `guard` 재지정이 사거리를 못 넘는다 — 뒤를 노리는 카드가 지킴이를 지나간다 |
| 신의 입장 | 4칸이 꽉 차면 대기, 적이 죽어 빈 칸이 생기면 **그 칸**에 선다 |
| 게이트 | `npm run tune` 하한만 본다. 새 지표·밴드를 만들지 않는다 (CLAUDE.md) |
| 화면 | 4칸이 1440px에서 안 넘치고, 카드가 닿는 칸을 그린다 |

## 설계

### 1 · 자리는 배열 인덱스다 — 새 필드를 만들지 않는다

`combat.enemies`는 이미 배열이고 시체가 `hp: 0`으로 남는다(`core/combat.ts:166`이 그것으로 승리를 잰다). **인덱스가 곧 칸이다.**

```
칸 0      칸 1      칸 2      칸 3
앞 ←—————————————————————————→ 뒤
```

- **0이 앞**(플레이어와 가까운 쪽), **3이 뒤**
- 죽은 적은 자리를 비운 채 배열에 남는다 — **아무도 밀려 오지 않는다**. StS와 같고, 그래야 「빈 칸」이 신이 들어설 자리로 그대로 쓰인다
- `EnemyState`에 `slot`을 넣지 않는다. 두 번째 진실이 된다
- 편성의 순서가 곧 배치다 — `data/enemies.json`의 `groups[].with` 순서가 칸 1·2·3이다. **`null`을 허용해 칸을 비운다**(`["enemy_a", null, null, "enemy_b"]`) — 그래야 `03` 같은 사거리가 뜻을 갖는다
- 상한 4는 `createCombat`이 던져서 지킨다(`core/combat.ts:29`). 게이트도 `with.length <= 3`을 본다

`MAX_SLOTS = 4`를 `core/combat.ts`에 상수로 둔다 — `laneCount`가 3을 박아 둔 것과 같은 자리다.

### 2 · 사거리는 마스크 문자열이다 — 모양 표를 코드에 두지 않는다

`Card`에 `reach?: string`을 더한다. 값은 **닿는 칸을 오름차순으로 적은 숫자열**이다. **없으면 `"0123"`** — 배포된 카드 129장이 한 줄도 안 바뀐다.

| `reach` | 이름 | 그림 | 쓰임 |
|---|---|---|---|
| `0123` | 전체 | ▮▮▮▮ | 기본값 |
| `0` | 앞 한 칸 | ▮▯▯▯ | 근접 대형 무기 — 아레스 도끼·처형 |
| `01` | 앞 둘 | ▮▮▯▯ | 휩쓸기 |
| `012` | 앞 셋 | ▮▮▮▯ | 광역의 기본형 — 포세이돈 격랑·소용돌이 |
| `12` | 가운데 둘 | ▯▮▮▯ | 앞을 지나쳐 허리를 끊는다 |
| `123` | 뒤 셋 | ▯▮▮▮ | 앞 탱커만 빼고 전부 |
| `23` | 뒤 둘 | ▯▯▮▮ | 서포터 사냥 |
| `3` | 뒤 한 칸 | ▯▯▯▮ | 저격 — 아르테미스 관통·급소 |
| `03` | 양 끝 | ▮▯▯▮ | 앞뒤를 동시에 — 제우스 연쇄 계열 |

```ts
// core/targeting.ts
export const reachSlots = (reach = "0123"): number[] => [...reach].map(Number);
// 규칙은 정규식 하나다 — 모양을 표로 두면 열째 모양이 코드 수정이 된다
export const reachOk = (reach: string) => /^[0-3]{1,4}$/.test(reach) && [...reach].every((d, i, all) => i === 0 || d > all[i - 1]);
```

이름과 그림은 **화면에만** 있는 표다(`ui/card.tsx`) — 아홉 개에 한글 이름을 주고, 모르는 마스크는 `칸 0·3` 꼴로 떨어진다.

- `resolveTargets`가 사거리로 한 번 더 거른다 — `enemy`는 고른 적이 사거리 안이어야 하고, `all_enemies`는 **사거리 안의 산 적 전부**다
- `resolveChainTargets`도 같은 필터를 탄다. 연쇄가 사거리를 넘으면 `0` 카드가 전체 공격이 된다
- **사거리 밖만 남은 `target: enemy` 카드는 낼 수 없다.** `resolveTargets`가 던지는 대신 `sim/engine.ts:278`의 `affordable`에서 빠진다 — 손패에서 비활성으로 뜬다. `all_enemies`는 그대로 낼 수 있고 아무도 안 맞는다(적이 다 죽은 지금과 같다)
- 적의 행동에는 사거리를 주지 않는다. 뒷칸 적도 지금처럼 플레이어를 친다 — **적 사거리는 안 만든다.** 앞을 뚫는 값은 아래 `guard`가 만든다

**신별 3장씩 15장 + 융합 10장에 붙인다.** 아홉 모양이 하나도 안 쓰이면 안 되므로 그 조건을 게이트가 아니라 **완료 정의**가 본다.

### 3 · 자리가 역할을 정한다 — 런타임 보정이 아니라 배치 규칙이다

앞은 단단하고 뒤는 아프다. 이것을 **자리 보정(칸 0·1은 방어 +N)** 으로 만들지 않는다 — 그러면 배포된 편성 전부가 재측정 대상이 되고, 어느 값이 적의 것이고 어느 값이 자리의 것인지 화면에서 못 읽는다.

**역할이 이미 그 성격을 들고 있다.** `data/enemies.json`의 아홉 역할에 자리를 붙이고, 게이트가 어긋난 편성을 반려한다:

| 역할 | 허용 칸 | 성격 | 지금 데이터 |
|---|---|---|---|
| `guardian` | 0·1 | 방어·보루·`guard` | `guard 2`, 보루 3 |
| `attrition` | 0·1 | 고체력·`shell` | `shell 8`, 방어 4 |
| `brute` | 0·1 | 고체력·근접 대형 피해 | 피해 16, `angry` |
| `swarm` | 0·1 | 다수·저체력 | 체력 25 ← **올린다** |
| `pressure` | 2·3 | 커지는 피해 | `ramp 1`, 6→6→12 |
| `applier` | 2·3 | 토큰 살포 | — |
| `support` | 2·3 | `ally` 회복·방어 | `target: "ally"`가 이미 있다(`core/combat.ts:117`) |
| `zealot` | 2·3 | 자해·폭발 피해 | — |
| `boss`·`god` | 어디든 | 혼자 서거나 자리를 고른다 | — |

**데이터를 자리에 맞춘다** — 앞 넷의 체력·방어를 올리고 뒤 넷의 피해·토큰을 올린다. 기준선은 지금 실효 체력이 저승 40~87 · 지상 최대 124라는 것(색인의 「적 편성이 지역 밴드의 아래쪽에 몰려 있다」)이고, 판정은 **`tune` 하한 하나뿐**이다. 새 밴드를 만들지 않는다.

`support`가 이 계획의 알맹이다. 뒷칸 서포터가 앞칸 탱커를 회복·방어해 주는 편성이 「어느 칸을 먼저 뚫는가」를 처음으로 진짜 결정으로 만든다 — `ally` 경로는 이미 돌고 있고 지금 쓰는 적이 하나뿐이다.

### 4 · `guard`는 사거리를 못 넘는다

`guardFor`(`core/rules.ts:200`)가 아군에게 갈 피해를 지킴이에게 재지정한다. **같은 사거리 안에서만** 재지정하게 바꾼다.

- `012` 카드로 뒷칸을 때리려 하면 앞칸 지킴이가 대신 받는다 — 앞을 못 뚫으면 뒤에 못 닿는다
- `3`·`23` 카드는 지킴이를 **지나간다** — 좁은 사거리가 값을 갖는 유일한 이유고, 이것이 없으면 아홉 모양은 하향 아홉 종류일 뿐이다

이 한 줄이 §2와 §3을 서로 붙인다. **거리 시스템의 긴장은 전부 여기서 나온다.**

### 5 · 신의 입장 — 큐 하나, 입장 자리 둘

`CombatState`에 `pending: string[]`(적 정의 id)을 더한다. 조우 안에서만 산다.

**진노가 큐에 넣는다.** `data/gods.json`의 `wrath.on_encounter_start`에 `{ op: "join", god: "zeus", target: "self" }` 한 줄이고, `applyFavorStageEffects`는 **큐에만 넣는다** — 즉시 입장시키지 않는다(규칙이 한 줄이 되고, 아래 별칭 함정을 구조적으로 피한다). 이미 판에 서 있거나 큐에 있는 신은 다시 넣지 않는다.

**입장은 `admitPending(combat, definitions)` 하나가 한다.** 호출부는 둘뿐이다:

1. 조우 시작 개입 직후 (`sim/engine.ts:211`)
2. `endTurn` 맨 끝 — 적 행동·출혈·감전 청소가 다 끝난 뒤 (`core/combat.ts:155` 앞)

규칙:
- 빈 칸이 없으면 아무 일도 없다. **큐는 그대로 기다린다**
- 빈 칸이 여럿이면 **가장 앞(인덱스 최소)** 이다
- 시체를 그 자리에서 밀어낸다 — `defeated`는 이미 찍혀 있어 `rally`가 두 번 세지 않는다(`core/combat.ts:159`)
- 신의 정의는 조우 시작에 `enemyMap`(사전)에 미리 다 들어 있다. **판(`combat.enemies`)과 사전(`definitions`)을 갈라 둔다** — 그래야 `endTurn`의 `definitions.get`이 던지지 않고 `startTurn` 시그니처가 안 바뀐다

**카드 실행 중에는 절대 입장하지 않는다.** `executeCard`가 `chainTargets`를 카드 시작에 잡아 두므로(`core/rules.ts:241`) 실행 중 배열이 변하면 방금 들어온 신이 진행 중인 연쇄에 맞거나 별칭이 깨진다.

## 함정

- **사거리는 하향이고 `expectedValue`는 그것을 못 잰다.** 값 밴드(4~8)를 그대로 통과하는 카드가 실제로는 약해진다. 값 표를 미리 보정하지 않는다 — `tune` 하한이 잡으면 데이터로 되돌린다
- **`averageEnemies = 2`를 4로 올리지 않는다**(`tools/value.ts:34`). 올리면 광역·연쇄 전부가 재가격되어 129장에서 `value_outlier` 반려가 쏟아진다. 4칸 편성이 몇 층에 서는지 정해진 뒤 실측 평균으로만 움직인다
- **`regionBands`는 넷을 셀 수 없다**(`tools/validate.ts:334`). 지상 `count`가 `[2, 3]`이고 `hp`가 `[90, 170]`이라 4인 편성은 사람 수에서도 실효 체력 합에서도 반려된다. **`count` 상한만 4로 올린다** — 실효 체력은 앞/뒤 스탯 조정과 함께 실측으로 정하고, 상한을 넘으면 그때 한 번 올린다. 밴드를 새로 **만들지는** 않는다(CLAUDE.md)
- **4인 편성 + 앞칸 강화는 확실히 어렵다.** 하한을 깨면 다이얼은 셋 — 4인 그룹을 놓은 층 수, 앞칸 체력, 신 적 체력. 통과 못 하는 값을 테스트에 넣지도 깎지도 않는다(CLAUDE.md)
- **`guard`를 사거리에 묶으면 지킴이의 값이 내려간다.** `tokenWeights`에는 없지만 편성 세기에는 들어 있던 값이다 — `guardian` 편성의 실측이 먼저 움직인다
- **`hit_targets_in_turn` 천장이 3에서 4로 오른다.** `target_spread` 요구가 3에서 천장을 만나던 부채([R-29](../reviews/29-quest.md) §천장)가 열리지만 **요구 임계는 이번에 손대지 않는다**
- **스냅샷에 `pending`이 생긴다.** `runCombat`의 `snapshots`(`core/combat.ts:203`)와 반출 재생이 같은 꼴을 읽어야 한다
- **관측에 칸 번호가 없다.** `sim/engine.ts:253`이 `living()`만 실어 보낸다 — `EnemyView`에 칸을 실어야 UI가 구멍을 그린다
- **e2e의 빈 칸 검사**(`tools/e2e.ts:245` `halfEmpty`)가 의도적으로 빈 4칸 패널을 「빈 화면」으로 반려할 수 있다
- **아홉 모양을 다 쓰는 것이 목적이 되면 안 된다.** 쓰이지 않는 모양은 지우는 것이 옳다 — 리뷰에 실제 사용 분포를 적는다

## 다음 자리 — 이 계획이 안 하는 것

1. **`displace`를 「뒤로 밀어내기」로 바꾼다.** 지금은 적의 한 턴을 지우는 것이고 무게 6이 그것을 재고 있다(`tools/value.ts:8`). 거리 시스템이 서면 **밀쳐내기·심해 압력·격류 밀침이 이름 그대로** 작동하고, 앞칸 탱커를 뒤로 밀어 서포터를 앞으로 끌어내는 것이 포세이돈의 정체성이 된다. 완화 가치가 사라지므로 `pool_ratio`가 흔들린다 — **별도 계획**이다
2. **뒷칸 적의 조건 행동.** 앞칸 아군이 살아 있으면 서포트, 혼자 남으면 공격 — 패턴에 분기가 필요하고 지금 `pattern_mode`는 `cycle` 하나다
3. **요구에 자리 축.** 「앞칸만 죽이고 이겨라」류는 `target_spread`가 못 재는 새 축이다. 밸런스 게이트를 늘리지 않는 선에서만
4. **주인공 자리는 없다.** 영웅이 하나이므로 플레이어 위치는 만들지 않는다 — 넣으려면 은혜·파워가 전부 자리를 읽어야 한다
