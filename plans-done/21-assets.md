## 완료 정의

```bash
npm run art -- --check
#   → 누락 목록이 비어 있거나 남은 것이 의도된 우선순위 밖이다
npm run build && npm run size
#   → 자산 총량이 목표 안
npm run dev
#   → 1런 완주 → 반출 → npm run sim -- --replay  → 일치
```

## 1. 카드 일러스트 (~70장)

`art/cards/{card_id}.webp`에 넣는다. 코드 변경 없음(A-2.3).

**우선순위**

| 순위 | 대상 | 장수 |
|---|---|---|
| 1 | 시작 덱 카드 (신별 4장 × 5신) | 20 |
| 2 | 합성 카드 | 10 |
| 3 | 그 외 — `pick_rate` 높은 순 | ~40 |

**30장이면 화면에 뜨는 빈도의 대부분을 덮는다.**

---

## 2. 스프라이트 시트 이펙트

저빈도 극적 연출에 만든다(A-2.6).

| 대상 | 런당 | 우선순위 |
|---|---|---|
| 합성 카드 획득 | 0~1 | 1 |
| 역린 개입 (신별 5종) | 0~5 | 2 |
| 보스 등장 | 2 | 3 |
| 총애 전역 효과 (신별 5종) | ~10 | 4 |

**규격**(A-2.8) — `transform: translateX()` + `steps()`. 2x로 만들고 CSS에서 반으로 줄인다. 3072px 폭이면 세로로 감거나 시트를 나눈다. 프레임 수는 12 안팎.

---

## 3. 사운드 (~10종)

`audio/{event}.webm`에 넣는다. P-18의 `ui/sfx.ts`가 받는다.

| 사건 | 런당 | 지침 |
|---|---|---|
| 카드 사용 | ~100 | 아주 짧고 미묘하게 |
| 피격 · 회복 | ~200 | 짧게. 피해량에 따라 피치를 살짝 |
| 토큰 부여 | ~80 | 거의 들리지 않을 정도 |
| 요구 제시 | ~7 | 신의 개입임이 들리게 |
| 역린 개입 | 0~5 | 크게 |
| 합성 획득 | 0~1 | **가장 크게** |
| 승 · 패 | 1 | 런의 마침표 |

음소거 스위치는 P-18에 있다. 소리를 넣고 스위치가 도는지 확인한다.

---

## 4. 최적화

| 항목 | 목표 |
|---|---|
| 카드 일러스트 70장 | WebP, 장당 40KB 이하 → ~3MB |
| 스프라이트 시트 | WebP, 시트당 200KB 이하 |
| 사운드 10종 | 종당 30KB 이하 |

- **첫 화면에 필요한 것만 즉시 로드하고 나머지는 지연 로드한다**
- 카드 일러스트는 `loading="lazy"` + 손패에 들어올 때 프리페치
- 스프라이트 시트는 해당 연출이 처음 발생하기 전에 프리페치
- 배포 URL의 첫 로드 시간을 확인한다(T-1)
