## 동결 전 작업

### 1. UI 밀도 점검

**이 점검을 먼저 한다.** 결과가 손패 상한이나 적 수를 바꾸면 아래 2~5를 다시 돌려야 한다.

손패 상한 10(R-7.1)과 조우당 적 3체(R-6.3)는 여기서 동결되지만 UI는 P-17이다. **동결 전에 화면이 그 밀도를 버티는지 확인한다.**

Claude 아티팩트로 목업 하나를 만들어 눈으로 확인한다. 코드는 남기지 않는다.

```
카드 배틀러 UI가 이 밀도를 1280×800에 담을 수 있는지 확인하는 목업. 단일 HTML.

한 화면에 동시에:
- 적 3체. 각각 이름 / HP바 / 다음 행동 의도 텍스트("피해 6", "침수 2") / 상태 배지 3개
- 주인공. HP 100/100 / block 12 / 상태 배지 3개
- 게이지 2개. 각각 0~100 수치 + 단계 이름 (총애/평온/노여움/역린)
- 손패 10장. 카드마다 코스트 · 이름 · 2줄 효과문 · 일러스트 자리
- 에너지 3개 · 뽑기/버림 더미 수
- 상단 배너 1줄 (조건문 + 보상/대가)

상태 배지 = 한 글자 + 스택 수를 원 안에. 감 지 침 벽 반 혈 광 표 치 중에서.
카드 테두리 색 5종: #D4A017 #2E7D8F #7A8B5C #9B2226 #8E7CA6
어두운 배경. 외부 리소스 없이 자체 완결. 애니메이션 없음. 가로 스크롤 금지.

이 목업이 답할 것 — 하단에 두 줄로:
1. 다 들어가는가. 안 들어가면 무엇부터 줄여야 하는가
   (손패 상한? 적 수? 카드 크기? 효과문 줄 수?)
2. 배지 9개가 흩어져 있을 때 어느 대상 것인지 구분되는가
```

**안 들어가면 지금 고친다.**

| 줄일 것 | 고칠 곳 |
|---|---|
| 손패 상한 10 → 7~8 | R-7.1, S-5, `core/combat.ts` |
| 조우당 적 3체 → 2체 | R-6.3, T-6 조우 임계값, `data/enemies.json`의 `groups` |
| 카드 효과문 줄 수 | T-6 생성 프롬프트 |

적 수를 바꾸면 조우 총 HP와 의도 피해를 재산정하고, `min_enemies > 1` 요구를 점검한다.

### 2. 사람 플레이테스트 6~10런

`npm run play`(P-12)로 3~5명이 각 2런씩 돈다. 인원은 미리 섭외한다(A-4).

물어볼 것 — 상충 요구에서 어느 쪽을 왜 택했는지, 역린이 회복 불가능하게 느껴진 시점이 있었는지, 휴식과 전투 사이 선택이 실제로 고민이었는지.

**사람 런을 계측에 남긴다**(T-9.3).

### 3. HP 예산 확정

P-09의 `hp_curve` 실측과 사람 런을 함께 보고 R-8.3의 값을 확정한다. **판정 근거는 사람 플레이테스트다**(T-6 ⑤).

### 4. `block_efficiency` 확인

0.8~1.2 대역 안인지 본다(P-11). 벗어나면 **지금** 봇 정책을 고친다.

### 5. 룰 봇 승률 확인

분별 대역 15~70% 안인지 본다(T-6). 벗어나면 대역 안으로 되돌린다. 이 조정은 3번에 해당하므로 사람이 판단하고 계측에 남긴다.

3. `human_intervened`에 사유와 함께 남긴다
4. **이전 회차 데이터를 폐기한다**
