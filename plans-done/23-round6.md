## 완료 정의

B-0 3번 — **"승률 분산이 회차마다 줄어드는 것이 데이터로 확인된다"** — 에 처음으로 판정이 선다.

```bash
npm run tune -- --iteration 6
npm run sim -- --runs 32000 --stratified
npm run report -- --rounds 5,6
```

5회차와 6회차 두 점만 있으면 "감소"는 판정할 수 있다. 1~4회차는 폐기됐고 비교 대상이 아니다.

---

## 판정 규칙을 먼저 못 박는다

측정하고 나서 기준을 정하면 그건 판정이 아니다. **돌리기 전에 이 문장을 리뷰에 그대로 쓴다:**

> 6회차 `pairing_win_stddev` < 5회차 0.28793457135747436 이면 감소, 아니면 감소 아님.

`win_rate`는 판정 대상이 아니다. 어느 방향이든 기록만 한다(5회차 0.377, 반올림 후 0.391).

---

## 회차 사이에 바꿔도 되는 것

P-20에서 정한 표 그대로다.

| 바꿔도 됨 | 바꾸면 안 됨 |
|---|---|
| 프롬프트 (버전 올리고 통과율 비교) | 전역 파라미터 (`enemyDamageScale` 포함) |
| 카드·적·요구 수치 (게이트 안에서 자동 조정) | 룰 봇 정책 |
| 게이트 임계값 — 사유를 남기고 이전 회차와 구분 | 승리 조건 |

P-22가 게이트 규칙과 콘텐츠를 둘 다 바꿨으므로 `globalParamVersion` v3 → v4, `botPolicyVersion`은 정책을 안 건드렸다면 v4 유지다. **버전이 올라간 이상 5회차 숫자와 섞어 쓰지 않는다** — 비교는 하되 같은 표에 합산하지 않는다.

---

## 같이 처리하는 것

### `mark` 반올림 이후 32,000런 재측정

5회차 표(승률 0.377 / 편차 0.288)는 `mark`의 1.5배를 정수로 반올림하기 **전** 코드다. 2000런으로만 잰 반올림 후 값(0.391 / 0.292)은 산출물이 없다. 6회차 32,000런이 이 자리를 대신한다.

### 제우스 체크포인트

P-22 이후 제우스 행이 어떻게 됐는지 조합 행렬에서 확인한다. 5회차 기준 아테나와 짝일 때 0.561, 나머지 셋 ≤ 0.050이다. P-22의 제우스 상향이 이걸 움직였는지가 R2(신별 평균 EV 밴드)가 실제 축인지 아닌지의 답이다.

### 밴드 재동결

`matrix.test.ts`의 `pairing_win_stddev ≤ 0.35`는 5회차 이래 **덮은 숫자**다. 6회차 실측이 그보다 확실히 낮으면 그 값으로 내려 잠근다. 낮추지 않으면 다음 회차도 이 주석을 그대로 물려받는다.

`freeze`·`enemies`의 `block_efficiency`, `map`의 `low_rest_clear_rate`도 P-22가 완화 총량을 바꿨으니 같이 흔들린다. 재측정값으로 옮기고 각각 "재측정 / 되돌아오는 방향 / 덮음" 중 무엇인지 성격을 적는다.
