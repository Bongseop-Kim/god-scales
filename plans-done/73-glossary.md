# P-73 · 화면에 있는 것은 전부 사전에서 찾을 수 있다

UI와 테스트만 만진다 — 엔진·규칙·카드 데이터는 그대로다. 새 데이터 파일을 만들지 않는다:
설명의 원천은 이미 코드에 있는 표들(`opLabels`·`conditionText`·`intentBits`·`triggerLabels`·
`cards.json`)이고, 사전이 그 표들을 내보이기만 한다.

## 핵심

### 한 줄 결론

**은혜 조건이 `turn > 3` 원문으로 새는 것은 변환표 두 줄 누락이고, 사냥의 호흡·광전사의 각성이
안 읽히는 것은 파워 카드 설명이 데스크톱 호버 툴팁 한 곳에만 있기 때문이다. 변환표를 채우고,
「토큰과 기호」 사전이 파워·소멸·의도·효과 어휘·호의 단계까지 다 들도록 넓힌다.**

### 지금 무엇이 약한가

| 자리 | 지금 | 문제 |
|---|---|---|
| 은혜 조건 | 한글 변환표 `conditionText`(`ui/shared/card.tsx:69-86`)는 있으나 `graces.json`에만 있는 `turn > 3`·`enemy_count() >= 2` 두 개가 빠져 폴백(`card.tsx:87`)이 원문을 내보낸다 | 은혜 선택(`choices.tsx:118`)·인장 카드 툴팁(`card.tsx:207`)·aria까지 네 경로로 DSL이 샌다 |
| 회귀 테스트 | `test/ui.test.ts:525-530`이 `cards.json`의 `when`만 스캔 | `graces.json`이 구멍 — 같은 누락이 또 샌다 |
| 파워 카드 | 사냥의 호흡·광전사의 각성 등 6장. 효과 설명은 파워 칩의 네이티브 `title`(`combat.tsx:727`) **하나뿐** | 터치·스크린리더·사전 어디에도 없다 — 신고된 증상 |
| 소멸(exhaust) | 태그(`core/rules.ts:7`)와 동작(`core/combat.ts:185`)은 있는데 `ui/` 전체에 문자열 0회 | 카드 4장이 말없이 사라진다 |
| 적 의도 | `intentBits`(`combat.tsx:83-91`) 아이콘 6종 + 감춤(omen) | 범례가 사전에 없다 |
| 효과 어휘 | `CardSigns`(`card.tsx:129-147`)가 피해·방어·회복 아이콘만 설명 | 연쇄·자해·호의 등 `opLabels`(`card.tsx:47-56`)의 나머지가 정의 없음 |
| 호의 단계·은총 | 헌신/평온/분노/진노는 헤더 미터 title(`header.tsx:85`), 은총은 숫자만(`header.tsx:90`) | 사전·도움말 어디에도 없다 |

토큰 13종·적 능력 8종은 이미 사전에 완비다(`tokens.tsx:28-56`, `Record` 타입이 누락을 컴파일
에러로 막는다) — 「일부만 있다」는 인상은 위 빠진 것들 때문이다.

### 완료 모습

```text
은혜 선택   → "(4턴부터) 피해 3" — DSL 원문이 어디에도 안 보인다
토큰과 기호 → 토큰 · 적 능력 · 전투 상태 · 카드 기호(연쇄·자해·호의·소멸 포함)
              · 파워 6장(트리거+효과) · 적 의도 범례 · 호의 단계와 은총
파워 칩     → aria-label에도 트리거·효과가 실린다
소멸 카드   → 카드 면에 「소멸」 배지가 선다
```

## 구현

### 1. 은혜 조건 두 줄 (`ui/shared/card.tsx:69-86`)

- `conditionText`에 `"turn > 3": "4턴부터"`, `"enemy_count() >= 2": "적 둘 이상"` 추가.
  기존 항목("내 체력 절반 미만")과 같은 명사형 결이다. 표 한 곳을 채우면 네 노출 경로(은혜 선택·
  인장 요약·카드 툴팁·aria)가 한 번에 닫힌다. 새 파서를 만들지 않는다 — 배포된 조건은 전부
  리터럴이고, 폴백이 원문을 내보내는 것은 누락 경보로서 설계 의도다(`card.tsx:64-68` 주석).
- `test/ui.test.ts:526`의 스캔 소스에 `graces.json`을 합친다 — `when`을 가진 데이터 파일은
  둘뿐이므로 이걸로 구멍이 없다.

### 2. 사전에 파워 섹션 (`ui/shared/tokens.tsx` + 주입)

- `TokenDictionary`는 이미 `children`을 받는다(`tokens.tsx:132`) — `CardSigns`와 같은 꼴로
  파워 목록 컴포넌트를 주입한다(`app.tsx:376`).
- 내용은 데이터에서 그대로 생성: `cards.json`의 `tags.includes("power")` 6장 →
  `이름 · triggerLabels[trigger] · effectText(card)`. 새 문구를 쓰지 않고 기존 표기 체계를
  재사용한다. `triggerLabels`는 지금 `combat.tsx:671`에 있으니 export 위치만 옮긴다.
- 파워 칩(`combat.tsx:722`)의 `aria-label`에 `title`(`:727`)과 같은 내용을 싣는다 — 터치·
  스크린리더가 설명에 닿는 최소 경로다. 칩 클릭으로 사전 열기 같은 새 동선은 만들지 않는다 —
  사전은 이미 `T`와 「토큰」 버튼으로 연다.

### 3. 소멸 배지 + 카드 기호 보강 (`ui/shared/card.tsx`)

- 카드 면의 `kind` 슬롯(`card.tsx:250`, 지금 파워/전체 두 값)에 `소멸`을 더한다 —
  `tags.includes("exhaust")` 카드 4장이 대상이다.
- `CardSigns`에 줄 추가 (WRITING.md 명사형·키워드 표기):
  - 소멸 — "내면 이 전투에서 사라짐"
  - 연쇄 — "인접 칸에 추가 타격" (`core/rules.ts:452-455`)
  - 자해·호의 등 `opLabels`에 있으나 설명 없는 어휘를 마저 채운다. 이미 하는 damage/block/heal
    아이콘 설명과 같은 표 형식이다.

### 4. 의도 범례 · 호의 단계 · 은총 (`ui/shared/tokens.tsx`)

- `intentBits`(`combat.tsx:83-91`)를 export해서 사전에 「적 의도」 범례 섹션으로 편다 —
  공격·방어·회복·토큰·호의·대기 6종 + 「의도 감춤」(omen, `combat.tsx:619`).
- 「신과 호의」 섹션 하나: 헌신/평온/분노/진노 네 단계가 각각 무엇을 하는지, 은총 숫자가
  무엇인지(다음 은혜의 격·융합의 전제) 합니다체 한 문장씩(WRITING.md UI 문체). 수치·규칙
  설명은 UI의 몫이다 — 대사에 숫자를 못 넣는 만큼 여기가 정확해야 한다.
- 섹션이 늘어 사전이 길어지면 기존 오버레이 스크롤 규칙 안에서 해결한다 — 새 모달을 만들지
  않는다.

## 설명

### 왜 설명을 데이터 파일로 안 빼는가

토큰·패시브 설명은 `Record<TokenName, …>` 타입이라 누락이 컴파일 에러다 — JSON으로 빼면 이
보증을 잃는다. 파워·조건은 이미 있는 표기 함수(`effectText`·`conditionLabel`)가 데이터에서
생성하므로 별도 설명 원고 자체가 없다. 지금 구조가 이미 가장 게으른 구조다.

### 데이터가 답인 것과 원고가 답인 것

파워·카드 기호·조건은 **생성**(기존 함수 재사용)이고, 호의 단계·은총·의도 범례만 **원고**다.
원고는 전부 WRITING.md 문체 표를 따른다 — 토큰·효과 계열은 명사형, 시스템 설명은 합니다체
한 문장.
